配置与环境 ​

本指南涵盖 AdonisJS 应用中的配置。你将了解到：

  • config 目录中的配置文件
  • 环境变量与 .env 文件
  • 以类型安全的方式验证环境变量
  • .env 文件中的变量插值
  • 针对开发、测试和生产环境的特定 .env 文件
  • 在 Edge 模板中访问配置
  • 用于框架配置的 adonisrc.ts 文件

概述 ​

AdonisJS 中的配置分为三个不同的系统，每个系统都有特定的用途。

  • 配置文件包含你的应用设置。这些文件位于 config 目录中，定义数据库连接、邮件设置和会话配置等内容。

  • 环境变量存储在 .env 文件中，保存运行时密钥和因环境而异的值。API 密钥、数据库密码和环境特定的 URL 都属于此类。AdonisJS 支持针对不同环境的多个 .env 文件，并提供类型安全的验证，在启动时捕获缺失的变量。

  • adonisrc.ts 文件配置框架本身。它告诉 AdonisJS 你的工作区如何组织、要加载哪些提供者以及哪些命令可用。

配置文件 ​

配置文件位于项目根目录的 config 目录中。每个文件为应用的特定部分（数据库连接、邮件设置、身份认证、会话处理等）导出一个配置对象。

一个典型的 AdonisJS 项目开箱即包含多个配置文件。config/database.ts 文件配置数据库连接，config/mail.ts 处理邮件发送，config/auth.ts 定义身份认证设置。

以下是数据库配置文件的样子。

ts
import app from '@adonisjs/core/services/app'
import { defineConfig } from '@adonisjs/lucid'

const dbConfig = defineConfig({
  connection: 'sqlite',
  prettyPrintDebugQueries: true,
  connections: {
    sqlite: {
      client: 'better-sqlite3',
      connection: {
        filename: app.tmpPath('db.sqlite3'),
      },
      useNullAsDefault: true,
      migrations: {
        naturalSort: true,
        paths: ['database/migrations'],
      },
      debug: app.inDev,
    },
  },
})

export default dbConfig

邮件配置遵循类似的模式。

ts
import env from '#start/env'
import { defineConfig, transports } from '@adonisjs/mail'

const mailConfig = defineConfig({
  default: env.get('MAIL_MAILER'),

  from: {
    address: env.get('MAIL_FROM_ADDRESS'),
    name: env.get('MAIL_FROM_NAME'),
  },

  mailers: {
    resend: transports.resend({
      key: env.get('RESEND_API_KEY'),
      baseUrl: 'https://api.resend.com',
    }),
  },
})

export default mailConfig

declare module '@adonisjs/mail/types' {
  export interface MailersList extends InferMailers<typeof mailConfig> {}
}

注意这个配置文件如何通过 env.get() 引用环境变量。这是在配置中使用环境特定值的正确方式。配置文件定义结构和默认值，而 .env 文件提供实际值。

配置文件何时加载 ​

配置文件在应用启动周期中加载，早于路由和控制器就绪。这意味着你应该保持配置文件简单，避免导入模型、服务或控制器等应用级代码。

配置文件应只导入框架工具、定义配置对象和引用环境变量。导入应用代码会创建循环依赖，并导致应用在启动时失败。

在 Edge 模板中访问配置 ​

Edge 模板可以通过 config 全局变量访问应用的配置。这允许你直接在视图中引用配置值，而无需从控制器显式传递。

edge
<!DOCTYPE html>
<html>
<head>
  <title>{{ config('app.appName') }}</title>
</head>
<body>
  <footer>
    <p>Running in {{ config('app.nodeEnv') }} mode</p>
  </footer>
</body>
</html>

config() 辅助函数接受指向任何配置值的点号表示法路径。路径对应配置文件名及其中的属性。例如，config('database.connection') 读取 config/database.ts 中的 connection 属性。

你也可以提供默认值作为第二个参数。

edge
<p>{{ config('app.timezone', 'UTC') }}</p>

环境变量 ​

环境变量存储因环境而异的密钥和配置。在开发期间，你在 .env 文件中定义这些变量。在生产环境中，你必须通过托管提供商的 UI 或配置界面定义它们。

典型的 .env 文件如下所示。

bash
HOST=0.0.0.0
PORT=3333
APP_KEY=your-secret-app-key-here
MAIL_MAILER=resend
MAIL_FROM_ADDRESS=hello@example.com
MAIL_FROM_NAME=My App
RESEND_API_KEY=re_your_api_key_here

.env 文件已在 AdonisJS 启动套件的 .gitignore 中列出，因此你不会意外地将密钥提交到仓库。

APP_KEY ​

APP_KEY 是一个特殊的环境变量，AdonisJS 用它来加密 cookie、签名会话和其他加密操作。每个 AdonisJS 应用都需要一个 APP_KEY 才能安全运行。

运行 generate:key 命令来创建你的 APP_KEY。

bash
node ace generate:key

这会创建一个加密安全的随机密钥，并自动将其添加到你的 .env 文件中。

APP_KEY 必须保密。任何有权访问此密钥的人都可以解密你应用的加密数据并伪造会话令牌。部署到生产环境时，为每个环境（开发、预发布、生产）使用不同的 APP_KEY。切勿跨环境重用密钥。

如果你的 APP_KEY 泄露，请立即生成新的。这将使所有现有用户会话和加密数据失效。

在配置文件中使用环境变量 ​

配置文件通过 env 服务访问环境变量，该服务提供对 .env 文件值的类型安全访问。你导入 env 服务并使用变量名调用 env.get()。

ts
import env from '#start/env'

const apiKey = env.get('RESEND_API_KEY')

这种模式让你的配置保持有条理且经过验证。env 服务确保必需的变量存在，并在缺失时抛出清晰的错误。

你绝不应该在控制器、服务或其他应用代码中直接访问环境变量。始终通过配置文件访问它们。这为配置创建了单一的事实来源。

变量插值 ​

.env 文件支持变量插值，允许你在一个值中引用其他环境变量。使用 $VAR 或 ${VAR} 语法来插值变量。

bash
HOST=localhost
PORT=3333
APP_URL=http://$HOST:$PORT

在此示例中，APP_URL 解析为 http://localhost:3333。当你需要从其他变量组合值而无需重复时，这很有用。

你也可以使用花括号以增强清晰度，或在变量名与其他字符相邻时使用。

bash
S3_BUCKET=my-app-uploads
S3_REGION=us-east-1
S3_URL=https://${S3_BUCKET}.s3.${S3_REGION}.amazonaws.com

要在值中包含字面美元符号，请用反斜杠转义。

bash
PRICE=\$99.99

环境特定的 .env 文件 ​

AdonisJS 支持针对不同环境和用例的多个 .env 文件。框架按特定顺序加载这些文件，后面的文件会覆盖前面的。

文件用途Git 状态
.env所有环境的基础环境变量忽略
.env.local本地覆盖，在除测试外的所有环境中加载忽略
.env.development开发特定变量忽略
.env.staging预发布特定变量忽略
.env.production生产特定变量忽略
.env.test测试特定变量，在 NODE_ENV=test 时加载忽略
.env.example展示所需变量及占位符值的模板提交

加载顺序取决于你的 NODE_ENV 值。对于 NODE_ENV=development，AdonisJS 按以下顺序加载文件：

  1. .env（基础变量）
  2. .env.development（环境特定）
  3. .env.local（本地覆盖）

对于 NODE_ENV=test，顺序为：

  1. .env（基础变量）
  2. .env.test（测试特定）

注意 .env.local 在测试期间不会加载。这防止本地开发设置干扰测试运行。

.env.example 文件作为团队的文档。它列出所有必需的环境变量及占位符值，帮助新开发者设置本地环境。与其他 .env 文件不同，你应该将 .env.example 提交到版本控制。

bash
HOST=0.0.0.0
PORT=3333
APP_KEY=<generate-with-node-ace-generate:key>
DATABASE_URL=postgresql://user:password@localhost:5432/myapp
RESEND_API_KEY=<your-resend-api-key>

验证环境变量 ​

AdonisJS 在启动时通过 start/env.ts 文件验证环境变量。此验证确保你的应用不会以缺失或无效的配置启动，从而在早期捕获错误，而不是在运行时更难调试时才发现。

start/env.ts 文件使用基于模式的验证来定义你的应用期望哪些环境变量、它们的类型以及任何约束。

ts
import { Env } from '@adonisjs/core/env'

export default await Env.create(new URL('../', import.meta.url), {
  /**
   * 用于配置 HTTP 服务器的变量
   */
  HOST: Env.schema.string({ format: 'host' }),
  PORT: Env.schema.number(),

  /**
   * 应用特定变量
   */
  APP_KEY: Env.schema.string(),
  NODE_ENV: Env.schema.enum(['development', 'production', 'test'] as const),

  /**
   * 数据库配置
   */
  DATABASE_URL: Env.schema.string(),

  /**
   * 带默认值的可选变量
   */
  LOG_LEVEL: Env.schema.enum(['debug', 'info', 'warn', 'error'] as const).optional(),
  CACHE_DRIVER: Env.schema.string.optional(),
})

当你的应用启动时，AdonisJS 读取 .env 文件并根据此模式验证每个变量。如果必需变量缺失或值无效，应用会抛出描述性错误并拒绝启动。

该模式提供了多种验证方法。

Env.schema.string

验证值是非空字符串。你可以通过指定以下格式之一来验证字符串格式。

ts
// 验证值是有效的主机名或 IP
Env.schema.string({ format: 'host' })

// 验证值是有效的 URL
Env.schema.string({ format: 'url' })

// 验证值是有效的 URL（不含顶级域名）
Env.schema.string({ format: 'url', tld: false })

// 验证值是有效的 URL（不含协议）
Env.schema.string({ format: 'url', protocol: false })

// 验证值是有效的电子邮件地址
Env.schema.string({ format: 'email' })

Env.schema.number

验证并将值转换为数字

Env.schema.boolean

验证并将值转换为布尔值

Env.schema.enum

验证值是允许的选项之一

可选链

任何模式方法都可以通过链接 .optional() 变为可选。可选变量如果未设置则返回 undefined。

ts
import { Env } from '@adonisjs/core/env'

export default await Env.create(new URL('../', import.meta.url), {
  SENTRY_DSN: Env.schema.string.optional(),
  CACHE_DRIVER: Env.schema.string.optional()
})

验证后，env 服务提供完整的 TypeScript 类型推断。当你调用 env.get('NODE_ENV') 时，TypeScript 根据你的模式定义知道返回类型是 'development' | 'production' | 'test'。

adonisrc.ts 文件 ​

adonisrc.ts 文件配置框架本身，而不是你的应用。配置文件定义应用的行为，.env 存储密钥，而 adonisrc.ts 告诉 AdonisJS 你的工作区如何组织以及要加载哪些框架功能。

你很少需要直接修改此文件。大多数需要更改 adonisrc.ts 的操作都由 Ace 命令自动处理。当你运行 node ace make:provider 或 node ace make:command 时，这些命令会为你注册新的提供者或命令到 adonisrc.ts 文件中。

以下是基本的 adonisrc.ts 文件内容。

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  commands: [
    () => import('@adonisjs/core/commands'),
    () => import('@adonisjs/lucid/commands'),
  ],

  providers: [
    () => import('@adonisjs/core/providers/app_provider'),
    () => import('@adonisjs/core/providers/hash_provider'),
    () => import('@adonisjs/core/providers/vinejs_provider'),
    () => import('@adonisjs/session/session_provider'),
    () => import('@adonisjs/lucid/database_provider'),
    () => import('@adonisjs/auth/auth_provider'),
  ],

  preloads: [
    () => import('#start/routes'),
    () => import('#start/kernel')
  ],

  hooks: {
    buildStarting: [
      () => import('@adonisjs/vite/build_hook')
    ],
  },
})

providers 数组列出 AdonisJS 在应用启动时应加载的所有服务提供者。提供者设置数据库访问、身份认证和会话处理等框架功能。

commands 数组注册来自包的 Ace 命令。你应用 commands 目录中的命令会被自动发现，因此你只需在此列出包命令。

hooks 对象定义在特定生命周期事件期间运行的函数。buildStarting 钩子在你为生产构建应用时运行。

你可以在 AdonisRC 文件参考指南中了解更多可用属性。
