目录结构 ​

当你创建一个新的 AdonisJS 应用时，它会自带一套经过精心设计的默认目录结构，旨在保持项目整洁、可预测且易于重构。

这套结构体现了对大多数项目都行之有效的约定，但 AdonisJS 并不会把你束缚其中。你可以自由地重新组织文件和目录，以适应团队的工作流程。

根据你选择的启动套件，某些文件或目录可能有所不同。例如，Inertia 启动套件包含一个顶层的 inertia 目录，而超媒体启动套件则没有这个目录。

概览 ​

以下是刚创建的 AdonisJS 项目的样子。

sh
├── app
├── bin
├── config
├── database
├── resources
├── start
├── tests
├── ace.js
├── adonisrc.ts
├── eslint.config.js
├── package-lock.json
├── package.json
├── tsconfig.json
└── vite.config.ts
sh
├── apps
│   ├── backend           # AdonisJS 应用
│   │   ├── app
│   │   ├── bin
│   │   ├── config
│   │   ├── database
│   │   ├── start
│   │   ├── tests
│   │   ├── ace.js
│   │   ├── adonisrc.ts
│   │   ├── package.json
│   │   └── tsconfig.json
│   └── frontend          # 你的前端应用
│       ├── package.json
│       └── ...
├── package.json          # 带工作区的根 package.json
├── package-lock.json
└── turbo.json            # Turborepo 流水线配置

对于 API 套件：API 启动套件是由 Turborepo 管理的包含两个工作区的单体仓库。

apps/backend 目录包含一个标准的 AdonisJS 应用——下文的所有部分（app/、config/、start/ 等）都适用于该目录。apps/frontend 目录是你设置前端框架（TanStack Start、Next.js、Nuxt 或其他）的地方。

根 package.json 定义了工作区：

json
{
  "workspaces": ["apps/*"]
}

而 turbo.json 配置了 dev、build 及其他脚本，使其在两个应用中运行。当你从项目根目录运行 npm run dev 时，Turborepo 会并行启动后端和前端的开发服务器。

每个目录和文件都有特定的用途。以下部分解释每一项的作用以及你可能会在其中找到的内容。

app/ ​

app 目录组织应用领域逻辑的代码。例如，控制器、模型、邮件、中间件等都位于 app 目录内。

你可以随时在 app 目录中创建额外的文件夹，以更好地组织代码库。

sh
├── app
│   ├── controllers
│   ├── exceptions
│   ├── mails
│   ├── middleware
│   ├── models
│   ├── transformers
│   └── validators

bin/ ​

bin 目录包含用于在不同环境中启动 AdonisJS 应用的入口文件。

  • console.ts 文件使用 Ace 命令行框架来执行 CLI 命令。
  • server.ts 文件在 Web 环境中启动应用以监听 HTTP 请求。
  • test.ts 文件用于在测试环境中启动应用。

除非你想自定义应用在特定上下文中的启动方式，否则通常不需要修改这些文件。

sh
├── bin
│   ├── console.ts
│   ├── server.ts
│   └── test.ts

config/ ​

所有应用和第三方配置文件都位于 config 目录内。你也可以将应用本地的配置存储在此目录中。

sh
├── config
│   ├── app.ts
│   ├── auth.ts
│   ├── bodyparser.ts
│   ├── database.ts
│   ├── hash.ts
│   ├── limiter.ts
│   ├── logger.ts
│   ├── mail.ts
│   ├── session.ts
│   ├── shield.ts
│   ├── static.ts
│   └── vite.ts

database/ ​

database 目录存放与数据库层相关的产物。默认情况下，AdonisJS 附带配置为 SQLite 的 Lucid ORM；切换数据库不需要重新组织此文件夹。

  • migrations/ - 带版本控制的模式变更
  • seeders/ - 用于插入初始数据或测试数据的脚本
  • factories/ - 用于在测试或填充文件中生成模型实例的蓝图
  • schema.ts - 模型使用的自动生成的数据库模式
  • schema_rules.ts - 验证器使用的自动生成的模式规则

另请参阅：Lucid 文档

sh
database/
  ├── migrations/
  ├── seeders/
  ├── factories/
  ├── schema.ts
  └── schema_rules.ts

providers/ ​

providers 目录用于存储应用使用的服务提供者。你可以使用 node ace make:provider 命令创建新的提供者。

sh
├── providers
│  └── app_provider.ts

public/ ​

public 目录包含原始静态资源，这些资源无需任何编译步骤即可直接提供给浏览器。此目录中的文件可通过 http://localhost:3333/public/<file-name> URL 公开访问。

TIP

API 启动套件不包含 public 目录，因为后端仅提供 JSON 响应，不提供静态资源。

存储在此文件夹中的文件的典型示例包括：

  • 网站图标 (favicon.ico)
  • 爬虫文件 (robots.txt)
  • 静态图片 (logo.png, social-banner.jpg)
  • 可下载资源 (manual.pdf)

resources/ ​

resources 目录存储 Edge 模板和未编译的前端资源，如 CSS 和 JavaScript 文件。

TIP

API 启动套件不包含 resources 目录，因为后端仅提供 JSON 响应，不渲染 HTML 模板。

对于使用 Inertia（搭配 Vue 或 React）的应用，前端代码保存在 inertia 目录中，而 resources 目录仅包含根 Edge 模板。可以将这个根模板视为包含前端应用 HTML 外壳的 index.html 文件。

sh
├── resources
│   ├── css
│   ├── js
│   └── views
│       ├── home.edge
sh
├── resources
│   └── views
│       └── inertia_layout.edge

inertia/ ​

inertia 目录仅存在于使用 Inertia 启动套件的项目中。它代表一个包含前端源代码的子应用，包括 React 或 Vue 组件、页面和支持工具。

  • pages/ - 存储用 React 或 Vue 编写的 Inertia 页面。
  • app.(tsx|vue) - 客户端应用的主入口点。
  • ssr.(tsx|vue) - 服务端渲染（SSR）的入口点。
  • tsconfig.json - 前端代码库的 TypeScript 配置文件。默认值针对浏览器环境、JSX/TSX 语法和基于 Vite 的构建进行了优化。

你可以自由创建额外的子文件夹，如 components/、layouts/ 或 utils/，来组织你的前端代码。

sh
├── inertia
│   ├── css
│   ├── layouts
│   ├── pages
│   │   └── home.tsx
│   ├── app.tsx
│   ├── ssr.tsx
│   ├── tsconfig.json
│   └── types.ts

前后端清晰分离 ​

AdonisJS 在后端和前端之间保持清晰的边界。你绝不应该将后端代码（如模型、服务或转换器）导入到前端应用中。

在实践中，你的前端通过 HTTP 请求与后端通信，并接收纯 JSON 数据。AdonisJS 鼓励你明确地对这一现实建模。数据通过 API 响应获取和转换，而不是隐藏在共享抽象之后。

共享类型 ​

前端仍然可以依赖 AdonisJS 自动生成的共享 TypeScript 类型。这些类型存储在 .adonisjs/client 目录中，包含路由、props 和其他共享契约的类型定义。

这种方法让前端代码保持强类型，同时不损害客户端和服务器之间的分离。

TIP

你应该将 .adonisjs 目录提交到版本控制。框架依赖这些生成的文件进行导入解析（例如 #generated/controllers）和 TypeScript 类型检查。没有它们，生产构建和 CI 流水线将会失败。

我们建议阅读类型生成文档，了解 AdonisJS 如何创建共享类型。

start/ ​

start 目录包含你希望在应用启动生命周期中导入的文件。例如，注册路由和定义事件监听器的文件应该位于此目录中。

sh
├── start
│   ├── env.ts
│   ├── kernel.ts
│   └── routes.ts

AdonisJS 不会自动导入 start 目录中的文件。它仅仅作为一种约定，用于将相似的文件分组。我们建议阅读预加载文件和应用启动生命周期，以更好地理解哪些文件应保留在 start 目录下。

tests/ ​

tests 目录包含自动化测试。AdonisJS 使用 Japa 测试运行器。

测试组织在特定的子文件夹中。运行 unit 测试时，AdonisJS 会启动应用但不启动 HTTP 服务器。而在 functional 测试期间，我们会启动 HTTP 服务器和 Vite 开发服务器。

另请参阅：测试文档

sh
├── tests
│   ├── unit
│   ├── functional
│   └── bootstrap.ts

tmp/ ​

应用生成的临时文件存储在 tmp 目录中。例如，这些可能是用户上传的文件（开发期间生成的）或写入磁盘的日志。

tmp 目录必须被 .gitignore 规则忽略，你也不应该将其复制到生产服务器。

ace.js ​

ace.js 文件是执行 Ace 命令的入口点。该文件配置 JIT TypeScript 编译器，然后导入 bin/console.ts 文件。

adonisrc.ts ​

adonisrc.ts 是项目清单。它告诉 AdonisJS 如何发现和加载应用的各个部分，并包含以下配置：

  • 目录别名（用于 app、start 等）
  • 预加载文件
  • 注册的提供者和命令
  • 组装器钩子

另请参阅：AdonisRC 文件参考

eslint.config.js ​

此文件为项目配置 ESLint。默认规则针对 TypeScript 和 AdonisJS 约定进行了调整。你可以修改或扩展此配置以匹配团队的风格。

package.json 和 package-lock.json ​

  • package.json - 项目元数据、脚本和依赖声明。
  • package-lock.json - 锁定确切的依赖版本以确保安装一致。

tsconfig.json ​

tsconfig.json 控制 TypeScript 编译器选项、模块解析和路径别名。提供的配置适用于开发和生产构建。不过，你可以调整编译器设置以匹配你的特定工作流程。

TIP

AdonisJS 依赖 experimentalDecorators 来实现依赖注入、Ace 命令和 Lucid ORM。

以下配置选项是 AdonisJS 内部正常工作所必需的。

json
{
  "compilerOptions": {
    "module": "NodeNext",
    "isolatedModules": true,
    "declaration": false,
    "outDir": "./build",
    "esModuleInterop": true,
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "skipLibCheck": true
  },
  "include": ["**/*", ".adonisjs/server/**/*"]
}
json
{
  "compilerOptions": {
    "module": "NodeNext",
    "isolatedModules": true,
    "declaration": false,
    "outDir": "./build",
    "esModuleInterop": true,
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "skipLibCheck": true
  },
  "references": [
    {
      "path": "./tsconfig.inertia.json"
    }
  ],
  "include": ["**/*", ".adonisjs/server/**/*"]
}

vite.config.ts ​

当项目使用 Vite（Edge 或 Inertia 启动套件）时，vite.config.ts 定义了前端资源如何编译和提供。如果你需要特殊的打包行为，可以在此处自定义入口点、别名和插件设置。
