简介 ​

AdonisJS 是一个后端优先、类型安全的框架，用于使用 Node.js 和 TypeScript 构建 Web 应用。它提供了编写和维护完整后端所需的核心构建块，无需借助第三方服务来处理身份认证、文件上传、缓存和速率限制等常见功能。

每个 AdonisJS 应用都用 TypeScript 编写，以 ESM 模式运行，并在整个技术栈中提供端到端的类型安全。

AdonisJS 适合谁？ ​

AdonisJS 专为构建生产级 Web 应用的开发者设计，他们需要比 Express 更多的结构，但比企业级框架更少的繁文缛节。如果你正在构建 REST API、服务端渲染应用或全栈 Web 应用，并且看重约定优于配置，那么 AdonisJS 会让你感到得心应手。

如果你来自 Laravel、Rails 或 Django，你会认出 MVC 模式和约定。如果你用过 Express 或 Fastify，你会欣赏它在不牺牲简洁性的同时，提供了结构和开箱即用的功能。

为什么选择 AdonisJS ​

AdonisJS 提供了全功能框架应有的结构、一致性和工具链，同时在设计上保持轻量和现代。

它适合重视以下方面的团队：

  • 后端逻辑的自主权：在内部构建关键功能，而不是依赖外部服务来处理身份认证、速率限制或后台任务。

  • 一致的开发者体验：每个 AdonisJS 应用都遵循相同的约定和目录结构，便于新开发者上手和团队间的知识共享。

  • 统一的生态系统：核心功能在一致的质量标准下共同维护，消除了依赖碎片化。

  • 可扩展性和自由度：核心功能由底层包构建而成，你可以直接使用这些包来创建自定义流程、集成或抽象。

AdonisJS 旨在为真实世界的后端应用提供所需的一切，同时保持平易近人且易于配置。

用 AdonisJS 能构建什么？ ​

AdonisJS 专为真实世界的后端应用而设计：

  • REST API：为移动应用或 SPA 构建类型安全的 API。许多公司使用 AdonisJS 来支撑处理数百万请求的 API。

  • 全栈 Web 应用：使用 Edge 模板实现服务端渲染页面，或搭配 Vue/React 构建混合应用。MVC 结构让你的后端在应用增长时保持条理。

  • SaaS 平台：构建多租户应用，而无需依赖第三方服务来实现身份认证、授权或后台任务等核心功能。

无论你是在构建初创公司的 MVP 还是服务数千用户的生产系统，AdonisJS 都能提供基础支撑，而不会妨碍你。

实用，而非过度设计 ​

许多框架引入了企业级抽象，使项目复杂化却没有增加清晰度。AdonisJS 则专注于不同的方式。

它提供了一种实用的开发模型，专注于清晰性、类型安全和可维护性，而不是为了模式而模式。该框架通过约定鼓励良好的结构，但从不强制实施繁重的架构分层。

该框架开箱即用地包含路由、中间件、验证和 ORM 等功能，让团队可以专注于应用逻辑，而不是反复构建常见模式。

AdonisJS 的 API 是函数式且现代的。你可以在需要结构化方法的地方使用基于类的组件，例如控制器、模型和服务。

AdonisJS 的对比 ​

对比 Express/Fastify：AdonisJS 提供了 Express 所缺乏的结构和约定，同时保持同样出色的性能。你无需自己组装各种包，而是开箱即得一个集成工具包。

对比 NestJS：AdonisJS 专注于实用模式，而非企业级抽象。没有满屏的装饰器，没有需要配置的依赖注入容器，只有遵循清晰约定的直白 TypeScript 代码。

对比 Laravel/Rails：如果你喜欢 Laravel 或 Rails 但在 Node.js 中工作，AdonisJS 带来了同样一致的体验：迁移、填充文件、工厂、模型关系和一致的约定。

当你想要全功能框架的生产力，又不想承受企业级模式的复杂性或极简框架的碎片化时，请选择 AdonisJS。

具有可配置视图层的 MVC ​

AdonisJS 使用**模型-视图-控制器（MVC）**模式，将数据、逻辑和展示分离。视图层是可选的，可以根据你的需求进行配置。

你可以使用：

  • Edge，官方服务端模板引擎，用于传统的全栈应用。

  • Vue、React 或其他前端框架来构建单页或混合应用。

  • 或者在构建 API 优先或仅后端的服务时，完全跳过视图层。

大多数后端代码，如路由、控制器、模型和中间件，无论你如何渲染视图都保持不变。这种灵活性允许你从服务端渲染开始，之后再过渡到现代 SPA 架构，而无需修改核心后端逻辑。

生态系统与稳定性 ​

AdonisJS 自 2015 年以来一直在积极开发，版本 7 代表了多年真实世界使用和打磨的成果。该框架由其创建者全职维护，并得到核心团队成员和活跃社区的支持。

生态系统包括满足常见后端需求的官方包，全部由核心团队按照相同的质量标准维护。社区包则针对支付处理、云存储和第三方集成等特定需求扩展功能。

所有文档、工具和包都遵循语义化版本控制，确保稳定的升级和长期可维护性。
