数据库与模型 ​

在本章中，你将创建 Post 和 Comment 资源的模型和迁移，建立它们之间的关系，使用工厂和填充文件生成虚拟数据，并使用 REPL 查询数据。

概述 ​

本章介绍 Lucid，AdonisJS 的 SQL ORM。你不再编写原始 SQL 查询，而是使用称为模型的 JavaScript 类来表示数据库表。在本章及教程的其余部分，你将完全通过模型与数据库交互。

一个重要区别：模型定义你如何与数据交互，但它们不修改数据库结构。那是迁移的工作，迁移负责创建和修改表。在构建 DevShow 的数据库结构时，你会同时使用两者。

TIP

关于学习的说明： 本章一次性介绍了多个数据库概念。如果你没有完全理解所有内容，不用担心——目标是通过实践来学习并让某些东西运转起来。更深入的理解会随着实践而来。

创建 Post 模型 ​

我们的应用需要帖子，所以让我们创建一个 Post 模型及其对应的数据库迁移。在 AdonisJS 中，每个数据库表创建一个模型。Lucid 使用命名约定自动将模型连接到它们的表——Post 模型映射到 posts 表，User 模型映射到 users 表，依此类推。

步骤 1：生成模型和迁移 ​

运行此命令一次性创建两个文件。

bash
node ace make:model Post -m

-m 标志告诉 Ace 在创建模型的同时创建一个迁移文件。你会看到以下输出。

bash
DONE:    create app/models/post.ts
DONE:    create database/migrations/1763866156451_create_posts_table.ts

步骤 2：了解生成的模型 ​

让我们看看模型文件中生成了什么。

ts
import { PostSchema } from '#database/schema'

export default class Post extends PostSchema {
}

该模型继承自 PostSchema——一个从数据库迁移自动生成的类。你不需要在模型文件中定义列。当你运行迁移时，AdonisJS 会扫描数据库表并生成 database/schema.ts 文件，其中包含所有列定义、类型和装饰器。模型文件是你添加关系和业务逻辑的地方。

步骤 3：在迁移中定义表结构 ​

让我们更新迁移文件以定义数据库表结构。这是你添加列的地方——模型会在运行迁移后自动获取它们。

ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'posts'

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments('id')
      table.string('title').notNullable()
      table.string('url').notNullable()
      table.text('summary').notNullable()
      table.timestamp('created_at')
      table.timestamp('updated_at')
    })
  }

  async down() {
    this.schema.dropTable(this.tableName)
  }
}

关于迁移的几个重要事项：

  • up 方法在你执行迁移时运行并创建表。
  • down 方法在你回滚迁移时运行并删除表。
  • 注意数据库中的列名使用 snake_case（如 created_at），而模型属性使用 camelCase（如 createdAt）。Lucid 会自动处理这种转换。

创建 Comment 模型 ​

让我们按照创建帖子时使用的相同流程创建 Comment 模型。

步骤 1：生成模型和迁移 ​

运行此命令。

bash
node ace make:model Comment -m

你会看到显示已创建文件的输出。

bash
DONE:    create app/models/comment.ts
DONE:    create database/migrations/1763866347711_create_comments_table.ts

步骤 2：在迁移中定义表结构 ​

更新迁移以创建带有 content 列的 comments 表。

ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'comments'

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments('id')
      table.text('content').notNullable()
      table.timestamp('created_at')
      table.timestamp('updated_at')
    })
  }

  async down() {
    this.schema.dropTable(this.tableName)
  }
}

运行迁移 ​

现在让我们通过运行迁移在你的数据库中创建这些表。

bash
node ace migration:run

你会看到显示哪些迁移被执行的输出。

bash
❯ migrated database/migrations/1763866156451_create_posts_table
❯ migrated database/migrations/1763866347711_create_comments_table

你的数据库现在有了 posts 和 comments 表！你还会注意到 database/schema.ts 已更新，包含 PostSchema 和 CommentSchema 类及所有列定义。此文件在每次运行迁移时自动生成——你永远不需要手动编辑它。

迁移记录在数据库中一个特殊的 adonis_schema 表中。一旦迁移成功运行，即使你多次执行 node ace migration:run，它也不会再次运行。

添加关系 ​

目前我们的帖子和评论独立存在，但在我们的 DevShow Web 应用中，评论属于帖子，帖子属于用户。我们需要在数据库和模型中建立这些连接。

要创建这些关系，我们需要在表中添加外键列。外键是引用另一个表主键的列。例如，comments 表中的 post_id 列将引用 posts 表中的 id 列，将每条评论链接到它的帖子。

由于我们的表已经存在，我们将创建一个新迁移来添加这些外键列。

步骤 1：创建外键迁移 ​

以下命令将创建一个新的迁移文件来修改我们现有的表。

bash
node ace make:migration add_foreign_keys_to_posts_and_comments

步骤 2：添加外键列 ​

更新迁移文件以添加外键列。

ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  async up() {
    /**
     * 向 posts 表添加 user_id
     */
    this.schema.alterTable('posts', (table) => {
      table.integer('user_id').unsigned().notNullable()
      table.foreign('user_id').references('users.id').onDelete('CASCADE')
    })

    /**
     * 向 comments 表添加 user_id 和 post_id
     */
    this.schema.alterTable('comments', (table) => {
      table.integer('user_id').unsigned().notNullable()
      table.foreign('user_id').references('users.id').onDelete('CASCADE')

      table.integer('post_id').unsigned().notNullable()
      table.foreign('post_id').references('posts.id').onDelete('CASCADE')
    })
  }

  async down() {
    this.schema.alterTable('posts', (table) => {
      table.dropForeign(['user_id'])
      table.dropColumn('user_id')
    })

    this.schema.alterTable('comments', (table) => {
      table.dropForeign(['user_id'])
      table.dropForeign(['post_id'])
      table.dropColumn('user_id')
      table.dropColumn('post_id')
    })
  }
}

关于此迁移需要理解的几点：

  • 我们使用 alterTable 而不是 createTable，因为我们在修改现有的表。
  • 外键约束通过确保 user_id 或 post_id 始终引用相应表中的有效记录来帮助维护数据完整性。
  • onDelete('CASCADE') 意味着如果用户或帖子被删除，他们的评论也会自动删除。

步骤 3：运行迁移 ​

bash
node ace migration:run
bash
❯ migrated database/migrations/1732089800000_add_foreign_keys_to_posts_and_comments

步骤 4：在 Post 模型中定义关系 ​

现在数据库有了外键列，让我们更新模型来定义这些关系。

ts
import { PostSchema } from '#database/schema'
import { hasMany, belongsTo } from '@adonisjs/lucid/orm'
import type { HasMany, BelongsTo } from '@adonisjs/lucid/types/relations'
import Comment from '#models/comment'
import User from '#models/user'

export default class Post extends PostSchema {
  /**
   * 一个帖子有多条评论
   */
  @hasMany(() => Comment)
  declare comments: HasMany<typeof Comment>

  /**
   * 一个帖子属于一个用户
   */
  @belongsTo(() => User)
  declare user: BelongsTo<typeof User>
}

记住，像 title、url、summary 和 userId 这样的列定义已由 PostSchema（从你的迁移自动生成）处理。模型文件是你添加关系和业务逻辑的地方。

@hasMany 装饰器定义一对多关系——一个帖子有多条评论。@belongsTo 装饰器定义反向关系——一个帖子属于一个用户。

步骤 5：在 Comment 模型中定义关系 ​

ts
import { CommentSchema } from '#database/schema'
import { belongsTo } from '@adonisjs/lucid/orm'
import type { BelongsTo } from '@adonisjs/lucid/types/relations'
import Post from '#models/post'
import User from '#models/user'

export default class Comment extends CommentSchema {
  /**
   * 一条评论属于一个帖子
   */
  @belongsTo(() => Post)
  declare post: BelongsTo<typeof Post>

  /**
   * 一条评论属于一个用户
   */
  @belongsTo(() => User)
  declare user: BelongsTo<typeof User>
}

完美！我们的模型现在理解了它们的关系。当你加载一个帖子时，你可以通过 post.comments 轻松访问它的评论；当你加载一条评论时，你可以通过 comment.post 访问它的帖子，或通过 comment.user 访问它的用户。

TIP

我们没有在 User 模型上添加反向的 hasMany 关系（例如 user.posts 或 user.comments），因为本教程中不需要它们。如果你的应用需要从用户侧查询帖子或评论，你可以稍后添加它们。

创建工厂 ​

现在我们的模型和数据库表已经准备好了，我们需要用虚拟数据填充它们以用于开发和测试。工厂充当创建填充了逼真假数据的模型实例的蓝图。你只需定义一次蓝图，然后用一行代码生成任意数量的实例。

AdonisJS 工厂使用一个名为 Faker 的库来生成逼真的数据，如姓名、URL、文本段落等。这使你的虚拟数据看起来真实，而不是明显的测试占位符。

步骤 1：创建 Post 工厂 ​

bash
node ace make:factory Post
bash
DONE:    create database/factories/post_factory.ts

这会创建一个工厂文件，我们将在其中定义如何生成虚拟 Post 数据。

步骤 2：定义 Post 工厂数据 ​

打开工厂文件并配置每个 Post 要生成的数据。

ts
import factory from '@adonisjs/lucid/factories'
import Post from '#models/post'

export const PostFactory = factory
  .define(Post, async ({ faker }) => {
    return {
      title: faker.helpers.arrayElement([
        'My First iOS Weather App',
        'Personal Portfolio Website with Dark Mode',
        'Real-time Chat Application',
        'Expense Tracker Progressive Web App',
        'Markdown Blog Engine',
        'Recipe Finder with AI Recommendations',
        '2D Platformer Game in JavaScript',
        'Task Management Dashboard',
        'URL Shortener with Analytics',
        'Fitness Tracking Mobile App',
      ]),
      url: faker.internet.url(),
      summary: faker.lorem.paragraphs(3),
    }
  })
  .build()
  • faker.helpers.arrayElement() 从数组中随机选择一个标题。
  • faker.internet.url() 生成一个逼真的 URL。
  • faker.lorem.paragraphs(3) 创建三段占位文本。

步骤 3：创建 Comment 工厂 ​

现在让我们使用相同的流程为评论创建工厂。

bash
node ace make:factory Comment
bash
DONE:    create database/factories/comment_factory.ts

步骤 4：定义 Comment 工厂数据 ​

打开 Comment 工厂并添加数据生成逻辑。

ts
import factory from '@adonisjs/lucid/factories'
import Comment from '#models/comment'

export const CommentFactory = factory
  .define(Comment, async ({ faker }) => {
    return {
      content: faker.lorem.paragraph(),
    }
  })
  .build()

Comment 工厂更简单。它只需要使用 faker.lorem.paragraph() 生成 content 字段，这会创建一段文本。我们将在填充文件中处理 userId 和 postId 关系。

创建填充文件 ​

工厂定义如何创建假数据，但它们不会自动创建数据。这就是填充文件的用武之地——它们是使用工厂向数据库填充实际数据的脚本。每次你重置数据库或队友克隆项目时，运行 node ace db:seed 就会向数据库填充一致、逼真的数据。

步骤 1：创建填充文件 ​

让我们创建一个将生成帖子和评论的填充文件。

bash
node ace make:seeder PostSeeder
bash
DONE:    create database/seeders/post_seeder.ts

步骤 2：实现填充逻辑 ​

现在打开填充文件并添加创建带有评论的帖子的逻辑。

ts
import User from '#models/user'
import { BaseSeeder } from '@adonisjs/lucid/seeders'
import { PostFactory } from '#database/factories/post_factory'
import { CommentFactory } from '#database/factories/comment_factory'

export default class extends BaseSeeder {
  async run() {
    const user = await User.findByOrFail('email', 'jane@example.com')
    const posts = await PostFactory.merge({ userId: user.id }).createMany(10)

    for (const post of posts) {
      await CommentFactory.merge({ postId: post.id, userId: user.id }).createMany(
        Math.floor(Math.random() * 3) + 3
      )
    }
  }
}

让我们分解这个填充文件做了什么：

首先，我们获取邮箱为 jane@example.com 的用户。这是我们在上一章探索 CLI 和 REPL 时创建的用户。如果你跟着做了，这个用户应该存在于你的数据库中。如果用户不存在，findByOrFail 方法会抛出错误。

接下来，我们使用 PostFactory.merge({ userId: user.id }).createMany(10) 创建 10 个帖子。merge() 方法在这里很重要——它将额外数据与工厂生成的值合并。我们需要它来设置每个帖子的 userId 外键。没有它，外键约束会失败，因为 userId 会是 undefined。

然后，对于每个帖子，我们使用类似的方法创建 3 到 5 条评论。公式 Math.floor(Math.random() * 3) + 3 生成 3 到 5 之间的随机数。

步骤 3：运行填充文件 ​

现在执行填充文件来填充你的数据库。

bash
node ace db:seed
bash
❯ running PostSeeder

你的数据库现在有 10 个帖子，每个帖子都有几条评论！

理解我们使用的工具 ​

在我们继续查询数据之前，让我们花点时间理解我们构建了什么。AdonisJS 提供了专门的数据库工具，每个都有特定的用途。

迁移定义数据库结构。它们创建表、添加列并建立约束。将它们视为转换数据库模式的指令。当你运行 node ace migration:run 时，这些指令执行并修改你的数据库结构。作为额外好处，AdonisJS 会自动生成 database/schema.ts 文件，为你的模型提供列定义。

模型是你与数据库表交互的 JavaScript 接口。它们继承提供列定义的自动生成模式类，你在其上添加关系和业务逻辑。模型提供了一个干净、类型安全的 API 来查询和操作数据，而无需编写原始 SQL。

工厂为你的模型生成逼真的虚拟数据。你不必一遍又一遍地手动创建测试数据，只需定义一次蓝图，工厂就会创建你需要的任意数量的逼真实例。这在开发和测试期间非常宝贵。

填充文件是向数据库填充数据的脚本。它们通常使用工厂来生成数据，但也可以创建特定记录或从其他来源导入数据。运行 node ace db:seed 会执行所有填充文件，给你一个一致的数据库状态。

这些工具协同工作：迁移塑造数据库，模型与之交互，工厂生成数据，填充文件填充数据。每个工具都专注于其特定工作，使你的数据库工作流有条理且可维护。

使用 REPL 查询数据 ​

现在我们的数据库中有数据，让我们使用 AdonisJS 的 REPL（Read-Eval-Print Loop）来探索它。REPL 是一个交互式 shell，你可以运行 JavaScript 代码并实时与模型交互。

启动 REPL 并加载模型 ​

首先，启动 REPL。

bash
node ace repl

REPL 启动后，加载所有模型。

ts
await loadModels()

这使你的所有模型在 models 对象下可用。

获取所有帖子 ​

让我们从数据库获取所有帖子。

ts
await models.post.all()

你会看到包含所有 10 个帖子及其数据的数组。

ts
[
  Post {
    id: 1,
    title: 'My First iOS Weather App',
    url: 'https://example.com/fp',
    summary: 'Lorem ipsum dolor sit amet...',
    userId: 1,
    createdAt: DateTime { ... },
    updatedAt: DateTime { ... }
  },
  // ... 还有 9 个帖子
]

每个帖子都是 Post 模型实例，而不是普通的 JavaScript 对象。

按标题搜索帖子 ​

让我们使用 query() 方法搜索标题中包含 "Task Management" 的帖子。

ts
await models.post.query().where('title', 'like', '%Task Management%')

query() 方法返回一个基于 Knex 构建的可链式查询构建器，在保持 JavaScript 的同时为你提供强大的 SQL 查询能力。你会看到匹配的帖子数组，根据工厂生成的内容，可能只有一个或零个。

获取帖子并加载其评论 ​

现在让我们演示如何使用关系。首先，通过 ID 获取特定帖子。

ts
const post = await models.post.find(1)

帖子已加载，但它的评论尚未加载（关系默认是懒加载的）。使用 load 方法加载 comments 关系。

ts
await post.load('comments')

现在你可以访问评论了。

ts
post.comments

你会看到属于这个帖子的所有评论。

使用 preload 高效加载关系 ​

你也可以在最初获取帖子时加载关系。

ts
const postWithComments = await models.post.query().preload('comments').first()

这在一次操作中获取第一个帖子及其评论。preload 方法比单独加载关系更高效，因为它避免了 N+1 查询问题。它不是为帖子做一次查询然后为每条评论做一次查询，而是总共只做两次查询。

退出 REPL ​

探索完成后，输入 .exit 离开 REPL 并返回终端。
