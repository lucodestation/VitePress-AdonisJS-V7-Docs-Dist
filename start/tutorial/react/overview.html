构建 DevShow - 一个社区展示网站 ​

在本教程中，你将构建 DevShow。DevShow 是一个小型的社区展示网站，用户可以在其中分享他们构建的东西。 每个用户都可以创建账户、发布“展示条目”（一个项目、工具、实验或任何他们引以为豪的东西），并浏览其他人创建的条目。

概述 ​

我们在本教程中采用动手实践的方式，从头到尾构建一个真实的应用。你不是孤立地学习各项功能，而是会看到 AdonisJS 和 React 中的所有部分如何协同工作：路由、控制器、模型、验证、身份认证、转换器和 React 组件共同协作，创建一个可运行的 Web 应用。

完成本教程后，你将构建出：

  • 帖子列表和详情页 - 显示所有帖子和单个帖子详情及评论
  • 帖子创建和编辑 - 带有验证的创建和更新帖子的表单
  • 评论系统 - 允许用户对帖子发表评论
  • 授权 - 确保用户只能编辑/删除自己的帖子和评论
  • 导航和样式 - 在页面之间具有适当导航的精美 UI

身份认证系统（注册、登录、登出）已包含在你的启动套件中，并且功能完整。

了解启动套件 ​

我们从 AdonisJS Inertia + React 启动套件开始，它已经内置了身份认证。让我们打开路由文件，看看有什么可用。

ts
import { middleware } from '#start/kernel'
import { controllers } from '#generated/controllers'
import router from '@adonisjs/core/services/router'

router.on('/').renderInertia('home')

/**
 * 注册和登录路由 - 仅对访客可访问
 */
router
  .group(() => {
    router.get('signup', [controllers.NewAccount, 'create'])
    router.post('signup', [controllers.NewAccount, 'store'])

    router.get('login', [controllers.Session, 'create'])
    router.post('login', [controllers.Session, 'store'])
  })
  .use(middleware.guest())

/**
 * 登出路由 - 仅对已认证用户可访问
 */
router
  .group(() => {
    router.post('logout', [controllers.Session, 'destroy'])
  })
  .use(middleware.auth())

启动套件为我们提供了用户注册、登录和登出路由。注意 middleware.guest() 如何确保只有已登出的用户才能访问注册/登录，而 middleware.auth() 保护登出路由。

TIP

我们将在整个教程中使用 auth 中间件来保护需要身份认证的路由。

控制器如何与 Inertia 协作 ​

让我们看看注册控制器，了解请求如何通过 Inertia 在应用中流转。

ts
import User from '#models/user'
import { signupValidator } from '#validators/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class NewAccountController {
  async create({ inertia }: HttpContext) {
    return inertia.render('auth/signup')
  }

  async store({ request, response, auth }: HttpContext) {
    /**
     * 验证提交的数据
     */
    const payload = await request.validateUsing(signupValidator)

    /**
     * 在数据库中创建新用户
     */
    const user = await User.create(payload)

    /**
     * 自动登录
     */
    await auth.use('web').login(user)

    /**
     * 重定向到首页
     */
    response.redirect().toRoute('home')
  }
}

每个控制器方法接收一个 HTTP 上下文对象作为第一个参数。上下文包含当前请求的所有信息：请求数据、响应对象、认证状态、Inertia 渲染器等。我们只解构需要的属性（inertia 用于渲染 React 组件，request 用于表单数据，response 用于重定向，auth 用于身份认证）。

create 方法使用 inertia.render() 渲染注册表单。不像传统的服务端渲染应用那样返回 HTML，Inertia 发送一个包含组件名称和任何属性的 JSON 响应。你的 React 前端接收此响应并渲染相应的组件。

store 方法做繁重的工作。它验证数据、创建用户、登录并重定向到首页。这种将验证器、模型和认证结合在一起的方式，你将在整个教程中看到。

你可能注意到控制器引用了 User 模型和 signupValidator。启动套件已经包含了这些。我们将在数据库与模型章节探讨模型如何工作，在表单与验证章节探讨验证器。

关于 Inertia 和 React ​

如果你使用过 Next.js 或 Remix 等元框架，这个启动套件可能看起来不寻常。我们的大部分代码位于 AdonisJS（后端），React 仅用于渲染视图。 没有前端路由，没有在服务器和客户端同时运行的同构代码，也没有复杂的状态管理库。

这是有意为之的。Inertia 的理念很简单：保持前后端分离，但让它们无缝协作。

  • 你的后端（AdonisJS）处理路由、身份认证、数据库查询、验证和业务逻辑
  • 你的前端（React）处理渲染和用户交互
  • Inertia 充当粘合剂，将控制器中的 JSON 响应发送到你的 React 组件

如果你是第一次听说 Inertia，可能想访问 inertiajs.com 了解更多关于其理念的信息。或者直接读完本教程，亲自看看它比元框架提供的复杂性鸡尾酒简单多少。

以下是 AdonisJS + Inertia 应用中请求的流转方式：

浏览器请求
    ↓
AdonisJS 路由
    ↓
控制器（验证、查询数据库等）
    ↓
inertia.render('component-name', props)
    ↓
React 组件（通过 Vite 渲染）
    ↓
浏览器响应

注册表单如何工作 ​

当控制器调用 inertia.render('auth/signup') 时，Inertia 会在 inertia/pages/auth/signup.tsx 查找 React 组件并渲染它。让我们看看那个组件。

tsx
import { Form } from '@adonisjs/inertia/react'

export default function Signup() {
  return (
    <div className="form-container">
      <div>
        <h1>Signup</h1>
        <p>Enter your details below to create your account</p>
      </div>

      <div>
        <Form route="new_account.store">
          {({ errors }) => (
            <>
              <div>
                <label htmlFor="fullName">Full name</label>
                <input
                  type="text"
                  name="fullName"
                  id="fullName"
                  data-invalid={errors.fullName ? 'true' : undefined}
                />
                {errors.fullName && <div>{errors.fullName}</div>}
              </div>

              <div>
                <label htmlFor="email">Email</label>
                <input
                  type="email"
                  name="email"
                  id="email"
                  autoComplete="email"
                  data-invalid={errors.email ? 'true' : undefined}
                />
                {errors.email && <div>{errors.email}</div>}
              </div>

              <div>
                <label htmlFor="password">Password</label>
                <input
                  type="password"
                  name="password"
                  id="password"
                  autoComplete="new-password"
                  data-invalid={errors.password ? 'true' : undefined}
                />
                {errors.password && <div>{errors.password}</div>}
              </div>

              <div>
                <label htmlFor="passwordConfirmation">Confirm password</label>
                <input
                  type="password"
                  name="passwordConfirmation"
                  id="passwordConfirmation"
                  autoComplete="new-password"
                  data-invalid={errors.passwordConfirmation ? 'true' : undefined}
                />
                {errors.passwordConfirmation && <div>{errors.passwordConfirmation}</div>}
              </div>

              <div>
                <button type="submit" className="button">
                  Sign up
                </button>
              </div>
            </>
          )}
        </Form>
      </div>
    </div>
  )
}

页面组件位于 inertia/pages 目录中。来自 @adonisjs/inertia/react 的 Form 组件处理表单提交。它接受一个 route prop（要提交到的命名路由），并通过渲染 prop 模式提供一个 errors 对象。当你提交表单时，Inertia 将请求发送到后端并自动处理响应，包括显示验证错误。
