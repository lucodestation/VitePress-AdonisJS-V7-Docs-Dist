授权 ​

在上一章中，我们改进了 DevShow 的导航和样式。现在让我们添加让用户编辑和删除自己的帖子和评论的能力。目前，如果我们添加这些功能，任何已登录用户都可以修改任何人的内容。我们需要添加授权检查来防止这种情况。

概述 ​

为了正确处理权限，我们将使用 AdonisJS 的 Bouncer 包。Bouncer 让你将授权逻辑组织到策略中（策略是类，其中每个方法代表一个权限检查）。例如，PostPolicy 可以有一个 edit 方法，检查用户是否可以编辑特定帖子。

与其在控制器中散布权限检查，不如在策略中定义一次规则，然后在任何地方使用它们。在本章中，我们将安装 Bouncer，为帖子和评论创建策略，并实现带有适当授权的编辑和删除功能。

安装 Bouncer ​

让我们使用以下命令安装并配置 Bouncer 包。

bash
node ace add @adonisjs/bouncer

运行此命令将首先安装包，然后执行以下操作。

  • 创建一个 app/abilities/main.ts 文件，你可以在其中定义授权能力（我们现在不需要这个文件，所以不用担心）
  • 注册一个中间件，为每个 HTTP 请求初始化 Bouncer
  • 使 bouncer 对象在 HttpContext 上可用，以便你可以在控制器中使用它

一切就绪！现在让我们创建第一个策略。

创建 PostPolicy ​

策略是类，其中每个方法代表一个权限检查。让我们为帖子创建一个策略。

bash
node ace make:policy post

打开生成的文件，添加编辑和删除帖子的权限检查。

ts
import type User from '#models/user'
import type Post from '#models/post'
import { BasePolicy } from '@adonisjs/bouncer'

export default class PostPolicy extends BasePolicy {
  /**
   * 只有帖子所有者可以编辑他们的帖子
   */
  edit(user: User, post: Post) {
    return user.id === post.userId
  }

  /**
   * 只有帖子所有者可以删除他们的帖子
   */
  delete(user: User, post: Post) {
    return user.id === post.userId
  }
}

每个策略方法接收当前登录用户作为第一个参数，后面是被检查的资源（在这种情况下是 post）。如果用户被允许执行该操作，方法返回 true，否则返回 false。这里，我们只是检查用户的 ID 是否匹配帖子的 userId。

你可能注意到 edit 和 delete 目前有相同的逻辑。即使它们相同，将它们分开也给了你灵活性。以后，你可能决定帖子在 24 小时后不能编辑，或者管理员可以删除任何帖子但不能编辑它们。拥有单独的方法使这类更改更容易。

添加编辑功能 ​

步骤 1：创建更新验证器 ​

我们将为更新帖子添加一个验证器。由于我们已经有用于创建帖子的 validators/post.ts 文件，我们也会在那里添加更新验证器。一个验证器文件可以导出多个验证器（这使相关的验证逻辑保持在一起）。

打开你现有的帖子验证器文件并添加更新验证器。

ts
import vine from '@vinejs/vine'

export const createPostValidator = vine.create({
  title: vine.string().minLength(3).maxLength(255),
  url: vine.string().url(),
  summary: vine.string().minLength(80).maxLength(500),
})

/**
 * 与创建帖子相同的验证规则
 */
export const updatePostValidator = vine.create(
  createPostValidator.schema.clone()
)

我们正在克隆 createPostValidator 模式以重用相同的验证规则。这种方法使我们的验证逻辑保持 DRY（Don't Repeat Yourself，不要重复自己）。如果你以后需要更改规则，只需在一个地方更新。在许多应用中，你可能希望创建和更新有不同的规则，但对于 DevShow，要求是相同的。

步骤 2：添加控制器方法 ​

我们将添加两个控制器方法：edit 用于显示编辑表单，update 用于处理表单提交。两个方法都将使用 Bouncer 在执行任何操作之前检查当前用户是否被允许修改帖子。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'
import PostTransformer from '#transformers/post_transformer'
import { createPostValidator, updatePostValidator } from '#validators/post'
import PostPolicy from '#policies/post_policy'

export default class PostsController {
  // ... 现有方法（index、create、store、show）

  /**
   * 显示编辑表单
   */
  async edit({ bouncer, params, inertia }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 检查当前用户是否可以编辑此帖子
    await bouncer.with(PostPolicy).authorize('edit', post)

    return inertia.render('posts/edit', {
      post: PostTransformer.transform(post),
    })
  }

  /**
   * 更新帖子
   */
  async update({ bouncer, params, request, response, session }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 再次检查授权。有人可能直接发送 PUT 请求
    await bouncer.with(PostPolicy).authorize('edit', post)

    // 验证并更新帖子
    const data = await request.validateUsing(updatePostValidator)
    await post.merge(data).save()

    session.flash('success', 'Post updated successfully')
    return response.redirect().toRoute('posts.show', { id: post.id })
  }
}

这里的关键部分是 bouncer.with(PostPolicy).authorize('edit', post)。这一行：

  • 调用 PostPolicy 中的 edit 方法
  • 将帖子传递给策略方法
  • 如果策略返回 false，Bouncer 会自动抛出 403 Forbidden 错误
  • 如果策略返回 true，代码继续执行

我们在两个方法中都检查了授权。即使 edit 检查了权限，有人也可能绕过表单直接向 update 路由发送 PUT 请求。在执行敏感操作之前始终验证权限。

你还会注意到 update 方法中的 session.flash('success', 'Post updated successfully')。闪存消息是存储在会话中的临时消息，仅在下一个请求中可用，然后自动移除。这非常适合在表单提交后显示成功或错误消息。

你不需要添加任何代码来显示这些消息——启动套件的布局已经包含了一个自动渲染闪存消息的组件。当设置了闪存消息时，它会在下一个请求时作为通知出现在页面顶部。

步骤 3：更新 Post 转换器以包含授权 ​

现在我们了解了如何在控制器中使用策略，让我们也在转换器中使用它们，向前端发送授权标志。

这里有一个重要的考虑：Bouncer 策略在后端环境中运行，因此它们不能被导入或直接在 React 代码中使用。 你的 React 组件无法访问后端的授权逻辑。

解决方案是在转换器中预先计算用户权限并将其作为标志发送到前端。转换器在后端运行，可以访问策略，并可以在序列化数据中包含权限检查。

我们将为此使用转换器变体。变体允许你为同一资源定义多种输出形状。例如，你可能希望列表视图使用最少的数据，而详情视图使用详细数据（包括权限）。在转换器文档中了解更多关于变体的信息。

让我们为 PostTransformer 添加一个 forDetailedView 变体：

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'
import UserTransformer from '#transformers/user_transformer'
import CommentTransformer from '#transformers/comment_transformer'
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import PostPolicy from '#policies/post_policy'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return {
      ...this.pick(this.resource, ['id', 'title', 'url', 'summary', 'createdAt']),
      author: UserTransformer.transform(this.resource.user),
      comments: CommentTransformer.transform(this.whenLoaded(this.resource.comments)),
    }
  }

  /**
   * 为帖子详情视图包含授权数据
   */
  @inject()
  async forDetailedView({ bouncer }: HttpContext) {
    return {
      ...this.toObject(),
      can: {
        edit: await bouncer.with(PostPolicy).allows('edit', this.resource),
        delete: await bouncer.with(PostPolicy).allows('delete', this.resource),
      },
    }
  }
}

注意我们使用了与控制器中相同的 bouncer.with(PostPolicy) 模式，但使用的是 .allows()（返回布尔值）而不是 .authorize()（抛出错误）。@inject() 装饰器允许我们在转换器中访问 HTTP 上下文。

当你的 React 组件接收到此数据时，它有简单的布尔标志（post.can.edit、post.can.delete）可用于条件渲染——而无需了解任何关于授权逻辑本身的信息。

现在更新 show 方法以使用此变体：

ts
async show({ inertia, params }: HttpContext) {
  const post = await Post.query()
    .where('id', params.id)
    .preload('user')
    .preload('comments', (query) => {
      query.preload('user').orderBy('createdAt', 'asc')
    })
    .firstOrFail()

  return inertia.render('posts/show', {
    post: PostTransformer.transform(post),
  })
  return inertia.render('posts/show', {
    post: PostTransformer.transform(post).useVariant('forDetailedView'),
  })
}

步骤 4：注册路由 ​

现在让我们注册编辑帖子的路由。打开你的路由文件。

ts
import router from '@adonisjs/core/services/router'
import { middleware } from '#start/kernel'
import { controllers } from '#generated/controllers'

router.get('/posts', [controllers.Posts, 'index'])
router.get('/posts/create', [controllers.Posts, 'create']).use(middleware.auth())

我们需要两个路由（一个用于显示编辑表单，另一个用于处理表单提交）。两者都需要身份认证。

步骤 5：创建编辑表单组件 ​

创建编辑表单组件。

bash
node ace make:page posts/edit

现在添加表单标记。

tsx
import { InertiaProps } from '~/types'
import { Data } from '@generated/data'
import { Form, Link } from '@adonisjs/inertia/react'

type PageProps = InertiaProps<{
  post: Data.Post
}>

export default function PostsEdit(props: PageProps) {
  const { post } = props

  return (
    <div className="form-container">
      <Link route="posts.show" routeParams={{ id: post.id }}>
        &lsaquo; Back to post
      </Link>

      <h1>Edit Post</h1>

      <Form route="posts.update" routeParams={{ id: post.id }}>
        {({ errors }) => (
          <>
            <div>
              <label htmlFor="title">Post title</label>
              <input
                type="text"
                name="title"
                id="title"
                defaultValue={post.title}
                data-invalid={errors.title ? 'true' : undefined}
              />
              {errors.title && <div>{errors.title}</div>}
            </div>

            <div>
              <label htmlFor="url">URL</label>
              <input
                type="url"
                name="url"
                id="url"
                defaultValue={post.url}
                data-invalid={errors.url ? 'true' : undefined}
              />
              {errors.url && <div>{errors.url}</div>}
            </div>

            <div>
              <label htmlFor="summary">Short summary</label>
              <textarea
                name="summary"
                id="summary"
                rows={4}
                defaultValue={post.summary}
                data-invalid={errors.summary ? 'true' : undefined}
              />
              {errors.summary && <div>{errors.summary}</div>}
            </div>

            <div>
              <button type="submit" className="button">
                Update Post
              </button>
            </div>
          </>
        )}
      </Form>
    </div>
  )
}

此表单与创建表单类似，但有几个关键区别：

  • 预填值：每个字段显示当前帖子数据（defaultValue={post.title} 等），以便用户可以看到他们正在编辑的内容
  • 路由：通过 routeParams 提交到 posts.update 路由，帖子 ID 包含在其中。HTTP 方法（PUT）从路由定义自动推断

步骤 6：向帖子详情页添加编辑按钮 ​

现在向帖子详情页添加一个编辑按钮。打开你的 posts/show.tsx 组件。

tsx
import { InertiaProps } from '~/types'

        <div className="post-meta">

我们使用 post.can?.edit 进行条件渲染，仅向帖子所有者显示编辑按钮。can 对象来自我们转换器的 forDetailedView 变体，它使用了与控制器中相同的 PostPolicy。

非所有者甚至不会在组件中看到编辑按钮。如果有人尝试直接访问编辑 URL，他们仍然会从控制器的授权检查中获得 403 错误。

访问你创建的帖子，你会看到编辑按钮。点击它并尝试更新你的帖子！

添加删除功能 ​

步骤 1：添加控制器方法 ​

删除帖子比编辑简单，因为没有表单要显示（只是一个提交 DELETE 请求的按钮）。让我们添加控制器方法来处理删除。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'
import PostTransformer from '#transformers/post_transformer'
import { createPostValidator, updatePostValidator } from '#validators/post'
import PostPolicy from '#policies/post_policy'

export default class PostsController {
  // ... 现有方法

  /**
   * 删除帖子
   */
  async destroy({ bouncer, params, response, session }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 检查用户是否可以删除此帖子
    await bouncer.with(PostPolicy).authorize('delete', post)

    await post.delete()

    session.flash('success', 'Post deleted successfully')
    return response.redirect().toRoute('posts.index')
  }
}

这个模式现在应该很熟悉了：找到帖子，使用策略授权操作，执行删除，闪现成功消息，然后重定向。删除帖子后，我们重定向到帖子索引页面，因为帖子详情页面不再存在。

添加评论删除功能 ​

步骤 1：更新 Comment 转换器以包含授权 ​

与帖子类似，我们需要向评论添加授权数据。我们将使用之前学到的相同策略模式。在 CommentTransformer 中创建一个变体：

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Comment from '#models/comment'
import UserTransformer from '#transformers/user_transformer'
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import CommentPolicy from '#policies/comment_policy'

export default class CommentTransformer extends BaseTransformer<Comment> {
  toObject() {
    return {
      ...this.pick(this.resource, ['id', 'content', 'createdAt']),
      author: UserTransformer.transform(this.resource.user),
    }
  }

  /**
   * 为评论包含授权数据
   */
  @inject()
  async withAuthorization({ bouncer }: HttpContext) {
    return {
      ...this.toObject(),
      can: {
        delete: await bouncer.with(CommentPolicy).allows('delete', this.resource),
      },
    }
  }
}

步骤 2：更新 Post 转换器以使用评论授权变体 ​

现在更新 PostTransformer 以使用评论授权变体：

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'
import UserTransformer from '#transformers/user_transformer'
import CommentTransformer from '#transformers/comment_transformer'
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import PostPolicy from '#policies/post_policy'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return {
      ...this.pick(this.resource, ['id', 'title', 'url', 'summary', 'createdAt']),
      author: UserTransformer.transform(this.resource.user),
      comments: CommentTransformer.transform(this.whenLoaded(this.resource.comments)),
    }
  }

  @inject()
  async forDetailedView({ bouncer }: HttpContext) {
    return {
      ...this.toObject(),
      comments: CommentTransformer.transform(this.whenLoaded(this.resource.comments)),
      comments: CommentTransformer.transform(this.whenLoaded(this.resource.comments))
        .useVariant('withAuthorization')
        .depth(2),
      can: {
        edit: await bouncer.with(PostPolicy).allows('edit', this.resource),
        delete: await bouncer.with(PostPolicy).allows('delete', this.resource),
      },
    }
  }
}

步骤 3：添加控制器方法 ​

让我们添加用于删除评论的控制器方法。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Comment from '#models/comment'
import { createCommentValidator } from '#validators/comment'
import CommentPolicy from '#policies/comment_policy'

export default class CommentsController {
  // ... 现有 store 方法

  /**
   * 删除评论
   */
  async destroy({ bouncer, params, response, session }: HttpContext) {
    const comment = await Comment.findOrFail(params.id)

    // 加载帖子以便我们可以重定向回它
    await comment.load('post')

    // 检查用户是否可以删除此评论
    await bouncer.with(CommentPolicy).authorize('delete', comment)

    await comment.delete()

    session.flash('success', 'Comment deleted successfully')
    return response.redirect().toRoute('posts.show', { id: comment.post.id })
  }
}

以下是此方法的作用：

  • 查找评论：使用路由参数中的 ID
  • 加载帖子关系：以便我们可以访问 comment.post.id 用于删除后重定向
  • 检查授权：使用 CommentPolicy。如果用户不拥有该评论，他们会得到 403 错误
  • 删除评论：从数据库中
  • 重定向回去：到显示评论的帖子详情页面

步骤 5：向评论添加删除按钮 ​

最后，在帖子详情组件的评论列表中添加删除按钮。

tsx
import { InertiaProps } from '~/types'
import { Data } from '@generated/data'
import { Form, Link } from '@adonisjs/inertia/react'

type PageProps = InertiaProps<{
  post: Data.Post.Variants['forDetailedView']
}>

export default function PostsShow(props: PageProps) {
  const { post } = props

  return (
    <div className="container">
      <Link route="posts.index">&lsaquo; Go back to posts listing</Link>
      <div>
        <h1>{post.title}</h1>
      </div>

      <div className="post">
        <div className="post-meta">{/* ... */}</div>
        <div className="post-summary">{post.summary}</div>
        <div className="post-actions">{/* ... */}</div>

        <div className="post-comments">
          <h2>Comments</h2>

          <div className="post-comment-form">{/* ... */}</div>

          {post.comments && post.comments.length > 0 ? (
            post.comments.map((comment) => (
              <div key={comment.id} className="comment-item">
                <p>{comment.content}</p>
                <div className="comment-meta">
                  By {comment.author.fullName} on{' '}
                  {comment.createdAt && new Date(comment.createdAt).toLocaleDateString('en-US', {
                    month: 'short',
                    day: 'numeric',
                    year: 'numeric',
                  })}
                </div>
                <div className="comment-actions">
                  {comment.can?.delete && (
                    <Form route="comments.destroy" routeParams={{ id: comment.id }}>
                      {() => (
                        <button type="submit" className="destructive">
                          Delete
                        </button>
                      )}
                    </Form>
                  )}
                </div>
              </div>
            ))
          ) : (
            <p>No comments yet.</p>
          )}
        </div>
      </div>
    </div>
  )
}

评论删除按钮的工作方式：

  • 策略检查 - comment.can?.delete 检查当前用户是否可以删除每条评论
  • 可见性 - 只有评论作者会看到删除按钮
  • 操作 - 按钮向 comments.destroy 路由提交 DELETE 请求

访问一个包含你创建的评论的帖子，你会看到评论旁边的删除按钮。尝试查看其他用户的评论，不会出现删除按钮。

你构建了什么 ​

你已成功使用 Bouncer 的策略系统为 DevShow 添加了授权。以下是你完成的内容：

  • 创建了 PostPolicy 和 CommentPolicy，将所有权限逻辑集中在一个地方
  • 在控制器中使用 bouncer.with(Policy).authorize() 在执行操作之前强制执行权限
  • 了解了转换器变体——根据上下文为同一资源提供多种输出形状
  • 使用 @inject() 装饰器在转换器变体中访问 HTTP 上下文
  • 在转换器中使用策略预先计算用户权限，并将它们作为 can 标志发送到前端
  • 实现了完整的编辑帖子功能，包括表单、验证和授权
  • 为帖子和评论添加了删除功能，并带有适当的权限检查
  • 在 React 组件中使用条件渲染，仅向授权用户显示操作按钮

这种方法的关键好处是你的授权逻辑完全在后端，无法被绕过。Bouncer 策略在安全的环境中运行，转换器将预先计算的权限标志发送到 React 组件以供 UI 决策。这使你的前端保持简单，同时维护了安全性。
