部署到生产环境 ​

在上一章中，我们为 DevShow 添加了授权，使用户只能编辑和删除自己的内容。我们现在已经构建了一个完整的应用，包含身份认证、帖子、评论和适当的权限。让我们将它部署到生产环境，让全世界都能使用它。

概述 ​

在整个教程中，我们一直使用 SQLite 作为数据库。SQLite 非常适合本地开发，因为它简单且无需设置。但对于生产环境，我们需要一个能够处理多个连接且不绑定到单台服务器文件系统的数据库。

在本章中，我们将切换到 PostgreSQL，创建应用的生产构建，并将一切部署到 Cloud Galaxy。Cloud Galaxy 是一个 PAAS（平台即服务），为我们处理基础设施，这样我们就可以专注于应用，而不是管理服务器。

Cloud Galaxy 赞助 AdonisJS

我们在本教程中使用 Cloud Galaxy，但 AdonisJS 可与任何支持 Node.js 运行时的平台配合使用。无论你部署到 Heroku、DigitalOcean、AWS 还是任何其他托管提供商，相同的概念都适用。

切换到 PostgreSQL ​

在部署之前，我们需要从 SQLite 切换到 PostgreSQL。别担心——这比听起来容易。我们的模型、迁移和查询将完全相同地工作，因为 Lucid（AdonisJS 的 ORM）抽象掉了数据库特定的细节。

步骤 1：安装 PostgreSQL 包 ​

首先，让我们安装 Lucid 的 PostgreSQL 驱动并移除 better-sqlite3 包。

bash
npm install pg
npm uninstall better-sqlite3

步骤 2：更新数据库配置 ​

打开你的数据库配置文件，将默认连接更新为使用 PostgreSQL。

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/lucid'

const dbConfig = defineConfig({
  connection: 'postgres',
  connections: {
    sqlite: {
      client: 'better-sqlite3',
      connection: {
        filename: app.tmpPath('db.sqlite3'),
      },
      migrations: {
        naturalSort: true,
        paths: ['database/migrations'],
      },
    },
    postgres: {
      client: 'pg',
      connection: {
        host: env.get('DB_HOST'),
        port: env.get('DB_PORT'),
        user: env.get('DB_USER'),
        password: env.get('DB_PASSWORD'),
        database: env.get('DB_DATABASE'),
      },
      migrations: {
        naturalSort: true,
        paths: ['database/migrations'],
      },
    },
  },
})

export default dbConfig

我们将默认连接从 sqlite 改为 postgres，并配置它从环境变量读取连接详情。这意味着我们可以在开发和生产环境中使用不同的数据库，而无需更改任何代码。

步骤 3：更新环境变量 ​

现在让我们将 PostgreSQL 连接详情添加到环境变量文件中。

dotenv
TZ=UTC
PORT=3333
HOST=localhost
LOG_LEVEL=info
APP_KEY=your-app-key-here
NODE_ENV=development
SESSION_DRIVER=cookie

DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=postgres
DB_DATABASE=devshow

这些是典型的本地 PostgreSQL 设置。如果你本地安装的 PostgreSQL 使用不同的凭据，请更新这些值以匹配你的设置。

步骤 4：验证环境变量 ​

更新你的环境验证文件以包含新的数据库变量。

ts
import { Env } from '@adonisjs/core/env'

export default await Env.create(new URL('../', import.meta.url), {
  NODE_ENV: Env.schema.enum(['development', 'production', 'test'] as const),
  PORT: Env.schema.number(),
  APP_KEY: Env.schema.string(),
  HOST: Env.schema.string({ format: 'host' }),
  LOG_LEVEL: Env.schema.enum(['fatal', 'error', 'warn', 'info', 'debug', 'trace']),
  DB_HOST: Env.schema.string({ format: 'host' }),
  DB_PORT: Env.schema.number(),
  DB_USER: Env.schema.string(),
  DB_PASSWORD: Env.schema.string.optional(),
  DB_DATABASE: Env.schema.string(),
})

这确保 AdonisJS 在启动时验证你的数据库环境变量，并在缺少或格式不正确时给出有用的错误。

步骤 5：创建 PostgreSQL 数据库 ​

在运行迁移之前，你需要创建数据库。如果你本地安装了 PostgreSQL，打开终端并运行：

bash
createdb devshow

或者连接到 PostgreSQL 并手动创建：

bash
psql postgres
CREATE DATABASE devshow;
\q

如果你本地没有安装 PostgreSQL，那没关系。我们将通过 Cloud Galaxy 在生产环境中设置它，你可以通过在配置文件中暂时切换回 SQLite 连接来继续本地开发。

步骤 6：运行迁移 ​

现在让我们在 PostgreSQL 数据库中创建所有表。

bash
node ace migration:run

你应该会看到所有迁移成功执行：

bash
❯ migrated database/migrations/1758943358073_create_users_table
❯ migrated database/migrations/1766383750528_create_posts_table
❯ migrated database/migrations/1766384692875_create_comments_table
❯ migrated database/migrations/1766384816152_create_add_foreign_keys_to_posts_and_comments_table

你的 PostgreSQL 数据库现在具有与 SQLite 数据库相同的结构！

步骤 7：填充数据库 ​

让我们用一些测试数据填充新数据库。

bash
node ace db:seed

用 npm run dev 启动开发服务器并访问 /posts。一切都应该和之前完全一样地工作，但现在你运行在 PostgreSQL 而不是 SQLite 上。

创建生产构建 ​

现在我们已经使用 PostgreSQL，让我们通过创建优化构建来为生产环境准备应用。在开发期间，AdonisJS 即时编译 TypeScript，这很方便但会增加开销。对于生产环境，我们创建一个预编译的 JavaScript 构建，运行更快且不需要 TypeScript 作为依赖。

步骤 1：创建构建 ​

运行构建命令以创建应用的生产就绪版本。

bash
node ace build

你会看到显示构建过程的输出：

bash
[ info ] loading hooks...
[ info ] generating indexes...
[ info ] created .adonisjs/server/events.ts (1.08 ms)
[ info ] created .adonisjs/server/listeners.ts (266 μs)
[ info ] created .adonisjs/server/controllers.ts (1.11 ms)
[ info ] created .adonisjs/server/policies.ts (383 μs)
[ info ] cleaning up output directory (build)
[ info ] building assets with vite

[ info ] compiling typescript source (tsc)
[ info ] created ace file (build/ace.js)
[ info ] copying meta files to the output directory
[ success ] build completed

这会在你的项目中创建一个新的 build 目录，包含应用的编译后 JavaScript 版本。

步骤 2：理解 build 目录 ​

让我们看看 build 目录中生成了什么：

build/
├── app/                    # 编译后的应用代码
├── config/                 # 配置文件
├── database/              # 迁移和填充文件
├── public/                # 静态资源（CSS、图片）
├── resources/             # Edge 模板
├── start/                 # 应用启动文件
├── ace.js                 # Ace 命令行工具
├── bin/                   # 服务器和控制台入口点
│   ├── server.js          # HTTP 服务器
│   └── console.js         # 控制台命令
├── package.json           # 生产环境依赖
└── package-lock.json      # 锁定的依赖版本

最重要的文件是 bin/server.js——这是你在生产环境中运行以启动应用的文件。注意 TypeScript 文件（*.ts）已被编译为 JavaScript（*.js），类型定义已消失，因为 JavaScript 不需要它们。

步骤 3：在本地测试生产构建 ​

在部署之前，让我们验证构建在本地可以工作。进入 build 目录并安装生产依赖。

bash
cd build
npm ci --omit=dev

npm ci 命令完全按照 package-lock.json 中的指定安装依赖，--omit=dev 跳过 TypeScript 等开发依赖，因为我们在生产环境中不需要它们。

现在将你的 .env 文件复制到 build 目录（运行应用需要环境变量）：

bash
cp ../.env .env

启动生产服务器：

bash
node bin/server.js

访问 http://localhost:3333，你应该会看到应用从编译后的构建中运行！测试完成后，用 Ctrl+C 停止服务器并返回项目根目录：

bash
cd ..

部署到 Cloud Galaxy ​

现在我们准备使用 Cloud Galaxy 将 DevShow 部署到生产环境。Cloud Galaxy 专为 AdonisJS 应用设计，处理从 HTTPS 证书到数据库管理的一切。

步骤 1：创建 Cloud Galaxy 账户 ​

访问 cloud.adonisjs.com 并创建账户。注册后，你会进入仪表盘，可以在其中创建和管理应用。

步骤 2：创建新应用 ​

点击 "New Application" 按钮并填写详细信息：

  • 应用名称：devshow（或你喜欢的任何名称）
  • 区域：选择离你的用户最近的区域
  • 计划：选择适合你需求的计划（入门计划非常适合本教程）

点击 "Create Application"，Galaxy 将为你配置应用环境。

步骤 3：连接你的 Git 仓库 ​

Cloud Galaxy 直接从你的 Git 仓库部署。如果你还没有，将代码推送到 GitHub、GitLab 或 Bitbucket：

bash
git add .
git commit -m "Ready for production deployment"
git push origin main

回到 Galaxy，转到应用的 "Settings" 标签页并连接你的 Git 仓库。按照提示授权 Galaxy 访问你的仓库。

步骤 4：创建 PostgreSQL 数据库 ​

在你的 Galaxy 应用仪表盘中，导航到 "Databases" 标签页并点击 "Create Database"。选择 PostgreSQL 并选择一个计划。Galaxy 将为你配置一个托管的 PostgreSQL 数据库。

创建后，你会看到连接详情。保持此标签页打开——下一步我们需要这些详情。

步骤 5：配置环境变量 ​

转到 Galaxy 应用仪表盘中的 "Environment" 标签页。在这里，你将添加应用所需的所有环境变量：

NODE_ENV=production
PORT=3333
HOST=0.0.0.0
LOG_LEVEL=info
APP_KEY=your-production-app-key-here

DB_HOST=<from-galaxy-database-details>
DB_PORT=<from-galaxy-database-details>
DB_USER=<from-galaxy-database-details>
DB_PASSWORD=<from-galaxy-database-details>
DB_DATABASE=<from-galaxy-database-details>

WARNING

为生产环境生成新的 APP_KEY——绝不要在生产环境中使用你的开发密钥。运行 node ace generate:key 创建一个新的。

关于这些变量的重要说明：

  • HOST 在生产环境中必须是 0.0.0.0——这告诉服务器接受来自任何网络接口的连接，这对于云平台是必需的
  • 数据库凭据应来自 Galaxy 数据库详情页面
  • APP_KEY 应该是专门为生产环境生成的新安全密钥

步骤 6：部署你的应用 ​

现在我们准备部署！在 "Deployments" 标签页中，点击 "Deploy Now"。Galaxy 将：

  1. 克隆你的 Git 仓库
  2. 运行 node ace build 创建生产构建
  3. 安装生产依赖
  4. 启动你的应用

观察部署日志以查看进度。首次部署通常需要几分钟。

步骤 7：在生产环境中运行迁移 ​

应用部署后，你需要运行迁移以创建数据库表。在 Galaxy 仪表盘中，转到 "Console" 标签页并运行：

bash
node ace migration:run --force

在生产环境中运行迁移时需要 --force 标志——这是一项安全检查，确保你不会意外地在错误的数据库上运行迁移。

你会看到迁移执行：

bash
❯ migrated database/migrations/1763866156451_create_posts_table
❯ migrated database/migrations/1763866347711_create_comments_table
❯ migrated database/migrations/1732089800000_add_foreign_keys_to_posts_and_comments

步骤 8：访问你的生产应用 ​

Galaxy 为你的应用提供一个 URL（通常类似于 devshow-abc123.galaxycloud.app）。访问此 URL，你应该会看到 DevShow 在生产环境中运行！

尝试创建账户、发布内容和添加评论。一切都应该与本地运行时完全一样地工作，但现在它运行在生产基础设施上，使用托管的 PostgreSQL 数据库。

你构建了什么 ​

恭喜！你已成功将 DevShow 部署到生产环境。在整个教程中，你从零开始构建了一个完整的 Web 应用，学习了如何：

  • 创建模型和迁移来管理数据库结构
  • 构建控制器来处理 HTTP 请求和业务逻辑
  • 使用 Edge 模板渲染动态视图
  • 实现身份认证和授权
  • 使用表单验证用户输入
  • 使用正确的配置部署到生产环境

这些是你在构建的每个 AdonisJS 应用中都会使用的基本技能。准备好继续学习了吗？查看指南深入了解高级主题。
