授权 ​

在上一章中，我们改进了 DevShow 的导航和样式。现在让我们添加让用户编辑和删除自己的帖子和评论的能力。目前，如果我们添加这些功能，任何已登录用户都可以修改任何人的内容。我们需要添加授权检查来防止这种情况。

概述 ​

为了正确处理权限，我们将使用 AdonisJS 的 Bouncer 包。Bouncer 让你将授权逻辑组织到策略中（策略是类，其中每个方法代表一个权限检查）。例如，PostPolicy 可以有一个 edit 方法，检查用户是否可以编辑特定帖子。

与其在控制器中散布权限检查，不如在策略中定义一次规则，然后在任何地方使用它们。在本章中，我们将安装 Bouncer，为帖子和评论创建策略，并实现带有适当授权的编辑和删除功能。

安装 Bouncer ​

让我们使用以下命令安装并配置 Bouncer 包。

bash
node ace add @adonisjs/bouncer

运行此命令将首先安装包，然后执行以下操作。

  • 创建一个 app/abilities/main.ts 文件，你可以在其中定义授权能力（我们现在不需要这个文件，所以不用担心）
  • 注册一个中间件，为每个 HTTP 请求初始化 Bouncer
  • 使 bouncer 对象在 HttpContext 上可用，以便你可以在控制器中使用它

一切就绪！现在让我们创建第一个策略。

创建 PostPolicy ​

策略是类，其中每个方法代表一个权限检查。让我们为帖子创建一个策略。

bash
node ace make:policy post

打开生成的文件，添加编辑和删除帖子的权限检查。

ts
import type User from '#models/user'
import type Post from '#models/post'
import { BasePolicy } from '@adonisjs/bouncer'

export default class PostPolicy extends BasePolicy {
  /**
   * 只有帖子所有者可以编辑他们的帖子
   */
  edit(user: User, post: Post) {
    return user.id === post.userId
  }

  /**
   * 只有帖子所有者可以删除他们的帖子
   */
  delete(user: User, post: Post) {
    return user.id === post.userId
  }
}

每个策略方法接收当前登录用户作为第一个参数，后面是被检查的资源（在这种情况下是 post）。如果用户被允许执行该操作，方法返回 true，否则返回 false。这里，我们只是检查用户的 ID 是否匹配帖子的 userId。

你可能注意到 edit 和 delete 目前有相同的逻辑。即使它们相同，将它们分开也给了你灵活性。以后，你可能决定帖子在 24 小时后不能编辑，或者管理员可以删除任何帖子但不能编辑它们。拥有单独的方法使这类更改更容易。

创建 CommentPolicy ​

现在为评论创建一个策略。

bash

import type User from '#models/user'

export default class CommentPolicy extends BasePolicy {

完美！现在让我们把这些策略付诸实践。

添加编辑功能 ​

步骤 1：创建更新验证器 ​

我们将为更新帖子添加一个验证器。由于我们已经有用于创建帖子的 validators/post.ts 文件，我们也会在那里添加更新验证器。一个验证器文件可以导出多个验证器（这使相关的验证逻辑保持在一起）。

打开你现有的帖子验证器文件并添加更新验证器。

ts
import vine from '@vinejs/vine'

export const createPostValidator = vine.create({
  title: vine.string().minLength(3).maxLength(255),
  url: vine.string().url(),
  summary: vine.string().minLength(80).maxLength(500),
})

/**
 * 与创建帖子相同的验证规则
 */
export const updatePostValidator = vine.create(
  createPostValidator.schema.clone()
)

我们正在克隆 createPostValidator 模式以重用相同的验证规则。这种方法使我们的验证逻辑保持 DRY（Don't Repeat Yourself，不要重复自己）。如果你以后需要更改规则，只需在一个地方更新。在许多应用中，你可能希望创建和更新有不同的规则，但对于 DevShow，要求是相同的。

步骤 2：添加控制器方法 ​

我们将添加两个控制器方法：edit 用于显示编辑表单，update 用于处理表单提交。两个方法都将使用 Bouncer 在执行任何操作之前检查当前用户是否被允许修改帖子。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'
import { createPostValidator, updatePostValidator } from '#validators/post'
import PostPolicy from '#policies/post_policy'

export default class PostsController {
  // ... 现有方法（index、create、store、show）

  /**
   * 显示编辑表单
   */
  async edit({ bouncer, params, view }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 检查当前用户是否可以编辑此帖子
    await bouncer.with(PostPolicy).authorize('edit', post)

    return view.render('posts/edit', { post })
  }

  /**
   * 更新帖子
   */
  async update({ bouncer, params, request, response, session }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 再次检查授权。有人可能直接发送 PUT 请求
    await bouncer.with(PostPolicy).authorize('edit', post)

    // 验证并更新帖子
    const data = await request.validateUsing(updatePostValidator)
    await post.merge(data).save()

    session.flash('success', 'Post updated successfully')
    return response.redirect().toRoute('posts.show', { id: post.id })
  }
}

这里的关键部分是 bouncer.with(PostPolicy).authorize('edit', post)。这一行：

  • 调用 PostPolicy 中的 edit 方法
  • 将帖子传递给策略方法
  • 如果策略返回 false，Bouncer 会自动抛出 403 Forbidden 错误
  • 如果策略返回 true，代码继续执行

注意我们在两个方法中都检查了授权。即使 edit 检查了权限，有人也可能绕过表单直接向 update 路由发送 PUT 请求。在执行敏感操作之前始终验证权限。

步骤 3：理解闪存消息 ​

你会注意到 update 方法中的 session.flash('success', 'Post updated successfully')。这是我们在 DevShow 中第一次使用闪存消息，所以让我们了解它们的作用。

闪存消息是存储在会话中的临时消息。它们仅在下一个请求中可用，然后自动移除。这使它们非常适合在表单提交后显示成功或错误消息。

你不需要添加任何代码来显示这些消息——启动套件的布局已经包含了一个自动渲染闪存消息的组件。当设置了闪存消息时，它会在下一个请求时作为通知出现在页面顶部。

在本章剩余部分，每当我们想要确认某个操作（如更新或删除）成功时，都会使用闪存消息。

步骤 4：注册路由 ​

现在让我们注册编辑帖子的路由。打开你的路由文件。

ts
import router from '@adonisjs/core/services/router'
import { middleware } from '#start/kernel'
import { controllers } from '#generated/controllers'

router.get('/posts', [controllers.Posts, 'index'])
router.get('/posts/create', [controllers.Posts, 'create']).use(middleware.auth())
router.post('/posts', [controllers.Posts, 'store']).use(middleware.auth())
router.get('/posts/:id', [controllers.Posts, 'show'])

router.get('/posts/:id/edit', [controllers.Posts, 'edit']).use(middleware.auth())
router.put('/posts/:id', [controllers.Posts, 'update']).use(middleware.auth())

router.post('/posts/:id/comments', [controllers.Comments, 'store']).use(middleware.auth())

我们需要两个路由（一个用于显示编辑表单，另一个用于处理表单提交）。两者都需要身份认证。

步骤 5：创建编辑表单模板 ​

创建编辑表单模板。

bash
node ace make:view posts/edit

现在添加表单标记。

edge
@layout()
  <div class="form-container">
    @!link({
      route: 'posts.show',
      routeParams: post,
      text: '&lsaquo; Back to post'
    })

    <h1>Edit Post</h1>

    @form({ route: 'posts.update', routeParams: post, method: 'PUT' })
      <div>
        @field.root({ name: 'title' })
          @!field.label({ text: 'Post title' })
          @!input.control({ value: post.title })
          @!field.error()
        @end
      </div>

      <div>
        @field.root({ name: 'url' })
          @!field.label({ text: 'URL' })
          @!input.control({ type: 'url', value: post.url })
          @!field.error()
        @end
      </div>

      <div>
        @field.root({ name: 'summary' })
          @!field.label({ text: 'Short summary' })
          @!textarea.control({ rows: 4, value: post.summary })
          @!field.error()
        @end
      </div>

      <div>
        @!button({ text: 'Update Post', type: 'submit' })
      </div>
    @end
  </div>
@end

此表单与创建表单类似，但有几个关键区别：

  • HTTP 方法：使用 method: 'PUT' 表示这是一个更新请求，而不是用于创建新数据的 POST
  • 预填值：每个字段显示当前帖子数据（value: post.title、value: post.url、text: post.summary），以便用户可以看到他们正在编辑的内容
  • 路由：提交到 posts.update 路由，帖子 ID 包含在 URL 中

步骤 6：向帖子详情页添加编辑按钮 ​

现在向帖子详情页添加一个编辑按钮。打开你的 posts/show.edge 模板。

edge
@layout()
  <div class="container">
    <div class="post">
      <div class="post-meta">...</div>

      <div class="post-summary">...</div>

      <div class="post-actions">
        {{-- 仅向帖子所有者显示编辑按钮 --}}
        @can('PostPolicy.edit', post)
          @!link({
            route: 'posts.edit',
            routeParams: post,
            text: 'Edit post',
          })
        @end
      </div>
    </div>
  </div>
@end

@can 标签在模板中检查策略方法，类似于 bouncer.authorize() 在控制器中的工作方式：

  • 第一个参数（'PostPolicy.edit'）- 指定使用哪个策略和方法
  • 第二个参数（post）- 被检查的资源，传递给策略方法
  • 当检查失败时 - @can 和 @end 之间的所有内容都会从 HTML 输出中隐藏

非所有者甚至不会在页面源代码中看到编辑按钮。如果有人尝试直接访问编辑 URL，他们仍然会从控制器的授权检查中获得 403 错误。

访问你创建的帖子，你会看到编辑按钮。点击它并尝试更新你的帖子！

添加删除功能 ​

步骤 1：添加控制器方法 ​

删除帖子比编辑简单，因为没有表单要显示（只是一个提交 DELETE 请求的按钮）。让我们添加控制器方法来处理删除。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'
import { createPostValidator, updatePostValidator } from '#validators/post'
import PostPolicy from '#policies/post_policy'

export default class PostsController {
  // ... 现有方法

  /**
   * 删除帖子
   */
  async destroy({ bouncer, params, response, session }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 检查用户是否可以删除此帖子
    await bouncer.with(PostPolicy).authorize('delete', post)

    await post.delete()

    session.flash('success', 'Post deleted successfully')
    return response.redirect().toRoute('posts.index')
  }
}

这个模式现在应该很熟悉了：找到帖子，使用策略授权操作，执行删除，闪现成功消息，然后重定向。删除帖子后，我们重定向到帖子索引页面，因为帖子详情页面不再存在。

步骤 2：注册路由 ​

现在注册删除路由。

ts
import router from '@adonisjs/core/services/router'
import { middleware } from '#start/kernel'
import { controllers } from '#generated/controllers'

router.put('/posts/:id', [controllers.Posts, 'update']).use(middleware.auth())
router.delete('/posts/:id', [controllers.Posts, 'destroy']).use(middleware.auth())
router.post('/posts/:id/comments', [controllers.Comments, 'store']).use(middleware.auth())

步骤 3：向帖子详情页添加删除按钮 ​

在你的帖子详情模板中，在编辑按钮旁边添加一个删除按钮。

edge
@layout()
<div class="container">
    <div class="post">
      <div class="post-meta">...</div>

      <div class="post-summary">...</div>

      <div class="post-actions">
        {{-- 仅向帖子所有者显示编辑按钮 --}}
        @can('PostPolicy.edit', post)
          @!link({
            route: 'posts.edit',
            routeParams: post,
            text: 'Edit post',
          })
        @end

        {{-- 仅向帖子所有者显示删除按钮 --}}
        @can('PostPolicy.delete', post)
          <span>.</span>
          @form({ route: 'posts.destroy', routeParams: post, method: 'DELETE' })
            @!button({ text: 'Delete', class: 'destructive' })
          @end
        @end
      </div>
    </div>
  </div>
@end

关于这个删除按钮的几个重要事项：

  • DELETE 方法 - 我们在表单中使用 method: 'DELETE'，但 HTML 表单原生只支持 GET 和 POST 方法
  • 表单方法欺骗 - 在底层，@form 组件提交一个带有 ?_method=DELETE 查询字符串的 POST 请求。AdonisJS 识别这种模式并将请求视为 DELETE。这种技术称为表单方法欺骗
  • 授权检查 - @can('PostPolicy.delete', post) 标签确保只有帖子所有者看到按钮

试试看！访问你创建的帖子，你会看到编辑和删除按钮。访问别人创建的帖子，不会出现任何按钮。

添加评论删除功能 ​

步骤 1：添加控制器方法 ​

让我们添加用于删除评论的控制器方法。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Comment from '#models/comment'
import { createCommentValidator } from '#validators/comment'
import CommentPolicy from '#policies/comment_policy'

export default class CommentsController {
  // ... 现有 store 方法

  /**
   * 删除评论
   */
  async destroy({ bouncer, params, response, session }: HttpContext) {
    const comment = await Comment.findOrFail(params.id)

    // 加载帖子以便我们可以重定向回它
    await comment.load('post')

    // 检查用户是否可以删除此评论
    await bouncer.with(CommentPolicy).authorize('delete', comment)

    await comment.delete()

    session.flash('success', 'Comment deleted successfully')
    return response.redirect().toRoute('posts.show', { id: comment.post.id })
  }
}

以下是此方法的作用：

  • 查找评论：使用路由参数中的 ID
  • 加载帖子关系：以便我们可以访问 comment.post.id 用于删除后重定向
  • 检查授权：使用 CommentPolicy。如果用户不拥有该评论，他们会得到 403 错误
  • 删除评论：从数据库中
  • 重定向回去：到显示评论的帖子详情页面

步骤 2：注册路由 ​

现在注册评论的删除路由。

ts
import router from '@adonisjs/core/services/router'
import { middleware } from '#start/kernel'
import { controllers } from '#generated/controllers'

router.get('/posts/:id/edit', [controllers.Posts, 'edit']).use(middleware.auth())
router.put('/posts/:id', [controllers.Posts, 'update']).use(middleware.auth())
router.delete('/posts/:id', [controllers.Posts, 'destroy']).use(middleware.auth())
router.post('/posts/:id/comments', [controllers.Comments, 'store']).use(middleware.auth())

router
  .delete('/comments/:id', [controllers.Comments, 'destroy'])
  .use(middleware.auth())

步骤 3：向评论添加删除按钮 ​

最后，在帖子详情模板的评论列表中添加删除按钮。

edge
@layout()
  <div class="container">
    <div class="post">
      {{-- ... 帖子内容 ... --}}

      <div class="post-comments">
        <h2>Comments</h2>

        @each(comment in post.comments)
          <div class="comment-item">
            {{-- ... 评论内容 ... --}}

            <div class="comment-actions">
              @can('CommentPolicy.delete', comment)
                @form({ route: 'comments.destroy', routeParams: [comment.id], method: 'DELETE' })
                  @!button({ type: 'submit', text: 'Delete', class: 'destructive' })
                @end
              @end
            </div>
          </div>
        @else
          <p> No comments yet. </p>
        @end
      </div>
    </div>
  </div>
@end

评论删除按钮的工作方式：

  • 策略检查 - @can 标签检查 CommentPolicy 以确定当前用户是否可以删除每条评论
  • 可见性 - 只有评论作者会看到删除按钮
  • 操作 - 按钮向 comments.destroy 路由提交 DELETE 请求

访问一个包含你创建的评论的帖子，你会看到评论旁边的删除按钮。尝试查看其他用户的评论，不会出现删除按钮。

你构建了什么 ​

你已成功使用 Bouncer 的策略系统为 DevShow 添加了授权。以下是你完成的内容：

  • 创建了 PostPolicy 和 CommentPolicy，将所有权限逻辑集中在一个地方
  • 在控制器中使用 bouncer.with(Policy).authorize() 在执行操作之前强制执行权限
  • 实现了完整的编辑帖子功能，包括表单、验证和授权
  • 为帖子和评论添加了删除功能，并带有适当的权限检查
  • 在模板中使用 @can 标签，仅向授权用户有条件地显示操作按钮

这种方法的关键好处是你的授权逻辑可重用且可维护。当你需要更改权限规则时，只需在一个地方（策略）更新它，它会自动应用于你使用该策略的所有地方（控制器、模板以及应用中的任何其他地方）。
