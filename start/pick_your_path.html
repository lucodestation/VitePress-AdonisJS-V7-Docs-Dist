选择你的路径 ​

本指南介绍 AdonisJS 的前端开发方法以及你可以选择的三种主要技术栈。你将了解到：

  • 为什么 AdonisJS 是后端优先但前端灵活的。
  • 理解超媒体、Inertia 和仅 API 方法之间的区别。
  • 了解视图层在每个技术栈中如何工作。
  • 了解为每种方法提供预设配置的启动套件。

概述 ​

AdonisJS 对后端有着深入的设计理念，提供内置的身份认证、授权、验证、数据库工具等，但有意对前端保持灵活。这种后端优先的理念意味着你拥有构建服务端逻辑的坚实基础，同时可以自由选择如何构建用户界面。

你可以创建传统的服务端渲染应用、现代单页应用，或介于两者之间的任何形式，全部使用同一个后端框架。营销网站与管理员仪表盘的需求不同，后者又与移动应用的 API 后端不同。AdonisJS 不会强迫你采用单一方法，而是让你选择适合需求的前端技术栈。

三种方法 ​

AdonisJS 支持三种主要的构建前端的方法。每种方法代表了在你的应用架构中思考视图层的不同方式。

超媒体 ​

超媒体应用在服务器上生成完整的 HTML 页面并发送到浏览器。你使用模板引擎（AdonisJS 提供 Edge）构建界面，并在需要时使用 Alpine.js 或 HTMX/Unpoly 等轻量级 JavaScript 库添加交互性。

什么是超媒体

“超媒体”一词指的是将 HTML 作为构建交互式应用的媒介，其中服务器驱动应用状态，客户端（浏览器）负责展示。如果你对这个概念不熟悉，HTMX 项目有一篇出色的文章深入解释了超媒体驱动应用。

在超媒体应用中：

  • 服务器负责渲染你的视图。
  • 你的控制器返回 HTML 而不是 JSON。
  • 页面之间的导航通过传统的页面加载或渐进增强的请求进行。

这种方法拥抱 Web 的原生能力，并将应用的大部分逻辑保留在服务器上，让你拥有完全控制权。

当你想要构建由服务器控制的应用，或者想要最小化用户下载的 JavaScript 量时，选择这种方法。超媒体应用可以使用 Alpine.js 和 HTMX 等库实现高度交互，同时保持前端代码库精简、部署简单。

Inertia（React 或 Vue） ​

Inertia.js 在服务端渲染模板和 SPA 之间提供了一种折中方案。你使用 React 或 Vue 组件作为视图，同时保留服务端路由和控制器。AdonisJS 通过 Inertia 官方支持使用 React 或 Vue 构建应用，让你获得现代前端框架的基于组件的开发体验，而无需维护单独的单页应用的复杂性。

使用 Inertia 时：

  • 你的后端路由直接映射到前端组件，消除了双路由系统的复杂性。
  • 你的控制器将数据返回给 Inertia 组件，而不是渲染模板或返回 JSON。
  • 导航感觉像单页应用一样流畅，但你的路由逻辑保留在服务器上，更容易保护和维护。

Inertia 还简化了表单提交和数据获取，同时让你的应用保持单体部署。你无需构建和维护单独的 API 层，就能获得现代、响应式的用户体验。

当你想要使用 React 或 Vue 但偏好服务端路由，想要避免前后端分离部署的复杂性，或者想要紧密集成的全栈开发体验时，选择这种方法。访问 inertiajs.com 了解更多关于 Inertia 如何弥合服务端和客户端框架之间差距的信息。

仅 API ​

你可以使用 AdonisJS 构建 JSON API 后端，而前端则位于完全独立的代码库中。这种方法实现了清晰的分离：AdonisJS 处理所有后端逻辑并通过 API 端点暴露数据，而你的前端应用（用任何框架构建）消费这些端点。

在仅 API 的设置中：

  • 你的控制器返回 JSON 响应。
  • 你的前端和后端是独立的部署，拥有各自的构建过程、仓库（或单体仓库）和部署流水线。
  • 两者仅通过 HTTP 请求与你的 API 端点进行通信。

TIP

在单体仓库中，你可以使用类型安全的 API 客户端实现前后端之间真正的端到端类型检查。转换器也会生成可复用、独立的响应类型，因此你的 UI 可以直接依赖序列化后的 API 契约。

这种方法适用于多种应用：移动应用（iOS、Android）的 API、用任何前端框架构建的 Web 应用、桌面应用，甚至多个前端（Web 和移动端）消费同一个 API。这种分离为每一层的独立部署和扩展提供了灵活性。

当你构建的服务于多个客户端应用的 API，你的团队偏好使用独立的前端和后端仓库，你需要独立部署和扩展前端与后端，或者你正在构建供外部开发者消费的公共 API 时，选择这种方法。

同一个控制器，三种不同的返回 ​

在下面的示例中，你可以看到我们使用了相同的路由、相同的控制器、相同的数据获取逻辑。只有返回语句发生了变化。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('posts', [controllers.Posts, 'index'])
ts
import Post from '#models/post'
import { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ view }: HttpContext) {
    const posts = await Post.all()
    return view.render('posts/index', { posts }) 
  }
}

ts
import Post from '#models/post'

不要期望什么 ​

如果你来自元框架，有些模式在 AdonisJS 中找不到。这些差异是有意为之的，能让你清楚地了解应用如何工作。

TIP

AdonisJS 被设计为驱动前端应用的后端，而不是元框架的替代品。你可以将 AdonisJS 与 TanStack Start、Nuxt、Next.js 等框架一起使用，两者之间有清晰的边界和定义良好的 API 契约。

没有基于文件的路由：AdonisJS 在你的路由文件中使用显式路由定义。路由通过 router API 声明，让你完全控制和了解应用的 URL 结构。这样可以轻松地在一个地方查看所有路由，并根据需要应用中间件或约束。

没有“use”指令的编译器魔法：你不会找到像“use server”或“use client”这样模糊代码执行边界的魔法语句。AdonisJS 在后端代码（在服务器上运行）和前端代码（在浏览器中运行）之间保持清晰的分离。

没有服务器和客户端代码的混合：你的后端逻辑位于控制器、模型和服务中。你的前端代码位于模板、组件或独立的前端应用中。代码在哪里运行没有任何歧义，这使得调试变得直接，并帮助团队在明确定义的边界下工作。

这种分离清晰地表明了代码在哪里执行，使调试可预测，并允许团队在前端和后端之间使用清晰的契约。当你的前端需要来自后端的数据时，你使用显式的 API 调用或模板数据传递，而不是在编译时模糊边界的魔法。

启动套件 ​

AdonisJS 为每种方法提供启动套件，其中已经包含了预设配置和最佳实践。你不必从头配置所有内容。

这些启动套件包括正确配置的构建工具、身份认证脚手架以及所有正确设置的集成。当你创建新的 AdonisJS 应用时，可以根据你决定的方法选择使用哪个启动套件。

这为你提供了**“灵活但不孤单”**的体验。你可以选择自己的技术栈，但一旦选定，你就会获得一个开箱即用的完整配置。

  • 超媒体启动套件
  • React 启动套件
  • Vue 启动套件
  • 仅 API
  • API 单体仓库
