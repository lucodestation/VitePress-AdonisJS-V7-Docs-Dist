AdonisRC 文件 ​

本指南涵盖 adonisrc.ts 配置文件。你将了解到如何：

  • 注册服务提供者和预加载文件
  • 为脚手架命令配置目录路径
  • 为常用 Ace 命令定义命令别名
  • 设置用于构建时代码生成的 Assembler 钩子
  • 指定要包含在生产构建中的元文件
  • 配置测试套件和运行器选项

概述 ​

adonisrc.ts 文件是你 AdonisJS 工作区的中央配置。它控制框架如何启动、脚手架命令将生成的文件放在哪里、要加载哪些提供者以及构建过程如何运作。

该文件由主应用之外的多个工具处理，包括 Ace CLI、Assembler（处理开发服务器和生产构建）以及各种代码生成器。由于这种广泛使用，该文件必须保持与环境无关，不包含应用特定的逻辑。

该文件包含运行应用所需的最低配置。你可以通过运行 node ace inspect:rcfile 命令查看完整的展开配置（包括所有默认值）。

sh
node ace inspect:rcfile

你可以使用 app 服务以编程方式访问解析后的 RCFile 内容。

ts
import app from '@adonisjs/core/services/app'

console.log(app.rcFile)

directories ​

directories 对象将逻辑目录名称映射到其文件系统路径。脚手架命令使用这些映射来确定生成文件的位置。

如果你在项目结构中重命名目录，请更新此处对应的路径，以便 node ace make:controller 等命令继续正常工作。

ts
{
  directories: {
    config: 'config',
    commands: 'commands',
    contracts: 'contracts',
    public: 'public',
    providers: 'providers',
    languageFiles: 'resources/lang',
    migrations: 'database/migrations',
    seeders: 'database/seeders',
    factories: 'database/factories',
    views: 'resources/views',
    start: 'start',
    tmp: 'tmp',
    tests: 'tests',
    httpControllers: 'app/controllers',
    models: 'app/models',
    services: 'app/services',
    exceptions: 'app/exceptions',
    mailers: 'app/mailers',
    mails: 'app/mails',
    middleware: 'app/middleware',
    policies: 'app/policies',
    validators: 'app/validators',
    events: 'app/events',
    listeners: 'app/listeners',
    transformers: 'app/transformers',
    stubs: 'stubs',
    generatedClient: '.adonisjs/client',
    generatedServer: '.adonisjs/server',
  }
}

preloads ​

preloads 数组指定在应用启动期间要导入的文件。这些文件在服务提供者注册并启动后立即导入，使其非常适合需要访问容器但应在应用开始处理请求之前运行的设置代码。

你可以注册一个预加载文件在所有环境中运行，或将其限制在特定环境中。

环境描述
webHTTP 服务器进程
consoleAce 命令（repl 除外）
repl交互式 REPL 会话
test测试运行器进程

最简单的形式是注册一个在所有环境中运行的文件。

ts
{
  preloads: [
    () => import('#start/view')
  ]
}

要将预加载文件限制在特定环境中，使用带有 environment 数组的对象形式。

ts
{
  preloads: [
    {
      file: () => import('#start/view'),
      environment: ['web', 'console', 'test']
    },
  ]
}

TIP

你可以使用 node ace make:preload 命令创建并注册预加载文件。

providers ​

providers 数组列出在应用启动期间要加载的服务提供者。提供者按它们在数组中的出现顺序加载，当提供者相互依赖时这很重要。

与预加载文件类似，提供者可以为所有环境注册，或使用相同的环境值限制在特定环境：web、console、repl 和 test。

ts
{
  providers: [
    () => import('@adonisjs/core/providers/app_provider'),
    () => import('@adonisjs/core/providers/http_provider'),
    () => import('@adonisjs/core/providers/hash_provider'),
    () => import('./providers/app_provider.js'),
  ]
}

要仅在特定环境中加载提供者，使用对象形式。

ts
{
  providers: [
    () => import('@adonisjs/core/providers/app_provider'),
    () => import('@adonisjs/core/providers/hash_provider'),
    {
      file: () => import('@adonisjs/core/providers/http_provider'),
      environment: ['web']
    },
    {
      file: () => import('./providers/app_provider.js'),
      environment: ['web', 'console', 'test']
    },
  ]
}

另请参阅：服务提供者

commands ​

commands 数组注册来自已安装包的 Ace 命令。你的应用自己的命令（位于 commands 目录中）会自动发现，无需在此注册。

ts
{
  commands: [
    () => import('@adonisjs/core/commands'),
    () => import('@adonisjs/lucid/commands')
  ]
}

另请参阅：创建 Ace 命令

commandsAliases ​

commandsAliases 对象为常用命令创建快捷方式。这对于名称较长的命令或你经常运行的命令很有用。

ts
{
  commandsAliases: {
    migrate: 'migration:run'
  }
}

你可以定义多个别名指向同一命令。

ts
{
  commandsAliases: {
    migrate: 'migration:run',
    up: 'migration:run'
  }
}

另请参阅：创建命令别名

hooks ​

hooks 对象注册在 Assembler 生命周期特定点运行的回调。Assembler 是负责运行开发服务器、创建生产构建、运行测试和执行代码生成的工具。

钩子可以内联定义，也可以作为懒加载模块定义。它们在与你 AdonisJS 应用不同的进程中运行，无法访问 IoC 容器或框架服务。

ts
import { defineConfig } from '@adonisjs/core/app'
import { indexEntities } from '@adonisjs/core/app'

export default defineConfig({
  hooks: {
    init: [indexEntities()],
    buildStarting: [() => import('@adonisjs/vite/build_hook')],
  },
})

indexEntities() 钩子为控制器、事件和监听器生成 barrel 文件，实现懒加载和类型安全引用。像 @adonisjs/vite/build_hook 这样的包钩子处理构建时的资源编译。

另请参阅：Assembler 钩子了解可用钩子的完整参考以及如何创建用于代码生成的自定义钩子。

metaFiles ​

metaFiles 数组指定在创建生产构建时要复制到 build 文件夹的非 TypeScript 文件。这包括模板、语言文件以及你的应用在运行时需要的其他资源。

每个条目接受一个 glob 模式和可选的 reloadServer 标志，当匹配的文件更改时触发开发服务器重启。

属性描述
pattern用于匹配文件的 glob 模式
reloadServer当这些文件更改时是否重启开发服务器
ts
{
  metaFiles: [
    {
      pattern: 'public/**',
      reloadServer: false
    },
    {
      pattern: 'resources/views/**/*.edge',
      reloadServer: false
    }
  ]
}

tests ​

tests 对象配置测试运行器，包括全局超时设置和测试套件定义。

ts
{
  tests: {
    timeout: 2000,
    forceExit: false,
    suites: [
      {
        name: 'functional',
        files: ['tests/functional/**/*.spec.ts'],
        timeout: 30000
      }
    ]
  }
}
属性描述
timeout所有测试的默认超时时间（毫秒）
forceExit测试完成后是否强制退出进程。推荐优雅退出
suites[].name测试套件的唯一标识符
suites[].files用于发现测试文件的 glob 模式
suites[].timeout套件特定的超时时间，覆盖全局默认值

另请参阅：测试简介
