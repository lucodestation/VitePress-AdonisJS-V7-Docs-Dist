应用 ​

本指南涵盖 AdonisJS 中的 Application 类。你将了解到如何：

  • 访问运行时环境（web、console、repl、test）
  • 检查 Node.js 环境和应用状态
  • 监听进程信号并通知父进程
  • 生成项目目录和文件的绝对路径
  • 使用生成器保持一致的命名约定

概述 ​

Application 类处理 AdonisJS 应用组装的繁重工作。它管理应用生命周期、提供对环境信息的访问、跟踪当前状态，并提供用于生成各种项目目录路径的辅助方法。

你通过 app 服务访问 Application 实例，该服务在应用中随处可用。

另请参阅：应用生命周期

ts
import app from '@adonisjs/core/services/app'

环境 ​

环境指的是你的应用运行时的上下文。AdonisJS 识别四种不同的环境：

环境描述
web为 HTTP 服务器启动的进程
consoleAce 命令（REPL 命令除外）
repl使用 node ace repl 启动的进程
test使用 node ace test 启动的进程

你可以使用 getEnvironment 方法访问当前环境。

ts
import app from '@adonisjs/core/services/app'

console.log(app.getEnvironment())

切换环境 ​

你可以在应用启动之前切换应用环境。当命令需要在与其启动时不同的上下文中运行时，这很有用。例如，node ace repl 命令在 console 环境中启动，但在呈现提示符之前切换到 repl。

ts
import app from '@adonisjs/core/services/app'

if (!app.isBooted) {
  app.setEnvironment('repl')
}

Node 环境 ​

nodeEnvironment 属性提供对 Node.js 环境的访问，派生自 NODE_ENV 环境变量。AdonisJS 规范化常见变体，以确保不同部署配置之间的一致性。

ts
import app from '@adonisjs/core/services/app'

console.log(app.nodeEnvironment)
NODE_ENV规范化为
devdevelopment
developdevelopment
stagestaging
prodproduction
testingtest

简写属性 ​

你可以使用这些布尔属性来检查当前环境，而不是比较字符串。

ts
import app from '@adonisjs/core/services/app'

/**
 * 检查是否在生产环境中运行
 */
app.inProduction
app.nodeEnvironment === 'production'

/**
 * 检查是否在开发环境中运行
 */
app.inDev
app.nodeEnvironment === 'development'

/**
 * 检查是否在运行测试
 */
app.inTest
app.nodeEnvironment === 'test'

状态 ​

状态表示应用在其生命周期中的位置。你可以访问的功能取决于当前状态——例如，在应用达到 booted 状态之前，你无法访问容器绑定或容器服务。

状态描述
created创建 Application 实例时的默认状态
initiated环境变量已解析且 adonisrc.ts 已处理
booted服务提供者已注册并启动
ready应用准备好处理请求（含义因环境而异）
terminated应用已终止，进程即将退出
ts
import app from '@adonisjs/core/services/app'

console.log(app.getState())

简写属性 ​

ts
import app from '@adonisjs/core/services/app'

/**
 * 状态超过 'initiated' 时为 true
 */
app.isBooted

/**
 * 状态为 'ready' 时为 true
 */
app.isReady

/**
 * 正在优雅地尝试终止时为 true
 */
app.isTerminating

/**
 * 状态为 'terminated' 时为 true
 */
app.isTerminated

监听进程信号 ​

你可以使用 app.listen 或 app.listenOnce 方法监听 POSIX 信号。这些方法向 Node.js process 对象注册监听器。

ts
import app from '@adonisjs/core/services/app'

app.listen('SIGTERM', () => {
  // 处理 SIGTERM
})

app.listenOnce('SIGTERM', () => {
  // 处理一次 SIGTERM
})

条件监听器 ​

使用 listenIf 或 listenOnceIf 仅在满足条件时注册监听器。仅当第一个参数为真值时才注册监听器。

ts
import app from '@adonisjs/core/services/app'

/**
 * 仅在 pm2 下运行时监听 SIGINT
 */
app.listenIf(app.managedByPm2, 'SIGINT', () => {
  // 在 pm2 中处理 SIGINT
})

app.listenOnceIf(app.managedByPm2, 'SIGINT', () => {
  // 在 pm2 中处理一次 SIGINT
})

通知父进程 ​

当你的应用作为子进程运行时，你可以使用 app.notify 方法向父进程发送消息。这封装了 process.send 方法。

ts
import app from '@adonisjs/core/services/app'

app.notify('ready')

app.notify({
  isReady: true,
  port: 3333,
  host: 'localhost'
})

生成项目文件的路径 ​

Application 类提供辅助方法，生成项目中文件和目录的绝对路径。这些辅助方法尊重你在 adonisrc.ts 文件中配置的目录结构，确保即使你自定义目录位置，路径也保持正确。

makePath ​

返回项目根目录内文件或目录的绝对路径。

ts
import app from '@adonisjs/core/services/app'

app.makePath('app/middleware/auth.ts')
// /project_root/app/middleware/auth.ts

makeURL ​

返回项目根目录内文件或目录的文件 URL。这在动态导入文件时很有用。

ts
import app from '@adonisjs/core/services/app'

const files = [
  './tests/welcome.spec.ts',
  './tests/maths.spec.ts'
]

await Promise.all(files.map((file) => {
  return import(app.makeURL(file).href)
}))

tmpPath ​

返回项目根目录内 tmp 目录中文件的路径。

ts
app.tmpPath('logs/mail.txt')
// /project_root/tmp/logs/mail.txt

app.tmpPath()
// /project_root/tmp

生成器 ​

生成器为应用中的不同实体创建一致的类名和文件名。它们确保在以编程方式创建新文件时遵循命名约定。

ts
import app from '@adonisjs/core/services/app'

app.generators.controllerFileName('user')
// users_controller.ts

app.generators.controllerName('user')
// UsersController

查看 generators.ts 源代码了解可用生成器的完整列表。
