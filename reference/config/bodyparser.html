Body parser 配置 ​

本参考指南涵盖 BodyParser 中间件配置，包括：允许解析的 HTTP 方法、自动数据规范化（空字符串转 null、空白修剪），以及针对 JSON、HTML 表单、multipart 文件上传和原始请求体的各解析器设置。

概述 ​

BodyParser 中间件根据传入请求的 Content-Type 头自动解析请求体，将原始请求数据转换为你的应用可以处理的结构化对象。没有 bodyparser，你需要为每个接受数据的端点手动读取和解析请求流。

该中间件在 start/kernel.ts 中注册，并通过 config/bodyparser.ts 文件配置。配置允许你控制哪些 HTTP 方法触发解析、启用数据规范化功能、设置请求体大小的安全限制，以及自定义每种解析器类型（JSON、表单、multipart、raw）的行为。

另请参阅：读取请求体 另请参阅：文件上传

配置结构 ​

配置文件使用 defineConfig 方法导出配置对象。以下是完整结构：

ts
// title: config/bodyparser.ts
import { defineConfig } from '@adonisjs/core/bodyparser'

export default defineConfig({
  /**
   * 要解析请求体的 HTTP 方法
   */
  allowedMethods: ['POST', 'PUT', 'PATCH', 'DELETE'],

  /**
   * 解析 HTML 表单的设置
   */
  form: {},

  /**
   * 解析 JSON 请求体的设置
   */
  json: {},

  /**
   * 带文件上传的 multipart 请求的设置
   */
  multipart: {},

  /**
   * 解析原始文本负载的设置
   */
  raw: {},
})

允许的方法 ​

allowedMethods 属性定义哪些 HTTP 方法应触发请求体解析。bodyparser 中间件只会尝试解析此数组中列出的方法的请求体。

ts
{
  allowedMethods: ['POST', 'PUT', 'PATCH', 'DELETE']
}

默认情况下，配置包含通常发送请求体的方法。但是，你可以根据应用需求修改此数组以添加或删除方法。例如，如果你的 API 接受不带请求体的 PATCH 请求，你可能将其从此列表中移除。

数据规范化功能 ​

bodyparser 提供两个适用于多种解析器的数据规范化功能：将空字符串转换为 null 以及修剪字符串值中的空白。

将空字符串转换为 null ​

当输入字段没有值时，HTML 表单会在请求体中发送空字符串。这种行为使数据库层的数据规范化变得更加困难。

例如，如果你有一个设置为可空的数据库列 country，当用户未选择国家时，你希望存储 null 值。但是，使用 HTML 表单时，后端接收到的是空字符串，你可能向数据库插入空字符串而不是让该列保持为 null。

BodyParser 中间件在启用 convertEmptyStringsToNull 标志时，通过将所有空字符串值转换为 null 来处理这种不一致。这在解析后的数据结构中的所有嵌套层级都有效。

ts
{
  form: {
    convertEmptyStringsToNull: true
  },
  json: {
    convertEmptyStringsToNull: true
  },
  multipart: {
    convertEmptyStringsToNull: true
  }
}

示例转换：

ts
// 请求体（解析前）
{
  "name": "John",
  "country": "",
  "preferences": {
    "newsletter": "",
    "notifications": "email"
  }
}

// 解析结果（使用 convertEmptyStringsToNull: true）
{
  "name": "John",
  "country": null,
  "preferences": {
    "newsletter": null,
    "notifications": "email"
  }
}

修剪空白 ​

trimWhitespaces 选项移除解析后的请求体中所有字符串值的前导和尾随空白。这在处理用户可能意外包含额外空格的表单输入时特别有用。

空白修剪在所有嵌套层级都有效，并且仅影响字符串值，其他数据类型保持不变。

ts
{
  form: {
    trimWhitespaces: true
  },
  json: {
    trimWhitespaces: true
  },
  multipart: {
    trimWhitespaces: true
  }
}

示例转换：

ts
// 请求体（解析前）
{
  "username": "  john_doe  ",
  "profile": {
    "bio": "  Software developer  "
  }
}

// 解析结果（使用 trimWhitespaces: true）
{
  "username": "john_doe",
  "profile": {
    "bio": "Software developer"
  }
}

JSON 解析器 ​

当你的 API 接受来自 JavaScript 客户端、移动应用或其他发送 JSON 编码负载的服务时，使用 JSON 解析器。该解析器处理 Content-type 头匹配配置类型之一的请求。

配置选项 ​

选项类型描述默认值
encodingstring将请求体 Buffer 转换为字符串的字符编码。支持 iconv-lite 的任何编码。'utf-8'
limitstring | number请求体的最大大小。超过时返回 413 错误。'1mb'
strictboolean启用时，仅允许 JSON 顶层的对象和数组。拒绝字符串或数字等原始值作为根元素。true
typesstring[]应使用 JSON 解析器解析的 Content-Type 头值数组。见下文
convertEmptyStringsToNullboolean在所有嵌套层级将空字符串转换为 null。true
trimWhitespacesboolean移除所有字符串值的前导和尾随空白。true

默认配置 ​

ts
{
  json: {
    encoding: 'utf-8',
    limit: '1mb',
    strict: true,
    types: [
      'application/json',
      'application/json-patch+json',
      'application/vnd.api+json',
      'application/csp-report',
    ],
    convertEmptyStringsToNull: true,
    trimWhitespaces: true,
  }
}

添加自定义内容类型 ​

你可以扩展 types 数组以处理你的应用需要支持的自定义基于 JSON 的内容类型。例如，要支持 JSON API 格式：

ts
{
  json: {
    types: [
      'application/json',
      'application/json-patch+json',
      'application/vnd.api+json',
      'application/csp-report',
      // insert-start
      'application/vnd.api+json; charset=utf-8',
      // insert-end
    ],
  }
}

表单解析器 ​

对于使用 URL 编码数据的 HTML 表单提交，使用表单解析器。这是通过 <form> 元素提交且不包含文件上传的表单的标准编码。该解析器处理 Content-type 头设置为 application/x-www-form-urlencoded 的请求。

配置选项 ​

选项类型描述默认值
encodingstring将请求体 Buffer 转换为字符串的字符编码。支持 iconv-lite 的任何编码。'utf-8'
limitstring | number请求体的最大大小。超过时返回 413 错误。'1mb'
queryStringobject用于解析 URL 编码数据的 qs 包的配置选项。{}
typesstring[]应使用表单解析器解析的 Content-Type 头值数组。['application/x-www-form-urlencoded']
convertEmptyStringsToNullboolean在所有嵌套层级将空字符串转换为 null。true
trimWhitespacesboolean移除所有字符串值的前导和尾随空白。true

默认配置 ​

ts
{
  form: {
    encoding: 'utf-8',
    limit: '1mb',
    queryString: {},
    types: ['application/x-www-form-urlencoded'],
    convertEmptyStringsToNull: true,
    trimWhitespaces: true,
  }
}

查询字符串选项 ​

表单解析器内部使用 qs 包。你可以使用 queryString 属性自定义其行为：

ts
{
  form: {
    queryString: {
      allowDots: true,      // 解析点号表示法（user.name）
      allowSparse: true,    // 允许稀疏数组
      depth: 10,            // 嵌套对象的最大深度
    },
  }
}

另请参阅：qs 包文档了解所有可用选项。

Multipart 解析器 ​

对于包含文件上传的 HTML 表单，使用 multipart 解析器。该解析器处理 Content-type 头设置为 multipart/form-data 的请求，自动处理上传的文件和表单字段。

另请参阅：文件上传指南

配置选项 ​

选项类型描述默认值
autoProcessboolean | string[]控制自动文件处理。当为 true 时，处理所有路由的文件。当为数组时，仅处理匹配路由模式的文件。当为 false 时，需要手动流处理。true
processManuallystring[]应禁用自动处理的路由模式数组，即使 autoProcess 为 true。[]
encodingstring将字段数据 Buffer 转换为字符串的字符编码。支持 iconv-lite 的任何编码。'utf-8'
fieldsLimitstring | number表单字段（非文件数据）允许的最大大小。超过时返回 413 错误。'2mb'
limitstring | number所有上传文件合计允许的最大总大小。单个文件限制可以使用 request.file() 设置。'20mb'
typesstring[]应使用 multipart 解析器解析的 Content-Type 头值数组。['multipart/form-data']
convertEmptyStringsToNullboolean在所有嵌套层级为表单字段将空字符串转换为 null。true
trimWhitespacesboolean移除所有字符串字段值的前导和尾随空白。true

默认配置 ​

ts
{
  multipart: {
    autoProcess: true,
    processManually: [],
    encoding: 'utf-8',
    fieldsLimit: '2mb',
    limit: '20mb',
    types: ['multipart/form-data'],
    convertEmptyStringsToNull: true,
    trimWhitespaces: true,
  }
}

控制自动处理 ​

默认情况下，当 autoProcess 为 true 时，bodyparser 会自动将所有上传的文件移动到操作系统的 tmp 目录。然后你可以在控制器中验证文件并将它们移动到持久位置或云存储。

选择性自动处理：

你可以通过提供路由模式数组将自动处理限制在特定路由。模式必须与 start/routes.ts 中的路由定义完全匹配（检查条件是 request.route.pattern === mentionedPattern）。

ts
{
  multipart: {
    autoProcess: [
      '/uploads',
      '/posts/:id/attachments'
    ],
  }
}

为特定路由禁用自动处理：

使用 processManually 为特定路由禁用自动处理，同时保持全局启用。当你需要为某些端点直接处理文件流时，这很有用。

ts
{
  multipart: {
    autoProcess: true,
    processManually: [
      '/file_manager',
      '/projects/:id/assets'
    ],
  }
}

WARNING

路由模式匹配：autoProcess 和 processManually 选项需要精确的路由模式匹配。模式必须与你在 start/routes.ts 中定义的方式完全相同。

示例：

ts
// title: start/routes.ts
router.post('/posts/:id/upload', handler)

// title: config/bodyparser.ts
autoProcess: ['/posts/:id/upload'] // ✅ 精确匹配
autoProcess: ['/posts/*/upload']   // ❌ 不会匹配

另请参阅：自行处理 multipart 流

原始解析器 ​

当你的应用需要处理其他解析器未覆盖的内容类型的请求体时，使用原始解析器。这对于 XML、CSV 或自定义基于文本的协议等格式很有用。原始解析器将请求体存储为字符串，然后你可以在控制器中使用 request.raw() 手动解析它。

配置选项 ​

选项类型描述默认值
encodingstring将请求体 Buffer 转换为字符串的字符编码。支持 iconv-lite 的任何编码。'utf-8'
limitstring | number请求体的最大大小。超过时返回 413 错误。'1mb'
typesstring[]应作为原始文本捕获的 Content-Type 头值数组。['text/*']

默认配置 ​

ts
{
  raw: {
    encoding: 'utf-8',
    limit: '1mb',
    types: ['text/*'],
  }
}

示例：处理 XML 请求 ​

ts
// title: config/bodyparser.ts
{
  raw: {
    encoding: 'utf-8',
    limit: '1mb',
    types: [
      'text/*',
      // insert-start
      'application/xml',
      'text/xml',
      // insert-end
    ],
  }
}
ts
// title: app/controllers/webhooks_controller.ts
import type { HttpContext } from '@adonisjs/core/http'
import { parseXML } from 'some-xml-parser'

export default class WebhooksController {
  async handle({ request }: HttpContext) {
    /**
     * 以字符串形式访问原始请求体
     */
    const rawBody = request.raw()

    /**
     * 使用你偏好的 XML 解析器解析它
     */
    const data = parseXML(rawBody)

    // 处理解析后的数据
  }
}
