应用配置参考 ​

本参考指南记录 config/app.ts 文件中所有可用的配置选项。应用配置控制 AdonisJS 应用的 HTTP 服务器行为、cookie 设置、请求解析以及各种其他运行时设置。

概述 ​

config/app.ts 文件导出控制你的 AdonisJS 应用如何处理 HTTP 请求的配置。这包括请求标识、cookie 管理、查询字符串解析和超时配置的设置。配置使用来自 @adonisjs/core/http 的 defineConfig 辅助函数定义，它提供完整的 TypeScript 支持。

有三个主要导出可用：

  • appKey - 用于加密 cookie、生成签名 URL，并被加密模块使用
  • appUrl - 应用的规范 URL，用于生成绝对 URL
  • http - 包含所有运行时设置的 HTTP 服务器配置对象

应用密钥 ​

appKey 用于加密 cookie、生成签名 URL，并被加密模块使用。如果密钥丢失或更改，加密模块将无法解密数据，因此请妥善保管应用密钥。

ts
// title: config/app.ts
import env from '#start/env'

export const appKey = env.get('APP_KEY')

使用以下 Ace 命令生成新的应用密钥：

sh
node ace generate:key

应用 URL ​

appUrl 用于你需要创建指向应用的绝对 URL 的各种地方。例如，发送电子邮件时，图片应使用绝对 URL。

ts
// title: config/app.ts
import env from '#start/env'

export const appUrl = env.get('APP_URL')

请求 ID 生成 ​

generateRequestId 选项控制是否为每个传入的 HTTP 请求生成唯一标识符。这对于关联日志和调试跨应用的请求流程很有用。

ts
// title: config/app.ts
import { defineConfig } from '@adonisjs/core/http'

export const http = defineConfig({
  generateRequestId: true
})

启用后，每个请求都会收到一个唯一 ID，可通过 request.id() 访问。默认值为 true。

表单方法欺骗 ​

HTML 表单只支持 GET 和 POST 方法。方法欺骗允许你通过查询参数指定其他 HTTP 方法（PUT、PATCH、DELETE），从而使用标准 HTML 表单实现完整的 RESTful 路由。

ts
// title: config/app.ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/core/http'

export const http = defineConfig({
  /**
   * 为 HTML 表单启用方法欺骗。
   * 这允许表单通过向表单 action 添加 ?_method=PUT
   * 来使用 PUT、PATCH 和 DELETE 方法。
   */
  allowMethodSpoofing: true
})

启用方法欺骗后，你可以在表单中使用 _method 查询参数：

html
<!-- 表单将作为 PUT 请求处理 -->
<form method="POST" action="/posts/1?_method=PUT">
  <input type="text" name="title" />
  <button type="submit">Update Post</button>
</form>

<!-- 表单将作为 DELETE 请求处理 -->
<form method="POST" action="/posts/1?_method=DELETE">
  <button type="submit">Delete Post</button>
</form>

出于安全原因，方法欺骗默认禁用。仅当你需要支持需要非 GET/POST 方法的传统 HTML 表单时才启用它。

异步本地存储 ​

异步本地存储允许你从应用中的任何地方访问 HTTP 上下文，而无需通过函数参数显式传递它。这对于在工具函数、服务类或深层嵌套代码中访问当前请求上下文很有用。

ts
// title: config/app.ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/core/http'

export const http = defineConfig({
  /**
   * 启用异步本地存储以全局访问 HTTP 上下文。
   * 启用后，你可以从任何地方使用 HttpContext.getOrFail()。
   */
  useAsyncLocalStorage: true
})

启用异步本地存储后，你可以访问 HTTP 上下文而无需显式传递它：

ts
// title: app/services/audit_logger.ts
import { HttpContext } from '@adonisjs/core/http'

export class AuditLogger {
  log(action: string) {
    /**
     * 访问当前请求上下文而不将其作为参数传递。
     * 这之所以有效，是因为异步本地存储
     * 在异步操作之间维护上下文。
     */
    const ctx = HttpContext.getOrFail()

    console.log({
      action,
      userId: ctx.auth.user?.id,
      ip: ctx.request.ip(),
      url: ctx.request.url()
    })
  }
}

重定向配置 ​

redirect 选项控制 HTTP 重定向的行为，包括 back() 的引用者主机验证和查询字符串转发。

ts
// title: config/app.ts
import { defineConfig } from '@adonisjs/core/http'

export const http = defineConfig({
  redirect: {
    /**
     * 基于引用者的重定向允许的主机数组。
     * back() 方法会根据当前请求的 Host 头验证 Referer 头。
     * 如果你的应用跨越多个域，请在此处添加额外的可信主机。
     *
     * 默认为 []
     */
    allowedHosts: [],

    /**
     * 是否默认将当前请求的查询字符串
     * 转发到重定向目标。
     *
     * 默认为 false
     */
    forwardQueryString: true,
  },
})

当启用 forwardQueryString 时，所有重定向会自动携带当前 URL 的查询参数。你可以通过在重定向实例上调用 withQs(false) 为特定重定向禁用转发。

当 back() 验证 Referer 头时，allowedHosts 数组会与请求的 Host 头一起检查。来自不在此列表中且不匹配当前请求主机的引用者将导致 back() 使用回退 URL。
