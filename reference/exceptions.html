异常参考 ​

在本指南中，我们将介绍框架核心和官方包引发的已知异常列表。一些异常被标记为自处理。自处理异常可以将自己转换为 HTTP 响应。

E_ROUTE_NOT_FOUND ​

当 HTTP 服务器收到对不存在路由的请求时引发该异常。默认情况下，客户端将收到 404 响应，你也可以选择使用状态页面渲染 HTML 页面。

  • 状态码：404
  • 自处理：否
ts
import { errors } from '@adonisjs/core'
if (error instanceof errors.E_ROUTE_NOT_FOUND) {
  // 处理错误
}

E_ROW_NOT_FOUND ​

当查找单个项目的数据库查询失败时引发该异常[例如使用 Model.findOrFail() 时]。默认情况下，客户端将收到 404 响应，你也可以选择使用状态页面渲染 HTML 页面。

  • 状态码：404
  • 自处理：否
ts
import { errors as lucidErrors } from '@adonisjs/lucid'
if (error instanceof lucidErrors.E_ROW_NOT_FOUND) {
  // 处理错误
  console.log(`${error.model?.name || 'Row'} not found`)
}

E_AUTHORIZATION_FAILURE ​

当 bouncer 授权检查失败时引发该异常。该异常是自处理的，并使用内容协商向客户端返回适当的错误响应。

  • 状态码：403
  • 自处理：是
  • 翻译标识符：errors.E_AUTHORIZATION_FAILURE
ts
import { errors as bouncerErrors } from '@adonisjs/bouncer'
if (error instanceof bouncerErrors.E_AUTHORIZATION_FAILURE) {
}

E_TOO_MANY_REQUESTS ​

当请求耗尽了在给定时长内允许的所有请求时，@adonisjs/rate-limiter 包引发该异常。该异常是自处理的，并使用内容协商向客户端返回适当的错误响应。

  • 状态码：429
  • 自处理：是
  • 翻译标识符：errors.E_TOO_MANY_REQUESTS
ts
import { errors as limiterErrors } from '@adonisjs/limiter'

}

E_BAD_CSRF_TOKEN ​

当使用 CSRF 保护的表单在没有 CSRF 令牌的情况下提交，或 CSRF 令牌无效时引发该异常。

  • 状态码：403
  • 自处理：是
  • 翻译标识符：errors.E_BAD_CSRF_TOKEN
ts
import { errors as shieldErrors } from '@adonisjs/shield'
if (error instanceof shieldErrors.E_BAD_CSRF_TOKEN) {
}

E_BAD_CSRF_TOKEN 异常是自处理的，用户将被重定向回表单，你可以使用闪存消息访问错误。

edge
@error('E_BAD_CSRF_TOKEN')
  <p>
    {{ message }}
  </p>
@end

E_OAUTH_MISSING_CODE ​

当 OAuth 服务在重定向期间未提供 OAuth 代码时，@adonisjs/ally 包引发该异常。

如果你在调用 .accessToken 或 .user 方法之前处理错误，可以避免此异常。

  • 状态码：500
  • 自处理：否
ts
import { errors as allyErrors } from '@adonisjs/ally'
if (error instanceof allyErrors.E_OAUTH_MISSING_CODE) {
}

E_HTTP_EXCEPTION ​

E_HTTP_EXCEPTION 是在 HTTP 请求期间引发错误的通用异常。你可以直接使用此异常或创建继承它的自定义异常。

  • 状态码：在引发异常时定义
  • 自处理：是
ts
// title: 引发异常
import { errors } from '@adonisjs/core'

throw errors.E_HTTP_EXCEPTION.invoke(
  {
    errors: ['Cannot process request'],
  },
  422
)
ts
// title: 处理异常
import { errors } from '@adonisjs/core'
if (error instanceof errors.E_HTTP_EXCEPTION) {
  // 处理错误
}

E_HTTP_REQUEST_ABORTED ​

E_HTTP_REQUEST_ABORTED 是 E_HTTP_EXCEPTION 异常的子类。该异常由 response.abort 方法引发。

ts
import { errors } from '@adonisjs/core'
if (error instanceof errors.E_HTTP_REQUEST_ABORTED) {
  // 处理错误
}

E_MAIL_TRANSPORT_ERROR ​

当无法使用给定传输发送电子邮件时，@adonisjs/mail 包引发该异常。通常，这会在电子邮件服务的 HTTP API 返回非 200 HTTP 响应时发生。

你可以使用 error.cause 属性访问网络请求错误。cause 属性是 got（npm 包）返回的错误对象。

  • 状态码：400
  • 自处理：否
ts
import { errors as mailErrors } from '@adonisjs/mail'
if (error instanceof mailErrors.E_MAIL_TRANSPORT_ERROR) {
  console.log(error.cause)
}
