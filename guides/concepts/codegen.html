代码生成 ​

本指南解释 AdonisJS 中代码生成的工作原理。你将了解到如何：

  • 理解 AdonisJS 为何生成代码而不仅仅依赖类型推断
  • 识别写入 .adonisjs 目录的文件以及你的应用如何使用它们
  • 理解代码生成何时运行以及为什么它会预热你的应用
  • 保持生成的代码同步并解决合并冲突

概述 ​

代码生成（codegen）是 AdonisJS 用来根据你的应用创建源文件和类型声明的过程。生成的文件位于 .adonisjs 目录内，允许框架提供类型安全的 API，而无需你手动维护文件列表。

TypeScript 可以从你导入的文件推断类型，但它无法创建和维护目录中每个控制器、转换器、事件或 Inertia 页面的列表。AdonisJS 执行这种发现并将结果写入为 TypeScript 代码。

生成的 data.d.ts 文件是一个很好的例子。对于应用中的每个转换器，代码生成会添加一个导入和 Data 命名空间中对应的类型。

ts
import type { InferData } from '@adonisjs/core/types/transformers'
import type UserTransformer from '#transformers/user_transformer'

export namespace Data {
  export type User = InferData<UserTransformer>
}

TypeScript 仍然执行类型推断。在此示例中，InferData<UserTransformer> 从你的 UserTransformer 读取输出类型。代码生成只是发现转换器并将其添加到生成的文件中。这意味着添加或移除转换器不需要你更新中央列表。

路由需要不同的方法。你通过执行 router.get() 等调用来注册路由，这些调用可以出现在 start/routes.ts、服务提供者、已安装的包甚至循环中。扫描源文件无法可靠地确定最终的路由表。AdonisJS 必须组装你的应用并让路由注册代码运行，然后才能生成准确的路由类型。

生成什么 ​

生成的输出分为两组。AdonisJS 可以通过扫描项目目录生成基于文件的输出。它在预热应用并读取已注册的路由后生成基于路由的输出。

确切的文件取决于你安装的包和 adonisrc.ts 文件中的代码生成钩子。以下文件在 AdonisJS 应用中很常见。

基于文件的输出 ​

AdonisJS 在不运行应用的情况下创建此输出。

.adonisjs/server/controllers.ts

一个包含控制器懒加载导入的 barrel 文件。你的应用通过 #generated/controllers 导入它。AdonisJS 为事件、监听器和 Bouncer 策略创建类似的 barrel 文件。

.adonisjs/server/pages.d.ts

包含你的 Inertia 页面组件的类型声明。它确保 inertia.render() 只接受应用中存在的页面。

.adonisjs/client/data.d.ts

包含你的转换器负载类型的 Data 命名空间，以及你的 Inertia 共享 props 和闪存消息。

.adonisjs/client/manifest.d.ts

对你的配置文件的引用。这些引用允许前端代码使用你暴露的配置文件导出的类型。

基于路由的输出 ​

AdonisJS 在你的路由声明运行后创建基于路由的输出。

.adonisjs/server/routes.d.ts

包含每个已注册路由（包括其名称和参数）的 RoutesList 接口。它为 router.makeUrl()、response.redirect().toRoute() 和客户端 URL 构建器提供类型安全。

包可以扩展同一过程。例如，Tuyau 使用生成的路由信息创建一个类型化的 API 客户端，它知道你的端点、参数和响应类型。

代码生成如何运行 ​

代码生成在预热你的应用之前创建基于文件的输出。这个顺序是必需的，因为你的应用在启动时可以导入生成的文件。例如，start/routes.ts 可以导入 #generated/controllers，因此 .adonisjs/server/controllers.ts 必须在 AdonisJS 导入你的路由之前存在。

完整过程遵循以下顺序：

  1. 扫描配置的项目目录。
  2. 写入从这些目录派生的 barrel 文件和类型声明。
  3. 预热应用，以便提供者和预加载文件注册路由。
  4. 读取完成的路由表并写入路由类型。

由于基于文件的输出先生成，它不依赖你的路由。添加控制器会更新 controllers.ts，即使没有路由引用该控制器。损坏的路由声明可以阻止路由类型刷新，但它不会阻止 AdonisJS 先更新基于文件的输出。

预热和服务提供者 ​

代码生成使用预热阶段来组装你的应用而不启动它。在预热期间，AdonisJS 执行每个服务提供者的 start 方法，然后导入你的预加载文件。这允许所有路由声明运行。但是，应用永远不会达到就绪状态，因此 ready 钩子不会运行，HTTP 服务器也不会开始接受流量。

提供者 start 方法内的代码在代码生成期间仍然运行。因此，start 方法不得无条件地发送电子邮件、启动工作进程、创建定时器或连接代码生成不需要的服务。使用应用模式守卫该工作。

WARNING

不要使用应用模式来决定注册哪些路由、绑定或事件监听器。这样做会使预热的应用与运行的应用不同，生成的类型将无法描述你的真实应用。

始终先执行框架注册。然后守卫应仅在 run 模式下运行的操作性副作用。

创建循环任务调度会写入配置的队列后端，因此应仅在应用将运行时发生。以下提供者使用应用模式防止代码生成在检查应用时创建或更新调度。

ts
import CleanupExpiredSessions from '#jobs/cleanup_expired_sessions'
import type { ApplicationService } from '@adonisjs/core/types'

export default class SchedulerProvider {
  constructor(protected app: ApplicationService) {}

  async start() {
    if (this.app.getMode() !== 'run') {
      return
    }

    await CleanupExpiredSessions.schedule({ retentionDays: 30 })
      .id('cleanup-expired-sessions')
      .cron('0 0 * * *')
      .timezone('UTC')
      .run()
  }
}

提交生成的代码 ​

.adonisjs 目录是生成的，但它不是可丢弃的构建产物。你必须将其提交到 Git。文件是否生成不如你的应用如何使用它重要。

生成的模块如 #generated/controllers 是你应用模块图的一部分。TypeScript 和生产构建将这些文件作为输入读取，就像它们读取你在 app 和 start 中编写的文件一样。build 目录不同，因为它包含从这些输入产生的输出。

其他框架也做出相同的区分。TanStack Router 建议提交其生成的 routeTree.gen.ts 文件，因为该文件是应用运行时源代码的一部分，并且是构建其路由所必需的。Rails 也建议提交 db/schema.rb 或 db/structure.sql，因为生成的模式快照用于创建新数据库。

.adonisjs 目录服务于类似的目的。它以 TypeScript、框架和其他工具可以直接消费的形式捕获从你的应用派生的信息。当生成的代码是构建、运行或设置应用的输入时，它属于 Git。

如果你克隆一个没有 .adonisjs 目录的项目，TypeScript 无法解析生成的导入，应用将无法编译，直到你重新生成缺失的文件。提交该目录确保全新检出可以安装、类型检查和构建，而不需要未记录的设置步骤。

重新生成代码 ​

运行 codegen 命令刷新基于文件和基于路由的输出。

sh
node ace codegen

开发服务器也执行两个阶段，并在你添加和移除文件时保持基于文件的输出同步。测试运行器和生产打包器运行刷新基于文件输出的初始化阶段，但它们不刷新基于路由的输出。

在开发服务器未运行时运行 node ace codegen，特别是在切换分支、完成 rebase 或在 CI 中进行类型检查之前。

解决合并冲突 ​

当不同分支向同一索引添加文件时，生成的文件可能发生冲突。例如，两个各自添加控制器的分支都会修改 .adonisjs/server/controllers.ts。

不要手动编辑生成的条目。在源文件中完成冲突解决，然后从磁盘上的文件重新生成 .adonisjs 目录。

sh
node ace codegen

重新生成的输出代表源树的最终状态。将重新生成的文件添加到 Git 以标记其冲突已解决。
