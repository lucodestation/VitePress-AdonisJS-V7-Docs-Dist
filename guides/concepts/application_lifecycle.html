应用生命周期 ​

本指南涵盖 AdonisJS 中的应用生命周期。你将了解到：

  • 四个生命周期阶段（启动、预热、运行和终止）
  • 每个阶段何时执行以及期间发生什么
  • 如何使用服务提供者和预加载文件挂钩到各个阶段
  • 应用模式如何让工具在不运行应用的情况下组装它

概述 ​

AdonisJS 应用生命周期有四个阶段：启动（boot）、预热（warmup）、运行（start） 和终止（termination）。每个阶段在组装、运行和关闭应用中有特定作用。

理解生命周期有助于你正确放置设置和清理代码。例如，你可以在应用处理请求之前注册自定义验证规则，并在进程退出之前关闭数据库连接。

生命周期从启动到预热再到运行，随后在进程收到关闭信号时进入终止。这种可预测的顺序让你能在适当的时间运行设置和清理代码。

启动阶段 ​

启动阶段是 AdonisJS 准备应用执行的初始阶段。在此阶段，你可以使用 IoC 容器获取绑定并扩展框架的各个部分。

服务提供者将其绑定注册到容器并执行其 boot 方法。框架本身正在被配置，但你的应用尚未准备好处理请求或执行命令。

启动阶段在提供者启动和预加载文件导入之前完成。

预热阶段 ​

预热阶段组装你的应用。AdonisJS 执行每个服务提供者的 start 方法，运行 starting 钩子，并导入预加载文件。

应用特定的注册发生在这里。路由被注册，事件监听器被附加，命名中间件变得可用。到此阶段结束时，你的应用已完整，但还没有被要求运行任何东西。

该阶段是环境感知的，意味着你可以为 HTTP 服务器、Ace 命令、测试和 REPL 加载不同的提供者和预加载文件。AdonisJS 并行导入为当前环境配置的所有预加载文件。

顺序很重要。提供者在预加载文件导入之前启动，因此预加载文件可以依赖提供者在其 start 方法中建立的任何内容。例如，@adonisjs/queue 在 start 期间初始化其队列管理器，这使得 start/scheduler.ts 预加载文件能够针对它调度任务。

运行阶段 ​

运行阶段是你的应用焕发生机的地方。AdonisJS 首先预热应用，然后启动它，最后执行每个服务提供者的 ready 方法。

到此阶段结束时，你的应用完全可运行并准备好处理 HTTP 请求、执行 Ace 命令或运行测试（取决于环境）。

预热是运行的一部分，因此当你运行应用时，永远不需要自己触发它。只需要检查应用的工具体在预热阶段结束时停止。参阅应用模式。

终止阶段 ​

终止阶段在 AdonisJS 开始优雅关闭时发生。这通常发生在进程收到 SIGINT 或 SIGTERM 信号时，例如当你停止开发服务器或在部署期间替换应用实例时。

在此阶段，服务提供者执行其 shutdown 方法，允许它们执行清理操作，如关闭数据库连接、刷新日志或取消挂起的后台任务。

优雅关闭确保你的应用干净地停止，而不是在操作中途突然终止，有助于防止数据损坏。

当应用以 warmup 模式运行时，AdonisJS 会跳过提供者的 shutdown 方法。因此，提供者不得在预热期间打开长期存在的资源。

应用模式 ​

每个应用在创建时都有一个模式，声明它打算在生命周期中走多远。默认的 run 模式将应用带到就绪状态。warmup 模式在预热阶段结束时停止，这是工具用来检查应用而不运行它的方式。

node ace codegen 命令使用 warmup 模式读取你的路由并生成其类型。它需要你的应用被组装，但在这样做时绝不能启动 HTTP 服务器、启动队列工作进程或打开数据库连接。

在服务提供者内使用模式来跳過只对运行的应用有意义的工作。例如，以下提供者在 codegen 检查应用时避免创建或更新其循环调度。

ts
import CleanupExpiredSessions from '#jobs/cleanup_expired_sessions'
import type { ApplicationService } from '@adonisjs/core/types'

export default class SchedulerProvider {
  constructor(protected app: ApplicationService) {}

  async start() {
    if (this.app.getMode() !== 'run') {
      return
    }

    await CleanupExpiredSessions.schedule({ retentionDays: 30 })
      .id('cleanup-expired-sessions')
      .cron('0 0 * * *')
      .timezone('UTC')
      .run()
  }
}

挂钩到生命周期阶段 ​

你可以使用服务提供者和预加载文件挂钩到不同的生命周期阶段。服务提供者提供 boot、start、ready 和 shutdown 方法，而预加载文件在预热期间运行。

挂钩到启动阶段 ​

在服务提供者中使用 boot 方法在启动阶段执行代码。这是你应扩展框架或配置应用其他部分所依赖的服务的地方。

以下提供者用 phoneNumber 验证规则扩展 VineJS。由于宏在启动期间注册，该规则在你的应用创建验证器时可用。

ts
import vine, { VineString } from '@vinejs/vine'
import type { ApplicationService } from '@adonisjs/core/types'

declare module '@vinejs/vine' {
  interface VineString {
    phoneNumber(): this
  }
}

const phoneNumberRule = vine.createRule(function phoneNumber(value, _, field) {
  if (typeof value !== 'string') {
    return
  }

  if (!/^\d{10}$/.test(value)) {
    field.report('The {{ field }} must be a valid 10-digit phone number', 'phoneNumber', field)
  }
})

export default class AppProvider {
  constructor(protected app: ApplicationService) {}

  async boot() {
    VineString.macro('phoneNumber', function (this: VineString) {
      return this.use(phoneNumberRule())
    })
  }
}

挂钩到预热和运行阶段 ​

对于在预热期间组装应用的代码，使用提供者的 start 方法或预加载文件。对于应仅在应用启动后开始的操作性工作，使用提供者的 ready 方法。

使用服务提供者方法 ​

start 方法在预热期间执行，在预加载文件导入之前。ready 方法在应用已启动并准备好处理请求或命令后执行。以下提供者在 start 中守卫数据库健康检查，因为该检查不得在 codegen 期间运行，并使用 ready 执行启动后开始的工作。

ts
import type { ApplicationService } from '@adonisjs/core/types'

export default class AppProvider {
  constructor(protected app: ApplicationService) {}

  async start() {
    if (this.app.getMode() !== 'run') {
      return
    }

    const database = await this.app.container.make('lucid.db')
    await database.connection().select(1)
  }

  async ready() {
    const logger = await this.app.container.make('logger')
    logger.info('Application is ready')
  }
}

使用预加载文件 ​

预加载文件提供了一种更简单的方式来组装应用特定的行为，而无需创建服务提供者。它们非常适合注册路由、附加事件监听器和配置中间件。

使用 make:preload 命令创建预加载文件。

sh
node ace make:preload events

此命令在 start 目录中创建新文件，并自动在你的 adonisrc.ts 配置文件中注册它。

ts
import emitter from '@adonisjs/core/services/emitter'
import logger from '@adonisjs/core/services/logger'

emitter.on('user:registered', function (user) {
  logger.info({ userId: user.id }, 'New user registered')
})

emitter.on('order:placed', function (order) {
  logger.info({ orderId: order.id }, 'New order placed')
})

你可以配置预加载文件仅在特定的运行时环境中加载。

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  preloads: [
    () => import('#start/routes'),
    () => import('#start/kernel'),
    {
      file: () => import('#start/events'),
      environment: ['web', 'console']
    }
  ]
})

environment 属性接受一个值数组：web（HTTP 服务器）、console（Ace 命令）、test（测试运行器）和 repl（REPL 环境）。

挂钩到终止阶段 ​

在服务提供者中使用 shutdown 方法在优雅关闭期间执行清理操作。这确保在你的应用终止之前正确释放资源。

ts
import type { ApplicationService } from '@adonisjs/core/types'

export default class AppProvider {
  constructor(protected app: ApplicationService) {}

  async shutdown() {
    const redis = await this.app.container.make('redis')
    await redis.quitAll()
  }
}
