脚手架和 codemod ​

本指南涵盖 AdonisJS 中的脚手架和 codemod 系统。你将了解到如何：

  • 为你的 AdonisJS 包创建 configure 钩子
  • 使用 codemod 修改宿主应用的源文件
  • 创建 stub 来搭建配置文件和其他源代码
  • 使用生成器和变量自定义 stub 模板
  • 从现有包中 eject 和修改 stub

概述 ​

当你运行 node ace configure @adonisjs/lucid 时，该包会自动注册其提供者、设置环境变量并在你的项目中创建配置文件。这种无缝的设置体验由 AdonisJS 的脚手架和 codemod 系统驱动。

脚手架指的是从称为 stub 的模板生成源文件。Codemod 是通过解析和操作 AST（抽象语法树）来修改现有 TypeScript 源文件的程序化转换。它们一起允许包作者提供与官方 AdonisJS 包相同的精致 configure 体验。

Codemod API 由 ts-morph 提供支持，位于 @adonisjs/assembler 包中。由于 assembler 是开发依赖，ts-morph 永远不会使你的生产包膨胀。

构建块 ​

在深入教程之前，让我们简要定义你将使用的关键组件。

Stub 是生成源文件的模板文件（扩展名为 .stub）。它们使用 Tempura，一个轻量级的 handlebars 风格模板引擎。

生成器是强制执行 AdonisJS 命名约定的辅助函数。它们将像 user 这样的输入转换为格式正确的名称，如 UsersController 或 users_controller.ts。

Codemod 是用于常见修改（如注册提供者、添加中间件或定义环境变量）的高级 API。它们为你处理 AST 操作的复杂性。

Configure 钩子是包导出的函数，在用户执行 node ace configure <package-name> 时运行。这是你结合 stub 和 codemod 来设置包的地方。

创建 configure 钩子 ​

脚手架和 codemod 最常见的用途是为 AdonisJS 包创建 configure 钩子。让我们以缓存包为例逐步构建一个。

步骤 1：设置包结构 ​

具有 configure 钩子的典型 AdonisJS 包具有以下结构：

my-cache-package/
├── src/
│   └── ...
├── stubs/
│   ├── config.stub
│   └── main.ts
├── configure.ts
├── index.ts
└── package.json

stubs 目录包含你的模板文件，configure.ts 保存 configure 函数，index.ts 导出包括 configure 钩子在内的所有内容。

步骤 2：将 @adonisjs/assembler 安装为 peer 依赖 ​

Codemod API 需要 @adonisjs/assembler，它必须作为peer 依赖安装在你的包中。这很重要，因为宿主应用已经将 assembler 安装为开发依赖，它应在所有已配置的包之间共享而不是重复。

json
{
  "name": "@adonisjs/cache",
  "peerDependencies": {
    "@adonisjs/assembler": "^7.0.0"
  }
}

当用户安装你的包并运行 node ace configure 时，将使用他们项目中的 assembler。

步骤 3：导出 stubs 根目录 ​

创建一个 stubs/main.ts 文件，导出你的 stubs 目录的路径。调用 makeUsingStub 时需要此路径。

ts
export const stubsRoot = import.meta.url

步骤 4：编写 configure 函数 ​

configure 函数接收 Configure 命令实例，它提供对 codemod API 的访问。以下是缓存包的完整示例：

ts
import type Configure from '@adonisjs/core/commands/configure'
import { stubsRoot } from './stubs/main.ts'

export async function configure(command: Configure) {
  const codemods = await command.createCodemods()

  /**
   * 在 adonisrc.ts 文件中注册提供者和命令
   */
  await codemods.updateRcFile((rcFile) => {
    rcFile
      .addProvider('@adonisjs/cache/cache_provider')
      .addCommand('@adonisjs/cache/commands')
  })

  /**
   * 向 .env 和 .env.example 文件添加环境变量
   */
  await codemods.defineEnvVariables({
    CACHE_STORE: 'redis',
  })

  /**
   * 向 start/env.ts 添加验证规则
   */
  await codemods.defineEnvValidations({
    variables: {
      CACHE_STORE: `Env.schema.string()`,
    },
  })

  /**
   * 从 stub 创建 config/cache.ts 文件
   */
  await codemods.makeUsingStub(stubsRoot, 'config.stub', {
    store: 'redis',
  })
}

步骤 5：从包入口点导出 ​

从包的主入口点导出 configure 函数，以便 node ace configure 命令可以找到它：

ts
export { configure } from './configure.ts'

当用户运行 node ace configure @adonisjs/cache 时，AdonisJS 导入此文件并执行导出的 configure 函数。

创建 stub ​

Stub 是生成源代码的模板文件。它们将静态内容与运行时计算的动态值相结合。

基本 stub 语法 ​

Stub 使用双花括号进行变量插值。以下是一个简单的配置 stub。

TIP

由于 Tempura 的语法与 Handlebars 兼容，请配置你的编辑器对 .stub 文件使用 Handlebars 语法高亮。

handlebars
{{{
  exports({
    to: app.configPath('cache.ts')
  })
}}}
import { defineConfig, stores } from '@adonisjs/cache'

export default defineConfig({
  default: '{{ store }}',

  stores: {
    redis: stores.redis({}),
  },
})

顶部的 exports 函数定义有关生成文件的元数据，最重要的是目标路径。app 变量提供对 configPath、makePath 和 httpControllersPath 等应用路径的访问。

使用生成器遵循命名约定 ​

创建需要遵循 AdonisJS 命名约定的 stub 时，使用生成器模块。生成器将用户输入转换为格式正确的名称。

handlebars
{{#var entity = generators.createEntity(name)}}
{{#var modelName = generators.modelName(entity.name)}}
{{#var modelReference = string.camelCase(modelName)}}
{{#var resourceFileName = string(modelName).snakeCase().suffix('_resource').ext('.ts').toString()}}
{{{
  exports({
    to: app.makePath('app/api_resources', entity.path, resourceFileName)
  })
}}}
export default class {{ modelName }}Resource {
  serialize({{ modelReference }}: {{ modelName }}) {
    return {{ modelReference }}.toJSON()
  }
}

{{#var ...}} 语法在 stub 内创建内联变量。这种方法将所有命名逻辑保留在 stub 内部，当用户 eject stub 以自定义它们时，这变得很重要。

向 stub 传递数据 ​

调用 makeUsingStub 时，将数据对象作为第三个参数传递。这些值在 stub 模板中可用：

ts
await codemods.makeUsingStub(stubsRoot, 'config.stub', {
  store: 'dynamodb',
  region: 'us-east-1',
})
handlebars
{{{
  exports({
    to: app.configPath('cache.ts')
  })
}}}
export default defineConfig({
  default: '{{ store }}',
  region: '{{ region }}',
})

全局 stub 变量 ​

每个 stub 都可以访问这些内置变量：

变量描述
app对应用类实例的引用，带有路径辅助函数。
generators对生成器模块的引用，用于命名约定。
randomString对 randomString 辅助函数的引用。
string用于创建字符串构建器实例以进行转换的函数。
flags运行 ace 命令时传递的命令行标志。

在命令中使用 stub ​

除了 configure 钩子，你还可以在自己的 Ace 命令中使用 stub。这对于创建如 make:resource 或 make:service 等脚手架命令很有用。

ts
import { join } from 'node:path'
import { BaseCommand, args } from '@adonisjs/core/ace'

const STUBS_ROOT = join(import.meta.dirname, '../stubs')

export default class MakeResource extends BaseCommand {
  static commandName = 'make:resource'
  static description = 'Create a new API resource'

  @args.string({ description: 'Name of the resource' })
  declare name: string

  async run() {
    const codemods = await this.createCodemods()

    await codemods.makeUsingStub(STUBS_ROOT, 'resource.stub', {
      name: this.name,
    })
  }
}

Eject stub ​

宿主应用可以通过 eject 来自定义 stub 模板。node ace eject 命令将 stub 从包复制到项目的 stubs 目录中。

Eject 单个 stub ​

sh
node ace eject make/controller/main.stub

这会将控制器 stub 从 @adonisjs/core 复制到项目中的 stubs/make/controller/main.stub。任何未来的 make:controller 调用都将使用你自定义的版本。

Eject 目录 ​

复制整个 stub 目录：

sh
# 所有 make stub
node ace eject make

# 所有控制器相关的 stub
node ace eject make/controller

从其他包 eject ​

默认情况下，eject 从 @adonisjs/core 复制。对其他包使用 --pkg 标志：

sh
node ace eject make/migration/main.stub --pkg=@adonisjs/lucid

使用 CLI 标志自定义输出 ​

脚手架命令通过 flags 变量与 stub 模板共享 CLI 标志。你可以使用它来创建自定义工作流：

sh
node ace make:controller invoice --feature=billing
handlebars
{{#var controllerName = generators.controllerName(entity.name)}}
{{#var featureDirectoryName = flags.feature}}
{{#var controllerFileName = generators.controllerFileName(entity.name)}}
{{{
  exports({
    to: app.makePath('features', featureDirectoryName, controllerFileName)
  })
}}}
// import type { HttpContext } from '@adonisjs/core/http'

export default class {{ controllerName }} {
}

查找要 eject 的 stub ​

每个包将其 stub 存储在包根目录的 stubs 目录中。访问包的 GitHub 仓库查看可用的内容。

Stub 执行流程 ​

当你调用 makeUsingStub 时，会发生以下情况：

  1. AdonisJS 首先在宿主项目的 stubs 目录中查找已 eject 的 stub
  2. 如果未找到，则使用你的包中的原始 stub
  3. 使用 Tempura 处理 stub 模板，求值所有变量和表达式
  4. exports() 函数确定输出路径
  5. 生成的文件被写入目标位置

Codemod API 参考 ​

Codemod API 提供用于常见源文件修改的高级方法。所有方法都可以在 command.createCodemods() 返回的 codemod 实例上使用。

TIP

Codemod API 依赖 AdonisJS 的默认文件结构和命名约定。如果你对项目结构做了重大更改，某些 codemod 可能无法按预期工作。

updateRcFile ​

在 adonisrc.ts 中注册提供者、命令、元文件和命令别名。

ts
await codemods.updateRcFile((rcFile) => {
  rcFile
    .addProvider('@adonisjs/lucid/db_provider')
    .addCommand('@adonisjs/lucid/commands')
    .setCommandAlias('migrate', 'migration:run')
})

输出：

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  commands: [
    () => import('@adonisjs/lucid/commands')
  ],
  providers: [
    () => import('@adonisjs/lucid/db_provider')
  ],
  commandAliases: {
    migrate: 'migration:run'
  }
})

defineEnvVariables ​

向 .env 和 .env.example 文件添加环境变量。

ts
await codemods.defineEnvVariables({
  REDIS_HOST: 'localhost',
  REDIS_PORT: '6379',
})

要从 .env.example 中省略值（对密钥有用），使用 omitFromExample 选项：

ts
await codemods.defineEnvVariables({
  API_KEY: 'secret-key-here',
}, {
  omitFromExample: ['API_KEY']
})

这会在 .env 中插入 API_KEY=secret-key-here，在 .env.example 中插入 API_KEY=。

defineEnvValidations ​

向 start/env.ts 添加验证规则。codemod 不会覆盖现有规则，尊重用户所做的任何自定义。

ts
await codemods.defineEnvValidations({
  leadingComment: 'Cache environment variables',
  variables: {
    CACHE_STORE: 'Env.schema.string()',
    CACHE_TTL: 'Env.schema.number.optional()',
  }
})

输出：

ts
import { Env } from '@adonisjs/core/env'

export default await Env.create(new URL('../', import.meta.url), {
  /**
   * Cache environment variables
   */
  CACHE_STORE: Env.schema.string(),
  CACHE_TTL: Env.schema.number.optional(),
})

registerMiddleware ​

将中间件注册到中间件栈之一：server、router 或 named。

ts
// 路由器中间件
await codemods.registerMiddleware('router', [
  {
    path: '@adonisjs/core/bodyparser_middleware'
  }
])

// 命名中间件
await codemods.registerMiddleware('named', [
  {
    name: 'auth',
    path: '@adonisjs/auth/auth_middleware'
  }
])

输出：

ts
import router from '@adonisjs/core/services/router'

router.use([
  () => import('@adonisjs/core/bodyparser_middleware')
])

export const middleware = router.named({
  auth: () => import('@adonisjs/auth/auth_middleware')
})

registerJapaPlugin ​

在 tests/bootstrap.ts 中注册 Japa 测试插件。

ts
await codemods.registerJapaPlugin(
  'sessionApiClient(app)',
  [
    {
      isNamed: false,
      module: '@adonisjs/core/services/app',
      identifier: 'app'
    },
    {
      isNamed: true,
      module: '@adonisjs/session/plugins/api_client',
      identifier: 'sessionApiClient'
    }
  ]
)

输出：

ts
import app from '@adonisjs/core/services/app'
import { sessionApiClient } from '@adonisjs/session/plugins/api_client'

export const plugins: Config['plugins'] = [
  sessionApiClient(app)
]

registerPolicies ​

在 app/policies/main.ts 中注册 bouncer 策略。

ts
await codemods.registerPolicies([
  {
    name: 'PostPolicy',
    path: '#policies/post_policy'
  }
])

输出：

ts
export const policies = {
  PostPolicy: () => import('#policies/post_policy')
}

registerVitePlugin ​

在 vite.config.ts 中注册 Vite 插件。

ts
await codemods.registerVitePlugin(
  'vue({ jsx: true })',
  [
    {
      isNamed: false,
      module: '@vitejs/plugin-vue',
      identifier: 'vue'
    }
  ]
)

输出：

ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [
    vue({ jsx: true })
  ]
})

installPackages ​

使用项目检测到的包管理器安装 npm 包。

ts
await codemods.installPackages([
  { name: 'vinejs', isDevDependency: false },
  { name: '@types/lodash', isDevDependency: true }
])
