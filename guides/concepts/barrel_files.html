Barrel 文件 ​

本指南涵盖 AdonisJS 中的 barrel 文件以及它们如何减少代码库中的导入杂乱。你将了解到：

  • 什么是 barrel 文件以及它们存储在哪里
  • 它们为什么存在（减少导入杂乱）
  • 自动生成如何工作
  • 如果需要，如何禁用它们

概述 ​

Barrel 文件是为应用中特定实体类型自动生成的导出集合。AdonisJS 为控制器、Bouncer 策略、事件和事件监听器创建 barrel 文件，将它们存储在 .adonisjs/server 目录中。

Barrel 文件完全可选。如果你愿意，可以继续使用直接导入，并通过配置完全禁用 barrel 文件生成。

问题：导入杂乱 ​

随着应用增长，像 start/routes.ts 这样的文件会累积数十个控制器导入。

在以下示例中，仅四个控制器，导入就已经消耗了大量垂直空间。在具有 20 多个控制器的生产应用中，你花在滚动导入上的时间比处理路由的时间还多。

ts
import router from '@adonisjs/core/services/router'

const NewAccountController = () => import('#controllers/new_account_controller')
const SessionController = () => import('#controllers/session_controller')
const PostsController = () => import('#controllers/posts_controller')
const PostCommentsController = () => import('#controllers/post_comments_controller')

router.get('signup', [NewAccountController, 'create'])
router.post('signup', [NewAccountController, 'store'])
router.get('login', [SessionController, 'create'])
router.post('login', [SessionController, 'store'])
router.get('posts', [PostsController, 'index'])
router.get('posts/:id', [PostsController, 'show'])
router.get('posts/:id/comments', [PostCommentsController, 'index'])

解决方案：Barrel 文件 ​

Barrel 文件将所有那些单独的导入整合为一个导入语句。以下是使用控制器 barrel 文件的相同路由文件：

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('signup', [controllers.NewAccount, 'create'])
router.post('signup', [controllers.NewAccount, 'store'])
router.get('login', [controllers.Session, 'create'])
router.post('login', [controllers.Session, 'store'])
router.get('posts', [controllers.Posts, 'index'])
router.get('posts/:id', [controllers.Posts, 'show'])
router.get('posts/:id/comments', [controllers.PostComments, 'index'])

差异立即可见。四个导入变成一个，你的路由就在文件顶部你需要它们的地方。路由定义的唯一更改是使用 controllers 命名空间来访问每个控制器。

Barrel 文件如何工作 ​

Barrel 文件本身非常简单。它只是一个将控制器名称映射到懒加载函数的 JavaScript 对象。以下是 .adonisjs/server/controllers.ts 的样子：

ts
export const controllers = {
  NewAccount: () => import('#controllers/new_account_controller'),
  Session: () => import('#controllers/session_controller'),
  Posts: () => import('#controllers/posts_controller'),
  PostComments: () => import('#controllers/post_comments_controller')
}

当你运行 node ace serve 时，开发服务器会自动生成此文件。当你在开发期间创建或删除控制器时，开发服务器的监视器会更新 barrel 文件以与你的代码库保持同步。

文件位置和导入别名 ​

Barrel 文件组织在 .adonisjs/server 目录中，具有对应的导入别名：

Barrel 文件导入路径用途
controllers.ts#generated/controllers控制器导出
policies.ts#generated/policiesBouncer 策略导出
events.ts#generated/events事件导出
listeners.ts#generated/listeners事件监听器导出

.adonisjs/server 目录在你的 package.json 中注册为子路径导入别名，允许你使用 #generated 前缀。

ts
import { controllers } from '#generated/controllers'
import { events } from '#generated/events'
import { listeners } from '#generated/listeners'

TIP

.adonisjs 目录包含由框架管理的自动生成文件。你不应手动编辑此目录中的文件，因为当开发服务器重新生成它们时，你的更改会被覆盖。

TIP

你应该将 .adonisjs 目录提交到版本控制。这些文件是 TypeScript 解析 #generated/controllers 等导入所必需的，没有它们，你的生产构建和 CI 流水线将失败。

性能和懒加载 ​

你可能想知道一次性导入所有控制器是否会影响性能。答案是否定的，因为 barrel 文件使用懒加载。

Barrel 文件中的每个控制器都包装在一个返回动态导入的函数中。

ts
{
  Posts: () => import('#controllers/posts_controller')
}

() => import() 函数仅在你实际在路由中使用该控制器时才被调用。在此之前，控制器模块永远不会被加载。这意味着 barrel 文件具有零性能影响。控制器仍然按需加载，与使用直接导入时完全相同。

禁用 Barrel 文件 ​

如果你不想使用 barrel 文件，可以通过 adonisrc.ts 配置文件禁用它们的生成。生成通过 init assembler 钩子管理。

ts
import { indexEntities } from '@adonisjs/core'
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  // ...其他配置

  hooks: {
    init: [
      indexEntities({
        controllers: {
          enabled: false,
        },
        events: {
          enabled: false,
        },
        listeners: {
          enabled: false,
        }
      })
    ]
  }
})

禁用 barrel 文件生成后，现有的 barrel 文件将保留在 .adonisjs/server 目录中。你需要手动移除它们并更新任何引用它们的代码以改用直接导入。
