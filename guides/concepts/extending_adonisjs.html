扩展框架 ​

本指南涵盖如何使用自定义功能扩展 AdonisJS。你将了解到如何：

  • 使用宏向框架类添加自定义方法
  • 使用 getter 创建计算属性
  • 使用 TypeScript 声明合并确保类型安全
  • 在应用中组织扩展代码
  • 扩展 Hash、Session 和 Authentication 等特定框架模块

概述 ​

AdonisJS 提供强大的扩展系统，让你在不修改框架源代码的情况下向框架类添加自定义方法和属性。这意味着你可以用自定义验证逻辑增强 HttpRequest 类，向 HttpResponse 类添加工具方法，或扩展任何其他框架类以满足应用的具体需求。

扩展系统建立在两个核心概念之上：宏（自定义方法）和 getter（计算属性）。两者都在运行时添加，并通过声明合并与 TypeScript 无缝集成，为你的编辑器提供完整的类型安全和自动补全。

AdonisJS 自己的所有一方包都使用这套相同的扩展 API，使其成为构建可重用功能经过验证的模式。无论你是为应用添加几个辅助方法还是构建要与社区共享的包，扩展系统都提供了一种干净、类型安全的方式来增强框架。

为什么要扩展框架？ ​

在深入机制之前，让我们理解你何时以及为什么想扩展框架类。

没有扩展，你需要在应用中反复编写相同的逻辑。例如，检查请求是否期望 JSON 响应：

ts
export default class PostsController {
  async index({ request, response }: HttpContext) {
    // 在每个返回不同格式的动作中重复
    const acceptHeader = request.header('accept', '')
    const wantsJSON = acceptHeader.includes('application/json') ||
                      acceptHeader.includes('+json')

    if (wantsJSON) {
      return response.json({ posts: [] })
    }

    return view.render('posts/index')
  }
}

使用宏，你只需编写一次此逻辑并在各处使用：

ts
import { HttpRequest } from '@adonisjs/core/http'

/**
 * 根据 Accept 头检查请求是否期望 JSON 响应
 */
HttpRequest.macro('wantsJSON', function (this: HttpRequest) {
  const firstType = this.types()[0]
  if (!firstType) {
    return false
  }

  return firstType.includes('/json') || firstType.includes('+json')
})
ts
export default class PostsController {
  async index({ request, response }: HttpContext) {
    if (request.wantsJSON()) {
      return response.json({ posts: [] })
    }

    return view.render('posts/index')
  }
}

扩展在以下情况下是理想的选择：

  • 你有框架特定的逻辑在应用中重用
  • 你想要保持 AdonisJS 的流畅 API 风格
  • 你正在构建一个与框架深度集成的包
  • 你需要具有自动补全支持的类型安全自定义功能

理解宏和 getter ​

在我们开始添加扩展之前，让我们澄清宏和 getter 是什么以及何时使用它们。

宏是你添加到类的自定义方法。它们像常规方法一样工作，可以接受参数、执行计算并返回值。当你需要需要输入或执行动作的功能时使用宏。

Getter 是计算属性，在你访问时看起来像常规属性。它们按需计算，并可选地缓存结果。对于不需要参数的只读派生数据使用 getter。

宏和 getter 都使用声明合并，这是 TypeScript 的一个功能，扩展现有类型定义以包含你的自定义添加。这确保你的扩展具有完整的类型安全和自动补全支持。

在底层，AdonisJS 使用 macroable 包来实现此功能。如果你想了解实现细节，可以参考该包的文档。

创建你的第一个宏 ​

让我们逐步构建一个简单的宏。我们将向 HttpRequest 类添加一个方法，检查传入的请求是否来自移动设备。

步骤 1：创建扩展文件 ​

创建一个专用文件来存放所有框架扩展。这使你的扩展代码集中在一个地方。

ts
// 此文件包含应用的所有框架扩展

文件可以命名为任何你喜欢的名称，但 extensions.ts 清楚地传达了其用途。

步骤 2：导入你想扩展的类 ​

导入你想添加功能的框架类。对于我们的示例，我们将扩展 HttpRequest 类。

ts
import { HttpRequest } from '@adonisjs/core/http'

步骤 3：添加宏方法 ​

使用 macro 方法添加你的自定义功能。该方法接收类实例作为 this，让你访问类的所有现有属性和方法。

ts
import { HttpRequest } from '@adonisjs/core/http'

HttpRequest.macro('isMobile', function (this: HttpRequest) {
  /**
   * 获取 User-Agent 头，如果不存在则默认为空字符串
   */
  const userAgent = this.header('user-agent', '')

  /**
   * 检查 User-Agent 是否包含常见的移动标识符
   */
  return /mobile|android|iphone|ipad|phone/i.test(userAgent)
})

function (this: HttpRequest) 语法很重要，因为它为你提供正确的 this 上下文。不要在这里使用箭头函数，因为它们不保留 this 绑定。

步骤 4：添加 TypeScript 类型定义 ​

使用声明合并告诉 TypeScript 你的新方法。在扩展文件末尾添加以下内容。

ts
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    isMobile(): boolean
  }
}

declare module 中的模块路径必须与你使用的导入路径完全匹配。接口名称必须与类名称完全匹配。

步骤 5：在提供者中加载扩展 ​

在服务提供者的 boot 方法中导入你的扩展文件，以确保应用启动时注册扩展。

ts
export default class AppProvider {
  async boot() {
    await import('../src/extensions.ts')
  }
}

步骤 6：使用你的宏 ​

你的宏现在可以在整个应用中使用，具有完整的类型安全和自动补全。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class HomeController {
  async index({ request, view }: HttpContext) {
    /**
     * TypeScript 知道 isMobile() 并提供自动补全
     */
    if (request.isMobile()) {
      return view.render('mobile/home')
    }

    return view.render('home')
  }
}

创建你的第一个 getter ​

Getter 是计算属性，像常规属性一样工作但按需计算。让我们向 HttpRequest 类添加一个提供清理后的请求路径的 getter。

ts
import { HttpRequest } from '@adonisjs/core/http'

HttpRequest.getter('cleanPath', function (this: HttpRequest) {
  /**
   * 获取当前 URL 路径
   */
  const path = this.url()

  /**
   * 移除尾随斜杠并转换为小写
   */
  return path.replace(/\/+$/, '').toLowerCase()
})
ts
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    cleanPath: string  // 注意：是属性，不是方法
  }
}

注意类型声明与宏不同。Getter 是属性，不是方法，因此类型定义中不包含 ()。

你可以像常规属性一样使用 getter：

ts
export default class LogMiddleware {
  async handle({ request, logger }: HttpContext, next: NextFn) {
    /**
     * 像属性而不是方法一样访问 getter
     */
    logger.info('Request path: %s', request.cleanPath)

    await next()
  }
}

TIP

Getter 回调不能是异步的，因为 JavaScript getter 在设计上是同步的。如果你需要异步计算，请改用宏。

单例 getter ​

默认情况下，getter 每次访问时都会重新计算其值。对于昂贵的计算，你可以使 getter 成为单例，它在首次计算后缓存结果。

ts
import { HttpRequest } from '@adonisjs/core/http'

/**
 * 第三个参数 (true) 使其成为单例 getter
 */
HttpRequest.getter('ipAddress', function (this: HttpRequest) {
  /**
   * 首先检查代理头，回退到直接 IP
   * 这每个请求实例只运行一次
   */
  return this.header('x-forwarded-for') ||
         this.header('x-real-ip') ||
         this.ips()[0] ||
         this.ip()
}, true)
ts
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    ipAddress: string
  }
}

使用单例 getter 时，函数对类的每个实例执行一次，返回值对该实例缓存：

ts
const ip1 = request.ipAddress  // 执行 getter 函数
const ip2 = request.ipAddress  // 返回缓存值，不再执行
const ip3 = request.ipAddress  // 仍然返回缓存值

TIP

当计算值在实例生命周期内不会改变时，使用单例 getter。例如，请求的 IP 地址在单个 HTTP 请求期间不会改变，因此缓存它是有意义的。

不要对可能更改的值使用单例 getter，如基于可变状态的计算属性。

何时使用宏与 getter ​

在宏和 getter 之间选择取决于你的用例。以下是一个实用指南。

当你需要以下功能时使用宏：

  • 接受参数
  • 执行带副作用的动作
  • 根据输入返回不同的值
  • 执行异步操作
ts
/**
 * 宏示例：接受 role 参数
 */
HttpRequest.macro('hasRole', function (this: HttpRequest, role: string) {
  const user = this.ctx.auth.user
  return user?.role === role
})

// 用法：request.hasRole('admin')

当你需要以下功能时使用 getter：

  • 提供计算的只读属性
  • 从现有属性计算派生数据
  • 缓存昂贵计算（使用单例）
  • 保持类似属性的 API
ts
/**
 * Getter 示例：无参数的计算属性
 */
HttpRequest.getter('isAuthenticated', function (this: HttpRequest) {
  return this.ctx.auth.isAuthenticated
})

// 用法：request.isAuthenticated

两者可以在同一个类上共存。根据你想提供的 API 选择。

理解声明合并 ​

声明合并是 TypeScript 了解你运行时扩展的方式。正确做到这一点对类型安全至关重要。

declare module 语句中的模块路径必须与你用来导入类的路径完全匹配：

ts
// 如果你这样导入：
import { HttpRequest } from '@adonisjs/core/http'

// 你必须这样声明（完全相同的路径）：
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    isMobile(): boolean
  }
}

WARNING

为什么这很重要：TypeScript 使用模块路径来确定与哪个类型定义合并。

会发生什么：如果路径不匹配，TypeScript 不会识别你的扩展。即使你的代码运行正确，你也会看到"Property 'isMobile' does not exist on type 'Request'"之类的错误。

解决方案：编写声明时始终复制确切的导入路径：

ts
// ✅ 正确：路径匹配
import { HttpRequest } from '@adonisjs/core/http'
declare module '@adonisjs/core/http' { ... }

// ❌ 错误：路径不匹配
import { HttpRequest } from '@adonisjs/core/http'
declare module '@adonisjs/http-server' { ... }

你可以在同一个 declare module 块中声明多个扩展：

ts
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    isMobile(): boolean
    hasRole(role: string): boolean
    cleanPath: string
    ipAddress: string
  }
}

或者如果你偏好，将它们拆分到多个块中：

ts
declare module '@adonisjs/core/http' {
  interface HttpRequest {
    isMobile(): boolean
  }
}

declare module '@adonisjs/core/http' {
  interface HttpRequest {
    hasRole(role: string): boolean
  }
}

两种方法工作方式相同。根据你的组织偏好选择。

常见错误 ​

以下是开发者在扩展框架时遇到的最常见问题以及如何修复它们。

TIP

错误：为宏使用箭头函数

为什么失败：箭头函数没有自己的 this 绑定，因此你无法访问类实例。

ts
// ❌ 错误：箭头函数
HttpRequest.macro('isMobile', () => {
  return this.header('user-agent')  // `this` 是 undefined！
})

// ✅ 正确：常规函数
HttpRequest.macro('isMobile', function (this: HttpRequest) {
  return this.header('user-agent')  // `this` 是 Request 实例
})

TIP

错误：忘记单例参数默认为 false

会发生什么：你的 getter 每次访问时都会重新计算，即使值不会改变。

ts
// 这每次都会执行函数
HttpRequest.getter('expensiveCalculation', function (this: HttpRequest) {
  return someExpensiveOperation()
})

// 添加 true 作为单例以缓存结果
HttpRequest.getter('expensiveCalculation', function (this: HttpRequest) {
  return someExpensiveOperation()
}, true)  // 首次访问后缓存

TIP

错误：将 getter 当作方法处理

会发生什么：你会得到错误，因为 getter 是属性，不是函数。

ts
HttpRequest.getter('ipAddress', function (this: HttpRequest) {
  return this.ip()
})

// ❌ 错误：像方法一样调用它
const ip = request.ipAddress()

// ✅ 正确：像属性一样访问它
const ip = request.ipAddress

RouteMatchers（导入路径：@adonisjs/core/http）

路由匹配器类定义用于路由参数验证的可重用匹配器。扩展它以添加自定义验证和转换规则。

ts
import { RouteMatchers } from '@adonisjs/core/http'

  return {
    match: /^[1-9][0-9]*$/,
    cast: (value: string) => Number(value),

declare module '@adonisjs/core/http' {
  interface RouteMatchers {
    positiveInteger(): {
      match: RegExp
      cast: (value: string) => number
    }
  }
}

import router from '@adonisjs/core/services/router'

    return `Post ${params.id}`
  })
  .where('id', router.matchers.positiveInteger())

扩展特定模块 ​

除了宏和 getter，许多 AdonisJS 模块提供专用的扩展 API 用于添加自定义实现。这些专为更复杂的集成（如自定义驱动或加载器）而设计。

以下模块可以用自定义实现扩展：

  • 创建自定义 hash 驱动 - 添加对自定义密码哈希算法的支持
  • 创建自定义会话存储 - 将会话存储在 MongoDB 或 Redis 等自定义后端中
  • 创建自定义社交身份认证驱动 - 添加内置之外的 OAuth 提供者
  • 添加自定义 REPL 方法 - 用自定义命令扩展 REPL
  • 创建自定义翻译加载器 - 从自定义来源加载翻译
  • 创建自定义翻译格式化器 - 用自定义逻辑格式化翻译

这些扩展点超越了简单的方法和属性，允许你将自定义功能深度集成到框架中。
