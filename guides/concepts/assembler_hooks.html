Assembler 钩子 ​

本指南涵盖 AdonisJS 中的 Assembler 钩子。你将了解到如何：

  • 为开发、测试、构建和代码生成注册钩子
  • 在监视模式下响应文件更改
  • 挂钩到路由扫描管道
  • 使用 IndexGenerator 生成 barrel 文件和类型声明
  • 创建自定义代码生成工作流

概述 ​

Assembler 是启动开发服务器、运行测试、创建生产构建和生成框架拥有文件的工具层。钩子让你在这些工作流的特定点运行代码。例如，你可以在控制器更改时生成 barrel 文件，或在开发服务器启动时显示额外信息。

由于 Assembler 在与你的 AdonisJS 应用不同的进程中运行，钩子无法访问 IoC 容器、router 服务或数据库连接等框架功能。相反，钩子接收专门构建的实用工具，如用于代码生成的 IndexGenerator 和用于路由分析的扫描器实例。

常见用例包括生成 barrel 文件、检查路由元数据、响应文件更改和自定义命令输出。

钩子参考 ​

下表列出所有可用的钩子、它们何时执行以及它们接收什么参数。

钩子触发者描述
initDevServer、TestRunner、Bundler、CodeGen第一个执行的钩子。用于初始化任务
devServerStartingDevServer子进程启动之前
devServerStartedDevServer子进程运行之后
testsStartingTestRunner测试开始执行之前
testsFinishedTestRunner测试完成之后
buildStartingBundler生产构建开始之前
buildFinishedBundler生产构建完成之后
fileChangedDevServer、TestRunner监视模式下文件被修改时
fileAddedDevServer、TestRunner文件被创建时
fileRemovedDevServer、TestRunner文件被删除时
routesCommittedDevServer、CodeGen应用注册路由时
routesScanningDevServer、CodeGen路由类型扫描开始之前
routesScannedDevServer、CodeGen路由类型扫描完成之后

CodeGen 条目指的是 node ace codegen 命令。它运行代码生成而不启动服务器或文件监视器。打包器和测试运行器不执行路由钩子，因此使用 node ace codegen 在不运行开发服务器的情况下刷新路由派生的输出。

创建和注册钩子 ​

钩子在 adonisrc.ts 文件的 hooks 属性下注册。每个钩子接受懒加载导入数组，允许你将钩子逻辑拆分到单独的文件中并仅在需要时加载它们。

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  hooks: {
    devServerStarted: [() => import('./hooks/on_server_started.js')],
    fileChanged: [() => import('./hooks/on_file_changed.js')],
  },
})

钩子文件必须导出一个接收钩子参数的默认函数。每个钩子都有一个从 @adonisjs/core/app 可用的类型化辅助函数，为参数提供完整的 TypeScript 支持。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.devServerStarted((devServer, info, instructions) => {
  /**
   * info.host - 服务器绑定到的主机地址
   * info.port - 服务器运行的端口号
   * instructions - 用于显示格式化输出的 UI 辅助工具
   */
  console.log(`Server running at http://${info.host}:${info.port}`)
})

你可以为同一事件注册多个钩子。它们按注册顺序执行。

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  hooks: {
    devServerStarted: [
      () => import('./hooks/log_server_info.js'),
      () => import('./hooks/notify_external_service.js'),
    ],
  },
})

WARNING

Assembler 钩子在与你的 AdonisJS 应用不同的进程中运行。它们无法访问 IoC 容器、router、数据库或任何其他框架服务。如果你需要与应用交互，请使用路由扫描钩子提取元数据或通过 HTTP/IPC 通信。

Init 钩子 ​

init 钩子是 Assembler 启动操作时执行的第一个钩子。它接收父实例（DevServer、TestRunner、Bundler 或 CodeGen）、钩子管理器和 IndexGenerator。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.init((parent, hooksManager, indexGenerator) => {
  console.log('Assembler initialized')
})

init 钩子是配置 IndexGenerator 以生成 barrel 文件和类型的推荐位置，因为它先于任何其他操作运行。

Dev server 钩子 ​

开发服务器钩子在启动和运行开发服务器时执行。devServerStarting 钩子在子进程启动之前触发，devServerStarted 在服务器开始接受连接后触发。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.devServerStarting((devServer) => {
  /**
   * 在服务器启动之前执行设置任务。
   * 子进程尚未启动。
   */
  console.log('Preparing to start dev server...')
})
ts
import { hooks } from '@adonisjs/core/app'

export default hooks.devServerStarted((devServer, info, instructions) => {
  instructions.add(`API docs: http://${info.host}:${info.port}/docs`)
})

每次子进程重启时这些钩子会重新触发，例如由于文件更改发生完整重载时。

Test runner 钩子 ​

测试运行器钩子在测试套件之前和之后执行。使用 testsStarting 准备外部资源或生成的夹具，使用 testsFinished 生成报告或清理这些资源。这些钩子在应用进程外运行，无法解析框架服务。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.testsStarting((testRunner) => {
  console.log('Preparing test environment...')
})
ts
import { hooks } from '@adonisjs/core/app'

export default hooks.testsFinished((testRunner) => {
  console.log('Tests complete, generating coverage report...')
})

在监视模式下运行测试时，每次测试套件重新运行时这些钩子会重新触发。

Bundler 钩子 ​

打包器钩子在使用 node ace build 创建生产构建时执行。使用 buildStarting 进行构建前任务（如资源优化），使用 buildFinished 显示构建统计信息或运行构建后脚本。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.buildStarting((bundler) => {
  console.log('Starting production build...')
})
ts
import { hooks } from '@adonisjs/core/app'

export default hooks.buildFinished((bundler, instructions) => {
  instructions.add('Run `npm run start` in the build folder to start the server')
})

Watcher 钩子 ​

监视器钩子在开发或测试监视模式下文件更改时触发。在 HMR 模式下，Assembler 依赖 hot-hook 检测更改；否则，内置文件监视器处理检测。

每个监视器钩子都接收相对路径（从应用根目录，使用 Unix 风格斜杠）和受影响文件的绝对路径。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.fileChanged((relativePath, absolutePath, info, parent) => {
  /**
   * info.source - 'hot-hook' 或 'watcher'
   * info.hotReloaded - 如果文件被热重载而不重启则为 true
   * info.fullReload - 如果需要完整服务器重启则为 true
   */
  if (relativePath.startsWith('app/controllers/')) {
    console.log(`Controller changed: ${relativePath}`)
  }
})
ts
import { hooks } from '@adonisjs/core/app'

export default hooks.fileAdded((relativePath, absolutePath, parent) => {
  console.log(`New file created: ${relativePath}`)
})
ts
import { hooks } from '@adonisjs/core/app'

export default hooks.fileRemoved((relativePath, absolutePath, parent) => {
  console.log(`File deleted: ${relativePath}`)
})

Routes 钩子 ​

路由钩子提供对应用路由定义及其关联类型的访问。它们为开发服务器和 node ace codegen 运行，但不为构建或测试运行。

路由已提交 ​

routesCommitted 钩子在你的 AdonisJS 应用注册路由时触发。路由通过 IPC 从子进程传输到 Assembler，让你访问路由元数据而无需自己解析文件。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.routesCommitted((devServer, routes) => {
  /**
   * routes 是一个以域为键的对象。
   * 每个域包含路由定义数组。
   */
  const defaultRoutes = routes['root'] || []
  console.log(`${defaultRoutes.length} routes registered`)
})

路由扫描 ​

routesScanning 钩子在 Assembler 开始分析你的路由以提取请求和响应类型之前触发。使用此钩子配置扫描器，例如从分析中跳过某些路由。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.routesScanning((devServer, routesScanner) => {
  const excludedRoutes = ['session.create', 'session.store', 'oauth.callback']

  routesScanner.filter((route) => {
    return !excludedRoutes.includes(route.name)
  })
})

路由已扫描 ​

routesScanned 钩子在路由分析完成后触发。扫描器包含提取的类型信息，你可以用它生成 API 客户端或类型声明。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.routesScanned((devServer, routesScanner) => {
  const routes = routesScanner.getScannedRoutes()
  const controllers = routesScanner.getControllers()

  console.log(`Scanned ${routes.length} routes from ${controllers.length} controllers`)
})

TIP

路由扫描器提取的类型是指向你的控制器和验证器的内部导入引用。它们不是可以在单独项目中使用的完全解析的独立类型。生成独立类型需要额外的工具，如 Tuyau。

IndexGenerator ​

IndexGenerator 是一个用于监视目录并从其内容生成 barrel 文件或类型声明的实用工具。它自动处理文件监视，在源文件添加或移除时重新生成输出文件。

配置 IndexGenerator ​

在 init 钩子中注册 IndexGenerator 配置。每个配置指定要监视的源目录、要生成的输出文件以及如何转换源文件。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.init((parent, hooksManager, indexGenerator) => {
  indexGenerator.add('controllers', {
    source: './app/controllers',
    importAlias: '#controllers',
    as: 'barrelFile',
    exportName: 'controllers',
    removeSuffix: 'controller',
    output: './.adonisjs/server/controllers.ts',
  })
})

配置选项包括：

选项描述
source要扫描源文件的目录
importAlias生成的导入中使用的导入别名（例如 #controllers）
as'barrelFile' 用于自动生成，或用于自定义输出的回调
exportNamebarrel 文件中导出的常量名称
removeSuffix生成属性键时从文件名中剥离的后缀
output生成文件的写入路径

Barrel 文件生成 ​

当 as 设置为 'barrelFile' 时，IndexGenerator 递归扫描源目录并生成导出懒加载导入的 barrel 文件。目录结构保留为嵌套对象。

给定此控制器结构：

text
app/controllers/
├── auth/
│   ├── login_controller.ts
│   └── register_controller.ts
├── blog/
│   ├── posts_controller.ts
│   └── post_comments_controller.ts
└── users_controller.ts

IndexGenerator 生成：

ts
export const controllers = {
  auth: {
    Login: () => import('#controllers/auth/login_controller'),
    Register: () => import('#controllers/auth/register_controller'),
  },
  blog: {
    Posts: () => import('#controllers/blog/posts_controller'),
    PostComments: () => import('#controllers/blog/post_comments_controller'),
  },
  Users: () => import('#controllers/users_controller'),
}

此 barrel 文件使你可以在路由中懒加载控制器而无需手动管理导入。当你添加或移除控制器时文件会自动更新。

自定义输出生成 ​

对于自定义输出，向 as 选项传递回调。回调接收虚拟文件系统、文件缓冲区、源配置和用于生成导入路径的辅助函数。以下示例扫描 React 页面并生成 inertia.render() 使用的 InertiaPages 类型。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.init((_parent, _hooksManager, indexGenerator) => {
  indexGenerator.add('inertiaPages', {
    source: './inertia/pages',
    glob: ['**/*.ts', '**/*.tsx'],
    as: (vfs, buffer, _config, helpers) => {
      const pages = vfs.asList()

      buffer.writeLine(`import '@adonisjs/inertia/types'`)
      buffer.writeLine(`import type React from 'react'`)
      buffer.writeLine(`import type { Prettify } from '@adonisjs/core/types/common'`)
      buffer.writeLine(``)
      buffer.writeLine(`type ExtractProps<T> =`)
      buffer.indent().writeLine(`T extends React.FC<infer Props>`)
      buffer.indent().writeLine(`? Prettify<Omit<Props, 'children'>>`)
      buffer.writeLine(`: never`).dedent().dedent()
      buffer.writeLine(``)
      buffer.writeLine(`declare module '@adonisjs/inertia/types' {`).indent()
      buffer.writeLine(`export interface InertiaPages {`).indent()

      for (const [page, filePath] of Object.entries(pages)) {
        buffer.writeLine(
          `'${page}': ExtractProps<(typeof import('${helpers.toImportPath(filePath)}'))['default']>`
        )
      }

      buffer.dedent().writeLine(`}`)
      buffer.dedent().writeLine(`}`)
    },
    output: './.adonisjs/server/pages.d.ts',
  })
})

完整的 IndexGenerator 示例 ​

以下示例展示一个完整的 init 钩子，为控制器、事件和监听器配置 barrel 文件生成。这是 AdonisJS 使用的默认设置。

ts
import { hooks } from '@adonisjs/core/app'

export default hooks.init((parent, hooksManager, indexGenerator) => {
  /**
   * 为控制器生成 barrel 文件。
   * 在路由中启用懒加载：[controllers.Posts, 'index']
   */
  indexGenerator.add('controllers', {
    source: './app/controllers',
    importAlias: '#controllers',
    as: 'barrelFile',
    exportName: 'controllers',
    removeSuffix: 'controller',
    output: './.adonisjs/server/controllers.ts',
  })

  /**
   * 为事件类生成 barrel 文件。
   * 启用类型安全的事件发射。
   */
  indexGenerator.add('events', {
    source: './app/events',
    importAlias: '#events',
    as: 'barrelFile',
    exportName: 'events',
    output: './.adonisjs/server/events.ts',
  })

  /**
   * 为事件监听器生成 barrel 文件。
   * 在事件绑定中启用懒加载监听器。
   */
  indexGenerator.add('listeners', {
    source: './app/listeners',
    importAlias: '#listeners',
    as: 'barrelFile',
    exportName: 'listeners',
    output: './.adonisjs/server/listeners.ts',
  })
})
