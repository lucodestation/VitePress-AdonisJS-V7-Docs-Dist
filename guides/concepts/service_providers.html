服务提供者 ​

本指南涵盖 AdonisJS 应用中的服务提供者。你将了解到如何：

  • 使用生命周期钩子在应用启动和关闭期间的特定点执行代码
  • 创建自定义服务提供者
  • 向 IoC 容器注册绑定

概述 ​

服务提供者是带有生命周期钩子的 JavaScript 类，在应用启动和关闭期间的特定点运行。你可以使用它们注册 IoC 容器绑定、使用宏扩展框架类、初始化应用级服务，并在优雅关闭期间释放资源。

提供者将初始化逻辑集中在一个地方并按可预测的顺序运行。AdonisJS 应用和包使用它们将服务与应用生命周期集成。

理解服务提供者 ​

在创建自己的服务提供者之前，理解它们在 AdonisJS 应用中如何工作会很有帮助。

服务提供者在何处注册 ​

服务提供者在项目根目录的 adonisrc.ts 文件中注册。此文件定义应加载哪些提供者以及它们应在哪些运行时环境中执行。

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  providers: [
    () => import('@adonisjs/core/providers/app_provider'),
    () => import('@adonisjs/core/providers/hash_provider'),
    {
      file: () => import('@adonisjs/core/providers/repl_provider'),
      environment: ['repl', 'test'],
    },
    () => import('@adonisjs/core/providers/vinejs_provider'),
    () => import('@adonisjs/core/providers/edge_provider'),
  ],
})

提供者使用 () => import() 语法的懒加载，确保仅在需要时加载它们。

内置服务提供者 ​

典型的 AdonisJS 应用包含多个处理核心功能的框架提供者。

  • app_provider 注册应用、日志记录器、加密和 HTTP 服务器服务。
  • hash_provider 注册用于密码哈希和验证的 hash 服务。
  • repl_provider 添加 REPL 特定的绑定。在上面的示例中，它仅在 repl 和 test 环境中运行。
  • vinejs_provider 将 VineJS 与应用集成。
  • edge_provider 将 Edge 模板引擎与应用集成。

当你安装额外包如用于数据库访问的 @adonisjs/lucid 或用于身份认证的 @adonisjs/auth 时，这些包包含它们自己的服务提供者，你需要将它们添加到此数组中。

执行顺序和环境 ​

AdonisJS 在所有已注册的提供者之间分阶段调用生命周期钩子。首先，register 钩子按注册顺序为所有提供者运行。然后 boot 钩子按注册顺序为所有提供者运行，接着是 start、ready，最后是 shutdown。预加载文件在 start 和 ready 之间导入，因此预加载文件可以依赖提供者在其 start 方法中建立的任何内容。

环境限制决定提供者是否运行。例如，为 web 环境配置的 WebSocket 提供者在你运行控制台命令时不会执行。

执行顺序告诉你每个钩子可以使用哪些服务，而环境过滤防止提供者在不必要的地方加载。

何时创建服务提供者 ​

当你需要向 IoC 容器注册服务、使用宏扩展框架类、在特定生命周期点执行初始化、设置需要在关闭期间清理的资源，或在整个应用范围配置第三方包时，创建自定义服务提供者。

对于简单的工具函数、只在一个地方运行的一次性设置，或在单个控制器或中间件中使用的服务，你通常不需要服务提供者。在这些情况下，使用常规模块或直接注入依赖。

创建自定义服务提供者 ​

现在你理解了服务提供者何时合适，让我们构建一个向 IoC 容器注册 Cache 服务的提供者。

步骤 1：生成提供者 ​

AdonisJS 包含一个命令来生成服务提供者文件。

sh
node ace make:provider cache
# 输出：
# CREATE: providers/cache_provider.ts

该命令创建提供者文件。接受注册提示以将其添加到 adonisrc.ts 中的 providers 数组。

步骤 2：理解生成的代码 ​

打开生成的 providers/cache_provider.ts 文件。你会看到一个基本的提供者结构。

ts
import type { ApplicationService } from '@adonisjs/core/types'

export default class CacheProvider {
  constructor(protected app: ApplicationService) {}

  /**
   * 提供者注册时调用
   */
  register() {}

  /**
   * 应用启动时调用
   */
  async boot() {}

  /**
   * 应用预热期间调用
   */
  async start() {}

  /**
   * 应用就绪时调用
   */
  async ready() {}

  /**
   * 优雅关闭期间调用
   */
  async shutdown() {}
}

提供者通过其构造函数接收 ApplicationService，让你访问 IoC 容器和其他应用服务。所有生命周期方法都是可选的。你只需实现你需要的钩子。

步骤 3：注册容器绑定 ​

首先，创建一个小型内存缓存服务。将服务与其提供者分开，使其可以在整个应用中作为注入令牌使用。

ts
export default class Cache {
  #store = new Map<string, unknown>()

  get<T>(key: string): T | undefined {
    return this.#store.get(key) as T | undefined
  }

  set(key: string, value: unknown): void {
    this.#store.set(key, value)
  }
}

将 Cache 类注册为单例，以便每个消费者共享同一个存储。

ts
import Cache from '#services/cache'
import type { ApplicationService } from '@adonisjs/core/types'

export default class CacheProvider {
  constructor(protected app: ApplicationService) {}

  register() {
    this.app.container.singleton(Cache, () => {
      return new Cache()
    })
  }
}

步骤 4：使用你注册的服务 ​

注册后，你可以将 Cache 服务注入控制器或其他容器管理的类。

ts
import Cache from '#services/cache'
import Post from '#models/post'
import { inject } from '@adonisjs/core'

export default class PostsController {
  @inject()
  constructor(protected cache: Cache) {}

  async index() {
    const cachedPosts = this.cache.get<Post[]>('posts')

    if (cachedPosts) {
      return cachedPosts
    }

    const posts = await Post.all()
    this.cache.set('posts', posts)
    return posts
  }
}

理解所有生命周期钩子 ​

服务提供者提供五个生命周期钩子，在应用生命周期的不同阶段运行。以下是每个钩子执行的时间：

钩子类型运行时间常见用例
register同步提供者导入时立即运行注册 IoC 容器绑定
boot异步所有提供者注册后扩展框架类、配置服务
start异步预热期间，预加载文件导入之前注册路由、定义命名中间件
ready异步HTTP 服务器就绪后或命令运行之前附加到运行中的服务器、启动工作进程
shutdown异步优雅终止期间关闭连接、释放资源

register、boot 和 start 钩子在工具为检查而预热应用时也会运行。ready 和 shutdown 钩子仅在 run 模式下运行，这使 ready 成为长期副作用合适的位置。

register 钩子 ​

register 方法在 AdonisJS 导入你的提供者时立即调用，处于启动过程的早期，在任何其他钩子运行之前。其主要目的是向 IoC 容器注册绑定。

ts
import Cache from '#services/cache'
import type { ApplicationService } from '@adonisjs/core/types'

export default class CacheProvider {
  constructor(protected app: ApplicationService) {}

  register() {
    this.app.container.singleton(Cache, () => {
      return new Cache()
    })
  }
}

register 钩子必须保持同步。在此钩子期间不要解析绑定、执行 I/O 或访问框架服务，因为其他提供者尚未完成注册。

boot 钩子 ​

boot 方法在所有提供者完成其绑定注册后运行。此时，容器已完全填充，你可以安全地解析任何绑定。这使 boot 成为扩展框架类或配置依赖其他已注册绑定的服务的自然位置。以下提供者向 HttpResponse 添加 apiSuccess 宏。你可以使用相同的钩子配置验证器、注册 Edge 辅助函数或扩展其他框架类。

ts
import { HttpResponse } from '@adonisjs/core/http'

declare module '@adonisjs/core/http' {
  interface HttpResponse {
    apiSuccess(data: unknown): void
  }
}

export default class AppProvider {
  async boot() {
    HttpResponse.macro('apiSuccess', function (this: HttpResponse, data: unknown) {
      this.json({
        success: true,
        data,
      })
    })
  }
}

start 钩子 ​

start 方法在预热阶段运行，恰好在 HTTP 服务器启动之前（在 web 环境中）或在 Ace 命令执行之前（在 console 环境中）。预加载文件在此钩子完成后导入，因此用它来建立预加载文件所依赖的任何内容。常见示例包括注册路由、定义命名中间件和附加事件监听器。

当你的应用为检查而预热而不是启动时（例如由 node ace codegen 命令触发），该方法也会运行。守卫任何打开连接、启动工作进程或执行健康检查的操作，而不守卫注册本身。参阅应用模式。

ready 钩子 ​

ready 方法在 HTTP 服务器已开始接受连接后（在 web 环境中）或在执行 Ace 命令的 run 方法之前（在 console 环境中）运行。将其用于需要运行中的 HTTP 服务器的服务或其他长期副作用。以下提供者将 Socket.IO 附加到底层 Node.js 服务器并在关闭期间关闭它。

ts
import type { ApplicationService } from '@adonisjs/core/types'
import { Server } from 'socket.io'

export default class WebSocketProvider {
  #io?: Server

  constructor(protected app: ApplicationService) {}

  async ready() {
    if (this.app.getEnvironment() !== 'web') {
      return
    }

    const server = await this.app.container.make('server')
    this.#io = new Server(server.getNodeServer())

    this.#io.on('connection', (socket) => {
      console.log('Client connected:', socket.id)
    })
  }

  async shutdown() {
    await this.#io?.close()
  }
}

shutdown 钩子 ​

shutdown 方法在 AdonisJS 收到优雅终止信号时运行。这是你清理资源、关闭连接并确保应用在不丢失数据或留下悬空进程的情况下关闭的机会。

对于处于 warmup 模式的应用，此方法被跳过。因此提供者必须避免在 ready 之前打开长期存在的资源，或使用应用模式守卫该工作。上面的 WebSocketProvider 通过创建 Socket.IO 服务器（在 ready 中）并在 shutdown 中关闭它来演示完整的生命周期。

使用 shutdown 关闭数据库连接池、刷新挂起的日志写入、断开与 Redis 的连接、关闭文件句柄或执行优雅终止所需的任何其他清理。框架会等待所有 shutdown 钩子完成后再退出。
