HTTP 上下文 ​

本指南涵盖 AdonisJS 中的 HTTP 上下文对象。你将了解到：

  • HTTP 上下文是什么以及为什么存在
  • 如何在路由处理器和中间件中访问它
  • HTTP 上下文暴露哪些属性以及每个属性何时可用
  • 如何使用依赖注入将其注入到服务中
  • 如何向上下文添加自定义属性
  • 如何通过异步本地存储访问它

概述 ​

HTTP 上下文是一个请求作用域对象，保存处理 HTTP 请求所需的一切。它包含 request、response、auth、logger、session 等属性。AdonisJS 为每个传入请求创建一个新的 HTTP 上下文实例，并将其传递给你的路由处理器和中间件。

HTTP 上下文不使用全局变量或从不同模块导入请求/响应对象，而是提供了一种干净、类型安全的方式，在一个地方访问所有请求特定的数据和服务。上下文上的每个属性都专门绑定到当前请求，确保并发请求之间的完全隔离。

访问 HTTP 上下文 ​

在路由处理器中 ​

访问 HTTP 上下文最常见的方式是在路由处理器中将其作为参数接收。你通常只解构需要的属性，而不是使用完整的上下文对象。

ts
import router from '@adonisjs/core/services/router'

router.get('/posts/:id', async ({ params, request, response }) => {
  const id = params.id
  const include = request.qs().include

  return response.json({ id, include })
})

使用控制器时，模式完全相同。控制器方法接收 HTTP 上下文作为第一个参数：

ts
import { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'

export default class PostsController {
  async show({ params, response }: HttpContext) {
    const post = await Post.findOrFail(params.id)
    return response.json(post)
  }
}

在中间件中 ​

中间件函数也接收 HTTP 上下文作为第一个参数。第二个参数是 next 函数，它将控制权传递给链中的下一个中间件。下面使用的 logger 已经是请求作用域的，因此每条日志行都会自动标记当前请求 id。

ts
import { HttpContext } from '@adonisjs/core/http'
import { NextFn } from '@adonisjs/core/types/http'

export default class LogRequestMiddleware {
  async handle({ request, logger }: HttpContext, next: NextFn) {
    logger.info(`${request.method()} ${request.url()}`)
    await next()
  }
}

可用属性 ​

HTTP 上下文捆绑了处理请求所需的一切：传入数据、你正在构建的响应、日志记录、身份认证等。其上的属性来自三个来源：核心框架、你安装的可选包，以及位于项目内部的中间件或提供者。

始终可用 ​

这些属性由框架本身附加到每个 HTTP 上下文实例上。

request

类型：HttpRequest

HttpRequest 实例暴露传入的请求数据：查询字符串、请求体、头、cookie、上传的文件、客户端 IP、主机名和 HTTP 方法。当你需要读取客户端发送的任何内容时使用它。

ts
const page = ctx.request.input('page', 1)
const agent = ctx.request.header('user-agent')

response

类型：HttpResponse

HttpResponse 实例用于构建和发送响应。它提供设置状态码、头和 cookie 的方法，发送 JSON、HTML、文件或渲染视图，重定向客户端，流式传输内容，以及提前中止请求。

ts
return ctx.response.status(201).json({ id: post.id })

params

类型：Record<string, any>

保存从 URL 解析的路由参数的纯对象。对于定义为 /posts/:id/comments/:commentId 的路由，对 /posts/1/comments/42 的请求会使 params 等于 { id: '1', commentId: '42' }。参数值始终是字符串。如果你需要其他类型，请在处理器内部进行转换。

route

类型：Route | undefined

对匹配当前请求的路由定义的引用，包括模式、HTTP 方法、注册的中间件栈和处理器。对于不匹配任何路由的请求，这是 undefined，通常只发生在异常处理器内部。

logger

类型：Logger

请求作用域的 Logger 实例。通过 ctx.logger 写入的日志行会自动标记唯一请求 id，这使得在应用中追踪属于单个请求的所有输出变得简单直接。

ts
ctx.logger.info({ postId: id }, 'Loading post')

使用可选包时可用 ​

这些属性由可选包提供。只有当相应包已安装且其中间件（如适用）已注册时，它们才存在于上下文上。

session

类型：Session

Session 实例，用于读取和写入当前请求的会话数据，包括闪存消息。当安装了 @adonisjs/session 且会话中间件已注册时可用。

auth

类型：Authenticator

Authenticator 实例，用于认证请求并访问当前登录用户。当安装了 @adonisjs/auth 且 auth 中间件已注册时可用。

view

类型：EdgeRenderer

作用域为当前请求的 Edge 渲染器，用于渲染服务端模板。当安装了 edge.js 并通过 view 提供者注册时可用。

inertia

类型：Inertia

Inertia 实例，用于通过 Inertia.js 渲染 React 或 Vue 页面。当安装了 @adonisjs/inertia 且 Inertia 中间件已注册时可用。

bouncer

类型：Bouncer

Bouncer 实例，用于通过 Bouncer 能力和策略对已认证用户授权操作。当安装了 @adonisjs/bouncer 时可用。

i18n

类型：I18n

I18n 实例，作用域为请求检测到的语言，用于翻译消息和格式化日期、数字和货币。当安装了 @adonisjs/i18n 且 i18n 中间件已注册时可用。

由项目脚手架添加 ​

这些属性由位于项目内部的中间件或提供者附加，而不是由框架或已安装的包提供。它们的可用性取决于你的项目脚手架包含哪些文件，因此即使框架和包版本变化，它们也会留在你的项目中。

containerResolver

类型：ContainerResolver

请求作用域的 IoC 容器解析器，由每个新 AdonisJS 项目自带的 container_bindings_middleware 文件附加到上下文。当你需要在保留当前请求作用域的同时从容器手动解析类时使用它，例如在实例化构造函数中类型提示 HttpContext 的服务时。

serialize

类型：ApiSerializer

用于响应负载类型安全序列化的辅助工具，由 Inertia 和 API 启动套件自带的 providers/api_provider.ts 文件附加到上下文。从其他启动套件搭建的项目，或已移除此提供者的项目，将不会有 ctx.serialize 可用。

使用依赖注入 ​

当你需要在服务类或代码库的其他部分访问 HTTP 上下文时，可以使用依赖注入。这种模式比通过多次函数调用手动传递上下文更干净。

注入到服务中 ​

要将 HTTP 上下文注入到服务中，请在构造函数中进行类型提示，并使用 @inject() 装饰器标记该类。

ts
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'

@inject()
export default class PostService {
  constructor(protected ctx: HttpContext) {}

  async getVisiblePosts() {
    const user = this.ctx.auth.user

    if (user?.isAdmin) {
      return Post.all()
    }

    return Post.query().where('published', true)
  }
}

在控制器中使用服务 ​

要启用自动依赖注入，你必须将 PostService 注入到控制器方法中。当容器调用 index 方法时，它会构造整个依赖树并将 HTTP 上下文提供给 PostService。

ts
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import PostService from '#services/post_service'

export default class PostsController {
  @inject()
  async index({}: HttpContext, postService: PostService) {
    return postService.getVisiblePosts()
  }
}

使用异步本地存储 ​

异步本地存储（ALS）允许你从应用中的任何地方访问 HTTP 上下文，而无需通过函数参数显式传递它。

TIP

优先使用依赖注入或按引用传递 HttpContext 作为你的默认模式。只有在这些不可行时才使用 ALS，例如在无法重构为显式接受上下文的工具函数或第三方库中。

要使用 ALS，你必须首先在 config/app.ts 文件的 http 块中启用它。

ts
import { defineConfig } from '@adonisjs/core/http'

export const http = defineConfig({
  useAsyncLocalStorage: true
})

启用后，你可以使用静态 getOrFail() 方法访问当前 HTTP 上下文。

ts
import { HttpContext } from '@adonisjs/core/http'

export default class AnalyticsService {
  trackEvent(eventName: string) {
    const ctx = HttpContext.getOrFail()

    ctx.logger.info({
      event: eventName,
      userId: ctx.auth.user?.id,
      ip: ctx.request.ip(),
    })
  }
}

启用异步本地存储会带来小的性能开销，因此除非你确实需要 HttpContext.getOrFail()，否则保持禁用。

WARNING

HttpContext.getOrFail() 在 HTTP 请求生命周期之外调用时会抛出错误。只从你知道在请求期间运行的代码路径中调用它（路由处理器、中间件、控制器及它们调用的服务）。对于可能在请求之外运行的代码，如后台任务或 CLI 命令，请显式注入或传递 HttpContext。

添加自定义属性 ​

你可以通过在中间件文件中扩充 HttpContext 接口来向 HTTP 上下文添加自定义属性。当你需要在同一请求期间跨多个中间件和路由处理器共享数据时，这很有用。

ts
import { HttpContext } from '@adonisjs/core/http'
import { NextFn } from '@adonisjs/core/types/http'
import Tenant from '#models/tenant'

/**
 * 扩充 HttpContext 接口以添加 tenant 属性。
 * 这让 TypeScript 知道新属性。
 */
declare module '@adonisjs/core/http' {
  interface HttpContext {
    tenant: Tenant
  }
}

export default class IdentifyTenantMiddleware {
  async handle(ctx: HttpContext, next: NextFn) {
    /**
     * 从请求中提取租户标识符。
     * 这可能来自子域名、头或其他来源。
     */
    const subdomain = ctx.request.hostname().split('.')[0]

    /**
     * 查找租户并将其附加到上下文。
     * 现在所有路由处理器都可以访问 ctx.tenant。
     */
    ctx.tenant = await Tenant.findByOrFail('subdomain', subdomain)

    await next()
  }
}

为测试创建虚拟上下文 ​

编写测试时，你经常需要一个虚拟 HTTP 上下文实例来测试路由处理器、中间件或服务。使用 testUtils 服务创建这些测试实例。

ts
import testUtils from '@adonisjs/core/services/test_utils'

const ctx = testUtils.createHttpContext()

TIP

创建的上下文实例未附加到任何路由，因此 ctx.route 和 ctx.params 是 undefined。如果被测代码读取它们，请在运行断言之前手动在返回的上下文上赋值。

createHttpContext 方法默认使用底层 Node.js req 和 res 对象的假值。如果你需要用真实的请求和响应对象测试，可以提供它们。

ts
import { createServer } from 'node:http'
import testUtils from '@adonisjs/core/services/test_utils'

createServer((req, res) => {
  const ctx = testUtils.createHttpContext({ req, res })
})

如果你在 AdonisJS 应用之外构建包，可以直接使用 HttpContextFactory 类。testUtils 服务仅在 AdonisJS 应用内可用，但工厂在任何地方都可以工作。

ts
import { HttpContextFactory } from '@adonisjs/core/factories/http'

const ctx = new HttpContextFactory().create()
