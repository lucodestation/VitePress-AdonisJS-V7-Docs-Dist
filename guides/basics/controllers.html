控制器 ​

本指南涵盖 AdonisJS 应用中的控制器。你将了解到如何：

  • 创建和组织控制器来处理 HTTP 请求
  • 使用 barrel 文件系统导入控制器
  • 理解控制器生命周期和请求处理
  • 使用 IoC 容器向控制器注入依赖
  • 将单个操作包装为单动作控制器
  • 构建遵循约定的 RESTful 资源驱动控制器
  • 配置控制器位置和 barrel 文件生成

TIP

前置条件：在学习控制器之前，你应该熟悉路由，因为控制器通过路由连接到你的应用。

概述 ​

控制器将路由处理器组织到专用的 JavaScript 类中，解决了路由文件膨胀的问题。与其将所有路由逻辑内联定义，控制器让你将相关的请求处理器分组到一个类中，其中每个方法（称为动作）处理特定的路由。

一个典型的控制器代表一个资源（如 Users、Posts 或 Comments），并定义用于创建、读取、更新和删除该资源的动作。控制器让你的路由文件保持干净和可读，支持对服务和其他依赖的依赖注入，并遵循基于资源的 CRUD 操作的 RESTful 约定。

没有控制器，你的路由文件会因内联处理器而变得杂乱。

ts
import router from '@adonisjs/core/services/router'

router.get('/posts', async () => {
  // 获取所有帖子的逻辑
  return { posts: [] }
})

router.get('/posts/:id', async ({ params }) => {
  // 获取单个帖子的逻辑
  return { post: {} }
})

router.post('/posts', async ({ request }) => {
  // 创建帖子的逻辑
  return { post: {} }
})

// 随着路由增长，此文件变得难以管理

使用控制器，你将处理器组织到可重用的类中。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

// 干净、有条理的路由定义
router.get('/posts', [controllers.Posts, 'index'])
router.get('/posts/:id', [controllers.Posts, 'show'])
router.post('/posts', [controllers.Posts, 'store'])
ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ serialize }: HttpContext) {
    // 获取所有帖子的逻辑
    return serialize({ posts: [] })
  }

  async show({ params, serialize }: HttpContext) {
    // 获取单个帖子的逻辑
    return serialize({ post: {} })
  }

  async store({ request, serialize }: HttpContext) {
    // 创建帖子的逻辑
    return serialize({ post: {} })
  }
}

创建你的第一个控制器 ​

步骤 1：生成控制器 ​

控制器存储在 app/controllers 目录中。创建控制器最简单的方法是使用 make:controller 命令。

bash
node ace make:controller posts
# 输出
DONE:    create app/controllers/posts_controller.ts

此命令创建一个用纯 JavaScript 类和默认导出搭建的控制器。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
}

步骤 2：添加你的第一个动作 ​

控制器动作只是处理 HTTP 请求的方法。让我们添加一个 index 方法来列出所有帖子。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  /**
   * 处理 GET 请求以列出所有帖子
   */
  async index({ response }: HttpContext) {
    const posts = [
      { id: 1, title: 'Getting started with AdonisJS' },
      { id: 2, title: 'Understanding controllers' },
    ]

    return response.json({ posts })
  }
}

关于控制器动作需要了解的几个重要事项：

  • 第一个参数始终是 HTTPContext 对象
  • 你可以解构特定属性，如 request、response、params、session 或 auth
  • 控制器方法可以直接返回值（对象、数组）或显式调用 response.json() 或 response.send()

步骤 3：将控制器连接到路由 ​

现在将你的控制器动作绑定到路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('/posts', [controllers.Posts, 'index'])

第一个参数（controllers.Posts）引用你的 PostsController 类，第二个参数（'index'）指定要调用的方法。控制器是懒加载的，意味着只有在访问路由时才会被导入。

步骤 4：测试一下 ​

如果开发服务器尚未运行，请启动它。

bash
node ace serve --hmr

在浏览器中访问 http://localhost:3333/posts。你应该会看到来自控制器的 JSON 响应。

json
{
  "posts": [
    { "id": 1, "title": "Getting started with AdonisJS" },
    { "id": 2, "title": "Understanding controllers" }
  ]
}

Barrel 文件 ​

你在路由步骤中使用的 #generated/controllers 导入由 barrel 文件提供支持——一个将所有控制器导入整合到一个便利位置的单一文件。此 barrel 文件由 AdonisJS 自动生成和维护。

barrel 文件位于 .adonisjs/server/controllers.ts，在你启动开发服务器时自动创建。当你添加或移除控制器时，它会保持最新。

没有 barrel 文件，你需要在路由文件中手动逐个导入每个控制器。

ts
import router from '@adonisjs/core/services/router'

const PostsController = () => import('#controllers/posts_controller')
const UsersController = () => import('#controllers/users_controller')
const CommentsController = () => import('#controllers/comments_controller')
// ...随着应用增长还有几十个导入

router.get('/posts', [PostsController, 'index'])
router.get('/users', [UsersController, 'index'])
router.get('/comments', [CommentsController, 'index'])

barrel 文件消除了这种重复。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('/posts', [controllers.Posts, 'index'])
router.get('/users', [controllers.Users, 'index'])
router.get('/comments', [controllers.Comments, 'index'])

另请参阅：Barrel 文件生成指南了解详细配置选项。

理解控制器生命周期 ​

AdonisJS 中的控制器按请求实例化。每次 HTTP 请求匹配绑定到控制器的路由时，AdonisJS 使用 IoC 容器创建该控制器类的新实例。

这意味着：

  • 每个请求获得自己隔离的控制器实例
  • 没有请求之间状态泄漏的风险
  • 如果需要，你可以安全地使用实例属性
  • 请求完成后控制器实例会被垃圾回收
ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  // 此属性对每个请求都是唯一的
  #requestId = Math.random()

  async index({ response }: HttpContext) {
    // 每个请求都会看到不同的 requestId
    return response.json({ requestId: this.#requestId })
  }
}

依赖注入 ​

控制器支持依赖注入，允许你将服务、仓库或其他类注入到控制器方法或构造函数中。IoC 容器会自动为你解析和注入这些依赖。

另请参阅：依赖注入指南全面了解依赖注入在 AdonisJS 中的工作方式。

构造函数注入 ​

构造函数注入在控制器实例化时注入一次依赖。当控制器中的所有或大多数方法需要相同的依赖时使用此方式。

ts
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import UserService from '#services/user_service'

@inject() 
export default class UsersController {
  constructor(protected userService: UserService) {}

  async index(ctx: HttpContext) {
    return this.userService.all()
  }

  async show({ params }: HttpContext) {
    return this.userService.find(params.id)
  }

  async store({ request }: HttpContext) {
    const data = request.all()
    return this.userService.create(data)
  }
}
  • @inject() 装饰器告诉 AdonisJS 为此控制器使用依赖注入。
  • 依赖在构造函数参数中进行类型提示，IoC 容器在控制器实例化时自动解析并注入它们。

方法注入 ​

方法注入将依赖注入到单个控制器方法中。当只有特定方法需要某些依赖，或者不同方法需要不同依赖时使用此方式。

ts
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import UserService from '#services/user_service'
import EmailService from '#services/email_service'

export default class UsersController {
  async index(ctx: HttpContext) {
    return [{ id: 1, name: 'John' }]
  }

  @inject()
  async store(ctx: HttpContext, userService: UserService) {
    const data = ctx.request.all()
    return userService.create(data)
  }

  @inject()
  async sendEmail(
    ctx: HttpContext,
    userService: UserService,
    emailService: EmailService
  ) {
    const user = await userService.find(ctx.params.id)
    await emailService.send(user.email, 'Welcome!')
    return { sent: true }
  }
}

使用方法注入时：

  • @inject() 装饰器应用于单个方法而不是类。
  • 第一个参数必须始终是 HTTPContext，依赖跟在后面。
  • 这允许每个方法根据其特定需求拥有不同的依赖。

单动作控制器 ​

并非每个操作都属于具有多个动作的资源。注册新闻通讯订阅、导出报告或处理传入的 webhook 是独立的任务，没有 CRUD 兄弟项可以与之分组。将它们放在更广泛的控制器中会迫使你选择一个它们只是松散属于的类，而且路由不再告诉你请求实际做了什么。

单动作控制器将单个功能包装到一个命名清晰的类中。以操作命名类，然后定义一个 handle 方法来保存逻辑。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class RegisterNewsletterSubscriptionController {
  async handle({ request, response }: HttpContext) {
    const email = request.input('email')

    // 持久化订阅

    return response.created({ email })
  }
}

将方法名作为参数传递给 make:controller，以搭建已包含 handle 方法的类。这里需要 --singular 标志，因为生成器默认会将控制器名称复数化，否则会生成 RegisterNewsletterSubscriptionsController。

bash
node ace make:controller register_newsletter_subscription handle --singular
# 输出
DONE:    create app/controllers/register_newsletter_subscription_controller.ts

通过将它传递到数组中而不带方法名来在路由上引用控制器。路由器默认调用 handle 方法，因此没有第二个参数要写。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.post('/newsletter/subscriptions', [controllers.RegisterNewsletterSubscription])

路由会根据控制器自动命名，转换为 snake_case。上面的示例在生成 URL 或重定向时可通过 register_newsletter_subscription 访问。使用 .as() 方法分配不同的路由标识符。

单动作控制器是常规控制器，因此本指南涵盖的所有内容仍然适用于它们。你可以通过构造函数注入服务、将中间件附加到路由，并依赖相同的按请求生命周期。

ts
import { inject } from '@adonisjs/core'
import NewsletterService from '#services/newsletter_service'
import type { HttpContext } from '@adonisjs/core/http'

@inject() 
export default class RegisterNewsletterSubscriptionController {
  constructor(protected newsletterService: NewsletterService) {} 

  async handle({ request, response }: HttpContext) {
    const email = request.input('email')
    const subscription = await this.newsletterService.subscribe(email)

    return response.created(subscription)
  }
}

TIP

以单动作控制器执行的操作命名（RegisterNewsletterSubscriptionController、ExportInvoicesController），而不是以资源命名。类名中的动词是让路由一目了然可读的关键。

另请参阅：Make controller 命令了解生成器标志的完整列表。

资源驱动控制器 ​

资源驱动控制器遵循 RESTful 约定来处理资源上的 CRUD（创建、读取、更新、删除）操作。AdonisJS 提供特殊的路由方法，自动将 HTTP 动词映射到标准控制器方法。

七个资源化动作 ​

一个典型的资源化控制器定义七个方法，处理所有 CRUD 操作。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  /**
   * 显示所有帖子的列表
   * GET /posts
   */
  async index({ response }: HttpContext) {
    const posts = [] // 从数据库获取
    return response.json({ posts })
  }

  /**
   * 渲染创建新帖子的表单
   * GET /posts/create
   *
   * 仅 API 应用不需要
   */
  async create({ view }: HttpContext) {
    return view.render('posts/create')
  }

  /**
   * 处理创建新帖子的表单提交
   * POST /posts
   */
  async store({ request }: HttpContext) {
    const data = request.all()
    // 在数据库中创建帖子
    return { post: data }
  }

  /**
   * 按 id 显示单个帖子
   * GET /posts/:id
   */
  async show({ params }: HttpContext) {
    // 从数据库获取帖子
    return { post: { id: params.id } }
  }

  /**
   * 渲染编辑现有帖子的表单
   * GET /posts/:id/edit
   *
   * 仅 API 应用不需要
   */
  async edit({ params, view }: HttpContext) {
    return view.render('posts/edit', { id: params.id })
  }

  /**
   * 处理更新帖子的表单提交
   * PUT/PATCH /posts/:id
   */
  async update({ params, request }: HttpContext) {
    const data = request.all()
    // 在数据库中更新帖子
    return { post: { id: params.id, ...data } }
  }

  /**
   * 按 id 删除帖子
   * DELETE /posts/:id
   */
  async destroy({ params }: HttpContext) {
    // 从数据库删除帖子
    return { deleted: true }
  }
}

生成资源化控制器 ​

使用 --resource 标志创建预填充所有七个方法的控制器。这会生成一个已包含所有七个方法存根的控制器，节省你的时间并确保你遵循 RESTful 约定。

bash
node ace make:controller posts --resource

注册资源路由 ​

与其手动定义七个单独的路由，不如使用 router.resource() 方法在一行中创建所有七个路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.resource('posts', controllers.Posts)

这会生成以下路由。

方法路径动作名称用途
GET/postsPostsController.indexposts.index显示所有帖子的列表
GET/posts/createPostsController.createposts.create显示创建新帖子的表单
POST/postsPostsController.storeposts.store存储新创建的帖子
GET/posts/:idPostsController.showposts.show显示特定帖子
GET/posts/:id/editPostsController.editposts.edit显示编辑帖子的表单
PUT/PATCH/posts/:idPostsController.updateposts.update更新特定帖子
DELETE/posts/:idPostsController.destroyposts.destroy删除特定帖子

嵌套资源 ​

嵌套资源表示资源之间的层次关系。例如，属于帖子的评论。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.resource('posts.comments', controllers.Comments)

这会创建包含父 ID 和子 ID 的路由。

sh
GET        /posts/:post_id/comments
GET        /posts/:post_id/comments/create
POST       /posts/:post_id/comments

GET        /posts/:post_id/comments/:id
GET        /posts/:post_id/comments/:id/edit
PUT/PATCH  /posts/:post_id/comments/:id
DELETE     /posts/:post_id/comments/:id

你的控制器接收父参数和子参数。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class CommentsController {
  async index({ params }: HttpContext) {
    // params.post_id - 父帖子 ID
    // 获取此帖子的评论
    return { post_id: params.post_id, comments: [] }
  }

  async show({ params }: HttpContext) {
    // params.post_id - 父帖子 ID
    // params.id - 评论 ID
    return { post_id: params.post_id, comment: { id: params.id } }
  }
}

浅层嵌套资源 ​

浅层资源在子资源可以单独唯一标识的路由中省略父 ID。当子 ID 全局唯一且不需要限定到父级时，这很有用。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.shallowResource('posts.comments', controllers.Comments)

使用浅层资源时，show、edit、update 和 destroy 动作省略父 ID，因为评论可以通过自己的 ID 查找：

sh
GET        /posts/:post_id/comments
GET        /posts/:post_id/comments/create
POST       /posts/:post_id/comments

# 不含父 ID
GET        /comments/:id
GET        /comments/:id/edit
PUT/PATCH  /comments/:id
DELETE     /comments/:id

当子资源具有全局唯一标识符且查找时不需要父 ID 时，使用浅层嵌套。这创建更干净、更短的 URL，同时在需要的地方（创建和列表）保持层次关系。

命名资源路由 ​

router.resource() 创建的路由使用资源名称和控制器动作的组合自动命名。资源名称转换为 snake_case 并使用点（.）分隔符与动作名称连接。

例如，router.resource('posts', controllers.Posts) 生成如下路由名称：

  • posts.index
  • posts.show
  • posts.store

你可以使用 .as() 方法自定义路由名称。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router
  .resource('posts', controllers.Posts)
  .as('articles')

这会更改路由名称，同时保持 URL 路径不变。

资源动作名称路由名称
postsindexarticles.index
postsshowarticles.show
postsstorearticles.store
postsupdatearticles.update
postsdestroyarticles.destroy

命名路由很重要，因为它允许你通过名称引用路由，而不是在应用中硬编码 URL。

过滤资源路由 ​

默认情况下，router.resource() 创建所有七个 RESTful 路由。你可以使用多种方法过滤生成哪些路由。

仅 API 资源 ​

构建 API 时，你通常不需要 create 和 edit 路由，因为表单由客户端代码显示。.apiOnly() 方法排除这些路由，只创建五个路由：index、store、show、update 和 destroy：

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.resource('posts', controllers.Posts).apiOnly()

使用 only 和 except 进行选择性过滤 ​

对于更细粒度的控制，使用 .only() 或 .except() 方法。这些方法接受动作名称数组。

.only() 方法仅创建指定的路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router
  .resource('posts', controllers.Posts)
  .only(['index', 'store', 'destroy'])

.except() 方法创建除指定路由之外的所有路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router
  .resource('posts', controllers.Posts)
  .except(['create', 'edit'])

重命名资源参数 ​

默认情况下，资源路由使用 :id 作为参数名称。你可以使用 .params() 方法自定义，它接受一个对象，其中键是资源名称，值是所需的参数名称。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router
  .resource('posts', controllers.Posts)
  .params({ posts: 'post' })

这会将 URL 参数从 :id 更改为 :post：

之前（默认）之后（使用自定义参数）
/posts/:id/posts/:post
/posts/:id/edit/posts/:post/edit
/posts/:id（update/destroy）/posts/:post（update/destroy）

同样的方法适用于嵌套资源，生成如 /posts/:post/comments/:comment 的 URL。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router
  .resource('posts.comments', controllers.Comments)
  .params({ posts: 'post', comments: 'comment' })

为资源分配中间件 ​

你可以使用 .use() 方法将中间件应用到特定的资源路由。此方法接受动作名称数组和要应用的中间件。例如，仅将身份认证中间件应用到修改数据的路由（create、store、update、destroy），同时让只读路由（index、show）保持公开。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'
import { middleware } from '#start/kernel'

router
  .resource('posts', controllers.Posts)
  .use(
    ['create', 'store', 'update', 'destroy'],
    middleware.auth()
  )

要将中间件应用到所有资源路由，使用通配符 * 确保资源中的所有路由都需要身份认证。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'
import { middleware } from '#start/kernel'

router
  .resource('posts', controllers.Posts)
  .use('*', middleware.auth())

配置 ​

控制器开箱即用，无需初始配置。但是，你可以自定义控制器生成和组织的某些方面。

自定义控制器位置 ​

默认情况下，控制器存储在 app/controllers 目录中。你可以在 adonisrc.ts 文件中更改此位置。

另请参阅：AdonisRC 参考

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  directories: {
    controllers: 'app/http/controllers'
  }
})

Barrel 文件配置 ​

位于 #generated/controllers 的自动生成 barrel 文件可以自定义，以控制包含或排除哪些控制器，以及如何生成文件。

另请参阅：Barrel 文件生成指南

ts
import { defineConfig } from '@adonisjs/core/app'

export default defineConfig({
  barrelFiles: {
    controllers: {
      enabled: true,
      export: (path) => `export * as ${path.name} from '${path.modulePath}'`
    }
  }
})
