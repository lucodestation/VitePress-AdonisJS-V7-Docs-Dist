异常处理 ​

本指南涵盖 AdonisJS 应用中的异常处理。你将了解到如何：

  • 使用全局异常处理器将错误转换为 HTTP 响应
  • 为特定错误类型自定义错误处理
  • 向日志服务报告错误
  • 创建带有自包含处理逻辑的自定义异常类
  • 为不同环境配置调试模式和状态页面

概述 ​

AdonisJS 中的异常处理提供了一个集中式系统，用于管理 HTTP 请求期间的错误。你不需要将每个路由处理器和中间件都包裹在 try/catch 块中，而是让错误自然冒泡到全局异常处理器，由其将它们转换为适当的 HTTP 响应。

这种方法让你的代码保持干净，同时确保整个应用中的错误处理一致。

全局异常处理器 ​

当你创建新的 AdonisJS 项目时，全局异常处理器会在 app/exceptions/handler.ts 中创建。它继承自基础 ExceptionHandler 类，并提供两个主要方法：

  • handle 将错误转换为 HTTP 响应。
  • report 记录错误或将它们发送到监控服务。

默认处理器如下所示：

ts
import app from '@adonisjs/core/services/app'
import { HttpContext, ExceptionHandler } from '@adonisjs/core/http'
import type { StatusPageRange, StatusPageRenderer } from '@adonisjs/core/types/http'

export default class HttpExceptionHandler extends ExceptionHandler {
  /**
   * 控制是否显示带有堆栈跟踪的详细错误。
   * 在生产环境中自动禁用，以保护敏感信息。
   */
  protected debug = !app.inProduction

  /**
   * 为特定状态码启用自定义 HTML 错误页面。
   * 通常在生产环境中启用以获得更好的用户体验。
   */
  protected renderStatusPages = app.inProduction

  /**
   * 将状态码或范围映射到视图模板。
   * 键可以是特定代码如 '404' 或范围如 '500..599'。
   */
  protected statusPages: Record<StatusPageRange, StatusPageRenderer> = {
    '404': (error, { view }) => {
      return view.render('pages/errors/not_found', { error })
    },
    '500..599': (error, { view }) => {
      return view.render('pages/errors/server_error', { error })
    },
  }

  /**
   * 将错误转换为面向客户端的 HTTP 响应。
   * 覆盖此方法以自定义错误响应格式。
   */
  async handle(error: unknown, ctx: HttpContext) {
    return super.handle(error, ctx)
  }

  /**
   * 记录错误或将它们发送到监控服务。
   * 切勿尝试从此方法发送 HTTP 响应。
   */
  async report(error: unknown, ctx: HttpContext) {
    return super.report(error, ctx)
  }
}

内联注释解释了每个属性的用途。我们将在本指南后面详细探讨 debug、renderStatusPages 和 statusPages。

错误如何流经处理器 ​

当 HTTP 请求期间发生错误时，AdonisJS 会自动捕获它并将其转发到全局异常处理器。让我们看看实际效果。

ts
import router from '@adonisjs/core/services/router'
import { Exception } from '@adonisjs/core/exceptions'

router.get('fatal', () => {
  /**
   * 抛出一个带有 500 状态码
   * 和用于识别的自定义错误代码的异常
   */
  throw new Exception('Something went wrong', {
    status: 500,
    code: 'E_RUNTIME_EXCEPTION'
  })
})

在开发模式（启用 debug）下，访问此路由会显示由 Youch 提供支持的格式精美的错误页面，展示错误消息、完整堆栈跟踪和请求上下文。

在生产模式（禁用 debug）下，同样的错误返回简单的 JSON 或纯文本响应，仅包含错误消息，不暴露应用的内部结构。

处理特定错误类型 ​

全局异常处理器的 handle 方法接收所有未处理的错误。你可以检查错误类型并为特定异常提供自定义处理，同时让其他异常落到默认行为。

以下是使用自定义响应格式处理验证错误的示例。

ts
import { errors as vineJSErrors } from '@vinejs/vine'
import { HttpContext, ExceptionHandler } from '@adonisjs/core/http'

export default class HttpExceptionHandler extends ExceptionHandler {
  protected debug = !app.inProduction
  protected renderStatusPages = app.inProduction

  async handle(error: unknown, ctx: HttpContext) {
    /**
     * 使用 instanceof 安全地识别错误类型，
     * 检查错误是否为 VineJS 验证错误
     */
    if (error instanceof vineJSErrors.E_VALIDATION_ERROR) {
      /**
       * 将验证消息直接作为 JSON 返回，
       * 状态码为 422 Unprocessable Entity
       */
      ctx.response.status(422).send(error.messages)
      return
    }

    /**
     * 对于所有其他错误，委托给父类，
     * 由其处理默认的错误转换逻辑
     */
    return super.handle(error, ctx)
  }
}

这种使用 instanceof 检查错误类型并提供自定义处理的模式强大而灵活。你可以为应用中的不同错误类型添加任意数量的条件分支。

以下是如何在路由中使用此自定义验证错误处理。

ts
import router from '@adonisjs/core/services/router'
import { createPostValidator } from '#validators/post'

router.post('posts', async ({ request }) => {
  /**
   * 如果验证失败，VineJS 抛出 E_VALIDATION_ERROR，
   * 由我们的自定义处理器捕获并返回验证消息
   * 和 422 状态码
   */
  await request.validateUsing(createPostValidator)
})

调试模式和 Youch ​

debug 属性控制是否使用 Youch 显示错误，Youch 是一个错误可视化工具，可以创建美观、交互式的错误页面。当启用调试模式时，Youch 显示错误消息、完整的堆栈跟踪、请求详情，甚至以语法高亮显示错误发生的具体代码。

在生产环境中，调试模式应始终禁用，以防止暴露敏感信息。禁用时，错误通过内容协商（API 请求返回 JSON，其他返回纯文本）转换为简单响应，仅包含错误消息，不包含实现细节。

默认配置 protected debug = !app.inProduction 自动为你处理这一点，在开发环境中启用调试模式，在生产环境中禁用。

状态页面 ​

状态页面允许你为特定的 HTTP 状态码显示自定义 HTML 页面。此功能对于面向用户的应用特别有用，你希望提供品牌化的、有帮助的错误体验，而不是通用的错误消息。

statusPages 属性是一个键值映射，其中键是 HTTP 状态码或范围，值是渲染并返回 HTML 内容的回调函数。回调接收错误对象和 HTTP 上下文，让你完全访问视图渲染和错误详情。

ts
export default class HttpExceptionHandler extends ExceptionHandler {
  protected statusPages: Record<StatusPageRange, StatusPageRenderer> = {
    '404': (error, { view }) => {
      return view.render('pages/errors/not_found', { error })
    },
    '500..599': (error, { view }) => {
      return view.render('pages/errors/server_error', { error })
    },
  }
}
ts
export default class HttpExceptionHandler extends ExceptionHandler {
  protected statusPages: Record<StatusPageRange, StatusPageRenderer> = {
    '404': (error, { inertia }) => {
      return inertia.render('errors/not_found', { error })
    },
    '500..599': (error, { inertia }) => {
      return inertia.render('errors/server_error', { error })
    },
  }
}

使用 Inertia 启动套件时，状态页面渲染 Inertia 组件而不是 Edge 模板。回调从 HTTP 上下文接收 inertia 对象，你用它来渲染前端页面组件。页面路径（如 errors/not_found）映射到 inertia/pages/ 内的文件——例如 inertia/pages/errors/not_found.tsx。

状态页面仅在 renderStatusPages 属性设置为 true 时渲染。默认配置在生产环境中启用它们（app.inProduction），此时自定义错误页面提供更好的用户体验，同时在开发环境中保持禁用，此时详细的 Youch 错误页面对调试更有用。

TIP

状态页面仅适用于接受 HTML 或 Inertia 响应的请求。对于接受 JSON 的 API 请求（例如带有 Accept: application/json 的请求），异常处理器会返回 JSON 错误响应。这意味着 API 启动套件的异常处理器不包含 renderStatusPages 或 statusPages，因为所有响应都是 JSON。

报告错误 ​

report 方法记录错误或将它们发送到外部监控服务。与 handle 不同，它绝不应该发送 HTTP 响应。这是两个不同的关注点，应该保持分离。

基础 ExceptionHandler 类提供了 report 的默认实现，使用 AdonisJS 的日志记录器记录错误。你可以覆盖此方法以添加自定义报告逻辑，例如与错误监控服务集成。

ts
export default class HttpExceptionHandler extends ExceptionHandler {
  async report(error: unknown, ctx: HttpContext) {
    /**
     * 首先调用父类 report 方法以确保
     * 错误使用默认行为记录
     */
    await super.report(error, ctx)

    /**
     * 在此添加自定义报告逻辑，例如
     * 发送到 Sentry、Bugsnag 或其他服务
     */
  }
}

向错误报告添加上下文 ​

context 方法允许你定义应包含在每个错误报告中的附加数据。这些上下文信息帮助你理解错误发生的环境，使调试更加容易。

默认情况下，上下文包含请求 ID（x-request-id 头）。你可以覆盖此方法以包含与应用相关的任何附加信息。

ts
export default class HttpExceptionHandler extends ExceptionHandler {
  protected context(ctx: HttpContext) {
    return {
      /**
       * 包含唯一的请求 ID，用于在日志中
       * 跟踪此特定请求
       */
      requestId: ctx.request.id(),

      /**
       * 如果可用，添加已认证用户的 ID，
       * 以识别哪个用户遇到了错误
       */
      userId: ctx.auth.user?.id,

      /**
       * 包含 IP 地址用于安全监控
       * 和识别错误模式
       */
      ip: ctx.request.ip(),
    }
  }
}

这些上下文数据在每次报告错误时自动包含，为你提供每个错误环境的丰富信息，而无需手动将数据添加到每次报告调用中。

忽略来自报告的错误 ​

并非所有错误都需要报告。有些错误，如验证失败或未授权访问尝试，是正常应用流程的预期部分，不需要日志记录或监控。你可以使用 ignoreStatuses 和 ignoreCodes 属性配置哪些错误排除在报告之外。

ts
export default class HttpExceptionHandler extends ExceptionHandler {
  /**
   * 不应报告的 HTTP 状态码。
   * 这些通常是客户端错误，不表示
   * 应用本身有问题。
   */
  protected ignoreStatuses = [400, 401, 403, 404, 422]

  /**
   * 不应报告的错误代码。
   * 这些是预期错误条件的应用特定错误代码。
   */
  protected ignoreCodes = ['E_VALIDATION_ERROR', 'E_UNAUTHORIZED_ACCESS']
}

基础 ExceptionHandler 类在其 shouldReport 方法中检查这些属性，然后再报告错误。如果你实现自定义报告逻辑，必须尊重此检查。

ts
export default class HttpExceptionHandler extends ExceptionHandler {
  async report(error: unknown, ctx: HttpContext) {
    /**
     * 将错误转换为标准化的 HTTP 错误格式，
     * 包含状态码和错误代码
     */
    const httpError = this.toHttpError(error)

    /**
     * 仅在错误通过 shouldReport 检查时才报告，
     * 该检查验证它不在 ignoreStatuses 或 ignoreCodes 中
     */
    if (this.shouldReport(httpError)) {
      // 你的自定义报告逻辑
      // 例如：发送到外部监控服务
    }
  }
}

这种方法确保整个应用中的错误过滤一致，防止你的日志和监控服务被预期错误淹没。

自定义异常 ​

自定义异常允许你为应用业务逻辑中的特定错误条件创建专门的错误类。自定义异常继承自基础 Exception 类，并可以实现自己的 handle 和 report 方法，将错误条件及其处理逻辑封装在一个自包含的类中。

创建自定义异常 ​

你可以使用 make:exception 命令创建自定义异常。

sh
node ace make:exception PaymentFailed
sh
CREATE: app/exceptions/payment_failed_exception.ts

这会在 app/exceptions 目录中生成一个新的异常类。以下是包含处理逻辑和报告逻辑的完整自定义异常。

ts
import { Exception } from '@adonisjs/core/exceptions'
import { HttpContext } from '@adonisjs/core/http'

export default class PaymentFailedException extends Exception {
  /**
   * 此异常的 HTTP 状态码。
   * 设置为静态属性，以便无需实例化异常
   * 即可访问。
   */
  static status = 400

  /**
   * 通过将异常转换为 HTTP 响应来处理它。
   * 当此异常被抛出且未被捕获时，
   * 自动调用此方法。
   */
  handle(error: this, { response }: HttpContext) {
    return response
      .status(error.constructor.status)
      .send('Unable to process the payment. Please try again')
  }

  /**
   * 报告异常以进行日志记录和监控。
   * 在 handle() 之前调用此方法以记录
   * 错误的发生。
   */
  report(error: this, { logger, auth }: HttpContext) {
    logger.error(
      { user: auth.user },
      'Payment failed for user %s',
      auth.user?.id
    )
  }
}

当你在应用中的任何地方抛出此自定义异常时，AdonisJS 会自动调用其 handle 方法生成 HTTP 响应，并调用其 report 方法记录错误。实现了这些方法的自定义异常会完全绕过全局异常处理器。

何时使用自定义异常 ​

当你需要在整个应用中抛出有意义的、特定于业务逻辑的错误时，自定义异常是理想的选择。它们对于需要专门处理或报告的错误条件特别有用。与在全局异常处理器中处理错误不同，自定义异常封装了错误条件及其处理逻辑，使你的错误处理更有条理且易于维护。

另一方面，全局异常处理器旨在更改应用范围内处理异常的默认行为。它是处理横切关注点的正确位置，例如一致地格式化所有 API 错误或与监控服务集成。

当错误特定于你的领域并需要独特处理时，使用自定义异常。当你需要修改整个应用中某类错误的处理方式时，使用全局异常处理器。

配置参考 ​

异常处理器类提供多个控制错误处理行为的配置选项：

debug

类型：boolean

当为 true 时，使用 Youch 显示带有堆栈跟踪的详细错误页面。在生产环境中应为 false。默认：!app.inProduction

renderStatusPages

类型：boolean

当为 true 时，为配置的状态码渲染自定义 HTML 页面。默认：app.inProduction

statusPages

类型：Record<StatusPageRange, StatusPageRenderer>

将 HTTP 状态码或范围映射到自定义错误页面的视图渲染回调。

ignoreStatuses

类型：number[]

不应通过 report 方法报告的 HTTP 状态码数组。

ignoreCodes

类型：string[]

不应通过 report 方法报告的错误代码数组。
