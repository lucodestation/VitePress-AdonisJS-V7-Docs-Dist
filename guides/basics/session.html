会话 ​

本指南涵盖 AdonisJS 应用中 HTTP 会话的处理。你将了解到：

  • 安装和配置会话包
  • 存储和检索会话数据
  • 处理闪存消息
  • 选择合适的存储驱动
  • 实现自定义会话存储

概述 ​

HTTP 是一种无状态协议，意味着每个请求都是独立的，服务器不会在请求之间保留信息。会话通过提供一种在多个 HTTP 请求之间持久化状态并将该状态与唯一会话标识符关联的方式来解决这个问题。

在 AdonisJS 中，会话主要用于超媒体和 Inertia 应用，以维护用户身份认证状态并在请求之间传递临时数据（闪存消息）。例如，用户登录后，其身份认证状态存储在会话中，以便在后续请求中保持登录状态。同样，当你在表单提交后重定向时，存储在会话中的闪存消息可以在下一个页面显示成功或错误通知。

TIP

如果你对会话的概念不熟悉，我们建议在继续之前阅读这篇 HTTP 会话介绍。

安装 ​

通过运行以下 Ace 命令安装和配置会话包：

sh
node ace add @adonisjs/session
查看 add 命令执行的步骤
  1. 使用检测到的包管理器安装 @adonisjs/session 包。
  2. 在 adonisrc.ts 文件中注册 @adonisjs/session/session_provider 服务提供者。
  3. 创建 config/session.ts 配置文件。
  4. 定义 SESSION_DRIVER 环境变量。
  5. 在 start/kernel.ts 文件中注册 @adonisjs/session/session_middleware 中间件。

选择存储驱动 ​

会话驱动决定会话数据的存储位置。每个驱动都有不同的特性，使其适用于特定用例：

TIP

基于 cookie 的会话会静默截断超过 4KB 的数据。对于会话数据较大的生产应用，请切换到 Redis。

驱动描述最适合
cookie将数据存储在加密 cookie 中（最大约 4KB）简单应用、小数据、无后端存储
file将数据存储在本地文件系统开发、单服务器部署
redis将数据存储在 Redis 数据库生产环境、多服务器、较大数据
dynamodb将数据存储在 AWS DynamoDBAWS 基础设施、无服务器应用
database将数据存储在 SQL 数据库使用 SQL 的生产应用、现有数据库基础设施
memory将数据存储在内存中（重启后丢失）仅测试

配置 ​

会话配置存储在安装期间创建的 config/session.ts 中。以下是默认配置：

ts
import env from '#start/env'
import app from '@adonisjs/core/services/app'
import { defineConfig, stores } from '@adonisjs/session'

export default defineConfig({
  enabled: true,
  cookieName: 'adonis-session',
  clearWithBrowser: false,
  age: '2h',

  cookie: {
    path: '/',
    httpOnly: true,
    secure: app.inProduction,
    sameSite: 'lax',
  },

  store: env.get('SESSION_DRIVER'),

  stores: {
    cookie: stores.cookie(),

    file: stores.file({
      location: app.tmpPath('sessions')
    }),

    redis: stores.redis({
      connection: 'main'
    }),

    database: stores.database({
      connectionName: 'pg',
      tableName: 'sessions',
    }),

    dynamodb: stores.dynamodb({
      region: env.get('AWS_REGION'),
      endpoint: env.get('AWS_ENDPOINT'),
      tableName: 'sessions',
    }),
  }
})

age

类型：string | number

会话过期前的生命周期。接受像 '2 hours' 或 '7 days' 这样的持续时间字符串，或毫秒数。此时间段后，会话过期并删除数据。

ts
age: '2 hours'
// 或
age: 7200000 // 2 小时的毫秒数

clearWithBrowser

类型：boolean

当为 true 时，用户关闭浏览器时会删除会话 cookie，无论配置的 age 如何。当为 false（默认值）时，会话在浏览器关闭后仍持续配置的 age 持续时间。

ts
clearWithBrowser: false

store

类型：string

决定使用哪个会话驱动。在 .env 文件中使用 SESSION_DRIVER 环境变量设置。该值必须匹配 stores 对象中定义的键之一。

dotenv
SESSION_DRIVER=cookie

cookie

类型：object

控制会话 cookie 行为的 Cookie 配置对象。包括 cookie 名称、域、路径和安全选项的设置。详细选项请参阅 Cookie 配置部分。

stores

类型：object

定义所有可用会话存储的对象。每个键代表一个驱动名称，值是存储配置。store 属性中指定的驱动必须存在于此对象中。

Cookie 配置 ​

会话使用 cookie 存储会话 ID（或 cookie 驱动的整个会话数据）。使用这些选项配置 cookie 行为：

cookie.name

类型：string

存储会话 ID 的 cookie 名称。仅当它与应用中的其他 cookie 冲突时才更改。

ts
cookie: {
  name: 'adonis-session'
}

cookie.domain

类型：string

Cookie 有效的域。留空以默认为当前域。设置为 '.example.com'（带前导点）以在 app.example.com 和 api.example.com 等子域之间共享 cookie。

ts
cookie: {
  domain: '' // 仅当前域
  // 或
  domain: '.example.com' // 所有子域
}

cookie.path

类型：string

Cookie 有效的 URL 路径。将其设置为 '/' 使 cookie 在整个应用中可用。

ts
cookie: {
  path: '/'
}

cookie.httpOnly

类型：boolean

当为 true 时，阻止 JavaScript 通过 document.cookie 访问 cookie，防止恶意脚本试图窃取会话 ID 的 XSS 攻击。为了安全，保持为 true。

ts
cookie: {
  httpOnly: true
}

cookie.secure

类型：boolean

当为 true 时，确保 cookie 仅通过 HTTPS 连接发送，防止在不安全网络上会话劫持。启动套件使用 app.inProduction 在生产环境中自动启用，同时在通过 HTTP 的本地开发期间保持禁用。

ts
cookie: {
  secure: app.inProduction
}

cookie.sameSite

类型：'lax' | 'strict' | 'none'

控制浏览器何时随跨站请求发送 cookie，防止 CSRF 攻击。

  • 'lax'：在顶级导航（点击链接）时发送 cookie。大多数应用的默认值和推荐值。
  • 'strict'：从不在跨站请求上发送 cookie。最安全，但可能破坏合法流程。
  • 'none'：始终发送 cookie。需要 secure: true，很少需要。
ts
cookie: {
  sameSite: 'lax'
}

Redis 驱动 ​

Redis 驱动将会话数据存储在 Redis 数据库中，非常适合具有多个服务器或较大会话数据的生产应用。

你可以使用以下命令添加 redis 包。完整设置说明请参阅 Redis 指南。

sh
node ace add @adonisjs/redis

stores.redis.connection

类型：string

用于会话存储的 Redis 连接名称。此连接必须在 config/redis.ts 文件中配置。

ts
stores: {
  redis: stores.redis({
    connection: 'main'
  })
}

Database 驱动 ​

Database 驱动将会话数据存储在 SQL 数据库中，非常适合已使用 SQL 数据库基础设施的生产应用。

stores.database.connectionName

类型：string

用于会话存储的数据库连接名称。此连接必须在 config/database.ts 文件中配置。

ts
stores: {
  database: stores.database({
    connectionName: 'pg'
  })
}

stores.database.tableName

类型：string

存储会话数据的数据库表名称。默认为 'sessions'。确保使用 node ace make:session-table 命令为会话表创建迁移。

ts
stores: {
  database: stores.database({
    tableName: 'sessions'
  })
}

DynamoDB 驱动 ​

DynamoDB 驱动将会话数据存储在 AWS DynamoDB 中，非常适合无服务器应用和 AWS 基础设施。

安装：首先安装 AWS SDK：

sh
npm install @aws-sdk/client-dynamodb

stores.dynamodb.region

类型：string

DynamoDB 表所在的 AWS 区域。

ts
stores: {
  dynamodb: stores.dynamodb({
    region: env.get('AWS_REGION')
  })
}

stores.dynamodb.endpoint

类型：string

DynamoDB 的可选自定义端点 URL。对于使用 DynamoDB Local 或自定义端点的本地开发很有用。

ts
stores: {
  dynamodb: stores.dynamodb({
    endpoint: env.get('AWS_ENDPOINT')
  })
}

stores.dynamodb.tableName

类型：string

存储会话数据的 DynamoDB 表名称。

ts
stores: {
  dynamodb: stores.dynamodb({
    tableName: 'sessions'
  })
}

File 驱动 ​

File 驱动将会话数据存储在本地文件系统，适合开发和单服务器部署。

stores.file.location

类型：string

存储会话文件的目录路径。默认为应用根目录下的 tmp/sessions。

ts
stores: {
  file: stores.file({
    location: app.tmpPath('sessions')
  })
}

基本用法 ​

安装后，你可以使用 session 属性从 HTTP 上下文访问会话。会话存储提供简单的键值 API 用于读写数据。

让我们构建一个简单的购物车示例，演示核心会话方法：

ts
import router from '@adonisjs/core/services/router'
import Product from '#models/product'

/**
 * 显示购物车中的商品。
 * 使用 get() 并提供空数组作为默认值。
 */
router.get('/cart', ({ session }) => {
  const cartItems = session.get('cart', [])
  return { items: cartItems, total: cartItems.length }
})

/**
 * 将商品添加到购物车。
 * 演示使用 put() 存储更新后的购物车数据。
 */
router.post('/cart', async ({ request, session }) => {
  const productId = request.input('product_id')
  const product = await Product.findOrFail(productId)

  const cartItems = session.get('cart', [])
  cartItems.push({
    id: product.id,
    name: product.name,
    quantity: 1
  })

  session.put('cart', cartItems)
  return { message: 'Item added', totalItems: cartItems.length }
})

/**
 * 从购物车中移除特定商品。
 * 展示如何更新和存储修改后的数据。
 */
router.delete('/cart/:productId', ({ params, session }) => {
  const cartItems = session.get('cart', [])
  const updatedCart = cartItems.filter(item => item.id !== params.productId)

  session.put('cart', updatedCart)
  return { message: 'Item removed' }
})

/**
 * 清空整个购物车。
 * 使用 forget() 移除特定键。
 */
router.delete('/cart', ({ session }) => {
  session.forget('cart')
  return { message: 'Cart cleared' }
})

检查值是否存在 ​

你可以在尝试检索之前检查会话中是否存在某个值。

ts
router.get('/checkout', ({ session, response }) => {
  /**
   * 在继续之前检查购物车是否存在且有商品。
   * has() 方法在键存在时返回 true。
   */
  if (!session.has('cart')) {
    return response.redirect('/cart')
  }

  const cartItems = session.get('cart')
  return { items: cartItems }
})

检索并移除值 ​

有时你需要获取一个值并立即从会话中移除它。pull() 方法结合了这两个操作。

ts
router.post('/process-payment', ({ session }) => {
  /**
   * 在一次操作中获取购物车数据并移除它。
   * 这在处理一次性数据时很有用。
   */
  const cartItems = session.pull('cart', [])

  // 使用 cartItems 处理支付
  // 购物车现在已自动从会话中移除

  return { processed: cartItems.length }
})

处理数值 ​

会话提供递增和递减数值的便捷方法，对计数器或跟踪数值状态很有用。

ts
router.post('/visit', ({ session }) => {
  /**
   * 将访问计数器递增 1。
   * 如果 'visits' 不存在，初始化为 1。
   */
  session.increment('visits')

  const totalVisits = session.get('visits')
  return { visits: totalVisits }
})

router.post('/undo', ({ session }) => {
  /**
   * 递减计数器。
   * 如果 'actions' 不存在，初始化为 -1。
   */
  session.decrement('actions')

  return { actionsRemaining: session.get('actions', 0) }
})

检索所有会话数据 ​

你可以使用 all() 方法将所有会话数据作为对象检索。

ts
router.get('/debug/session', ({ session }) => {
  /**
   * 将所有会话数据作为对象返回。
   * 对调试或显示会话状态很有用。
   */
  const allData = session.all()
  return allData
})

清空整个会话 ​

要从会话存储中移除所有数据，使用 clear() 方法。

ts
router.post('/logout', ({ session, auth, response }) => {
  // 清除身份认证
  await auth.logout()

  /**
   * 移除所有会话数据。
   * 这在登出期间清理所有用户状态时很有用。
   */
  session.clear()

  return response.redirect('/login')
})

闪存消息 ​

闪存消息是存储在会话中的临时数据，仅在下一个 HTTP 请求中可用。它们在被访问一次后自动删除，非常适合在重定向后显示一次性通知。

基本闪存消息 ​

使用 flash() 方法为下一个请求存储消息。第一个参数是消息类型（用于分类消息的约定），第二个是消息内容。

ts
router.post('/cart', async ({ session, response }) => {
  // 将商品添加到购物车...

  /**
   * 为下一个请求闪现成功消息。
   * 在模板中通过 flashMessages.get('success') 访问。
   */
  session.flash('success', 'Item added to the cart')

  return response.redirect().back()
})

AdonisJS 使用 success 和 error 作为标准消息类型约定。虽然你可以使用任何字符串作为消息类型，但这些约定有助于组织不同种类的通知。

ts
export default class OrdersController {
  async store({ session, response }: HttpContext) {
    try {
      // 处理订单...
      session.flash('success', 'Order placed successfully!')
      return response.redirect('/orders')
    } catch (error) {
      session.flash('error', 'Payment failed. Please try again.')
      return response.redirect().back()
    }
  }
}

显示闪存消息 ​

如果你使用超媒体或 Inertia 启动套件，闪存消息已在布局文件中自动显示。启动套件检查 success 和 error 消息并以适当的样式渲染它们。

对于自定义布局或应用，使用全局 flashMessages 辅助函数在 Edge 模板中显示闪存消息。

edge
@if(flashMessages.has('success'))
  <div class="alert alert-success">
    {{ flashMessages.get('success') }}
  </div>
@end

@if(flashMessages.has('error'))
  <div class="alert alert-error">
    {{ flashMessages.get('error') }}
  </div>
@end

自定义闪存消息 ​

除了标准消息类型，你还可以为特定用例创建自定义消息类型。

ts
router.post('/newsletter/subscribe', ({ session, response }) => {
  // 订阅用户...

  session.flash('newsletter', 'Check your email to confirm subscription')
  return response.redirect().back()
})

在模板中显示自定义消息。

edge
@if(flashMessages.has('newsletter'))
  <div class="alert alert-newsletter">
    {{ flashMessages.get('newsletter') }}
  </div>
@end

闪现表单数据 ​

当表单处理期间发生错误且你需要将用户重定向回表单时，你可以闪现提交的表单数据以预填充表单字段。

ts
export default class PostsController {
  async store({ request, session, response }: HttpContext) {
    try {
      // 尝试创建帖子...
      throw new Error('Unable to publish post')
    } catch (error) {
      /**
       * 闪现表单数据以重新填充表单。
       * 用户不必重新输入他们的数据。
       */
      session.flashAll()
      session.flash('error', 'Failed to create post. Please try again.')

      return response.redirect().back()
    }
  }
}

你也可以仅闪现特定字段或排除敏感字段。

ts
// 仅闪现特定字段
session.flashOnly(['title', 'content', 'category'])

// 闪现除敏感字段之外的所有内容
session.flashExcept(['password', 'credit_card'])

在模板中使用 old() 辅助函数访问闪现的表单数据。

edge
<input type="text" name="title" value="{{ old('title') }}" />
<textarea name="content">{{ old('content') }}</textarea>

TIP

使用 AdonisJS 验证器时，验证失败时会自动闪现验证错误和表单数据。你不需要手动闪现它们。

重新闪现消息 ​

有时你需要为额外的请求保留闪存消息。使用 reflash() 将前一个请求的所有消息保留一个周期。

ts
export default class CheckSubscriptionMiddleware {
  async handle({ auth, session, response }: HttpContext, next: NextFn) {
    const user = auth.getUserOrFail()

    if (!user.hasActiveSubscription) {
      /**
       * 为再多一个请求保留所有闪存消息。
       */
      session.reflash()
      session.flash('error', 'Please subscribe to continue')

      return response.redirect('/subscribe')
    }

    await next()
  }
}

你也可以选择性地仅重新闪现特定消息类型。

ts
// 仅重新闪现错误消息
session.reflashOnly(['error'])

// 重新闪现除 success 之外的所有消息
session.reflashExcept(['success'])

预期 URL ​

预期 URL 功能允许你存储用户完成中间步骤后应重定向到的 URL。例如，你可以在将用户重定向到登录页面之前存储当前页面 URL，登录后将其重定向回他们所在的页面。

URL 在存储之前经过验证，以防止开放重定向攻击。无效或不安全的 URL（如协议相对的 //evil.com）会被静默忽略。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async show({ request, session, view }: HttpContext) {
    /**
     * 如果登录页面通过 ?intended 查询参数访问，
     * 将会话中存储预期 URL 以供登录后使用
     */
    const intended = request.input('intended')
    if (intended) {
      session.setIntendedUrl(intended)
    }

    return view.render('auth/login')
  }

  async store({ request, auth, response }: HttpContext) {
    const user = await User.verifyCredentials(
      request.input('email'),
      request.input('password')
    )
    await auth.use('web').login(user)

    /**
     * 如果存储了预期 URL 则重定向到它，
     * 否则回退到 dashboard
     */
    return response.redirect().toIntendedRoute('dashboard')
  }
}

你也可以直接读取、消费或清除预期 URL。

ts
import router from '@adonisjs/core/services/router'

router.get('/example', ({ session }) => {
  /**
   * 读取但不消费
   */
  const url = session.getIntendedUrl()

  /**
   * 在一次操作中读取并移除
   */
  const consumed = session.pullIntendedUrl()

  /**
   * 移除但不读取
   */
  session.clearIntendedUrl()
})

另请参阅：登录后重定向到预期 URL

会话再生 ​

会话再生创建一个新的会话 ID，同时保留所有现有会话数据。这是一项关键的安全措施，用于防止会话固定攻击，即攻击者诱骗用户使用由攻击者控制的会话 ID。

当用户登录时，其身份认证状态从未认证变为已认证。如果保持相同的会话 ID，知道登录前会话 ID 的攻击者可以劫持已认证的会话。登录后重新生成会话 ID 可防止此攻击。

使用官方 Auth 包时，AdonisJS 自动处理会话再生。但是，如果你实现自定义身份认证，必须在成功登录后手动调用 session.regenerate()。

ts
export default class AuthController {
  async login({ request, session, response }: HttpContext) {
    const { email, password } = request.only(['email', 'password'])

    // 验证凭据...
    const user = await User.verifyCredentials(email, password)

    /**
     * 在保留数据的同时生成新的会话 ID。
     * 这防止会话固定攻击。
     */
    await session.regenerate()

    // 在新会话中存储用户信息
    session.put('user_id', user.id)

    return response.redirect('/dashboard')
  }
}

创建自定义会话存储 ​

如果内置驱动都不能满足你的需求，你可以通过实现 SessionStoreContract 接口来创建自定义会话存储。这对于集成 MongoDB 或自定义存储解决方案很有用。

实现存储契约 ​

创建一个实现四个必需方法的类。

ts
import {
  SessionData,
  SessionStoreFactory,
  SessionStoreContract,
} from '@adonisjs/session/types'

/**
 * 你想接受的配置
 */
export type MongoDBConfig = {
  collection: string;
  database: string
}

/**
 * MongoDbStore 类处理实际的存储操作。
 * 它实现四个必需的方法：read、write、destroy 和 touch。
 */
export class MongoDbStore implements SessionStoreContract {
  constructor(protected config: MongoDBConfig) {}

  /**
   * 读取给定会话 ID 的会话数据。
   * 如果会话不存在，返回 null。
   */
  async read(sessionId: string): Promise<SessionData | null> {
    // 查询你的存储并返回会话数据
  }

  /**
   * 写入给定会话 ID 的会话数据。
   */
  async write(
    sessionId: string,
    data: SessionData,
    expiresAt: Date
  ): Promise<void> {
    // 将会话数据保存到你的存储
  }

  /**
   * 删除给定会话 ID 的会话数据。
   */
  async destroy(sessionId: string): Promise<void> {
    // 从你的存储中移除会话
  }

  /**
   * 在不更改数据的情况下更新会话的过期时间。
   */
  async touch(sessionId: string, expiresAt: Date): Promise<void> {
    // 更新你存储中的过期时间戳
  }
}

/**
 * 工厂函数接受配置并返回驱动函数。
 * 驱动函数在会话管理器调用时创建存储类的新实例。
 */
export function mongoDbStore(config: MongoDbConfig): SessionStoreFactory {
  return (ctx, sessionConfig) => {
    return new MongoDBStore(config)
  }
}

注册自定义存储 ​

使用工厂函数在 config/session.ts 中注册自定义存储。

ts
import { defineConfig } from '@adonisjs/session'
import { mongoDbStore } from '#session_stores/mongodb_store'

export default defineConfig({
  store: env.get('SESSION_DRIVER'),

  stores: {
    mongodb: mongoDbStore({
      collection: 'sessions',
      database: 'myapp'
    })
  }
})

设置环境变量以使用自定义存储。

dotenv
SESSION_DRIVER=mongodb
