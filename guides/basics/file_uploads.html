文件上传 ​

本指南涵盖 AdonisJS 中的文件上传，从基本的单文件上传到使用云存储提供商的高级直传。你将了解到如何：

  • 在应用中接受和验证文件上传
  • 使用 FlyDrive 永久存储文件
  • 处理多文件上传和云端直传
  • 保护你的文件上传端点

概述 ​

文件上传允许用户从浏览器向你的 AdonisJS 应用发送文件。与许多需要额外包来实现此功能的 Node.js 框架不同，AdonisJS 通过其 body parser 内置支持解析 multipart 请求和处理文件上传。

当文件上传时，AdonisJS 会自动将其保存到服务器的 tmp 目录。从那里，你可以在控制器中验证文件，然后将其移动到永久存储。

对于永久存储，AdonisJS 集成了 FlyDrive，它提供了统一的 API，可用于本地文件系统以及 Amazon S3、Cloudflare R2 和 Google Cloud Storage 等云存储解决方案。

上传你的第一个文件 ​

我们将构建一个允许用户更新个人头像的功能。这是一个常见需求，并演示了所有基本概念。

步骤 1：创建上传表单 ​

首先，创建一个接受文件上传的表单。关键部分是将表单编码设置为 multipart/form-data。没有它，浏览器将无法正确发送文件。

edge
@form({ route: 'profile_avatar.update', enctype: 'multipart/form-data' })
  @field.root({ name: 'avatar' })
    @!input.control({ type: 'file' })
    @!field.label({ text: 'Upload new avatar' })
    @!field.error()
  @end

  @!button({ type: 'Submit', text: 'Update Avatar' })
@end
tsx
import { Form } from '@adonisjs/inertia/react'

export default function Profile() {
  return (
    <Form route="profile_avatar.update" encType="multipart/form-data">
      {({ errors }) => (
        <>
          <div>
            <label htmlFor="avatar">Upload new avatar</label>
            <input type="file" name="avatar" id="avatar" />
            {errors.avatar && <div>{errors.avatar}</div>}
          </div>
          <button type="submit">Update Avatar</button>
        </>
      )}
    </Form>
  )
}

步骤 2：注册路由 ​

接下来，注册一个路由来处理文件上传。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.put('/profile/avatar', [controllers.profileAvatar, 'update'])

步骤 3：创建控制器 ​

现在创建一个接受上传文件的控制器。request.file() 方法通过字段名让你访问上传的文件。

ts
import { HttpContext } from '@adonisjs/core/http'

export default class ProfileAvatarController {
  async update({ request, response }: HttpContext) {
    const avatar = request.file('avatar')

    if (!avatar) {
      return response.badRequest('Please upload an avatar image')
    }

    console.log(avatar)

    return 'Avatar uploaded successfully'
  }
}

此时，你的应用可以接收文件上传。当你访问它时，文件已经保存在 tmp 目录中。文件对象包含有用的属性：

  • tmpPath - 文件当前在服务器上的存储位置
  • clientName - 来自用户计算机的原始文件名
  • size - 文件大小（字节）
  • extname - 文件扩展名（例如 'jpg'、'png'）
  • type - MIME 类型（例如 'image/jpeg'）

验证上传的文件 ​

接受任何文件而不进行验证是危险的。用户可能上传过大的文件、格式不正确的文件，甚至可能是恶意的文件。AdonisJS 提供两种验证方法。

内联验证 ​

你可以通过将验证选项作为第二个参数传递给 request.file() 调用来直接验证文件。

ts
import { HttpContext } from '@adonisjs/core/http'

export default class ProfileAvatarController {
  async update({ request, response }: HttpContext) {
    const avatar = request.file('avatar', {
      size: '2mb',
      extnames: ['jpg', 'png', 'jpeg']
    })

    if (!avatar) {
      return response.badRequest('Please upload an avatar image')
    }

    if (avatar.hasErrors) {
      return response.badRequest(avatar.errors)
    }

    return 'Avatar uploaded and validated successfully'
  }
}

验证在你调用 request.file() 时立即发生。如果文件太大或扩展名无效，avatar.hasErrors 属性将为 true，avatar.errors 数组将包含错误消息。

VineJS 验证 ​

虽然内联验证可以工作，但使用 VineJS 验证器是推荐的方法，因为它提供更好的错误消息、一致的验证模式和更简单的测试。

首先，创建一个验证器文件。

ts
import vine from '@vinejs/vine'

export const updateAvatarValidator = vine.create({
  avatar: vine.file({
    size: '2mb',
    extnames: ['jpg', 'png', 'jpeg']
  })
})

然后在你的控制器中使用验证器。

ts
import { HttpContext } from '@adonisjs/core/http'
import { updateAvatarValidator } from '#validators/user'

export default class ProfileAvatarController {
  async update({ request }: HttpContext) {
    const payload = await request.validateUsing(updateAvatarValidator)

    console.log(payload.avatar)
    return 'Avatar uploaded and validated successfully'
  }
}

如果验证失败，AdonisJS 会自动返回带有详细错误消息的 422 响应。如果验证成功，你会在 payload 对象中获得验证后的数据。此时头像已通过大小和扩展名检查。

安全特性

AdonisJS 的一个关键安全特性是它使用魔数检测来验证文件类型。这意味着即使有人将 .exe 文件重命名为 .jpg，AdonisJS 也会检测到实际文件类型并拒绝它。这保护你的应用免受试图通过简单更改文件扩展名来绕过验证的用户的影响。

将文件与其他字段组合 ​

当你的表单同时包含文件上传和常规字段时，验证后的 payload 包含两者。在将剩余数据传递给模型之前，单独解构文件字段——将 multipart 文件对象直接传递给 Model.create() 会导致错误：

ts
import vine from '@vinejs/vine'

export const createTaskValidator = vine.create({
  title: vine.string(),
  description: vine.string().optional(),
  attachment: vine.file({ size: '5mb', extnames: ['pdf', 'jpg', 'png'] }).optional(),
})
ts
import { HttpContext } from '@adonisjs/core/http'
import { createTaskValidator } from '#validators/task'

export default class TasksController {
  async store({ request }: HttpContext) {
    const { attachment, ...data } = await request.validateUsing(createTaskValidator)

    const task = await Task.create(data)

    if (attachment) {
      await attachment.moveToDisk(`tasks/${task.id}.${attachment.extname}`)
      task.attachmentFileName = `tasks/${task.id}.${attachment.extname}`
      await task.save()
    }

    return task
  }
}

{ attachment, ...data } 解构将文件与标量字段分开，以便你可以将 data 直接传递给模型并单独处理文件。

存储和提供上传的文件 ​

通过表单上传的文件临时存储在 tmp 目录中。大多数操作系统会自动清理临时文件，因此你不能依赖它们持久存在。对于永久存储，你需要将文件移动到它们会被保留的位置。

AdonisJS 使用 FlyDrive 进行永久文件存储。FlyDrive 提供统一的 API，在开发期间可用于本地文件系统，在生产环境中可用于 S3 或 R2 等云存储提供商。

通过运行以下命令安装和配置 FlyDrive：

bash
node ace add @adonisjs/drive

此命令安装 @adonisjs/drive 包并创建一个 config/drive.ts 配置文件，本地磁盘存储已准备好使用。对于云存储配置（S3、R2、GCS），请参阅 Drive 文档。

将文件移动到永久存储 ​

一旦安装了 FlyDrive，你就可以将验证过的文件从 tmp 目录移动到永久存储。@adonisjs/drive 包用 moveToDisk() 方法扩展了文件对象，该方法自动处理此操作。

ts
import { HttpContext } from '@adonisjs/core/http'
import string from '@adonisjs/core/helpers/string'
import { updateAvatarValidator } from '#validators/user'

export default class ProfileAvatarController {
  async update({ request, auth }: HttpContext) {
    const payload = await request.validateUsing(updateAvatarValidator)

    /**
     * 使用唯一的随机名称存储文件
     */
    const fileName = `${string.uuid()}.${payload.avatar.extname}`

    /**
     * 使用预配置的 drive 磁盘移动文件。
     */
    await payload.avatar.moveToDisk(fileName)

    /**
     * 更新数据库中的用户行以反映
     * 新更新的头像文件名
     */
    const user = auth.getUserOrFail()
    user.avatarFileName = fileName
    await user.save()

    return 'Avatar uploaded and saved successfully'
  }
}

  • 我们使用 UUID 生成唯一文件名以防止冲突。多个用户可能上传名为 "avatar.jpg" 的文件，因此唯一名称可防止覆盖。

  • moveToDisk() 方法处理从 tmp 到永久存储的传输。它使用配置的磁盘（开发环境中的本地文件系统或生产环境中的云存储）。

  • 移动后将文件名存储在数据库中。你稍后需要它来显示头像或生成下载链接。

访问你上传的文件 ​

@adonisjs/drive 包包含一个内置的文件服务器，自动提供上传的文件。文件服务器在 /uploads 下注册路由，后跟你的目录结构。

例如，如果你将文件存储为 avatars/123e4567.jpg，它可以通过以下方式访问：

http://localhost:3333/uploads/avatars/123e4567.jpg

现在，不要硬编码此路径，而是使用适合你应用类型的方法来生成 URL。这确保无论你使用本地存储还是 S3 或 R2 等云提供商，都会返回正确的 URL。

edge
在模板中使用 `driveUrl` Edge 辅助函数：

<img src="{{ await driveUrl(user.avatarFileName) }}" alt="User avatar">
ts
在返回 JSON 或渲染 Inertia 页面的控制器中，使用 `drive` 服务生成 URL：

import drive from '@adonisjs/drive/services/main'

// 在控制器或转换器内部
const avatarUrl = await drive.use().getUrl(user.avatarFileName)

你可以在 API 响应或 Inertia props 中包含此 URL：

return inertia.render('profile', {
  user: {
    name: user.name,
    avatarUrl: await drive.use().getUrl(user.avatarFileName),
  }
})

上传多个文件 ​

许多应用需要在单个请求中接受多个文件。例如，允许用户为项目上传多个文档，或一次上传多张产品图片。

在表单中接受多个文件 ​

要接受多个文件，请在你的文件输入中添加 multiple 属性并使用数组风格的字段名。

edge
@form({ route: 'projects.documents.store', enctype: 'multipart/form-data' })
  @field.root({ name: 'documents[]' })
    @!input.control({ type: 'file', multiple: true })
    @!field.label({ text: 'Upload project documents' })
    @!field.error()
  @end

  <button type="submit">Upload Documents</button>
@end

访问多个文件 ​

使用 request.files()（复数）而不是 request.file() 来访问多个上传的文件。此方法返回文件对象数组，即使只上传了一个文件。

ts
import { HttpContext } from '@adonisjs/core/http'

export default class ProjectDocumentsController {
  async store({ request, response }: HttpContext) {
    const documents = request.files('documents')

    if (documents.length === 0) {
      return response.badRequest('Please upload at least one document')
    }

    console.log(`Received ${documents.length} documents`)

    return 'Documents uploaded successfully'
  }
}

验证多个文件 ​

使用 VineJS 时，使用 vine.array() 验证文件数组。数组中的每个文件必须满足指定的大小和扩展名要求。

ts
import vine from '@vinejs/vine'

export const uploadDocumentsValidator = vine.create({
  documents: vine.array(
    vine.file({
      size: '5mb',
      extnames: ['pdf', 'doc', 'docx', 'txt'],
    })
  ),
})

处理多个文件 ​

遍历验证后的文件并将每个文件单独移动到永久存储。数组中的每个文件具有与单个文件相同的属性和方法，包括 moveToDisk()。

ts
import { HttpContext } from '@adonisjs/core/http'
import string from '@adonisjs/core/helpers/string'
import { uploadDocumentsValidator } from '#validators/project'

export default class ProjectDocumentsController {
  async store({ request, params }: HttpContext) {
    const payload = await request.validateUsing(uploadDocumentsValidator)
    const fileNames: string[] = []

    for (const document of payload.documents) {
      const fileName = `${string.uuid()}.${document.extname}`
      await document.moveToDisk(fileName)
      fileNames.push(fileName)
    }

    return { message: 'Documents uploaded', count: fileNames.length }
  }
}

直传 ​

直传允许文件直接从浏览器上传到 S3、R2 或 Google Cloud Storage 等云存储提供商，完全绕过你的 AdonisJS 服务器。

与标准的 浏览器 → 你的服务器 → 云存储 流程不同，直传直接从 浏览器 → 云存储。你的服务器只生成一个短期的签名 URL，授予上传到特定位置的临时权限。

在处理大文件上传（通常超过 100MB）时推荐使用此模式。为大型文件构建容错和可恢复的上传服务器是复杂的工作。通过使用直传，你将这一责任交给为此目的设计的专业服务。

其他好处包括减少服务器带宽使用、为用户提供更好的上传性能，以及云提供商内置的可恢复上传。

实现直传 ​

你需要一个云存储提供商的账户，如 Amazon S3、Cloudflare R2 或 Google Cloud Storage。确保 FlyDrive 已使用你的云提供商凭据配置（有关配置详情，请参阅 Drive 参考指南）。

创建一个生成签名上传 URL 的端点。

ts
import router from '@adonisjs/core/services/router'
import drive from '@adonisjs/drive/services/main'

router.post('/signed-upload-url', async ({ request }) => {
  const fileName = request.input('file_name')

  const url = await drive.use('r2').getSignedUploadUrl(fileName, {
    expiresIn: '30 mins',
  })

  return { signedUrl: url }
})

客户端提供他们想要上传的文件名。你应该考虑验证这一点并生成唯一文件名以防止冲突。

签名 URL 在 30 分钟后过期，以防止长期未授权访问。将 'r2' 替换为你配置的磁盘名称（可能是 's3'、'gcs' 等）。

客户端实现 ​

客户端代码比标准表单上传更复杂。你需要一个处理上传过程、进度跟踪和错误处理的 JavaScript 库。流行的库包括 Uppy.io、Filepond，或者你可以使用原生 JavaScript 和 Fetch API 进行自定义实现。

以下是使用 Fetch API 的高级示例。

javascript
async function uploadFile(file) {
  // 步骤 1：从你的服务器请求签名 URL
  const response = await fetch('/signed-upload-url', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ file_name: file.name })
  })

  const { signedUrl } = await response.json()

  // 步骤 2：使用签名 URL 直接上传到云存储
  await fetch(signedUrl, {
    method: 'PUT',
    body: file,
    headers: {
      'Content-Type': file.type
    }
  })

  console.log('File uploaded successfully!')
}

第一步从你的 AdonisJS 应用请求签名 URL。第二步使用该 URL 将文件直接上传到云存储。

对于生产应用，考虑使用 Uppy.io 等库，它提供上传进度跟踪、自动重试、可恢复上传和用户友好界面等附加功能。

限制文件上传路由 ​

现在你了解了如何实现文件上传，保护你的应用免受潜在滥用很重要。

默认情况下，AdonisJS 在使用 POST、PUT 和 PATCH 方法的所有路由上处理 multipart 请求（文件上传）。这意味着你应用中的任何端点都可能接收和处理文件上传，即使你并未打算让它处理文件。这种不受限制的访问允许攻击者针对你应用中的任何端点上传文件，可能耗尽你的服务器资源、填满磁盘空间，或利用你的应用分发恶意内容。

作为第一项安全措施，你必须仅在真正需要处理文件的特定路由上允许 multipart 自动处理。在 body parser 设置中配置。

ts
import { defineConfig } from '@adonisjs/core/bodyparser'

export default defineConfig({
  allowedMethods: ['POST', 'PUT', 'PATCH', 'DELETE'],

  multipart: {
    autoProcess: ['/profile/avatar', '/users/:id', '/projects/:id/files']
  },
})

此配置确保只有指定的路由才会处理 multipart 请求。所有其他路由将拒绝文件上传，防止攻击者将文件上传到随机端点。

如果你有接受文件上传的公共端点（不需要身份认证的端点），请应用严格的速率限制以防止滥用。有关实现细节，请参阅速率限制指南。

有关全面的 body parser 配置选项，请参阅 BodyParser 指南。
