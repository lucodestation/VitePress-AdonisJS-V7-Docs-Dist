中间件 ​

本指南涵盖 AdonisJS 应用中的中间件。你将了解到如何：

  • 使用三种中间件栈（服务器、路由器和命名）
  • 创建自定义中间件以处理横切关注点
  • 在适当的栈中注册中间件
  • 向命名中间件传递参数以实现路由特定逻辑
  • 在中间件构造函数中使用依赖注入
  • 在中间件管道期间修改请求和响应
  • 在中间件中处理异常
  • 使用自定义属性扩充 HttpContext

概述 ​

中间件是在 HTTP 请求期间、请求到达路由处理器之前执行的函数。链中的每个中间件可以通过发送响应来终止请求，或使用 next 方法将其转发到下一个中间件。

中间件层允许你将必须在请求期间运行的逻辑封装到专用的、可重用的函数或类中。你不必用解析请求体、认证用户或记录请求的重复逻辑弄乱控制器，而是可以将这些职责交给专用中间件。

你的应用处理的每个 HTTP 请求都流经中间件管道，因此理解中间件如何工作以及如何有效地组织它们至关重要。

中间件栈 ​

AdonisJS 将中间件分为三个类别，称为栈。每个栈服务于不同的目的，并在请求生命周期的不同时间点执行。

服务器中间件栈

  • 对每个 HTTP 请求执行，即使没有路由匹配
  • 在路由器尝试查找匹配路由之前运行
  • 用于：日志记录、CORS、安全头

路由器中间件栈

  • 仅在找到匹配路由时执行
  • 在路由匹配之后、命名中间件和处理器之前运行
  • 用于：加载共享数据、解析请求体

命名中间件集合

  • 显式应用到单个路由或路由组
  • 可以接受参数以实现按路由自定义
  • 用于：基于角色的授权、路由特定速率限制、功能标志

创建和使用中间件 ​

让我们逐步创建一个完整的日志记录中间件，用于跟踪请求持续时间。我们将生成中间件文件、实现日志记录逻辑，并注册它以在所有请求上运行。

步骤 1：生成中间件 ​

使用 make:middleware 命令创建一个新的中间件。此命令在 app/middleware 目录中生成一个搭建好的中间件类。

bash
node ace make:middleware LogRequests
bash
# CREATE: app/middleware/log_requests_middleware.ts

生成的中间件包含一个基本类结构，其中有一个 handle 方法，我们将在其中添加日志记录逻辑：

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'

export default class LogRequestsMiddleware {
  async handle(ctx: HttpContext, next: NextFn) {
    /**
     * 在请求处理器之前运行的逻辑
     */
    await next()
    /**
     * 在请求处理器之后运行的逻辑
     */
  }
}

步骤 2：实现日志记录逻辑 ​

现在让我们实现实际的日志记录功能。我们将通过在调用 next() 之前捕获开始时间，然后在响应就绪后计算持续时间，来跟踪每个请求花费的时间。

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'
import string from '@adonisjs/core/helpers/string'

export default class LogRequestsMiddleware {
  async handle({ request, response, logger }: HttpContext, next: NextFn) {
    /**
     * 在调用 next() 之前捕获开始时间。
     * 这发生在上行阶段。
     */
    const startTime = process.hrtime()

    /**
     * 调用 next() 以执行剩余的中间件和路由处理器。
     * await 确保我们等待整个链完成。
     */
    await next()

    /**
     * next() 完成后，我们处于下行阶段。
     * 响应已就绪，因此我们可以记录完成详情。
     */
    const endTime = process.hrtime(startTime)
    const responseStatus = response.getStatus()
    const uri = request.url()
    const method = request.method()

    logger.info(`${method} ${uri}: ${responseStatus} (${string.prettyHrTime(endTime)})`)
  }
}

步骤 3：注册中间件 ​

最后，让我们将日志记录中间件注册到服务器中间件栈中，使其对每个请求运行。我们将把它注册为第一个中间件，以便精确计时所有请求。

服务器中间件在 start/kernel.ts 文件中使用懒加载导入注册，并按注册顺序执行。

ts
import router from '@adonisjs/core/services/router'
import server from '@adonisjs/core/services/server'

server.use([
  () => import('#middleware/log_requests_middleware'), 
  () => import('#middleware/container_bindings_middleware'),
  () => import('#middleware/force_json_response_middleware'),
])

router.use([
  () => import('@adonisjs/core/bodyparser_middleware'),
])

带参数的命名中间件 ​

命名中间件通过允许你选择性地将它们应用到特定路由并传递参数以自定义其行为，提供了灵活性。让我们构建一个检查用户权限的授权中间件，用名称注册它，并将其应用到受保护的路由。

步骤 1：创建授权中间件 ​

我们将创建一个中间件，检查已认证用户是否具有访问路由所需的角色或权限。命名中间件可以接受第三个参数用于选项，使其可按路由配置。

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'

type AuthorizationOptions =
  | { permissions: string[] }
  | { role: string }

export default class AuthorizeRequestMiddleware {
  /**
   * 第三个参数 'options' 包含将此外中间件
   * 应用到路由时指定的授权要求。
   */
  async handle({ auth, response }: HttpContext, next: NextFn, options: AuthorizationOptions) {
    /**
     * 获取已认证用户或抛出异常
     */
    const user = auth.getUserOrFail()

    /**
     * 检查用户是否具有所需角色
     */
    if ('role' in options && user.role !== options.role) {
      return response.unauthorized('Not authorized to access this route')
    }

    /**
     * 检查用户是否具有所有所需权限
     */
    if ('permissions' in options) {
      const hasPermission = options.permissions.every(permission =>
        user.permissions.includes(permission)
      )

      if (!hasPermission) {
        return response.unauthorized('Not authorized to access this route')
      }
    }

    /**
     * 用户已授权，继续到下一个中间件或处理器
     */
    await next()
  }
}

步骤 2：注册命名中间件 ​

现在让我们在 start/kernel.ts 文件中以名称 authorize 注册我们的授权中间件。导出中间件集合可以在路由中使用时获得完整的 TypeScript 类型安全。

ts
import router from '@adonisjs/core/services/router'

export const middleware = router.named({
  authorize: () => import('#middleware/authorize_request_middleware'),
})

步骤 3：将中间件应用到路由 ​

最后，让我们将 authorize 中间件应用到特定路由。从 start/kernel.ts 导入中间件集合，以获得 options 参数的完整 TypeScript 自动补全和类型检查。

ts
import router from '@adonisjs/core/services/router'
import { middleware } from '#start/kernel'

router
  .get('/admin/reports', async () => {
    return { message: 'Admin reports' }
  })
  .use(middleware.authorize({ role: 'admin' }))

router
  .post('/posts', async () => {
    return { message: 'Post created' }
  })
  .use(middleware.authorize({ permissions: ['posts.create'] }))

你的授权中间件现在正在用类型安全的、可配置的权限检查保护路由！

中间件中的依赖注入 ​

中间件类使用 IoC 容器实例化，允许你将依赖直接注入到中间件构造函数中。依赖只能通过构造函数注入，不能作为方法参数注入。容器在创建中间件实例时会自动解析并注入你的依赖。

另请参阅：依赖注入指南

ts
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'
import RateLimitService from '#services/rate_limit_service'

@inject() 
export default class RateLimitMiddleware {
  /**
   * IoC 容器自动创建 RateLimitService 实例
   * 并在这里注入它。
   */
  constructor(protected rateLimitService: RateLimitService) {
  }

  async handle({ request, response }: HttpContext, next: NextFn) {
    const ip = request.ip()
    const isAllowed = await this.rateLimitService.checkLimit(ip)

    if (!isAllowed) {
      return response.tooManyRequests('Rate limit exceeded')
    }

    await next()
  }
}

理解中间件执行流程 ​

中间件在两个阶段执行：下行阶段和上行阶段。理解此流程对于知道在中间件中放置逻辑的位置至关重要。

下行阶段发生在 await next() 调用之前。在此阶段，请求按顺序穿过每个中间件。

sh
下行（请求 →）

  服务器中间件
        │
        ▼
  路由器中间件
        │
        ▼
  命名中间件
        │
        ▼
   路由处理器

上行阶段发生在 await next() 调用之后。在此阶段，响应按相反顺序穿过中间件返回。

sh
上行（响应 ←）

  服务器中间件
        ▲
        │
  路由器中间件
        ▲
        │
  命名中间件
        ▲
        │
   路由处理器

这种两阶段执行允许中间件在路由处理器运行之前和之后执行逻辑。日志记录中间件示例通过在下行阶段捕获开始时间并在上行阶段计算持续时间来演示此模式。

修改响应 ​

中间件可以在下行阶段和上行阶段修改响应。由于响应对象是可变的，你在中间件中所做的更改将影响发送给客户端的最终响应。

在上行阶段添加头 ​

一个常见的模式是在路由处理器完成后向响应添加头。将头逻辑放在 await next() 之后，确保处理器已完全构建响应，然后你再修改它。

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'

export default class AddHeadersMiddleware {
  async handle({ response }: HttpContext, next: NextFn) {
    /**
     * 等待处理器构建响应
     */
    await next()

    /**
     * 在响应就绪后添加自定义头
     */
    response.header('X-Powered-By', 'AdonisJS')
    response.header('X-Response-Time', Date.now().toString())
  }
}

转换响应体 ​

你也可以通过在上行阶段访问和修改响应体，在中间件中转换响应体。此中间件将所有响应体包装在带元数据的一致格式中。

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'

export default class WrapResponseMiddleware {
  async handle({ response }: HttpContext, next: NextFn) {
    /**
     * 等待处理器生成响应
     */
    await next()

    /**
     * 将原始响应包装在标准信封中
     */
    const body = response.getBody()

    response.send({
      success: true,
      data: body,
      timestamp: new Date().toISOString()
    })
  }
}

异常处理 ​

当中间件抛出异常时，AdonisJS 的全局异常处理器会像处理路由处理器抛出的异常一样捕获并处理它。上行流程照常继续，这意味着已在下行阶段执行的任何中间件仍将执行其上行代码。

另请参阅：异常处理指南

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'
import { errors } from '@adonisjs/core'

export default class ValidateApiKeyMiddleware {
  async handle({ request }: HttpContext, next: NextFn) {
    const apiKey = request.header('X-API-Key')

    if (!apiKey) {
      /**
       * 抛出异常会终止请求。
       * 全局异常处理器将捕获并处理它。
       */
      throw new errors.E_UNAUTHORIZED_ACCESS('API key is required')
    }

    await next()
  }
}

条件中间件执行 ​

AdonisJS 不提供在运行时条件性注册或应用中间件的方式。但是，中间件可以使用配置文件在运行时决定是否应为当前请求执行。这种模式让你可以通过环境变量或配置文件控制中间件行为，而无需更改中间件注册。

ts
export default {
  enableRateLimit: env.get('ENABLE_RATE_LIMIT', true),
}
ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'
import featuresConfig from '#config/features'

export default class RateLimitMiddleware {
  async handle(ctx: HttpContext, next: NextFn) {
    /**
     * 如果在配置中禁用，则跳过速率限制。
     * 立即调用 next() 使此中间件成为空操作。
     */
    if (!featuresConfig.enableRateLimit) {
      return next()
    }

    /**
     * 启用时应用速率限制逻辑
     */
    // ... 速率限制检查

    await next()
  }
}

扩展 HttpContext ​

中间件可以向 HttpContext 对象添加自定义属性，以与下游中间件和路由处理器共享数据。但是，这需要 TypeScript 模块扩充以确保属性在类型级别出现。

向上下文添加属性 ​

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { NextFn } from '@adonisjs/core/types/http'

export default class DetectTenantMiddleware {
  async #detectTenant(ctx: HttpContext) {
    // ... 租户检测逻辑
    return { id: 1, name: 'Acme Corp' }
  }

  async handle(ctx: HttpContext, next: NextFn) {
    /**
     * 从子域名、头或数据库检测租户
     */
    const tenant = await this.#detectTenant(ctx)

    /**
     * 将租户添加到上下文，供下游中间件
     * 和路由处理器使用
     */
    ctx.tenant = tenant

    await next()
  }
}

扩充 HttpContext 类型 ​

要让 TypeScript 知道新的 tenant 属性，你必须扩充 HttpContext 接口。扩充后，TypeScript 将在你所有的中间件和路由处理器中识别 ctx.tenant。

WARNING

当你扩充 HttpContext 接口时，类型更改是全局的。但是，如果你通过仅在特定路由上运行的命名中间件添加属性，这些属性在中间件不执行的路由上运行时将不存在。

只在广泛运行于应用中的服务器或路由器中间件中扩充 HttpContext。

ts
declare module '@adonisjs/core/http' {
  interface HttpContext {
    tenant: {
      id: number
      name: string
    }
  }
}
