URL 构建器 ​

本指南涵盖 AdonisJS 应用中的 URL 生成。你将了解到如何：

  • 为命名路由生成 URL，并具有类型安全的自动补全
  • 使用数组或对象传递路由参数
  • 向生成的 URL 添加查询字符串
  • 创建带加密签名以确保链接安全的签名 URL
  • 验证签名 URL 以防止篡改
  • 使用 Inertia 将 URL 生成集成到前端应用中

概述 ​

URL 构建器提供了一个类型安全的 API，用于从命名路由生成 URL。与其在模板、前端组件、API 响应或重定向中硬编码 URL，不如通过名称引用路由。这确保当你更改路由路径时，不需要在代码库中查找并更新每个 URL 引用。

一旦路由被命名，你可以使用模板中的 urlFor 辅助函数、用于重定向的 response.redirect().toRoute() 方法，或从 URL 构建器服务导入 urlFor 函数用于其他上下文来为其生成 URL。

URL 构建器是类型安全的，这意味着你的 IDE 将为路由名称提供自动补全，并且如果你引用不存在的路由，TypeScript 会捕获错误。这消除了一整类 bug，即重构路由后 URL 可能静默失效。

定义命名路由 ​

每个使用控制器的路由都会根据控制器和方法名称自动分配一个名称。命名约定遵循 controller.method 模式（在路由指南中有详细说明）。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

// 自动命名为 'posts.show'
router.get('/posts/:id', [controllers.posts, 'show'])

// 自动命名为 'posts.index'
router.get('/posts', [controllers.posts, 'index'])

对于不使用控制器的路由，你必须使用 .as() 方法显式分配名称。

ts
router.get('/about', async () => {
  return 'About page'
}).as('about')

你可以使用以下 Ace 命令查看应用中的所有命名路由。

bash
node ace list:routes

在模板中生成 URL ​

Edge 模板默认可以访问 urlFor 辅助函数。此辅助函数为命名路由生成 URL，并接受数组或对象形式的路由参数。

edge
<a href="{{ urlFor('posts.show', { id: post.id }) }}">
  View post
</a>

使用超媒体启动套件时，你也可以使用 @link 组件，它接受路由和参数作为组件 props。

edge
@link({ route: 'posts.show', routeParams: { id: post.id } })
  View post
@end

在重定向期间生成 URL ​

当将用户重定向到不同页面时，使用 response.redirect().toRoute() 方法而不是硬编码 URL。你只能重定向到 GET 路由。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'

export default class PostsController {
  async store({ request, response }: HttpContext) {
    const post = await Post.create(request.all())

    return response
      .redirect()
      .toRoute('posts.show', { id: post.id })
  }
}

在其他上下文中生成 URL ​

对于模板和 HTTP 响应之外的上下文，如后台任务、电子邮件通知或服务类，从 URL 构建器服务导入 urlFor 函数。

ts
import { urlFor } from '@adonisjs/core/services/url_builder'

export default class NotificationService {
  async sendPostNotification(post: Post) {
    const postUrl = urlFor('posts.show', { id: post.id })

    await mail.send({
      subject: 'New post published',
      html: `<a href="${postUrl}">View post</a>`
    })
  }
}

传递路由参数 ​

路由参数可以以数组（位置匹配）或对象（名称匹配）形式传递。选择使你的代码更可读的方式。

数组（位置参数）： 参数按位置与路由模式匹配。

ts
// 路由：/posts/:id
urlFor('posts.show', [1])
// 输出：/posts/1

// 路由：/users/:userId/posts/:postId
urlFor('users.posts.show', [5, 10])
// 输出：/users/5/posts/10

对象（命名参数）： 参数按名称与路由模式匹配。

ts
// 路由：/posts/:id
urlFor('posts.show', { id: 1 })
// 输出：/posts/1

// 路由：/users/:userId/posts/:postId
urlFor('users.posts.show', { userId: 5, postId: 10 })
// 输出：/users/5/posts/10

添加查询字符串 ​

通过传递带有 qs 属性的第三个选项参数，可以向生成的 URL 添加查询字符串。查询字符串对象可以包含嵌套值，这些值会自动序列化为适当的格式。

ts
import { urlFor } from '@adonisjs/core/services/url_builder'

const url = urlFor('posts.index', [], {
  qs: {
    filters: {
      title: 'typescript',
    },
    order: {
      direction: 'asc',
      column: 'id'
    },
  }
})

// 输出：/posts?filters[title]=typescript&order[direction]=asc&order[column]=id

同样的 qs 选项在模板和重定向中也有效。

edge
<a href="{{ urlFor('posts.index', [], { qs: { page: 2, sort: 'title' } }) }}">
  Next page
</a>
ts
response.redirect().toRoute('posts.index', [], {
  qs: { page: 2, sort: 'title' }
})

签名 URL ​

签名 URL 包含加密签名以防止篡改。如果有人修改 URL，签名将失效，请求可以被拒绝。这对于 URL 可公开访问但需要防止操纵的场景很有用，如新闻通讯退订链接或密码重置令牌。

创建签名 URL ​

签名 URL 使用从 URL 构建器服务导出的 signedUrlFor 辅助函数创建。API 与 urlFor 相同，但生成的 URL 包含签名。

ts
import User from '#models/user'
import { appUrl } from '#config/app'
import { BaseMail } from '@adonisjs/mail'
import { signedUrlFor } from '@adonisjs/core/services/url_builder'

export default class NewsletterMail extends BaseMail {
  subject = 'Weekly Newsletter'

  constructor(protected user: User) {
    super()
  }

  prepare() {
    const unsubscribeUrl = signedUrlFor(
      'newsletter.unsubscribe',
      { email: this.user.email },
      {
        expiresIn: '30 days',
        prefixUrl: appUrl,
      }
    )

    this.message.htmlView('emails/newsletter', {
      user: this.user,
      unsubscribeUrl
    })
  }
}

expiresIn 选项设置签名 URL 的过期时间。过期后，签名不再有效。当 URL 将在外部共享时（如在电子邮件或外部通知中），需要 prefixUrl 选项以确保 URL 包含完整域名。对于内部应用导航，不带域名的相对 URL 就足够了。

从路由模式创建签名 URL ​

默认情况下，signedUrlFor 按名称查找路由并使用路由定义构建 URL。当你需要从路由器中未注册的路由模式签名 URL 时，可以禁用查找。

ts
import { signedUrlFor } from '@adonisjs/core/services/url_builder'

const url = signedUrlFor(
  '/files/:key',
  { key: 'invoice.pdf' },
  {
    disableRouteLookup: true,
    prefixUrl: 'https://example.com',
    qs: {
      download: true,
    },
  }
)

启用 disableRouteLookup 时，第一个参数被解析为路由模式并直接签名。常规的 signedUrlFor 调用继续使用路由查找并保持其路由名称类型安全。

生成的签名 URL 包含追加到 URL 的签名查询参数。

text
https://example.com/newsletter/unsubscribe?email=user@example.com&signature=eyJtZXNzYWdlIjoiL25ld3NsZXR0ZXIvdW5zdWJzY3JpYmU_ZW1haWw9dXNlckBleGFtcGxlLmNvbSIsInB1cnBvc2UiOiJzaWduZWRfdXJsIn0.1234567890abcdef

TIP

签名 URL 只能在后端代码中创建，不能在前端应用中创建。这是因为它们依赖使用密钥的加密模块。将此密钥暴露给前端会危及安全。

验证签名 URL ​

生成签名 URL 的路由可以在 HTTP 请求期间使用 request.hasValidSignature() 方法验证签名。此方法同时检查签名和过期时间。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class NewsletterController {
  async unsubscribe({ request, response }: HttpContext) {
    if (!request.hasValidSignature()) {
      return response.badRequest('Invalid or expired unsubscribe link')
    }

    const email = request.qs().email
    // 处理退订请求
  }
}

前端集成 ​

URL 构建器服务仅在后端应用中可用，因为那是定义路由的地方。但是，使用 Inertia 或单体仓库中独立前端的应用可以为前端代码库生成类似的 URL 构建器。

为什么要分离前后端 URL 构建器？ ​

AdonisJS 在前端和后端代码库之间强制执行清晰的边界，以防止向客户端泄露敏感信息等问题。后端路由包含控制器映射和内部应用结构的详细信息。在 Frontend 上提供所有这些信息不仅会泄露不必要的信息，还会显著增加你的包大小。

此外，从运行时角度来看，你不能在两个不同的运行时（Node.js 和浏览器）之间共享对象。我们不支持也不相信创建共享 URL 构建器的幻象。

在 Inertia 应用中使用 URL 构建器 ​

Inertia React 和 Vue 启动套件已预配置 URL 构建器。URL 构建器（以及 API 客户端）使用 Tuyau 生成并写入 .adonisjs/client 目录。

在前端组件中导入并使用 URL 构建器，其 API 与后端版本完全相同。

tsx
import { urlFor } from '~/client'

export default function PostsIndex({ posts }) {
  return (
    <div>
      {posts.map(post => (
        <a key={post.id} href={urlFor('posts.show', { id: post.id })}>
          {post.title}
        </a>
      ))}
    </div>
  )
}

使用 API 与后端 URL 构建器服务完全相同，支持数组和对象参数，以及查询字符串。

ts
// 使用位置参数
urlFor('posts.show', [post.id])

// 使用命名参数
urlFor('posts.show', { id: post.id })

// 添加查询字符串
urlFor('posts.index', [], {
  qs: { page: 2, sort: 'title' }
})

从前端包中排除路由 ​

你可以配置前端 URL 构建器中可用的路由，以减少包大小并防止暴露内部路由。URL 构建器使用在 adonisrc.ts 文件中注册的名为 generateRegistry 的 Assembler 钩子生成。

使用 exclude 选项定义要排除的路由。

ts
import { defineConfig } from '@adonisjs/core/app'
import { generateRegistry } from '@adonisjs/assembler/hooks'

export default defineConfig({
  init: [
    generateRegistry({
      exclude: ['admin.*'],
    })
  ],
})

排除模式可以使用以下方法之一，针对路由名称进行测试：

通配符模式

排除所有以通配符前的前缀开头的路由。

ts
generateRegistry({
  exclude: ['admin.*', 'api.internal.*'],
})

正则表达式

使用自定义正则表达式排除匹配的路由。

ts
generateRegistry({
  exclude: [/^admin\./, /^api\.internal\./],
})

自定义函数

编写自定义函数以实现高级过滤逻辑。返回 false 跳过路由，返回 true 包含它。

ts
generateRegistry({
  exclude: [
    (route) => {
      // 排除 admin 域上的所有路由
      if (route.domain === 'admin.myapp.com') {
        return false
      }
      // 包含所有其他路由
      return true
    }
  ],
})

你可以组合多种模式以满足复杂的过滤需求。

ts
generateRegistry({
  exclude: [
    'admin.*',
    /^api\.internal\./,
    (route) => route.domain !== 'admin.myapp.com'
  ],
})
