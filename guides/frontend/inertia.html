Inertia ​

本指南涵盖使用 Inertia 配合 AdonisJS 构建单页应用。你将了解到如何：

  • 配置 Inertia 并使用端到端类型安全的 props 渲染页面
  • 在页面之间导航、提交表单以及发起非 Inertia HTTP 请求
  • 共享数据、显示闪存消息以及处理验证错误
  • 使用延迟、可合并、一次性以及无限滚动 props 加载数据
  • 配置重定向、浏览器历史和服务器端渲染

概述 ​

Inertia 充当桥梁，连接 AdonisJS 与 React、Vue 等前端框架。它通过拥抱服务器优先架构，消除了对客户端路由或复杂状态管理库的需求。

你像在传统服务端渲染应用中一样编写控制器和路由，但不是返回 HTML 或 JSON，而是渲染 Inertia 页面，由前端框架显示。

这种方法让你两全其美。服务端路由和数据获取的简洁性，结合 React 或 Vue 为视图层带来的丰富交互性。AdonisJS 通过 Inertia 启动套件官方支持这两个框架。

基本示例 ​

让我们从头到尾走一遍渲染帖子列表的流程。该流程包含四个部分：一个路由、一个转换器、一个调用 inertia.render() 的控制器，以及 inertia/pages/ 内的一个页面组件。

步骤 1：注册路由 ​

路由看起来与任何其他 AdonisJS 路由完全相同。Inertia 没有特殊的路由层。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('/posts', [controllers.Posts, 'index'])

步骤 2：创建转换器 ​

转换器定义发送到前端的数据并生成其 TypeScript 类型。使用以下命令为 Post 模型创建一个转换器。

sh
node ace make:transformer post

在 toObject 方法内定义你想从每个帖子中暴露的字段。

ts
import type Post from '#models/post'
import { BaseTransformer } from '@adonisjs/core/transformers'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return this.pick(this.resource, ['id', 'title'])
  }
}

步骤 3：从控制器渲染页面 ​

HTTP 上下文暴露一个 inertia 对象。使用上一步中的字段转换帖子，并将结果连同页面组件路径一起传递给 inertia.render()。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ inertia }: HttpContext) {
    const posts = await Post.all()

    return inertia.render('posts/index', {
      posts: PostTransformer.transform(posts),
    })
  }
}

步骤 4：创建页面组件 ​

字符串 'posts/index' 解析为 inertia/pages/posts/index.tsx（或 .vue）。使用 node ace make:page posts/index 搭建文件。组件直接接收来自 inertia.render() 的 props。

tsx
import type { InertiaProps } from '~/types'
import type { Data } from '@generated/data'

type PageProps = InertiaProps<{ posts: Data.Post[] }>

export default function PostsIndex({ posts }: PageProps) {
  return (
    <>
      {posts.map((post) => (
        <div key={post.id}>
          <h2>{post.title}</h2>
        </div>
      ))}
    </>
  )
}
vue
<script setup lang="ts">
import type { Data } from '@generated/data'

defineProps<{ posts: Data.Post[] }>()
</script>

<template>
  <div v-for="post in posts" :key="post.id">
    <h2>{{ post.title }}</h2>
  </div>
</template>

InertiaProps 辅助函数将你的页面特定 props 与共享数据合并，因此像 user 这样的全局 props 会与 posts 一起被类型化。

从路由渲染 ​

对于没有控制器逻辑的页面，跳过控制器并使用 renderInertia() 直接从路由定义渲染。

ts
router.on('/about').renderInertia('about')

router.on('/pricing').renderInertia('marketing/pricing', {
  plans: ['starter', 'pro', 'enterprise'],
})

组件名称会针对生成的 InertiaPages 接口进行类型检查，因此拼写错误会在编译时被捕获。

幕后发生了什么 ​

在对 /posts 的首次请求中，Inertia 返回一个 HTML 外壳，其中包含 <script type="application/json"> 标签内的页面对象（组件名称和序列化的 props），以及一个空的 <div id="app"> 挂载元素。前端包读取 JSON 负载并将 React 或 Vue 启动到挂载元素中。

对于后续的每次导航（链接点击、表单提交），Inertia 发起一个带有 X-Inertia 头的 fetch 请求。服务器运行相同的控制器，但返回 JSON 页面对象而不是 HTML。客户端换入新组件并更新 URL。没有完整页面重载，没有单独的 API。

inertia 目录 ​

inertia/ 目录包含你的前端应用。以下是启动套件创建的结构：

sh
inertia/
├── app.tsx (或 app.vue)     # 前端应用入口
├── client.ts                # Tuyau API 客户端设置
├── ssr.tsx (或 ssr.vue)     # SSR 入口（启用时）
├── tsconfig.json            # 前端代码的 TypeScript 配置
├── types.ts                 # 共享类型定义
├── css/
│   └── app.css              # 全局样式
├── layouts/                 # 可重用布局组件
│   └── default.tsx
└── pages/                   # 由控制器渲染的页面组件
    └── home.tsx

pages/ 目录是 Inertia 在调用 inertia.render() 时查找组件的位置。你传递的路径（如 posts/index）直接映射到此目录中的文件（inertia/pages/posts/index.tsx）。

app.tsx（或 app.vue）文件是启动前端应用的入口。它使用你的页面组件和任何全局配置初始化 Inertia。ssr.tsx 文件为服务器端渲染提供相同的目的。

随着项目增长，你可以创建额外的目录，如用于共享 UI 元素的 components/ 或用于自定义 React 钩子的 hooks/。

配置文件 ​

两个配置文件控制 Inertia 在你的 AdonisJS 应用中的工作方式。

config/inertia.ts 文件定义 Inertia 适配器设置。

ts
import { defineConfig } from '@adonisjs/inertia'

const inertiaConfig = defineConfig({
  rootView: 'inertia_layout',

  ssr: {
    enabled: false,
    entrypoint: 'inertia/ssr.tsx',
  },
})

export default inertiaConfig

支持的选项包括：

rootView

类型：string | (ctx) => string

渲染初始 HTML 外壳的 Edge 模板。默认为 inertia_layout。传递函数可以为每个请求选择不同的模板，例如为未认证用户渲染营销布局。

ts
rootView: (ctx) => ctx.auth.isAuthenticated ? 'app_layout' : 'marketing_layout'

encryptHistory

类型：boolean

加密存储在浏览器历史状态中的敏感页面 props。默认为 false。参阅 Inertia 文档中的历史加密。

assetsVersion

类型：string | number

固定用于资源版本管理的资源版本字符串。省略时，版本从 Vite manifest 计算。设置此项可以用 git 提交哈希、构建时间戳或任何自定义标识符覆盖默认值。

ssr.enabled

类型：boolean

启用服务器端渲染。参阅服务器端渲染。

ssr.entrypoint

类型：string

SSR 入口文件相对于项目根目录的路径。默认为 inertia/ssr.tsx。

ssr.pages

类型：string[] | (ctx, page) => boolean

将 SSR 限制为页面子集。传递组件名称数组，或为每个页面返回布尔值的函数。

ts
ssr: {
  enabled: true,
  entrypoint: 'inertia/ssr.tsx',
  pages: ['home', 'marketing/pricing'],
}

resources/views/inertia_layout.edge 模板渲染包含前端应用挂载的根 div 的初始 HTML 外壳。可用 Edge 标签请参阅根模板。

根模板 ​

在 rootView 下配置的 Edge 模板为首次请求渲染。它包含前端应用挂载的根元素以及 SSR 输出需要插入的任何 HTML。

Inertia 包为此模板注册了两个 Edge 标签。

edge
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  @inertiaHead()
  @vite(['inertia/app.tsx'])
</head>
<body>
  @inertia()
</body>
</html>

@inertia 标签渲染两个元素：一个保存编码页面对象的 <script type="application/json"> 标签，以及前端应用挂载的元素。前端读取 JSON 负载以启动 SPA。默认情况下，挂载元素是 <div id="app">。传递对象以覆盖标签、id 或 class。

edge
@inertia({ as: 'main', id: 'app-root', class: 'min-h-screen' })

@inertiaHead 标签输出服务器端渲染期间收集的 head 片段（标题、meta 标签）。只要启用 SSR 就包含它。对于非 SSR 响应，它是空操作。

向模板传递数据 ​

inertia.render() 的第三个参数作为视图 props 转发给根模板。用于应属于 HTML 外壳而不是页面 props 的值，如页面标题或非 SSR 页面的 <meta> 标签。

ts
return inertia.render(
  'posts/show',
  { post: PostTransformer.transform(post) },
  { title: post.title, description: post.summary }
)
edge
<head>
  <title>{{ title ?? 'My App' }}</title>
  @if(description)
    <meta name="description" content="{{ description }}">
  @end
  @inertiaHead()
</head>

生成的类型 ​

配置类型生成后，AdonisJS 将对以下内容进行类型检查：

  • 在控制器和页面组件之间传递的转换器数据。参阅转换器。
  • 传递给 inertia.render() 的页面名称和 props。
  • Link、Form 和 useRouter 使用的路由名称、参数、查询字符串、HTTP 方法和请求体。

Inertia 启动套件已为你配置类型生成。如果你要将 Inertia 添加到现有应用，请在 adonisrc.ts 中注册以下钩子。将 framework 设置为 'react' 或 'vue3'，仅当你的页面位于 inertia/pages 之外时才使用 source。

ts
import { indexPages } from '@adonisjs/inertia'
import { indexEntities } from '@adonisjs/core'
import { defineConfig } from '@adonisjs/core/app'
import { generateRegistry } from '@tuyau/core/hooks'

export default defineConfig({
  hooks: {
    init: [
      indexEntities({
        transformers: { enabled: true, withSharedProps: true },
      }),
      indexPages({ framework: 'react' }),
      generateRegistry(),
    ],
  },
})

类型化共享数据 ​

从 Inertia 中间件返回的共享数据通过 InertiaProps 辅助函数在每个页面上可用。在中间件文件底部添加以下扩充，以从 share() 方法推断这些类型。启动套件默认包含此设置。

ts
import type { HttpContext } from '@adonisjs/core/http'
import type { InferSharedProps } from '@adonisjs/inertia/types'
import BaseInertiaMiddleware from '@adonisjs/inertia/inertia_middleware'

export default class InertiaMiddleware extends BaseInertiaMiddleware {
  share(ctx: HttpContext) {
    return {
      user: ctx.auth?.user,
    }
  }
}

declare module '@adonisjs/inertia/types' {
  type MiddlewareSharedProps = InferSharedProps<InertiaMiddleware>
  export interface SharedProps extends MiddlewareSharedProps {}
}

向 inertia/types.ts 添加以下扩充，以便 usePage().props 和布局回调也能接收共享数据类型。启动套件默认包含此设置。

ts
import type { Data } from '@generated/data'

declare module '@inertiajs/core' {
  interface InertiaConfig {
    sharedPageProps: Data.SharedProps
  }
}

数据加载模式 ​

Inertia 提供多种高效加载数据的模式。AdonisJS 在 inertia 对象上暴露辅助函数以支持每种模式。Props 可以解析为任何可序列化的值，包括 null。

TIP

Prop 辅助函数仅在 props 对象的顶层被检测。嵌套在普通对象内的辅助函数，如 stats: { views: inertia.defer(...) }，不会被解析。为每个包装的值分配自己的顶层键。

可选 props ​

可选 props 仅在前端在部分重载期间显式请求它们时才求值。这对于每次页面加载都不需要的昂贵查询很有用。

ts
return inertia.render('users/index', {
  /**
   * 数据库查询仅在前端在部分重载请求中
   * 包含 'users' 时运行。
   */
  users: inertia.optional(async () => {
    const users = await User.all()
    return UserTransformer.transform(users)
  })
})

另请参阅：Inertia 文档中的部分重载。

Always props ​

always 辅助函数确保 prop 始终包含在响应中，即使在未显式请求它的部分重载期间也是如此。这与可选 props 相反。

ts
return inertia.render('users/index', {
  /**
   * 权限始终被计算并包含，
   * 无论前端请求什么。
   */
  permissions: inertia.always(async () => {
    const permissions = await Permissions.all()
    return PermissionTransformer.transform(permissions)
  })
})

延迟 props ​

延迟 props 在初始页面渲染后加载，允许页面立即显示，而较慢的数据在后台加载。前端在延迟数据到达之前显示加载状态。

ts
return inertia.render('dashboard', {
  /**
   * 这些 props 在页面渲染后加载。
   * 前端可以显示加载指示器。
   */
  metrics: inertia.defer(async () => {
    return computeMetrics()
  }),
  newSignups: inertia.defer(async () => {
    return getNewSignups()
  })
})

你可以对延迟 props 进行分组，使它们在同一请求中一起加载。

ts
return inertia.render('dashboard', {
  /**
   * 两个 props 在同一个延迟请求中获取，
   * 因为它们共享 'dashboard' 组名。
   */
  metrics: inertia.defer(async () => {
    return computeMetrics()
  }, 'dashboard'),
  newSignups: inertia.defer(async () => {
    return getNewSignups()
  }, 'dashboard')
})

另请参阅：Inertia 文档中的延迟 props。

拯救失败的延迟 props ​

当延迟 prop 可能因数据库中断或上游 API 超时而失败时，传递 rescue: true。AdonisJS 将省略失败的 prop，允许前端渲染回退内容而不是保持加载状态。

ts
return inertia.render('dashboard', {
  /**
   * 如果分析服务宕机，该 prop 被省略，
   * 前端渲染其拯救回退内容。
   */
  analytics: inertia.defer(() => fetchAnalytics(), { rescue: true }),
})

defer() 的第二个参数接受组名字符串或带有 group 和 rescue 键的选项对象，因此分组和拯救可以自由组合。

在前端，Deferred 组件为服务器拯救的任何 prop 渲染其 rescue 内容。

tsx
import { Deferred } from '@inertiajs/react'
import { InertiaProps } from '~/types'

type PageProps = InertiaProps<{
  analytics?: { pageViews: number }
}>

export default function Dashboard({ analytics }: PageProps) {
  return (
    <Deferred
      data="analytics"
      fallback={<p>Loading analytics...</p>}
      rescue={<p>Analytics are temporarily unavailable.</p>}
    >
      <p>{analytics?.pageViews} page views</p>
    </Deferred>
  )
}
vue
<script setup lang="ts">
import { Deferred } from '@inertiajs/vue3'

defineProps<{
  analytics?: { pageViews: number }
}>()
</script>

<template>
  <Deferred data="analytics">
    <template #fallback>
      <p>Loading analytics...</p>
    </template>

    <template #rescue>
      <p>Analytics are temporarily unavailable.</p>
    </template>

    <p>{{ analytics?.pageViews }} page views</p>
  </Deferred>
</template>

拯救的错误永远不会到达响应，但它们不是静默的。默认情况下，每个错误通过请求日志记录器记录。在预加载文件中使用 Inertia.onRescue() 注册监听器，将拯救的错误路由到你的监控服务。

ts
import * as Sentry from '@sentry/node'
import { Inertia } from '@adonisjs/inertia'

Inertia.onRescue((error, { prop }) => {
  Sentry.captureException(error, { extra: { prop } })
})

可合并 props ​

可合并 props 与现有前端数据合并而不是替换它。这对于无限滚动或向列表追加新项很有用。

ts
return inertia.render('users/index', {
  /**
   * 新通知与现有通知合并，
   * 而不是替换整个数组。
   */
  notifications: inertia.merge(await fetchNotifications())
})

默认情况下，数据是浅合并的。对于需要递归合并的嵌套对象，使用 deepMerge() 代替。

ts
return inertia.render('users/index', {
  /**
   * 嵌套设置与现有设置深度合并，
   * 而不是替换整个对象。
   */
  settings: inertia.deepMerge(await fetchSettings())
})

你可以通过链式调用 merge() 或 deepMerge() 方法将合并与延迟加载结合。

ts
return inertia.render('users/index', {
  notifications: inertia.defer(() => {
    return fetchNotifications()
  }).merge()
})
ts
return inertia.render('users/index', {
  settings: inertia.defer(() => {
    return fetchSettings()
  }).deepMerge()
})

合并的数组默认追加到现有数据。当新项应位于前面时（如最新条目首先出现的 feed），链式调用 prepend()。方向仅适用于浅合并，因为 deepMerge() 没有顺序概念。append() 方法用于显式声明默认值。

ts
return inertia.render('feed', {
  /**
   * 新帖子被添加到前端现有列表的前面。
   */
  posts: inertia.merge(await fetchLatestPosts()).prepend(),
})

当连续响应可能包含相同记录时（一个项在页面之间移动，或 feed 在分页时发生偏移），链式调用 matchOn() 按键合并。传入的项替换具有相同键值的现有项，而不是作为重复项追加。

ts
return inertia.render('notifications', {
  /**
   * id 已存在于前端的通知
   * 替换旧条目而不是复制它。
   */
  notifications: inertia.merge(await fetchNotifications()).matchOn('id'),
})

TIP

当前端显式重置某个 prop 时（部分重载的 reset 选项），服务器将该 prop 作为普通替换发送，客户端丢弃先前合并的数据。你不需要在服务器上处理重置。

另请参阅：Inertia 文档中的合并 props。

一次性 props ​

一次性 props 在首次访问时计算，并在后续访问中重用。用于计算成本高且很少更改的数据，如查找表、国家列表或计划目录。

ts
return inertia.render('products/index', {
  /**
   * 在首次访问时计算。在客户端仍持有缓存值的
   * 后续访问中跳过。
   */
  categories: inertia.once(async () => {
    const categories = await Category.all()
    return CategoryTransformer.transform(categories)
  }),
})

缓存值默认永不过期。传递选项作为第二个参数以控制过期时间和缓存标识：

key

类型：string

客户端用于识别值的缓存键。默认为 prop 名称。在不同页面上为相同数据使用相同的键，以便它们共享一个缓存值。

expiresIn

类型：number | string

相对生存时间：数字形式的毫秒数，或像 '30m' 或 '2h' 这样的持续时间字符串。过期后，客户端丢弃缓存值，服务器在下次访问时重新计算 prop。

expiresAt

类型：Date | number

作为 Date 或 epoch 毫秒的绝对过期时间。优先于 expiresIn。

fresh

类型：boolean

即使客户端持有缓存副本，也为此响应重新计算值。在底层数据更改后立即使用很有用，例如在变更后的响应中。

一次性行为也可以链接到其他辅助函数。在 optional、defer、merge 或 deepMerge 上调用 .once() 以将客户端缓存与其加载行为结合。

ts
return inertia.render('dashboard', {
  /**
   * 首次加载时延迟，然后由客户端缓存，
   * 以便后续访问完全跳过计算。
   */
  stats: inertia.defer(() => computeStats()).once({ expiresIn: '15m' }),
})

TIP

显式请求一次性 prop 的部分重载始终重新计算它。缓存只短路标准访问，因此 router.reload({ only: ['categories'] }) 仍然是前端强制刷新值的可靠方式。

Link 和 Form 组件 ​

Inertia 提供 Link 和 Form 组件用于导航和表单提交。AdonisJS 用额外功能包装这些组件，让你通过名称引用路由而不是硬编码 URL。

从 AdonisJS 包导入组件，而不是直接从 Inertia 导入。

tsx
import { Form, Link } from '@inertiajs/react'
import { Form, Link } from '@adonisjs/inertia/react'
vue
<script setup>
import { Form, Link } from '@inertiajs/vue3'
import { Form, Link } from '@adonisjs/inertia/vue'
</script>

创建链接 ​

Link 组件使用 AdonisJS 路由中定义的路由名称创建导航链接。

tsx
<Link route="accounts.create">Signup</Link>
<Link route="session.create">Login</Link>

创建表单 ​

Form 组件处理带有自动 CSRF 保护和错误处理的表单提交。

tsx
import { Form } from '@adonisjs/inertia/react'

  return (
    <Form route="posts.update" routeParams={{ id: post.id }}>
      {({ errors }) => (
        <>
          <div>
            <label htmlFor="title">Post title</label>
            <input type="text" name="title" id="title" defaultValue={post.title} />
            {errors.title && <div>{errors.title}</div>}
          </div>

          <button type="submit">Update post</button>
        </>
      )}
    </Form>
  )
}
vue
<script setup lang="ts">
import { Form } from '@adonisjs/inertia/vue'

defineProps<{ post: { id: number; title: string } }>()
</script>

    :params="{ id: post.id }"

  >

Form 组件自动从路由名称推断 HTTP 方法（POST、PUT、PATCH、DELETE）。你不需要传递 method prop。事实上，AdonisJS 包装器从接受的 props 中省略了 method 和 action，因为两者都从路由定义派生。

当服务器验证失败时，AdonisJS 自动将验证错误添加到会话闪存消息。Inertia 中间件随后与前端共享这些错误，使其通过表单中的 errors 对象可用。

乐观提交的服务器响应 ​

乐观提交不需要特殊的服务器响应。在控制器中处理变更并返回到包含更新 props 的页面的普通重定向。

ts
import LaunchTask from '#models/launch_task'
import type { HttpContext } from '@adonisjs/core/http'

export default class LaunchTasksController {
  async toggle({ params, response }: HttpContext) {
    const task = await LaunchTask.findOrFail(params.id)

    task.completed = !task.completed
    await task.save()

    return response.redirect().back()
  }
}

使用错误袋限定错误范围 ​

当页面渲染多个独立表单时，设置 errorBag prop 以保持它们的验证错误分开。传递给 Form 回调的 errors 值已经限定到该袋，因此你可以直接访问每个字段。

tsx
<Form route="comments.store" errorBag="newComment">
  {({ errors }) => (
    /**
     * errors.body 仅包含来自此表单的错误。
     */
    <textarea name="body" />
  )}
</Form>

显示每个字段的多个错误 ​

默认情况下，errors 对象中的每个字段将第一个验证消息保存为字符串。当一个字段可以同时违反多个规则时（密码同时有长度和复杂度要求），在中间件中向 getValidationErrors() 传递 allMessages: true 以收集所有消息。

ts
import type { HttpContext } from '@adonisjs/core/http'
import BaseInertiaMiddleware from '@adonisjs/inertia/inertia_middleware'

export default class InertiaMiddleware extends BaseInertiaMiddleware {
  share(ctx: HttpContext) {
    return {
      errors: ctx.inertia.always(
        this.getValidationErrors(ctx, { allMessages: true }) 
      ),
    }
  }
}

现在每个字段都是 string[]，包括只有单条消息的字段，因此整个响应的形状保持一致。用一行模块扩充告诉 Inertia 客户端新的形状：

ts
declare module '@inertiajs/core' {
  interface InertiaConfig {
    errorValueType: string[]
  }
}

路由参数 ​

Link 和 Form 都为具有动态段的路由接受路由参数。对象中的键对应路由中定义的参数名称：

ts
// 单个参数 (:id)
router.get('posts/:id', [PostsController, 'show']).as('posts.show')

// 多个参数 (:userId 和 :postId)
router.get('users/:userId/posts/:postId', [PostsController, 'show']).as('users.posts.show')

将匹配的参数值传递给组件。在 React 中，使用 routeParams。在 Vue 中，使用 params。

tsx
{/* 单个参数 */}
<Link route="posts.show" routeParams={{ id: post.id }}>
  {post.title}
</Link>

{/* 多个参数 */}
<Link route="users.posts.show" routeParams={{ userId: user.id, postId: post.id }}>
  View post
</Link>
vue
<template>
  <!-- 单个参数 -->
  <Link route="posts.show" :params="{ id: post.id }">
    {{ post.title }}
  </Link>

  <!-- 多个参数 -->
  <Link route="users.posts.show" :params="{ userId: user.id, postId: post.id }">
    View post
  </Link>
</template>

TypeScript 强制你提供所有必需的参数及正确的名称。缺少或拼写错误的参数会在编译时被捕获。

查询参数 ​

两个组件都通过路由模式中的 qs prop 接受查询参数，因此添加像 ?page=2 这样的参数会保持类型安全的 route prop。查询字符串会为你序列化到生成的 URL 中：

tsx
<Link route="posts.index" qs={{ page: 2, status: 'published' }}>
  Page 2
</Link>
vue
<template>
  <Link route="posts.index" :qs="{ page: 2, status: 'published' }">
    Page 2
  </Link>
</template>

当路由声明查询字符串类型时（从其验证器推断），TypeScript 会根据它们检查 qs 键和值类型。未声明查询类型的路由接受任何对象。

编程式导航 ​

使用 useRouter 钩子进行链接和表单之外的导航，如事件处理器、键盘快捷键或客户端工作完成后的重定向。返回的路由器携带与 Link 和 Form 组件相同的路由感知：URL 和 HTTP 方法从你的路由定义解析，编译器验证路由名称、参数和请求体。

tsx
import { useRouter } from '@adonisjs/inertia/react'

export default function PostsIndex() {
  const router = useRouter()

  function openPost(id: number) {
    router.visit({ route: 'posts.show', routeParams: { id } })
  }

  function archivePost(id: number) {
    router.patch({ route: 'posts.archive', routeParams: { id } }, { reason: 'outdated' })
  }

  // ...
}
vue
<script setup lang="ts">
import { useRouter } from '@adonisjs/inertia/vue'

const router = useRouter()

function openPost(id: number) {
  router.visit({ route: 'posts.show', routeParams: { id } })
}

function archivePost(id: number) {
  router.patch({ route: 'posts.archive', routeParams: { id } }, { reason: 'outdated' })
}
</script>

visit 方法从路由定义解析 HTTP 方法，你可以用 method prop 覆盖它。get、post、put、patch 和 delete 快捷方式固定方法：每个只接受为该动词注册的路由。传递给 post、put 和 patch 的请求体遵循路由声明的请求体类型，因此发送路由不接受的字段是编译时错误。

传递 href 而不是 route 以直接导航到 URL。Href 导航跳过路由验证并接受任何请求负载。

ts
router.visit({ href: '/logout' }, { method: 'post' })

非 Inertia HTTP 请求 ​

当你需要服务器数据而不替换当前页面、更改浏览器历史或更新页面 props 时，使用非 Inertia HTTP 请求。AdonisJS useHttp 包装器将请求绑定到命名路由并推断其请求体、响应和验证错误。

步骤 1：定义请求验证器 ​

为请求体创建一个 VineJS 验证器。生成的路由类型将使用此验证器来类型化传递给 useHttp 的数据。

ts
import vine from '@vinejs/vine'

export const postLookupValidator = vine.create({
  id: vine.number(),
})

步骤 2：注册命名路由 ​

给端点一个路由名称。前端将使用此名称而不是手动构造 URL 和 HTTP 方法。

ts
import { controllers } from '#generated/controllers'
import router from '@adonisjs/core/services/router'

router.post('/api/posts/lookup', [controllers.Posts, 'lookup']).as('posts.lookup')

步骤 3：返回序列化响应 ​

使用 HttpContext.serialize 验证请求并返回转换后的值。生成的路由响应类型将匹配浏览器在序列化后接收的值。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'
import { postLookupValidator } from '#validators/post_lookup'

export default class PostsController {
  async lookup({ request, serialize }: HttpContext) {
    const { id } = await request.validateUsing(postLookupValidator)
    const post = await Post.findOrFail(id)

    return serialize({
      post: PostTransformer.transform(post),
    })
  }
}

步骤 4：从 React 提交请求 ​

将路由名称和初始表单数据传递给 useHttp。submit 方法使用路由的 URL 和 HTTP 方法，而 data、errors 和 response 从验证器和控制器推断。

tsx
import { useHttp } from '@adonisjs/inertia/react'

export default function PostLookup() {
  const request = useHttp({ route: 'posts.lookup' }, { id: 1 })

  async function lookup() {
    await request.submit()
  }

  return (
    <div>
      <button type="button" onClick={lookup} disabled={request.processing}>
        {request.processing ? 'Loading post…' : 'Load post'}
      </button>

      {request.errors.id && <p>{request.errors.id}</p>}
      {request.response && <p>{request.response.post.title}</p>}
    </div>
  )
}

共享数据 ​

共享数据对你的应用中的每个页面可用，无需从每个控制器显式传递。这对于全局数据如已认证用户、验证错误或应用设置很有用。对于一次性通知，使用闪存消息代替。

在 app/middleware/inertia_middleware.ts 的 share() 方法中返回共享数据。

WARNING

在启动套件创建的中间件上添加或更新方法。添加共享数据或闪存数据时不要替换中间件类。保留现有的 share()、flash() 和 handle() 方法。

ts
import type { HttpContext } from '@adonisjs/core/http'
import UserTransformer from '#transformers/user_transformer'
import BaseInertiaMiddleware from '@adonisjs/inertia/inertia_middleware'

export default class InertiaMiddleware extends BaseInertiaMiddleware {
  share(ctx: HttpContext) {
    /**
     * share 方法可能在所有中间件运行之前被调用。
     * 例如，在 404 响应期间。始终将上下文
     * 属性视为可能未定义。
     */
    const { auth } = ctx as Partial<HttpContext>

    return {
      /**
       * 使用 always() 确保这些 props 即使在
       * 部分重载期间也被包含。
       */
      errors: ctx.inertia.always(this.getValidationErrors(ctx)),
      user: ctx.inertia.always(
        auth?.user ? UserTransformer.transform(auth.user) : undefined
      ),
    }
  }
}

TIP

share 方法可能在请求经过所有中间件或到达控制器之前被调用。这在渲染错误页面或提前中止请求时发生。访问上下文属性之前始终检查它们是否存在。

TIP

共享 props 在即时访问期间无需额外配置即可保持可用。

访问共享数据 ​

共享数据自动包含在每个页面的 props 中。在 React 中，当你使用 InertiaProps 类型辅助函数定义页面 props 时，它包含你的页面特定 props 和所有共享数据。在 Vue 中，使用 usePage。

tsx
import { InertiaProps } from '~/types'
import { Data } from '@generated/data'

type PageProps = InertiaProps<{
  posts: Data.Post[]
}>

export default function PostsIndex(props: PageProps) {
  return (
    <div>
      {/**
        * 与页面特定 props 一起访问共享数据。
        */}
      {props.user && <p>Welcome, {props.user.name}</p>}
      {/* 渲染帖子 */}
    </div>
  )
}
vue
<script setup lang="ts">
import { computed } from 'vue'
import { usePage } from '@inertiajs/vue3'
import { Data } from '@generated/data'

defineProps<{
  posts: Data.Post[]
}>()

/**
 * 共享 props 已类型化，因此不需要泛型。
 */
const page = usePage()

const user = computed(() => page.props.user)
</script>

<template>
  <p v-if="user">Welcome, {{ user.name }}</p>
  <!-- 渲染帖子 -->
</template>

闪存消息 ​

闪存消息是存储在会话中的一次性通知，如成功变更后的 "Post created"。它们从 usePage().flash 可用，导航返回时不会重新出现。验证错误仍然通过共享页面 props 可用。

在 Inertia 中间件中定义 flash() 方法以选择哪些会话闪存消息发送到前端。更新中间件时保留现有的 share() 和 handle() 方法。

ts
import type { HttpContext } from '@adonisjs/core/http'
import BaseInertiaMiddleware from '@adonisjs/inertia/inertia_middleware'

export default class InertiaMiddleware extends BaseInertiaMiddleware {
  flash(ctx: HttpContext) {
    const success: string | undefined = ctx.session?.flashMessages.get('success')
    const error: string | undefined = ctx.session?.flashMessages.get('error')

    return { success, error }
  }
}

在控制器中闪现消息并重定向。中间件在随后的请求中接收它。

ts
async store({ request, response, session }: HttpContext) {
  await Post.create(request.all())

  session.flash('success', 'Post created')
  return response.redirect().toRoute('posts.index')
}

在前端，闪存数据在 page.flash 上可用，它是 props 的兄弟。启动套件的默认布局通过 usePage() 读取它并将消息转发到 toast 通知，在 URL 更改时关闭过期的 toast。

tsx
import { toast, Toaster } from 'sonner'
import { usePage } from '@inertiajs/react'
import { ReactElement, useEffect } from 'react'

export default function Layout({ children }: { children: ReactElement }) {
  const { url, flash } = usePage()

  useEffect(() => {
    toast.dismiss()
  }, [url])

  useEffect(() => {
    if (flash.error) {
      toast.error(flash.error)
    }
    if (flash.success) {
      toast.success(flash.success)
    }
  })

  return (
    <>
      <main>{children}</main>
      <Toaster position="top-center" richColors />
    </>
  )
}
vue
<script setup lang="ts">
import { watch } from 'vue'
import { usePage } from '@inertiajs/vue3'
import { toast, Toaster } from 'vue-sonner'

const page = usePage()

watch(() => page.url, () => toast.dismiss())

watch(
  () => page.flash,
  (flash) => {
    if (flash.error) {
      toast.error(flash.error)
    }
    if (flash.success) {
      toast.success(flash.success)
    }
  },
  { immediate: true }
)
</script>

<template>
  <main><slot /></main>
  <Toaster position="top-center" richColors />
</template>

对于在组件外处理闪存数据，客户端还暴露全局 flash 事件（router.on('flash', callback)）和单次访问上的 onFlash 回调。

另请参阅：Inertia 文档中的闪存数据。

闪存数据遵循会话的闪存语义：消息恰好经历一次重定向，之后被清除。当资源版本不匹配强制完整重载时，消息会自动重新闪现，因此不会丢失。

类型化闪存数据 ​

向 inertia/types.ts 添加以下扩充以从中间件的 flash() 方法推断 usePage().flash 和闪存事件负载。启动套件默认包含此设置。

ts
import type { InferFlashData } from '@adonisjs/inertia/types'
import type InertiaMiddleware from '#middleware/inertia_middleware'

declare module '@inertiajs/core' {
  interface InertiaConfig {
    flashDataType: InferFlashData<InertiaMiddleware>
  }
}

分页 ​

Inertia 应用中的分页需要控制器、转换器和前端组件之间的协调。以下是使用帖子列表的完整示例。

控制器 ​

使用转换器的 paginate 方法序列化数据和分页元数据，然后将一切传递给 inertia.render()：

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ request, inertia }: HttpContext) {
    const page = request.input('page', 1)
    const posts = await Post.query().paginate(page, 10)

    return inertia.render('posts/index', {
      posts: PostTransformer.paginate(posts.all(), posts.getMeta()),
    })
  }
}

前端组件 ​

使用 Data 命名空间类型化分页 props。分页元数据包括 currentPage、lastPage 和其他可用于渲染控件的字段：

tsx
import { Link } from '@adonisjs/inertia/react'
import { InertiaProps } from '~/types'
import { Data } from '@generated/data'

type PageProps = InertiaProps<{
  posts: {
    data: Data.Post[]
    metadata: {
      total: number
      perPage: number
      currentPage: number
      lastPage: number
      firstPage: number
    }
  }
}>

export default function PostsIndex({ posts }: PageProps) {
  const { data, metadata } = posts

  return (
    <div>
      {data.map((post) => (
        <article key={post.id}>
          <h2>{post.title}</h2>
        </article>
      ))}

      <nav>
        {metadata.currentPage > 1 && (
          <Link route="posts.index" qs={{ page: metadata.currentPage - 1 }}>
            Previous
          </Link>
        )}
        {metadata.currentPage < metadata.lastPage && (
          <Link route="posts.index" qs={{ page: metadata.currentPage + 1 }}>
            Next
          </Link>
        )}
      </nav>
    </div>
  )
}

分页链接使用 qs prop生成像 /posts?page=2 这样的 URL。关于 paginate 方法和元数据对象形状的详细信息，请参阅转换器。

对于连续加载而不是逐页加载的列表，请参阅无限滚动。

无限滚动 ​

无限滚动用随着用户滚动不断扩展的列表替换分页链接。在控制器中使用 inertia.scroll() 并使用 Inertia 的 InfiniteScroll 组件渲染 prop。

向 inertia.scroll() 传递一个从查询字符串读取当前页面并返回转换器 paginate() 输出的回调。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ request, inertia }: HttpContext) {
    return inertia.render('posts/index', {
      posts: inertia.scroll(async () => {
        const page = request.input('page', 1)
        const posts = await Post.query().paginate(page, 10)
        return PostTransformer.paginate(posts.all(), posts.getMeta())
      }),
    })
  }
}

在前端，使用 Scroll 标记类型化 prop 并将列表包装在 InfiniteScroll 组件中，通过 data 属性命名 prop。该标记强制端到端配对：声明为 Scroll<Data.Post> 类型的 prop 仅在服务器用 inertia.scroll() 生成它时通过类型检查。

tsx
import { InfiniteScroll } from '@inertiajs/react'
import type { Scroll } from '@adonisjs/inertia/types'
import { InertiaProps } from '~/types'
import { Data } from '@generated/data'

type PageProps = InertiaProps<{
  posts: Scroll<Data.Post>
}>

export default function PostsIndex({ posts }: PageProps) {
  return (
    <InfiniteScroll data="posts">
      {posts.data.map((post) => (
        <article key={post.id}>
          <h2>{post.title}</h2>
        </article>
      ))}
    </InfiniteScroll>
  )
}
vue
<script setup lang="ts">
import { InfiniteScroll } from '@inertiajs/vue3'
import type { Scroll } from '@adonisjs/inertia/types'
import { Data } from '@generated/data'

defineProps<{
  posts: Scroll<Data.Post>
}>()
</script>

<template>
  <InfiniteScroll data="posts">
    <article v-for="post in posts.data" :key="post.id">
      <h2>{{ post.title }}</h2>
    </article>
  </InfiniteScroll>
</template>

滚动 props 与你已经了解的模式组合。链式调用 matchOn() 以按键去重重叠页面，这在行在请求之间移动时很重要：

ts
return inertia.render('posts/index', {
  /**
   * 出现在两个连续页面上的帖子
   * 只渲染一次而不是两次。
   */
  posts: inertia.scroll(async () => {
    const posts = await Post.query().paginate(request.input('page', 1), 10)
    return PostTransformer.paginate(posts.all(), posts.getMeta())
  }).matchOn('id'),
})

链式调用 deferred() 以在初始渲染期间跳过第一页并在页面挂载后立即加载它，匹配延迟 props行为。由于延迟滚动 prop 在首次渲染时不存在，在前端将其声明为可选（posts?: Scroll<Data.Post>）。

自定义分页游标 ​

对于没有转换器分页器的数据源（游标分页、外部 API），传递提供者作为第二个参数。它接收解析的值，该值必须暴露 data 数组，并返回游标描述：查询参数名称以及当前、下一个和上一个页面。

ts
return inertia.render('activities/index', {
  activities: inertia.scroll(
    () => fetchActivities(request.input('cursor')),
    (result) => ({
      pageName: 'cursor',
      currentPage: result.meta.cursor,
      nextPage: result.meta.next,
      previousPage: null,
    })
  ),
})

WARNING

既不是转换器分页器也没有提供者伴随的值无法分页，服务器在渲染时抛出错误。只要值不是来自转换器的 paginate() 方法，就传递提供者。

另请参阅：Inertia 文档中的无限滚动了解 InfiniteScroll 组件选项，如自定义触发器和手动模式。

CSRF 保护 ​

CSRF 保护在 Inertia 启动套件中自动配置。config/shield.ts 中的 enableXsrfCookie 选项设置一个 cookie，Inertia 读取并随每个请求包含。你不需要手动向表单添加 CSRF 令牌。

另请参阅：Shield了解 CSRF 保护的更多细节。

资源版本管理 ​

资源版本管理告诉前端你的 JavaScript 或 CSS 包何时更改，触发完整页面重载而不是部分更新。这确保用户在部署后始终运行最新版本的前端代码。

默认情况下，AdonisJS 计算 .vite/manifest.json 文件（构建前端资源时创建）的哈希并将其用作版本标识符。要将版本固定为自定义值，将 config/inertia.ts 中的 assetsVersion 设置为 git 提交哈希、构建时间戳或你控制的任何其他标识符。

ts
const inertiaConfig = defineConfig({
  assetsVersion: process.env.RELEASE_SHA,
})

当资源版本在 GET 访问期间更改时，Inertia 在同一 URL 执行完整页面重载。后台请求（如轮询）将重载推迟到用户的下次访问。闪存消息在重载期间保留。

重定向与历史 ​

Inertia 的重定向和历史行为与传统服务端渲染应用不同，因为导航通过 fetch 发生。HTTP 上下文上的 inertia 对象为框架无法自动处理的情况暴露辅助函数。

变更后的重定向 ​

当 PUT、PATCH 或 DELETE 请求后跟 302 重定向时，浏览器对新 URL 重放原始方法。Inertia 中间件自动将这些重定向升级为 303，以便浏览器改为发出 GET。你不需要自己设置状态码。

ts
async update({ request, response }: HttpContext) {
  await Post.updateOrFail(request.param('id'), request.all())
  return response.redirect().toRoute('posts.index')
}

外部重定向 ​

Inertia 无法通过 fetch 跟随到不同源的重定向。使用 inertia.location() 向客户端发送带有 X-Inertia-Location 头的 409 响应，触发浏览器完全导航到目标 URL。

ts
async checkout({ inertia }: HttpContext) {
  const session = await stripe.createCheckoutSession()
  return inertia.location(session.url)
}

清除浏览器历史 ​

在渲染之前调用 inertia.clearHistory() 以清除客户端历史栈。这在登出后很有用，你不希望用户导航回已认证页面。

ts
async destroy({ inertia, auth }: HttpContext) {
  await auth.use('web').logout()
  inertia.clearHistory()
  return inertia.location('/')
}

加密历史状态 ​

Inertia 将每次访问的页面对象存储在浏览器历史状态中以支持后退/前进导航。对于包含敏感数据的页面（账户设置、账单详情），启用加密以使数据无法从历史 API 读取。

在调用 render() 之前按请求切换加密：

ts
async settings({ inertia, auth }: HttpContext) {
  inertia.encryptHistory()
  return inertia.render('account/settings', {
    user: UserTransformer.transform(auth.user),
  })
}

或通过 encryptHistory配置选项全局启用。

参阅 Inertia 文档中的历史加密了解权衡。

服务器端渲染 ​

服务器端渲染（SSR）在服务器上生成初始 HTML，改善感知性能和 SEO。

启动套件预接线了 SSR 所需的一切：inertia/ssr.tsx 入口存在，vite.config.ts 在 serverEntrypoints 下声明它，config/inertia.ts 指向它。启用 SSR 只需一个开关。

ts
import { defineConfig } from '@adonisjs/inertia'

const inertiaConfig = defineConfig({
  ssr: {
    enabled: true, 
    entrypoint: 'inertia/ssr.tsx',
  },
})

export default inertiaConfig

如果你要将 SSR 添加到现有应用，请在 vite.config.ts 中向 serverEntrypoints 添加相同的入口。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app.tsx'],
      serverEntrypoints: ['inertia/ssr.tsx'], 
    }),
  ],
})

理解 Inertia 请求生命周期 ​

Inertia 请求遵循两种流程：初始页面访问和后续 Inertia 访问。两种流程使用相同的 AdonisJS 路由、中间件、控制器和 inertia.render() 调用。响应格式根据请求是否包含 X-Inertia 头而变化。

初始页面访问 ​

初始访问是没有 X-Inertia 头的标准浏览器文档请求。浏览器需要完整的 HTML 文档才能启动你的 React 或 Vue 应用。

sh
初始访问（HTML 响应）

  浏览器文档请求
            │
            ▼
  AdonisJS 路由和中间件
            │
            ▼
  控制器调用 inertia.render()
            │
            ▼
  共享 props 和闪存数据被解析
            │
            ▼
  根 Edge 模板被渲染
            │
            ▼
  React 或 Vue 在浏览器中启动

没有服务器端渲染时，根模板包含应用挂载元素和序列化的页面对象。页面对象包含组件名称、props、URL 和启动前端应用所需的其他 Inertia 状态。

当页面启用 SSR 时，流程保持不变，但根模板还包含服务器渲染的组件 HTML 和文档 head 元素。

后续 Inertia 访问 ​

前端应用启动后，Inertia 拦截来自 Link、Form 和路由器访问的导航。它发送带有 X-Inertia 头的 fetch 请求，告诉服务器浏览器已经有 HTML 外壳。

sh
后续访问（JSON 响应）

  Link、Form 或路由器访问
            │
            ▼
  带有 X-Inertia 头的 Fetch 请求
            │
            ▼
  相同的 AdonisJS 路由和中间件
            │
            ▼
  相同的控制器调用 inertia.render()
            │
            ▼
  返回 JSON 页面对象
            │
            ▼
  Inertia 替换当前页面组件

服务器在 Inertia 访问期间不渲染根 Edge 模板。它将页面对象作为 JSON 返回，客户端替换当前组件、更新浏览器历史并管理滚动位置，而不执行完整页面重载。
