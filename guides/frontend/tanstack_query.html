TanStack Query 集成 ​

本指南涵盖 Tuyau 的 TanStack Query 集成。你将了解到如何：

  • 安装和配置 @tuyau/react-query 或 @tuyau/vue-query
  • 生成类型安全的查询和变更选项
  • 使用分页实现无限滚动
  • 在不同粒度级别管理缓存失效
  • 处理失败 API 调用的错误

概述 ​

@tuyau/react-query 和 @tuyau/vue-query 包在 Tuyau 和 TanStack Query 之间提供无缝集成。Tuyau 不是创建自定义钩子或组合式函数，而是生成类型安全的选项对象，你直接传递给 TanStack Query 的标准原语，如 useQuery、useMutation 和 useInfiniteQuery。

这种方法让你在保持端到端类型安全的同时，完全控制 TanStack Query 的功能。查询键根据你的路由名称和参数自动生成，缓存失效变得简单且类型安全。该集成仅使用路由名称，确保你的 API 调用与 URL 结构解耦。

两个适配器共享相同的 API 表面。唯一的区别是框架特定的导入和组件语法。

前置条件 ​

在使用 TanStack Query 集成之前，你必须在应用中安装并配置 Tuyau。先按照 Tuyau 安装指南设置你的 Tuyau 客户端。

你应该熟悉：

  • TanStack Query 基础（理解查询、变更和缓存管理）
  • Tuyau 路由名称和 API 调用

安装 ​

在前端应用中安装 TanStack Query 集成包。

bash
npm install @tanstack/react-query @tuyau/react-query
bash
npm install @tanstack/vue-query @tuyau/vue-query

TIP

确保 @tuyau/react-query（或 @tuyau/vue-query）和 @tuyau/core 处于兼容版本。如果你在安装后看到类型错误，请检查两个包是否共享相同的主版本和预发布标签（例如，都在 1.x 或都在 next）。

设置 ​

创建带有 TanStack Query 集成的 Tuyau 客户端。api 对象提供对所有路由的类型安全查询和变更选项的访问。client 对象是核心 Tuyau 客户端，queryClient 是用于缓存管理和失效的标准 TanStack Query 客户端。

ts
import { registry } from '~registry'
import { createTuyau } from '@tuyau/core/client'
import { QueryClient } from '@tanstack/react-query'
import { createTuyauReactQueryClient } from '@tuyau/react-query'

export const queryClient = new QueryClient()

export const client = createTuyau({ baseUrl: import.meta.env.VITE_API_URL, registry })
export const api = createTuyauReactQueryClient({ client })
ts
import { registry } from '~registry'
import { createTuyau } from '@tuyau/core/client'
import { QueryClient } from '@tanstack/vue-query'
import { createTuyauVueQueryClient } from '@tuyau/vue-query'

export const queryClient = new QueryClient()

export const client = createTuyau({ baseUrl: import.meta.env.VITE_API_URL, registry })
export const api = createTuyauVueQueryClient({ client })

重试行为 ​

Tuyau 构建在 Ky 之上，默认对失败的请求启用自动重试。使用 TanStack Query 集成时，Ky 的重试机制会自动禁用，让 TanStack Query 处理重试，因为它也内置了重试功能。

这防止了双重重试（Ky 重试，然后 TanStack Query 在其上再重试），并通过 TanStack Query 的配置让你完全控制重试行为。

ts
const postsQuery = useQuery(
  api.posts.index.queryOptions(
    {},
    {
      retry: 3, // TanStack Query 处理重试
    }
  )
)

基本查询 ​

使用 queryOptions() 为 TanStack Query 的 useQuery 钩子生成选项。所有查询使用路由名称而不是 URL。响应数据根据后端控制器的返回值完全类型化，因此 TypeScript 无需任何手动类型注解就能知道数据的确切形状。

tsx
import { useQuery } from '@tanstack/react-query'
import { api } from '~/lib/client'

export default function PostsList() {
  const postsQuery = useQuery(
    api.posts.index.queryOptions()
  )

  if (postsQuery.isLoading) return <div>Loading...</div>
  if (postsQuery.isError) return <div>Error loading posts</div>

  return (
    <div>
      {postsQuery.data?.posts.map(post => (
        <article key={post.id}>
          <h2>{post.title}</h2>
          <p>{post.content}</p>
        </article>
      ))}
    </div>
  )
}
vue
<script setup lang="ts">
import { useQuery } from '@tanstack/vue-query'
import { api } from '~/lib/client'

const { data, isLoading, isError } = useQuery(
  api.posts.index.queryOptions()
)
</script>

<template>
  <div v-if="isLoading">Loading...</div>
  <div v-else-if="isError">Error loading posts</div>
  <div v-else>
    <article v-for="post in data?.posts" :key="post.id">
      <h2>{{ post.title }}</h2>
      <p>{{ post.content }}</p>
    </article>
  </div>
</template>

带参数的查询 ​

将路由参数和查询参数作为第一个参数传递给 queryOptions()。第二个参数接受任何标准 TanStack Query 选项，如 staleTime、enabled 或 refetchInterval。

tsx
import { useQuery } from '@tanstack/react-query'
import { api } from '~/lib/client'

export default function PostDetail({ postId }: { postId: string }) {
  const postQuery = useQuery(
    api.posts.show.queryOptions(
      {
        params: { id: postId },
        query: { include: 'comments' }
      },
      {
        staleTime: 5000,
        refetchOnWindowFocus: false
      }
    )
  )

  return <div>{postQuery.data?.post.title}</div>
}
vue
<script setup lang="ts">
import { useQuery } from '@tanstack/vue-query'
import { api } from '~/lib/client'

const props = defineProps<{ postId: string }>()

const { data } = useQuery(
  api.posts.show.queryOptions(
    {
      params: { id: props.postId },
      query: { include: 'comments' }
    },
    {
      staleTime: 5000,
      refetchOnWindowFocus: false
    }
  )
)
</script>

<template>
  <div>{{ data?.post.title }}</div>
</template>

使用 skipToken 的条件查询 ​

使用 skipToken 有条件地禁用查询，同时保持类型安全。这比使用 enabled 选项进行条件获取更简洁，因为无论查询是否激活，查询函数签名都保持不变。当传递 skipToken 时，TanStack Query 完全跳过查询。一旦值变为真值，查询会自动获取。

tsx
import { useQuery, skipToken } from '@tanstack/react-query'
import { api } from '~/lib/client'

export default function UserProfile({ userId }: { userId: string | null }) {
  const userQuery = useQuery(
    api.users.show.queryOptions(
      userId ? { params: { id: userId } } : skipToken
    )
  )

  return <div>{userQuery.data?.user.name}</div>
}
vue
<script setup lang="ts">
import { useQuery, skipToken } from '@tanstack/vue-query'
import { api } from '~/lib/client'

const props = defineProps<{ userId: string | null }>()

const { data } = useQuery(
  api.users.show.queryOptions(
    props.userId ? { params: { id: props.userId } } : skipToken
  )
)
</script>

<template>
  <div>{{ data?.user.name }}</div>
</template>

变更 ​

使用 mutationOptions() 为 TanStack Query 的 useMutation 钩子生成选项。该方法接受标准 TanStack Query 变更选项，如 onSuccess、onError 和 onSettled。所有变更参数（params、body）都根据你的后端验证器完全类型化。

tsx
import { useMutation } from '@tanstack/react-query'
import { api, queryClient } from '~/lib/client'

export default function CreatePost() {
  const createPost = useMutation(
    api.posts.store.mutationOptions({
      onSuccess: () => {
        /**
         * 创建帖子后使帖子列表查询失效。
         * 这会导致列表重新获取并包含新帖子。
         */
        queryClient.invalidateQueries({
          queryKey: api.posts.list.pathKey()
        })
      }
    })
  )

  const handleSubmit = (data: { title: string; content: string }) => {
    createPost.mutate({
      body: {
        title: data.title,
        content: data.content,
        authorId: 1
      }
    })
  }

  return (
    <form onSubmit={(e) => {
      e.preventDefault()
      handleSubmit({ title: 'My Post', content: 'Content here' })
    }}>
      <input name="title" placeholder="Title" />
      <textarea name="content" placeholder="Content" />
      <button type="submit" disabled={createPost.isPending}>
        {createPost.isPending ? 'Creating...' : 'Create Post'}
      </button>

      {createPost.isError && (
        <p>Error: {createPost.error.message}</p>
      )}
    </form>
  )
}
vue
<script setup lang="ts">
import { useMutation } from '@tanstack/vue-query'
import { api, queryClient } from '~/lib/client'

const createPost = useMutation(
  api.posts.store.mutationOptions({
    onSuccess: () => {
      /**
       * 创建帖子后使帖子列表查询失效。
       * 这会导致列表重新获取并包含新帖子。
       */
      queryClient.invalidateQueries({
        queryKey: api.posts.list.pathKey()
      })
    }
  })
)

function handleSubmit(data: { title: string; content: string }) {
  createPost.mutate({
    body: {
      title: data.title,
      content: data.content,
      authorId: 1
    }
  })
}
</script>

<template>
  <form @submit.prevent="handleSubmit({ title: 'My Post', content: 'Content here' })">
    <input name="title" placeholder="Title" />
    <textarea name="content" placeholder="Content" />
    <button type="submit" :disabled="createPost.isPending">
      {{ createPost.isPending ? 'Creating...' : 'Create Post' }}
    </button>

    <p v-if="createPost.isError">
      Error: {{ createPost.error?.message }}
    </p>
  </form>
</template>

无限查询 ​

对于分页和无限滚动，使用 infiniteQueryOptions() 配合 TanStack Query 的 useInfiniteQuery。这需要前端查询配置和后端验证之间的协调。

前端配置 ​

pageParamKey 选项指定哪个查询参数保存页码。这必须与后端验证器中的参数名称匹配。

tsx
import { useInfiniteQuery } from '@tanstack/react-query'
import { api } from '~/lib/client'

export default function InfinitePosts() {
  const postsQuery = useInfiniteQuery(
    api.posts.list.infiniteQueryOptions(
      {
        query: {
          limit: 10,
          search: 'typescript'
        }
      },
      {
        initialPageParam: 1,
        getNextPageParam: (lastPage) => lastPage.meta.nextPage,
        pageParamKey: 'page',
      }
    )
  )

  const allPosts = postsQuery.data?.pages.flatMap(page => page.posts) || []

  return (
    <div>
      {allPosts.map(post => (
        <article key={post.id}>
          <h2>{post.title}</h2>
          <p>{post.content}</p>
        </article>
      ))}

      {postsQuery.hasNextPage && (
        <button
          onClick={() => postsQuery.fetchNextPage()}
          disabled={postsQuery.isFetchingNextPage}
        >
          {postsQuery.isFetchingNextPage ? 'Loading...' : 'Load More'}
        </button>
      )}
    </div>
  )
}
vue
<script setup lang="ts">
import { computed } from 'vue'
import { useInfiniteQuery } from '@tanstack/vue-query'
import { api } from '~/lib/client'

const { data, hasNextPage, isFetchingNextPage, fetchNextPage } = useInfiniteQuery(
  api.posts.list.infiniteQueryOptions(
    {
      query: {
        limit: 10,
        search: 'typescript'
      }
    },
    {
      initialPageParam: 1,
      getNextPageParam: (lastPage) => lastPage.meta.nextPage,
      pageParamKey: 'page',
    }
  )
)

const allPosts = computed(() => data.value?.pages.flatMap(page => page.posts) || [])
</script>

<template>
  <div>
    <article v-for="post in allPosts" :key="post.id">
      <h2>{{ post.title }}</h2>
      <p>{{ post.content }}</p>
    </article>

    <button
      v-if="hasNextPage"
      :disabled="isFetchingNextPage"
      @click="fetchNextPage()"
    >
      {{ isFetchingNextPage ? 'Loading...' : 'Load More' }}
    </button>
  </div>
</template>

后端验证 ​

定义一个包含 pageParamKey 引用的分页参数的验证器。验证器中的 page 参数必须与你前端配置中的 pageParamKey 值匹配。Tuyau 自动处理将分页参数从 TanStack Query 的分页系统传递到你的后端。

ts
import vine from '@vinejs/vine'

export const listPostsValidator = vine.create({
  page: vine.number().optional(),
  limit: vine.number().optional(),
  search: vine.string().optional(),
})

后端控制器 ​

在控制器中使用验证后的参数实现分页。前端的 getNextPageParam 函数检查 lastPage.meta.nextPage 以确定是否存在更多页面。当没有更多页面可加载时返回 null。

ts
import type { HttpContext } from '@adonisjs/core/http'
import { listPostsValidator } from '#validators/post'

export default class PostsController {
  async list({ request, serialize }: HttpContext) {
    const { page = 1, limit = 10, search } = await request.validateUsing(listPostsValidator)

    const posts = await Post.query()
      .if(search, (query) => query.where('title', 'like', `%${search}%`))
      .paginate(page, limit)

    return {
      posts: await serialize(PostTransformer.transform(posts.all())),
      meta: {
        currentPage: posts.currentPage,
        lastPage: posts.lastPage,
        nextPage: posts.hasNextPage ? posts.currentPage + 1 : null
      }
    }
  }
}

无限查询如何工作 ​

当组件挂载时，TanStack Query 使用 page: 1（initialPageParam）调用你的 API。响应包含数据和分页元数据。getNextPageParam 函数检查此元数据以确定接下来获取哪一页。

当用户点击 "Load More" 时，TanStack Query 自动使用下一页编号再次调用你的 API，将结果追加到现有数据。Tuyau 透明地处理将分页参数注入到你的查询字符串中。

响应式查询（Vue） ​

在 Vue 中，你经常需要查询在响应式状态更改时重新获取。将你的 queryOptions() 调用包装在 getter 函数中，以便 TanStack Query 自动跟踪依赖项并在它们更改时重新求值。

这之所以有效，是因为 Vue Query 的 useQuery 接受 MaybeRefOrGetter<Options>。当你传递 getter 函数时，TanStack Query 在 computed 内调用它，该 computed 跟踪求值期间访问的所有响应式依赖项。当 search.value 更改时，computed 重新求值，产生带有更新查询键和查询函数的新查询选项。

vue
<script setup lang="ts">
import { ref } from 'vue'
import { useQuery } from '@tanstack/vue-query'
import { api } from '~/lib/client'

const search = ref('')

const { data } = useQuery(
  () => api.posts.index.queryOptions({ query: { search: search.value } })
)
</script>

<template>
  <input v-model="search" placeholder="Search posts..." />
  <article v-for="post in data?.posts" :key="post.id">
    <h2>{{ post.title }}</h2>
  </article>
</template>

TIP

此模式在 React 中不需要，组件重新渲染自然会导致 queryOptions() 使用新值再次被调用。

缓存失效 ​

Tuyau 提供多种具有不同粒度级别的缓存失效方法。这些方法在 React 和 Vue 中工作方式完全相同。

queryKey() - 精确匹配 ​

当你确切知道需要使哪个查询失效并且拥有其所有参数时，使用 queryKey()。

ts
const updatePost = useMutation(
  api.posts.update.mutationOptions({
    onSuccess: (data, variables) => {
      /**
       * 仅使被更新的特定帖子失效。
       * 这是最精确的失效策略。
       */
      queryClient.invalidateQueries({
        queryKey: api.posts.show.queryKey({
          params: { id: variables.params.id }
        })
      })
    }
  })
)

pathKey() - 基础路径 ​

当你想要使不带参数的特定端点失效时使用 pathKey()，例如不依赖路由参数的列表查询。

ts
const deletePost = useMutation(
  api.posts.delete.mutationOptions({
    onSuccess: () => {
      /**
       * 使此确切路径的所有查询失效。
       * 这会使 posts.list 失效，但不会使 posts.show 失效。
       */
      queryClient.invalidateQueries({
        queryKey: api.posts.list.pathKey()
      })
    }
  })
)

pathFilter() - 子树匹配 ​

当变更可能影响多个相关查询且你想一次使它们全部失效时，pathFilter() 方法特别有用。

ts
const createProduct = useMutation(
  api.products.store.mutationOptions({
    onSuccess: () => {
      /**
       * 使跨任何路由的所有产品相关查询失效。
       * 这捕获 products.search、products.list、products.show、
       * products.byCategory 以及任何其他产品路由。
       */
      queryClient.invalidateQueries(
        api.products.pathFilter()
      )
    }
  })
)

queryFilter() - 自定义过滤 ​

使用 queryFilter() 配合谓词函数来精细控制哪些查询失效。谓词函数接收查询状态并可以检查缓存数据以做出失效决策。

ts
const archivePost = useMutation(
  api.posts.archive.mutationOptions({
    onSuccess: () => {
      /**
       * 仅使帖子标记为活跃的查询失效。
       * 使用谓词检查缓存数据并根据自定义逻辑
       * 决定是否失效。
       */
      const filter = api.posts.pathFilter({
        predicate: (query) => {
          const data = query.state.data
          return data?.post?.status === 'active'
        },
      })

      queryClient.invalidateQueries(filter)
    }
  })
)

错误处理 ​

当 API 调用失败时，Tuyau 抛出 HTTPError（来自 Ky），TanStack Query 捕获并通过其标准错误状态暴露。

在查询和变更中访问错误 ​

TanStack Query 通过结果对象上的 isError 和 error 暴露错误。

tsx
const postsQuery = useQuery(api.posts.index.queryOptions())

if (postsQuery.isError) {
  console.log(postsQuery.error.message)
}

检查 HTTP 状态码 ​

error 对象是带有 response 属性的 Ky HTTPError。使用它来检查状态码。

ts
import { HTTPError } from 'ky'

const postsQuery = useQuery(api.posts.index.queryOptions())

if (postsQuery.isError && postsQuery.error instanceof HTTPError) {
  const status = postsQuery.error.response.status

  if (status === 401) {
    window.location.href = '/login'
  }
}

全局错误处理器 ​

与其在每个组件中检查状态码，不如使用 queryClient 默认选项配置全局处理器。这防止重试未授权的请求，并让你在整个应用中一致地处理 401。

ts
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      retry: (failureCount, error) => {
        if (error instanceof HTTPError && error.response.status === 401) {
          return false // 401 时不重试
        }
        return failureCount < 3
      },
    },
  },
})
