类型安全的 API 客户端 ​

本指南涵盖 Tuyau，一个用于 AdonisJS 应用的端到端类型安全 HTTP 客户端。你将了解到如何：

  • 为 Inertia 和单体仓库设置安装和配置 Tuyau
  • 使用路由名称进行类型安全的 API 调用
  • 处理请求参数、验证和错误响应
  • 处理文件上传
  • 以编程方式生成 URL
  • 理解类型级序列化以实现端到端类型安全

概述 ​

Tuyau 是一个类型安全的 HTTP 客户端，可在你的 AdonisJS 后端和前端应用之间实现端到端类型安全。与其手动编写 API 客户端代码和管理类型，Tuyau 会根据你的路由、控制器和验证器自动生成完全类型化的客户端。

Tuyau 的关键好处是消除后端 API 定义和前端消费之间的差距。当你在 AdonisJS 中定义带验证的路由时，Tuyau 确保你的前端调用对请求体、查询参数、路由参数和响应数据使用完全相同的类型。这意味着 TypeScript 会在编译时捕获错误，而不是在运行时才发现。

Tuyau 通过分析你的 AdonisJS 路由并生成将路由名称映射到其类型的注册表来工作。你的前端导入此注册表并使用它进行类型安全的 API 调用。每个参数、请求体中的每个字段以及响应中的每个属性都在你的 IDE 中完全类型化和自动补全。

该库构建在 Ky 之上，这是一个现代 fetch 封装，这意味着你在保持完全类型安全的同时获得 Ky 的所有功能，如自动重试、超时处理和请求/响应钩子。

安装 ​

Tuyau 的安装因你是使用 Inertia（单一仓库）还是具有独立前端和后端应用的单体仓库设置而有所不同。

Inertia 应用 ​

对于 Inertia 应用，安装很简单，因为你的前端和后端位于同一个仓库中。React 和 Vue 的官方启动套件已预配置 Tuyau，因此无需手动设置。

步骤 1：安装包 ​

bash
npm install @tuyau/core

步骤 2：配置 assembler 钩子 ​

assembler 钩子在你的代码库更改时自动生成 Tuyau 注册表。将 generateRegistry 钩子添加到你的 adonisrc.ts 文件。indexEntities 钩子为类型生成索引你的模型和转换器，indexPages 索引你的 Inertia 页面组件，generateRegistry 在 .adonisjs/client 目录中生成 Tuyau 注册表文件。

ts
import { indexPages } from '@adonisjs/inertia'
import { indexEntities } from '@adonisjs/core'
import { defineConfig } from '@adonisjs/core/app'
import { generateRegistry } from '@tuyau/core/hooks'

export default defineConfig({
  // ... 其他配置
  hooks: {
    init: [
      indexEntities({ transformers: { enabled: true, withSharedProps: true } }),
      indexPages({ framework: 'react' }),
      generateRegistry(),
    ],
  },
})

步骤 3：配置 TypeScript 路径 ​

在 Inertia 的 tsconfig.json 中配置路径别名以导入生成的注册表。

json
{
  "compilerOptions": {
    // ... 其他选项
    "paths": {
      "~/*": ["./*"],
      "@generated/*": ["../.adonisjs/client/*"]
    }
  }
}

步骤 4：配置 Vite 别名 ​

向你的 vite.config.ts 添加匹配的别名。

ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/vite'

export default defineConfig({
  plugins: [
    react(),
    inertia({ ssr: { enabled: false, entrypoint: 'inertia/ssr.tsx' } }),
    adonisjs({ entrypoints: ['inertia/app.tsx'], reload: ['resources/views/**/*.edge'] }),
  ],

  resolve: {
    alias: {
      '~/': `${import.meta.dirname}/inertia/`,
      '@generated': `${import.meta.dirname}/.adonisjs/client/`,
    },
  },
})

步骤 5：创建 Tuyau 客户端 ​

创建一个文件来初始化你的 Tuyau 客户端。

ts
import { registry } from '@generated/registry'
import { createTuyau } from '@tuyau/core/client'

export const client = createTuyau({
  baseUrl: '/',
  registry,
})

export const urlFor = client.urlFor

baseUrl 设置为 '/'，因为在 Inertia 应用中前端和后端从同一源提供服务。

单体仓库应用 ​

对于前端和后端是独立包的单体仓库设置，配置需要额外的工作以在工作区之间共享类型。

本指南假设你使用 npm workspaces 配合 Turborepo（如 API 启动套件所使用的），但概念也适用于其他单体仓库工具，如 pnpm 或 Yarn workspaces，语法略有不同。

步骤 1：组织你的单体仓库 ​

使用独立的 API 和前端应用工作区组织你的单体仓库。

text
my-app/
├── apps/
│   ├── backend/      # AdonisJS 后端
│   └── frontend/     # 前端（React、Vue 等）
└── package.json

步骤 2：在后端安装 Tuyau ​

在后端工作区安装 @tuyau/core。它同时处理 assembler 钩子（注册表生成）并暴露客户端供你的前端导入。

json
{
  "name": "@my-app/backend",
  "private": true,
  "type": "module",
  "dependencies": {
    "@tuyau/core": "^1.0.0"
  }
}

然后，在你的前端工作区中，将后端添加为工作区依赖，以便它可以导入生成的注册表和 Tuyau 客户端。

json
{
  "name": "@my-app/frontend",
  "private": true,
  "type": "module",
  "dependencies": {
    "@my-app/backend": "*"
  }
}

"*" 版本范围告诉 npm 从你的本地工作区解析 @my-app/backend。确保包名称与后端 package.json 中的 name 字段匹配。

步骤 3：启用实验性装饰器 ​

Tuyau 内部使用 TypeScript 装饰器。在前端 tsconfig.json 中启用它们。你还需要包含后端源文件，以便 TypeScript 在类型检查期间可以解析共享类型。

json
{
  "compilerOptions": {
    "experimentalDecorators": true, 
    // ... 其他选项
  },
  "include": [
    "./**/*.ts",
    "./**/*.tsx",
    "../backend/**/*.ts",
    "../backend/.adonisjs/**/*.ts"
  ],
  "exclude": [
    "node_modules",
    "../backend/build",
    "../backend/node_modules"
  ]
}

步骤 4：配置后端 ​

在你的后端 AdonisJS 应用中，像 Inertia 设置一样添加 generateRegistry 钩子。

ts
import { indexEntities } from '@adonisjs/core'
import { defineConfig } from '@adonisjs/core/app'
import { generateRegistry } from '@tuyau/core/hooks'

export default defineConfig({
  hooks: {
    init: [
      indexEntities({ transformers: { enabled: true } }),
      generateRegistry(),
    ],
  },
})

步骤 5：导出注册表 ​

配置你的后端 package.json 以导出生成的 Tuyau 文件，以便你的前端可以导入它们。

json
{
  "name": "@my-app/backend",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { 
    "./registry": "./.adonisjs/client/registry/index.ts", 
    "./data": "./.adonisjs/client/data.d.ts"
  } 
}

这些导出允许你的前端使用 @my-app/backend/registry 导入注册表。

步骤 6：创建 Tuyau 客户端 ​

在你的前端中，创建一个文件来初始化 Tuyau。

ts
import { createTuyau } from '@tuyau/core/client'
import { registry } from '@my-app/backend/registry'

export const client = createTuyau({
  baseUrl: import.meta.env.VITE_API_URL || 'http://localhost:3333',
  registry,
  headers: { Accept: 'application/json' },
  hooks: {
    beforeRequest: [
      (request) => {
        const token = localStorage.getItem('auth_token')
        if (token) {
          request.headers.set('Authorization', `Bearer ${token}`)
        }
      }
    ]
  }
})

baseUrl 应使用环境变量，以便你可以为开发和生产环境配置不同的 API URL。

卡在某个地方了？

查看这个单体仓库启动套件，它使用 TanStack 作为前端，以及 Tuyau 作为类型安全的 API 客户端。

你的第一个 API 调用 ​

让我们构建一个完整的示例，展示 Tuyau 如何从后端路由到前端 API 调用提供端到端类型安全。

步骤 1：定义后端路由 ​

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.post('posts', [controllers.Posts, 'store'])

路由名称 posts.store 自动从控制器名称和动作派生。这是你从前端调用端点时将使用的名称。

步骤 2：创建验证器 ​

使用 VineJS 定义验证规则。

ts
import vine from '@vinejs/vine'

export const createPostValidator = vine.create({
  title: vine.string().minLength(3).maxLength(255),
  content: vine.string().minLength(10),
  published: vine.boolean().optional(),
})

步骤 3：实现控制器 ​

创建一个使用验证器的控制器动作。对 request.validateUsing() 的调用对于 Tuyau 理解你的请求体形状并在前端提供准确的类型至关重要。

ts
import type { HttpContext } from '@adonisjs/core/http'
import Post from '#models/post'
import { createPostValidator } from '#validators/post'

export default class PostsController {
  async store({ request }: HttpContext) {
    const payload = await request.validateUsing(createPostValidator)

    const post = await Post.create(payload)
    return post
  }
}

步骤 4：从前端进行 API 调用 ​

导入你的 Tuyau 客户端并使用其名称调用路由。

ts
import { client } from '~/client'

async function handleCreatePost() {
  const post = await client.api.posts.store({
    body: {
      title: 'My first blog post',
      content: 'This is the content of the blog post',
      published: true,
    },
  })

  console.log('Post created:', post)
}

注意路由名称 posts.store 如何变成方法链 client.api.posts.store()。body 参数基于你的验证器完全类型化。你的 IDE 会自动补全字段，TypeScript 会捕获任何错误。

进行 API 调用 ​

Tuyau 提供三种不同的方式进行 API 调用，每种适用于不同的用例。这三种方法都提供完整的类型安全，但它们在语法和灵活性上有所不同。

使用路由名称配合代理语法 ​

推荐的方法是使用路由名称配合代理语法。路由名称直接映射到 Tuyau 客户端上的方法链。

ts
// 路由：router.post('register', [controllers.Auth, 'register'])
const result = await client.api.auth.register({
  body: { email: 'foo@ok.com', password: 'password123' }
})

// 路由：router.get('users/:id', [controllers.Users, 'show'])
const user = await client.api.users.show({
  params: { id: '1' },
  query: { include: 'posts' }
})

路由名称的每个段都成为属性访问。路由 users.show 变成 client.api.users.show()。这种语法提供出色的自动补全并保持代码整洁。

TIP

包含下划线的路由名称段在代理语法中转换为 camelCase。例如，名为 auth.new_account.store 的路由变成 client.api.auth.newAccount.store()。

使用 request 方法 ​

request 方法提供了一种替代语法，显式地将路由名称作为字符串传递。

ts
const result = await client.request('auth.register', {
  body: { email: 'foo@ok.com', password: 'password123' }
})

const user = await client.request('users.show', {
  params: { id: '1' },
  query: { include: 'posts' }
})

这种方法在功能上与代理语法相同，但提供了不同的 API 来构建请求 URL。

使用 HTTP 方法函数 ​

有时你需要调用不属于 AdonisJS 后端的端点，例如第三方 API 或旧服务。在这些情况下，你可以使用直接接受 URL 的 HTTP 方法函数。

ts
const user = await client.get('/users/:id', {
  params: { id: '123' },
  query: { include: 'posts' }
})

const post = await client.post('/posts', {
  body: { title: 'Hello', content: 'World' }
})

const updated = await client.patch('/posts/:id', {
  params: { id: '456' },
  body: { title: 'Updated title' }
})

这种语法镜像了 fetch API，但保持参数和响应的类型安全。

处理参数 ​

API 调用通常需要不同类型的参数：路由参数用于动态 URL 段，查询参数用于过滤或分页，请求体用于数据提交。Tuyau 以完整的类型安全处理所有这些。

路由参数 ​

路由参数替换 URL 中的动态段。当你定义带参数的路由时，Tuyau 会自动为它们添加类型。

ts
router.get('users/:id', [controllers.Users, 'show'])
router.get('users/:userId/posts/:postId', [controllers.Posts, 'show'])

使用 params 选项传递路由参数。TypeScript 将强制你提供所有必需的参数及正确的名称，你的 IDE 将自动补全参数名称并在编译时捕获拼写错误。

ts
// 单个参数
const user = await client.api.users.show({
  params: { id: '123' }
})

// 多个参数
const post = await client.api.users.posts.show({
  params: { userId: '123', postId: '456' }
})

查询参数 ​

查询参数追加到 URL 用于过滤、分页或传递可选数据。使用 query 选项传递它们。查询参数自动 URL 编码，如果你的后端验证查询参数，这些类型会在前端被推断。

ts
// 路由：GET /posts
const posts = await client.api.posts.index({
  query: {
    page: 1,
    limit: 10,
    status: 'published'
  }
})
// 结果为：GET /posts?page=1&limit=10&status=published

请求体 ​

对于 POST、PUT 和 PATCH 请求，使用 body 选项发送数据。请求体类型自动从你的验证器推断。每个字段都被类型化，TypeScript 将阻止你发送验证器中不存在的字段或类型不正确的字段。

ts
const post = await client.api.posts.store({
  body: {
    title: 'My First Post',
    content: 'This is the content',
    published: true
  }
})

组合参数 ​

你可以在单个请求中组合路由参数、查询参数和请求体。Tuyau 处理构建完整 URL、编码查询参数和序列化请求体，同时保持所有三种参数类型的类型安全。

ts
const comment = await client.api.posts.comments.store({
  params: { postId: '123' },
  query: { notify: true },
  body: {
    content: 'Great post!',
    author: 'John Doe'
  }
})

请求验证和类型推断 ​

后端验证器和前端类型之间的连接是 Tuyau 类型安全成为可能的关键。理解其工作原理对于充分利用 Tuyau 至关重要。

request.validateUsing() 的作用 ​

为了让 Tuyau 从你的验证器推断类型，你必须在控制器动作中使用 request.validateUsing()。没有它，Tuyau 无法确定你的请求体应该是什么形状，你的前端类型将回退到 any。

ts
import type { HttpContext } from '@adonisjs/core/http'
import { createPostValidator } from '#validators/post'

export default class PostsController {
  async store({ request }: HttpContext) {
    const payload = await request.validateUsing(createPostValidator)

    const post = await Post.create(payload)
    return post
  }
}

定义验证器 ​

使用 VineJS 定义验证模式。你定义的每个字段都成为前端类型签名的一部分。

ts
import vine from '@vinejs/vine'

export const createPostValidator = vine.create({
  title: vine.string().minLength(3).maxLength(255),
  content: vine.string().minLength(10),
  published: vine.boolean().optional(),
  categoryId: vine.number(),
  tags: vine.array(vine.string()).optional(),
})

在你的前端，body 参数将具有完全相同的形状。TypeScript 将强制执行必填字段、阻止额外字段并确保每个属性的正确类型。

ts
await client.api.posts.store({
  body: {
    title: 'My Post',        // string（必填）
    content: 'Content here', // string（必填）
    published: true,         // boolean（可选）
    categoryId: 1,           // number（必填）
    tags: ['news', 'tech']   // string[]（可选）
  }
})

查询参数验证 ​

查询参数也可以被验证和类型化。为查询参数定义一个验证器并在控制器中使用它。前端查询参数将被类型化以匹配你的验证器，因此 TypeScript 只允许有效的值。

ts
export const listPostsValidator = vine.create({
  page: vine.number().optional(),
  limit: vine.number().optional(),
  status: vine.enum(['draft', 'published']).optional(),
  search: vine.string().optional(),
})
ts
export default class PostsController {
  async index({ request }: HttpContext) {
    const filters = await request.validateUsing(listPostsValidator)
    const posts = await Post.query()
      .where('status', filters.status)
      .paginate(filters.page || 1, filters.limit || 10)

    return posts
  }
}
ts
const posts = await client.api.posts.index({
  query: {
    page: 1,
    limit: 20,
    status: 'published', // 只允许 'draft' 或 'published'
    search: 'typescript'
  }
})

错误处理 ​

Tuyau 支持抛出和不抛出的错误处理。

默认情况下，请求的行为类似于常规 promise。成功的响应解析为响应负载，而失败的请求则抛出。HTTP 失败抛出 TuyauHTTPError，传输失败（如 DNS 问题、拒绝连接或离线状态）抛出 TuyauNetworkError。

使用 .safe() ​

如果你不想抛出，对请求调用 .safe()。它返回一个元组，第一个元素是数据，第二个元素是错误。错误始终类型化为 TuyauError，为 HTTP 和网络失败提供单一错误形状。

ts
const [data, error] = await client.api.posts.show({
  params: { id: '123' }
}).safe()

if (error) {
  console.log(error.message)
  return
}

console.log(data.title)

使用 isStatus() 缩小 HTTP 错误 ​

当你的控制器返回类型化的非 2xx 响应时，Tuyau 自动从控制器的返回类型中提取那些错误负载并使它们在前端可用。使用 isStatus() 将错误缩小到特定状态码。在 error.isStatus(404) 之后，TypeScript 将 error.response 缩小为控制器中 response.notFound() 返回的确切负载形状。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async show({ params, response }: HttpContext) {
    const post = await Post.find(params.id)

    if (!post) {
      return response.notFound({ message: 'Post not found', key: 'post_not_found' })
    }

    return response.ok({ post })
  }
}
ts
const [data, error] = await client.api.posts.show({
  params: { id: '123' }
}).safe()

if (error?.isStatus(404)) {
  // error.response 被缩小为 { message: string, key: string }（从控制器推断）
  console.log(error.response.message)
  console.log(error.response.key)
  return
}

console.log(data.post.title)

验证错误 ​

使用 request.validateUsing() 的路由自动获得类型化的 422 错误响应。该类型使用来自 @vinejs/vine/types 的 SimpleError。使用 isValidationError() 作为 isStatus(422) 的简写。

ts
const [data, error] = await client.api.posts.store({
  body: { title: '', content: '' }
}).safe()

if (error?.isValidationError()) {
  // error.response 类型为 { errors: SimpleError[] }
  for (const err of error.response.errors) {
    console.log(err.field, err.message)
  }
}

如果你的 API 对验证错误返回不同的形状，你可以通过 generateRegistry 钩子中的 validationErrorType 选项自定义错误类型或禁用它。

ts
generateRegistry({
  validationErrorType: '{ errors: { path: string; message: string }[] }',
  // 或设置为 `false` 以禁用
})

区分 HTTP 和网络失败 ​

TuyauError 类型包含 kind 属性。当你需要将网络失败与服务器响应区分对待时使用它。

ts
const [, error] = await client.api.posts.show({
  params: { id: '123' }
}).safe()

if (error?.kind === 'network') {
  console.log('The server is unreachable')
}

对于网络失败，status 和 response 是 undefined，因为服务器未发送响应。

使用 try/catch ​

如果你偏好抛出流程，使用 Route.Error 强制转换捕获的错误以获得完整的类型缩小。

ts
import type { Route } from '@tuyau/core/types'

try {
  await client.api.posts.show({ params: { id: '123' } })
} catch (e) {
  const error = e as Route.Error<'posts.show'>

  if (error.isStatus(404)) {
    // error.response 被缩小为控制器中的 404 负载
    console.log(error.response.message)
    return
  }

  if (error.kind === 'network') {
    console.log('The server is unreachable')
  }
}

检索类型 ​

Tuyau 提供两个类型辅助命名空间 Path 和 Route，让你从 API 定义中提取请求、响应和错误类型。当你需要根据 API 模式为变量、函数参数或返回类型添加类型时，这很有用。

两个辅助都从 @tuyau/core/types 导入，并暴露相同的实用工具：Request、Response、Error、Params、Body 和 Query。Route 按路由名称提取类型，而 Path 按 HTTP 方法和 URL 模式提取类型。

ts
import type { Route, Path } from '@tuyau/core/types'

// 按路由名称
type StoreRequest = Route.Request<'posts.store'>
type StoreResponse = Route.Response<'posts.store'>
type ShowError = Route.Error<'posts.show'>
type ShowParams = Route.Params<'posts.show'>
type StoreBody = Route.Body<'posts.store'>
type IndexQuery = Route.Query<'posts.index'>

// 按 HTTP 方法 + URL 模式
type LoginRequest = Path.Request<'POST', '/auth/login'>
type LoginResponse = Path.Response<'POST', '/auth/login'>
type LoginError = Path.Error<'POST', '/auth/login'>
type UserParams = Path.Params<'GET', '/users/:id'>
type LoginBody = Path.Body<'POST', '/auth/login'>
type PostsQuery = Path.Query<'GET', '/posts'>

Error 辅助解析为 TuyauError，这意味着它同时建模 HTTP 和网络失败，同时仍支持 isStatus() 进行 HTTP 错误缩小。

文件上传 ​

Tuyau 通过检测请求体中的 File 对象并切换到 FormData 编码来自动处理文件上传。你不需要手动构造 FormData 或更改内容类型。

基本文件上传 ​

当你在请求体中传递 File 对象时，Tuyau 自动将整个负载转换为 FormData。其他字段如 description 包含在同一个 FormData 负载中。

ts
import { client } from '~/client'

async function uploadAvatar(file: File) {
  const result = await client.api.users.avatar.update({
    body: {
      avatar: file,
      description: 'My new avatar'
    }
  })
}

// 在你的组件中
function handleFileSelect(event: ChangeEvent<HTMLInputElement>) {
  const file = event.target.files?.[0]
  if (file) {
    uploadAvatar(file)
  }
}

TIP

当 Tuyau 检测到请求体中的 File 对象时，它会将整个负载转换为 FormData。需要记住几点：

  • 字段名称必须与你的验证器匹配。 body 对象中的键（例如 avatar、description）成为 FormData 字段名称，必须与 VineJS 验证器中对应的键匹配。
  • 你可以混合文件和常规字段。 字符串和数字等标量值与文件字段一起包含在同一个 FormData 负载中。
  • 可选文件字段。 如果文件字段在你的验证器中是可选的，只需从 body 中省略该键。不要发送 undefined 或 null，因为它们可能在 FormData 中被序列化为字面字符串。

后端处理 ​

在后端，使用 AdonisJS 的标准文件验证处理文件上传。

ts
import vine from '@vinejs/vine'

export const updateAvatarValidator = vine.create({
  avatar: vine.file({
    size: '2mb',
    extnames: ['jpg', 'png', 'jpeg'],
  }),
  description: vine.string().optional(),
})
ts
import type { HttpContext } from '@adonisjs/core/http'
import { updateAvatarValidator } from '#validators/user'

export default class UsersController {
  async updateAvatar({ request, auth }: HttpContext) {
    const { avatar, description } = await request.validateUsing(updateAvatarValidator)

    // 将文件移动到存储
    await avatar.move('uploads/avatars', {
      name: `${auth.user!.id}.${avatar.extname}`
    })

    return { success: true }
  }
}

多文件上传 ​

通过在负载中包含多个 File 对象来上传多个文件。Tuyau 自动处理文件数组的 FormData 序列化。

ts
const result = await client.api.posts.attachments.create({
  params: { postId: '123' },
  body: {
    files: [file1, file2, file3],
    visibility: 'public'
  }
})

生成 URL ​

Tuyau 提供 urlFor 辅助函数以类型安全的方式从路由名称生成 URL。当你需要用于链接、重定向或共享的 URL 而不是进行实际的 API 调用时，这很有用。

基本 URL 生成 ​

urlFor 方法在所有 HTTP 方法中搜索并将 URL 作为字符串返回。TypeScript 确保你提供正确的路由名称和必需的参数。无效的路由名称或缺少的参数会在编译时被捕获。

ts
import { urlFor } from '~/client'

// 为命名路由生成 URL
const logoutUrl = urlFor('auth.logout')
// 返回：'/logout'

const profileUrl = urlFor('users.profile', { id: '123' })
// 返回：'/users/123/profile'

方法特定的 URL 生成 ​

为了更多的控制，使用方法特定的变体如 urlFor.get 或 urlFor.post。这些返回包含 HTTP 方法和 URL 的对象。

ts
const userUrl = urlFor.get('users.show', { id: 1 })
// 返回：{ method: 'get', url: '/users/1' }

const createUserUrl = urlFor.post('users.store')
// 返回：{ method: 'post', url: '/users' }

当你需要同时知道 URL 和应使用哪个 HTTP 方法时（例如构建通用链接组件），这很有用。

URL 中的查询参数 ​

使用 qs 选项向生成的 URL 添加查询参数。查询参数自动 URL 编码并追加到生成的 URL。

ts
const postsUrl = urlFor.get('posts.index', {}, {
  qs: { page: 2, limit: 10, status: 'published' }
})
// 返回：{ method: 'get', url: '/posts?page=2&limit=10&status=published' }

通配符参数 ​

对于带通配符参数的路由，将它们作为数组传递。

ts
// 路由：router.get('docs/*', [controllers.Docs, 'show'])

const docsUrl = urlFor.get('docs.show', { '*': ['introduction', 'getting-started'] })
// 返回：{ method: 'get', url: '/docs/introduction/getting-started' }

位置参数 ​

你可以按照路由中出现的顺序将参数作为数组传递，而不是对象。

ts
// 路由：/users/:id/posts/:postId

// 使用对象语法
const url1 = urlFor.get('users.posts.show', { id: '123', postId: '456' })

// 使用数组语法（位置）
const url2 = urlFor.get('users.posts.show', ['123', '456'])

// 两者都返回：{ method: 'get', url: '/users/123/posts/456' }

当参数名称从上下文中很明显时，位置参数可能很方便。

路由内省 ​

Tuyau 提供两种在运行时检查路由的方法。这些对于构建高亮活动链接的导航组件或根据应用中可用路由有条件渲染 UI 很有用。

检查路由是否存在 ​

has() 方法检查注册表中是否存在路由名称。

ts
client.has('users.show')   // true
client.has('auth.login')   // true
client.has('nope')         // false

这对于根据当前应用中路由是否可用来有条件渲染 UI 元素很有用。

获取当前路由 ​

current() 方法使用 window.location 确定用户当前所在的路由。它只匹配可导航路由（GET 或 HEAD）。

不带参数时，它返回当前路由名称，如果没有路由匹配（或在服务端运行时）返回 undefined。

ts
// 在 /users/42
client.current() // 'users.show'

// 在 /unknown/path
client.current() // undefined

带路由名称时，如果当前 URL 匹配该路由，则返回 true。

ts
// 在 /users/42
client.current('users.show') // true
client.current('auth.login') // false

带通配符模式时，你可以使用 * 匹配路由组：

ts
// 在 /users/42
client.current('users.*')    // true
client.current('posts.*')    // false

带选项时，你可以额外验证当前 URL 参数和/或查询字符串是否匹配预期值。

ts
// 在 /users/42?foo=bar
client.current('users.show', { params: { id: 42 } })           // true
client.current('users.show', { params: { id: 99 } })           // false
client.current('users.show', { query: { foo: 'bar' } })        // true
client.current('users.show', { query: { foo: 'baz' } })        // false

类型级序列化 ​

使用 Tuyau 时需要理解的一个重要概念是类型级序列化。这指的是类型如何自动转换以匹配实际作为 JSON 通过网络发送的内容。

日期序列化 ​

当你从后端向前端传递 Date 对象时，它不能通过 JSON 作为 Date 对象传输。相反，它被序列化为字符串。Tuyau 的类型自动反映这种转换。

ts
export default class PostsController {
  async show({ params }: HttpContext) {
    const post = await Post.find(params.id)

    return {
      id: post.id,
      title: post.title,
      createdAt: new Date() // 这里是一个 Date 对象
    }
  }
}

在前端，Tuyau 自动将类型推断为 string，而不是 Date。这是因为日期在通过 HTTP 发送时被序列化为 ISO 字符串格式，Tuyau 的类型系统在编译时反映这一现实。

ts
const post = await client.api.posts.show({ params: { id: '1' } })

// TypeScript 知道 createdAt 是字符串，不是 Date
console.log(post.createdAt.toUpperCase()) // ✅ 有效 - 字符串方法
console.log(post.createdAt.getTime())     // ❌ 错误 - Date 方法不存在

模型序列化 ​

一个常见的错误是直接从控制器返回 Lucid 模型。当你这样做时，Tuyau 无法准确推断响应类型，因为模型序列化为包含几乎无有用类型信息的通用 ModelObject 类型。

ts
export default class PostsController {
  async show({ params }: HttpContext) {
    const post = await Post.find(params.id)
    return post // 模型被序列化，但类型丢失
  }
}

在前端，你会得到一个没有特定字段的通用 ModelObject 类型。

ts
const post = await client.api.posts.show({ params: { id: '1' } })
// post 具有类型 ModelObject - 无自动补全，无类型安全

为了保持类型安全，在返回模型之前使用 HTTP 转换器显式将它们转换为纯对象。

ts
export default class PostsController {
  async show({ params, serialize }: HttpContext) {
    const post = await Post.find(params.id)
    return serialize(PostTransformer.transform(post))
  }
}

现在前端具有准确的类型。

ts
const post = await client.api.posts.show({ params: { id: '1' } })
// post.title 是 string
// post.author.name 是 string
// 完整的自动补全和类型安全

SuperJSON ​

如上所述，当数据跨越 HTTP 边界时，像 Date、BigInt、Map 或 Set 这样的富 JavaScript 类型会丢失——它们被 JSON.stringify() 序列化为字符串或纯对象。SuperJSON 通过在序列化期间自动保留类型信息来解决这个问题，因此你在前端收到正确类型化的值，而不是普通字符串。

@tuyau/superjson 包同时提供服务器端中间件和客户端插件，它们透明地协同工作。

安装 ​

步骤 1：安装和配置包 ​

bash
node ace add @tuyau/superjson

这会在你的应用中注册 SuperJSON 中间件。中间件拦截响应并使用类型元数据序列化它们，然后在服务器上反序列化传入的请求体。

步骤 2：添加客户端插件 ​

在前端，创建 Tuyau 客户端时添加 superjson 插件。

ts
import { superjson } from '@tuyau/superjson/plugin'

const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  plugins: [superjson()],
})

基本设置就这些。像 Date、BigInt、Map、Set、RegExp 和 URL 这样的原生 JavaScript 类型现在会自动跨 HTTP 调用保留。

自定义配方 ​

SuperJSON 开箱即只处理原生 JavaScript 类型。如果你的应用使用自定义类——如 Luxon DateTime（Lucid 模型用于日期字段的类）——SuperJSON 不会识别它们，它们最终会在前端变成普通字符串。

你可以通过注册配方教 SuperJSON 如何处理任何自定义类型，配方包含三个内容：isApplicable 检查以识别类型，serialize 函数将其转换为 JSON 安全值，以及 deserialize 函数在另一端重建它。

由于配方必须在服务器和客户端都注册，它们应该放在两边都导入的共享文件中。

以下是 Luxon DateTime 的示例，这是 AdonisJS 应用中最常见的情况。

步骤 1：创建共享配方文件 ​

ts
import { DateTime } from 'luxon'
import SuperJSON from 'superjson'

SuperJSON.registerCustom<DateTime, string>(
  {
    isApplicable: (v) => DateTime.isDateTime(v),
    serialize: (v) => v.toISO()!,
    deserialize: (v) => DateTime.fromISO(v),
  },
  'DateTime'
)

步骤 2：注册为服务器预加载 ​

将配方文件添加到你的预加载，以便在服务器启动时运行。

ts
export default defineConfig({
  preloads: [
    () => import('#start/routes'),
    () => import('#start/kernel'),
    () => import('#app/superjson_recipes'),
  ],
})

步骤 3：在客户端导入 ​

在创建 Tuyau 客户端的地方导入同一个文件，以便在任何 API 调用之前注册配方。

ts
import '#app/superjson_recipes'
import { superjson } from '@tuyau/superjson/plugin'

const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  plugins: [superjson()],
})

与转换器的类型级集成 ​

当将自定义 SuperJSON 配方与 HTTP 转换器一起使用时，你需要告诉转换器类型系统某些类型不应在类型级别转换为字符串。没有这一点，即使 SuperJSON 在运行时保留它们，TypeScript 仍会在前端响应类型中将你的 DateTime 字段推断为 string。

在你的 API 提供者中添加模块扩充以扩展允许的 JSON 类型。

ts
declare module '@adonisjs/core/types/transformers' {
  interface ExtendedJSONTypes {
    DateTime: import('luxon').DateTime
  }
}

有了这个扩充，返回 DateTime 值的转换器将在生成的前端类型中保留 DateTime 类型，而不是将其转换为 string。

响应解析 ​

默认情况下，Tuyau 根据 Content-Type 头解析响应：application/json 为 JSON，application/octet-stream 为 ArrayBuffer，其他一切为文本。

你可以使用 responseType 选项（'json'、'text'、'arrayBuffer' 或 'blob'）按请求覆盖此行为。

ts
const blob = await client.api.files.download({
  params: { id: '123' },
  responseType: 'blob',
})

配置参考 ​

createTuyau 函数接受多个配置选项来自定义你的 API 客户端行为。

ts
const client = createTuyau({
  baseUrl: import.meta.env.VITE_API_URL || 'http://localhost:3333',
  registry,
})

baseUrl

类型：string，必需

你的 API 服务器的基础 URL。所有请求都以此 URL 为前缀。使用环境变量为开发和生产配置不同的 URL。

registry

类型：object，必需

生成的注册表，将路由名称映射到 URL 和类型。从 .adonisjs/client 中的生成文件导入，或在单体仓库设置中从你的后端包导入。

推荐选项 ​

这些可选设置对大多数应用高度推荐。

ts
const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  headers: { Accept: 'application/json' },
  credentials: 'include',
})

headers

类型：object

随每个请求发送的默认头。设置 Accept: 'application/json' 确保你的 API 返回 JSON 响应，而不是 HTML 错误页面或其他格式。

ts
headers: {
  Accept: 'application/json',
  'X-Custom-Header': 'value'
}

credentials

类型：string

控制跨源请求是否发送 cookie。设置为 'include' 以在前端和后端位于不同域时为基于会话的身份认证发送 cookie。

ts
credentials: 'include'

TIP

当设置了 credentials: 'include' 时，Tuyau 自动处理 CSRF 保护。它读取 XSRF-TOKEN cookie 并随每个请求将其作为 X-XSRF-TOKEN 头发送。无需额外配置。

高级选项 ​

Tuyau 构建在 Ky 之上，这意味着你可以向 createTuyau 传递任何 Ky 选项。一些有用的高级选项包括：

timeout

类型：number

请求超时（毫秒）。超过此时长的请求会自动中止。

ts
const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  timeout: 30000, // 30 秒
})

retry

类型：number | object

配置失败请求的自动重试行为。

ts
const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  retry: {
    limit: 3,
    methods: ['get', 'post'],
    statusCodes: [408, 413, 429, 500, 502, 503, 504]
  }
})

hooks

类型：object

添加请求/响应拦截器用于日志记录、身份认证或错误处理。

ts
const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  hooks: {
    beforeRequest: [
      request => {
        console.log('Request:', request.url)
      }
    ],
    afterResponse: [
      (request, options, response) => {
        console.log('Response:', response.status)
      }
    ],
    beforeError: [
      error => {
        console.error('Error:', error.message)
        return error
      }
    ]
  }
})

访问令牌身份认证 ​

对于使用访问令牌身份认证的 API（如 API 启动套件），使用 hooks.beforeRequest 选项动态地将 Authorization 头附加到每个请求。

ts
const client = createTuyau({
  baseUrl: 'http://localhost:3333',
  registry,
  headers: { Accept: 'application/json' },
  hooks: {
    beforeRequest: [
      (request) => {
        const token = localStorage.getItem('auth_token')
        if (token) {
          request.headers.set('Authorization', `Bearer ${token}`)
        }
      }
    ]
  }
})

此模式在每次请求前从存储读取令牌。你可以根据应用在登录后存储令牌的位置，调整它从不同来源（例如状态管理存储或 cookie）读取。

可用选项的完整列表，请参阅 Ky 文档。

过滤路由 ​

默认情况下，generateRegistry 包含所有命名路由。使用 routes 选项在生成的注册表中包含或排除特定路由。

ts
generateRegistry({
  routes: {
    only: ['api.*'],                          // 子字符串匹配
    // 或
    except: [/^admin\./, (name) => name.startsWith('internal.')],
  },
})

过滤器接受字符串（子字符串匹配）、RegExp 或函数。你不能同时使用 only 和 except。
