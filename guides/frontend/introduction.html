AdonisJS 中的前端 ​

让我们试着理解 AdonisJS 在其全栈范式中如何处理前端，以及它与元框架主流方法的区别。我们将通过清晰的视角来审视这些事情，而不会迷失在前端生态系统中常用的无数缩写词里。

概述 ​

与你可能从元框架中期望的不同，AdonisJS 对前端采取了根本不同的方法。

元框架主要强调前端和在客户端做更复杂的事情，通常将后端视为事后考虑或将其外包给第三方服务。AdonisJS 则相反：它是一个后端优先的框架，在前端默认保持极简。

这意味着 AdonisJS 不会强迫你进入特定的前端范式。相反，它为你提供了灵活性，让你选择最适合应用需求的前端方法。该框架为你提供了坚实的后端基础，内置身份认证、授权、速率限制和缓存等功能，因此你可以拥有自己的基础设施，而不是将关键功能外包给第三方服务。

不要期望什么 ​

如果你来自元框架，有些事情你不应该期望从 AdonisJS 中获得：

  • 没有基于文件的路由：路由在你的路由文件中显式定义，而不是从文件结构推断。
  • 没有“use”语句的编译器魔法：你不会找到模糊服务器和客户端代码界限的魔法指令。
  • 前后端之间没有模糊的边界：AdonisJS 在前端和后端代码库之间保持严格分离。同一个文件中不混合服务器和客户端代码，当这些层需要通信时，你使用清晰的 API 契约。

这种分离是有意为之的。它清晰地表明了代码在哪里执行，使调试变得直接，并允许团队在明确定义的边界下工作。

AdonisJS 中的视图层 ​

在 AdonisJS 遵循的 MVC（模型-视图-控制器）架构中，视图层是处理前端的部分。不同于将你锁定到特定前端技术的框架，AdonisJS 不规定你应该如何构建这一层。

你拥有完全的自由来选择对你的应用有意义的前端方法。这种灵活性是设计使然，而不是缺乏主见。该框架认识到不同的应用有不同的前端需求，强迫所有人采用单一方法会适得其反。

默认在前端保持极简，AdonisJS 让你可以从零构建工具开始开发简单的应用。当你需要更复杂的前端工具时，可以逐步引入。即使你添加了 Vite 等工具，设置仍然简单，没有神奇的“use”语句弄乱你的代码库。

你的前端选项 ​

AdonisJS 支持三种主要的构建前端的方法，每种都适合不同的用例和团队偏好。

服务端渲染模板 ​

服务端渲染模板在后端生成完整的 HTML 页面并将其发送到浏览器。AdonisJS 提供 Edge，一个强大的模板引擎，让你可以在客户端使用极少或零 JavaScript 构建动态 HTML。

这种方法让你的应用保持简单和高性能，由服务器处理所有渲染逻辑。你可以在需要时使用轻量级 JavaScript 库逐步添加交互性，但默认是在服务端渲染一切。

当你想要拥抱简单性，且应用的交互性极少、不需要 React 或 Vue 这样的完整前端库时，选择这种方法。这让你的技术栈保持精简并减少应用中的活动部件数量。

带 API 后端的 SPA ​

你可以使用 AdonisJS 构建 JSON API 后端，而前端则位于完全独立的代码库中。这创建了清晰的分离：AdonisJS 处理所有后端逻辑并通过 API 端点暴露数据，而你的前端应用（用 React、Vue、Angular 或任何框架构建）消费这些端点。

当你为多个客户端应用（如移动应用和 Web 应用）创建 API 时，选择这种方法。许多组织也偏好这种方式，因为它允许不同的团队在各自的代码库中工作，边界清晰。你需要根据团队结构和应用需求做出这一架构决策。

Inertia.js ​

Inertia.js 在服务端渲染模板和 SPA 之间提供了一种折中方案。你使用 React 或 Vue 组件作为视图，同时保留服务端路由和控制器。这让你获得现代前端框架的基于组件的开发体验，而无需构建和维护单独 SPA 的复杂性。

使用 Inertia，你保留服务端路由、消除双路由系统、减少前端大量状态管理的需求，并简化表单提交。你的应用保持单体部署，同时提供流畅的、类似 SPA 的用户体验。

当你想要使用 React 或 Vue 但偏好更紧密的全栈开发体验、前端活动部件更少时，选择这种方法。Inertia 消除了对双路由系统的需求、前端大量状态管理的需求，并简化了表单提交，同时仍然为你提供现代前端框架的能力。

下一步 ​

现在你了解了 AdonisJS 的前端方法，你可以探索具体的实现指南：

  • Edge 模板 - 学习如何构建服务端渲染应用
  • Inertia.js - 使用 React 或 Vue 设置 Inertia
  • Vite 集成 - 配置 Vite 进行资源打包
  • 转换器 - 为 API 响应转换数据
