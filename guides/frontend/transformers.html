转换器 ​

本指南涵盖 AdonisJS 应用中的数据转换。你将了解到如何：

  • 将类、BigInt 和 Lucid 模型等富数据类型序列化为 JSON，同时保留类型信息
  • 通过包含或排除字段来塑造 API 响应
  • 为不同的输出上下文使用转换器变体
  • 处理关系和分页
  • 生成 TypeScript 类型，消除前后端之间的重复类型定义

概述 ​

转换器提供了一种结构化的方式，将你的后端数据转换为面向 HTTP 客户端的 JSON 响应。在构建 API 或全栈应用时，你在后端使用的数据结构（Lucid 模型、自定义类、DateTime 对象）无法直接通过 HTTP 发送——所有内容必须先序列化为 JSON，而 JSON 本质上是一种字符串格式。

与其让 AdonisJS 隐式处理序列化，转换器让你显式控制这个过程。你确切定义要包含哪些字段、如何格式化它们以及响应应该采用什么形状。这种方法带来几个好处：

  • 你可以将敏感信息排除在响应之外
  • 在整个应用中应用一致的格式化规则
  • 围绕前端需求而不是数据库结构塑造响应
  • 并生成前端可以直接引用的 TypeScript 类型

TIP

如果你正在构建 Inertia 应用或任何返回 JSON 数据的 API，我们强烈建议对所有 HTTP 响应使用转换器。生成的 TypeScript 类型消除了维护重复类型定义的需要，确保你的前端和后端自动保持同步。

理解 JSON 序列化 ​

在深入了解转换器之前，理解它们为什么存在很重要。当你通过 HTTP 发送数据时，所有内容都必须转换为字符串——具体来说是 JSON 字符串。这意味着你编程语言中的富数据类型无法直接传输。

考虑一个 Lucid 模型，其中 createdAt 字段是一个 Luxon DateTime 对象。在 JavaScript/TypeScript 中，这是一个复杂对象，带有 .toISO() 和 .diff() 等方法。但当通过 HTTP 发送时，它必须变成一个简单的字符串，如 "2024-01-15T10:30:00.000Z"。同样，BigInt 值或自定义类实例也必须转换为 JSON 兼容格式。

没有显式的序列化控制，你可能意外暴露敏感数据、发送不一致的日期格式，或包含前端不需要的内部实现细节。转换器通过要求你明确指定什么被序列化以及如何序列化来解决这个问题。

创建你的第一个转换器 ​

让我们从一个实际示例开始。假设你有一个 Post 模型，需要将帖子数据返回给前端。首先，以下是 Post 模型的样子。

ts
import User from '#models/user'
import { DateTime } from 'luxon'
import { BaseModel, belongsTo, column } from '@adonisjs/lucid/orm'
import type { BelongsTo } from '@adonisjs/lucid/types/relations'

export default class Post extends BaseModel {
  @column({ isPrimary: true })
  declare id: number

  @column()
  declare userId: number

  @column()
  declare title: string

  @column()
  declare content: string

  @column.dateTime({ autoCreate: true })
  declare createdAt: DateTime

  @column.dateTime({ autoCreate: true, autoUpdate: true })
  declare updatedAt: DateTime

  @belongsTo(() => User)
  declare author: BelongsTo<typeof User>
}

步骤 1：生成转换器 ​

运行以下命令为帖子创建转换器。

bash
node ace make:transformer post
# CREATE: app/transformers/post_transformer.ts

这会在 app/transformers 目录中创建一个具有以下默认结构的文件。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import Post from '#models/post'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return this.pick(this.resource, ['id'])
  }
}

转换器继承 BaseTransformer，并使用泛型类型参数指定它转换什么（在这种情况下是 Post）。toObject() 方法定义默认输出形状。this.resource 属性让你访问正在转换的 Post 实例。

步骤 2：定义输出形状 ​

toObject() 方法决定 JSON 响应中出现哪些字段。this.pick() 辅助函数从模型中选择特定字段。让我们扩展转换器以包含我们想要的字段。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return this.pick(this.resource, [
      'id',
      'title',
      'content',
      'createdAt',
      'updatedAt'
    ])
  }
}

此转换器显式只包含这五个字段。Post 模型上的任何其他字段（如内部元数据或敏感数据）都将被排除在输出之外。

步骤 3：在控制器中使用转换器 ​

现在让我们在控制器中使用此转换器返回数据。如果尚未存在，使用 node ace make:controller posts 命令创建控制器。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ serialize }: HttpContext) {
    const posts = await Post.all()
    return serialize(PostTransformer.transform(posts))
  }

  async show({ serialize, params }: HttpContext) {
    const post = await Post.findOrFail(params.id)
    return serialize(PostTransformer.transform(post))
  }
}

模式很直接：用你的数据调用 PostTransformer.transform()，然后将结果包裹在 HTTP 上下文的 serialize() 辅助函数中。serialize() 函数处理实际的 JSON 转换并发送响应。

同一个转换器既适用于单个帖子，也适用于帖子集合。AdonisJS 会自动检测你是在转换一个项目还是多个项目，并相应地构造输出。

步骤 4：注册路由 ​

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('posts', [controllers.Posts, 'index'])
router.get('posts/:id', [controllers.Posts, 'show'])

步骤 5：理解生成的类型 ​

当你使用 node ace serve --hmr 启动开发服务器时，AdonisJS 会自动为你的转换器生成 TypeScript 类型。这些类型存储在 .adonisjs/client/data.d.ts 中。

ts
import type { InferData, InferVariants } from '@adonisjs/core/types/transformers'
import type PostTransformer from '#transformers/post_transformer'

export namespace Data {
  export type Post = InferData<PostTransformer>

  export namespace Post {
    export type Variants = InferVariants<PostTransformer>
  }
}

你的前端代码现在可以导入并使用这些类型。在 Inertia 应用中，有一个预配置的别名使其更方便。

ts
import { Data } from '~/generated/data'

type Post = Data.Post

这意味着你的前端自动知道来自 API 的数据的确切形状。如果你在转换器中添加或删除字段，TypeScript 类型会在开发服务器重新加载时自动更新。你永远不需要手动维护重复的类型定义。

资源项和集合 ​

转换器自动处理单个资源和集合。当你调用 PostTransformer.transform() 时，根据你传入的内容，它返回 ResourceItem 或 ResourceCollection。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async show({ serialize, params }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    // 返回 ResourceItem（单个帖子）
    return serialize(PostTransformer.transform(post))
  }

  async index({ serialize }: HttpContext) {
    const posts = await Post.all()

    // 返回 ResourceCollection（帖子数组）
    return serialize(PostTransformer.transform(posts))
  }
}

序列化输出结构在项目和集合之间略有不同。单个项目直接返回你转换后的对象，而集合将项目包裹在 data 数组中。两者都经过你在转换器中定义的同一个 toObject() 方法。

分页数据 ​

处理大型数据集时，你通常会分页结果。Lucid 的查询构建器提供 paginate() 方法，返回数据行和分页元数据。转换器有专门的方法处理分页响应。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ serialize, request }: HttpContext) {
    const page = request.input('page', 1)
    const posts = await Post.query().paginate(page, 20)

    const data = posts.all()
    const metadata = posts.getMeta()

    return serialize(PostTransformer.paginate(data, metadata))
  }
}

PostTransformer.paginate() 方法接受两个参数：要转换的数据数组和分页元数据。生成的 JSON 响应同时包含转换后的数据和分页信息。

json
{
  "data": [
    {
      "id": 1,
      "title": "First Post",
      "content": "...",
      "createdAt": "2024-01-15T10:30:00.000Z",
      "updatedAt": "2024-01-15T10:30:00.000Z"
    }
  ],
  "metadata": {
    "total": 100,
    "perPage": 20,
    "currentPage": 1,
    "lastPage": 5,
    "firstPage": 1,
    "firstPageUrl": "/?page=1",
    "lastPageUrl": "/?page=5",
    "nextPageUrl": "/?page=2",
    "previousPageUrl": null
  }
}

你的前端可以使用 metadata 对象构建分页控件，而 data 数组包含转换后的帖子。

在 Inertia 中使用转换器 ​

构建 Inertia 应用时，你可以直接将转换器资源传递给 inertia.render() 而不使用 serialize() 辅助函数。Inertia 适配器自动处理 ResourceItem 和 ResourceCollection 对象的序列化。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ inertia }: HttpContext) {
    const posts = await Post.all()

    return inertia.render('posts/index', {
      posts: PostTransformer.transform(posts)
    })
  }

  async show({ inertia, params }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    return inertia.render('posts/show', {
      post: PostTransformer.transform(post)
    })
  }
}

所有转换器功能与 Inertia 一起使用时工作方式完全相同——包括变体、关系和自定义数据。在本指南的其余部分，我们将在示例中使用 serialize() 辅助函数，但使用 inertia.render() 时相同的原则也适用。

处理关系 ​

转换器可以通过与其他转换器组合来包含相关数据。应用中的每个实体都应该有自己的转换器，这些转换器在包含关系时可以相互引用。

基本关系包含 ​

首先，让我们为 User 模型创建一个转换器。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type User from '#models/user'

export default class UserTransformer extends BaseTransformer<User> {
  toObject() {
    return this.pick(this.resource, [
      'id',
      'fullName',
      'email',
      'createdAt',
      'updatedAt',
      'initials'
    ])
  }
}

现在你可以使用 UserTransformer 在 PostTransformer 中包含帖子的作者。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'
import UserTransformer from '#transformers/user_transformer'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return {
      ...this.pick(this.resource, [
        'id',
        'title',
        'content',
        'createdAt',
        'updatedAt'
      ]),
      author: UserTransformer.transform(this.resource.author)
    }
  }
}

关系只能作为转换器输出中的顶层属性出现。你通过用相关模型实例调用转换器的 transform() 方法来组合转换器。

预加载关系

转换器不发出任何数据库查询。它们只使用你已经加载的数据。如果你忘记预加载关系并尝试转换它，你将访问 undefined 数据并得到运行时错误。

条件关系 ​

有时关系可能根据请求上下文被加载或不被加载。例如，你可能只为特定端点预加载作者。在这些情况下，你需要显式防范 undefined 值。

this.whenLoaded() 辅助函数在尝试转换关系之前检查它是否已被加载。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'
import UserTransformer from '#transformers/user_transformer'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return {
      ...this.pick(this.resource, [
        'id',
        'title',
        'content',
        'createdAt',
        'updatedAt'
      ]),
      author: UserTransformer.transform(
        this.whenLoaded(this.resource.author)
      )
    }
  }
}

现在如果 author 关系尚未加载，转换器不会抛出错误。author 字段将简单地从输出中省略。如果你偏好更显式的控制，也可以使用三元运算符。

ts
author: this.resource.author
  ? UserTransformer.transform(this.resource.author)
  : undefined

控制关系深度 ​

默认情况下，转换器将关系序列化到一层深度。这防止意外过度获取前端可能不需要的嵌套数据。例如，如果 User 有 Posts 且每个 Post 有 Comments，默认情况下只序列化第一层（User → Posts）。

你可以使用 .depth() 方法手动控制此深度。

ts
toObject() {
  return {
    ...this.pick(this.resource, ['id', 'fullName', 'email']),
    posts: PostTransformer
      .transform(this.resource.posts)
      .depth(2)  // 现在序列化 user → posts → comments
  }
}

使用 .depth(2)，如果你预加载嵌套关系，它们将包含在转换中。这让你对每个关系的序列化深度进行细粒度控制。

深度如何在嵌套转换器中工作：

  • 你在顶层设置的深度值控制整个关系树
  • 在上面的示例中，当 UserTransformer 对 posts 设置 .depth(2) 时，该深度适用于 posts 内的所有嵌套关系——包括 comments
  • 即使 PostTransformer 有自己的深度设置，它们也不会覆盖父转换器设置的深度
  • 深度在起始点确定并向下级联到整个树

使用变体 ​

单个转换器可以为不同上下文产生不同的输出形状。当同一资源需要在应用中不同地显示时这很有用——例如，列表视图的轻量级版本和单项视图的详细版本。

定义变体 ​

变体通过在转换器中与 toObject() 一起创建额外方法来定义。这些方法可以命名为任何名称，但我们建议使用一致的约定如 for<Purpose> 以使它们的意图清晰。

ts
import type Post from '#models/post'
import UserTransformer from '#transformers/user_transformer'
import { BaseTransformer } from '@adonisjs/core/transformers'

export default class PostTransformer extends BaseTransformer<Post> {
  /**
   * 列出帖子的默认变体
   */
  toObject() {
    return {
      ...this.pick(this.resource, ['id', 'title', 'createdAt', 'updatedAt']),
      author: UserTransformer.transform(this.resource.author)
    }
  }

  /**
   * 显示单个帖子的详细变体
   * 包含转换为 HTML 的完整 markdown 内容
   */
  async forDetailedView() {
    return {
      ...this.toObject(),
      content: await markdownToHtml(this.resource.content)
    }
  }
}

默认的 toObject() 方法返回适合显示帖子列表的基本字段。forDetailedView() 变体扩展了这一点，添加了额外计算数据——在这种情况下，将 markdown 内容转换为 HTML。注意变体方法如果需要执行异步操作可以是异步的。

你可以通过调用 this.toObject() 并展开其结果来重用默认变体，然后添加或覆盖特定字段。这使你的变体保持 DRY 并确保一致性。

在控制器中使用变体 ​

要使用变体，在转换后的资源上调用 .useVariant() 方法。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  /**
   * 使用默认变体列出所有帖子
   */
  async index({ serialize }: HttpContext) {
    const posts = await Post.query().preload('author')
    return serialize(PostTransformer.transform(posts))
  }

  /**
   * 使用详细变体显示单个帖子
   */
  async show({ serialize, params }: HttpContext) {
    const post = await Post.query()
      .where('id', params.id)
      .preload('author')
      .firstOrFail()

    return serialize(
      PostTransformer.transform(post).useVariant('forDetailedView')
    )
  }
}

.useVariant() 方法接受变体方法的名称作为字符串。当响应被序列化时，它将调用 forDetailedView() 而不是默认的 toObject()。

前端的变体类型 ​

生成的 TypeScript 类型包含所有变体的定义。你的前端代码可以指定它期望的变体类型。

ts
import { Data } from '~/generated/data'
import { InertiaProps } from '~/types'

export default function ShowPost(
  props: InertiaProps<{
    post: Data.Post.Variants['forDetailedView']
  }>
) {
  // TypeScript 知道此帖子包含来自 forDetailedView 变体的 'content' 字段
}

使用 Data.<Resource>.Variants['<variantName>'] 访问变体类型。这确保你的前端组件接收与你的 API 为该特定变体返回的确切形状匹配的正确类型化 props。

依赖注入 ​

转换器方法可以使用 @inject() 装饰器从 AdonisJS 的 IoC 容器注入依赖。当你需要在转换期间访问服务或上下文信息时这很有用。

注入 HttpContext ​

一个常见用例是注入 HttpContext 以访问当前已认证用户。这允许你在转换期间计算授权权限或用户特定数据。

ts
import type Post from '#models/post'
import { inject } from '@adonisjs/core'
import { HttpContext } from '@adonisjs/core/http'
import UserTransformer from '#transformers/user_transformer'
import { BaseTransformer } from '@adonisjs/core/transformers'

export default class PostTransformer extends BaseTransformer<Post> {
  toObject() {
    return {
      ...this.pick(this.resource, [
        'id',
        'title',
        'createdAt',
        'updatedAt'
      ]),
      author: UserTransformer.transform(this.resource.author)
    }
  }

  /**
   * 带有授权检查的详细变体
   */
  @inject()
  async forDetailedView({ auth }: HttpContext) {
    return {
      ...this.toObject(),
      content: await markdownToHtml(this.resource.content),
      can: {
        view: true,
        edit: auth.user?.id === this.resource.userId,
        delete: auth.user?.id === this.resource.userId
      }
    }
  }
}

@inject() 装饰器告诉 AdonisJS 为此方法解析依赖。你可以从注入的 HttpContext 解构属性，如 auth、request 或你需要的任何其他上下文属性。

依赖注入如何工作 ​

当你调用 PostTransformer.transform(post) 时，它返回 ResourceItem 或 ResourceCollection 对象。这些对象不会立即执行你的转换器方法。相反，当你将它们传递给 serialize() 时，那是 IoC 容器解析依赖并用注入的值调用你的转换器方法的时候。

这意味着依赖注入在你的控制器中的序列化阶段自动发生。你不需要手动传递 HttpContext 或其他依赖——框架为你处理这些。

向转换器传递自定义数据 ​

有时你需要向转换器传递除被序列化资源之外的额外上下文。例如，你可能想包含用户特定数据，如当前用户是否喜欢了某个帖子，或影响数据转换方式的配置。

你可以通过在转换器的构造函数中接受额外参数来向转换器传递自定义数据。这些参数在 transform() 方法中位于资源参数之后。

ts
import { BaseTransformer } from '@adonisjs/core/transformers'
import type Post from '#models/post'

export default class PostTransformer extends BaseTransformer<Post> {
  constructor(
    resource: Post,
    protected likedPostsIds: number[]
  ) {
    super(resource)
  }

  toObject() {
    return {
      ...this.pick(this.resource, [
        'id',
        'title',
        'createdAt',
        'updatedAt'
      ]),
      isLiked: this.likedPostsIds.includes(this.resource.id)
    }
  }
}

调用转换器时，在资源之后将自定义数据作为额外参数传递。

ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'
import PostTransformer from '#transformers/post_transformer'

export default class PostsController {
  async index({ serialize, auth }: HttpContext) {
    const posts = await Post.all()

    // 获取当前用户已点赞的帖子 ID
    const likedPosts = await auth.user!
      .related('likedPosts')
      .query()
      .select('id')

    return serialize(
      PostTransformer.transform(posts, likedPosts.map(({ id }) => id))
    )
  }
}

由于自定义数据作为实例属性存储，它也会自动在所有变体方法中可用。这种模式与依赖注入、变体和所有其他转换器功能无缝协作。

重要区别 ​

在你开始在应用中使用转换器之前，理解它们是什么以及何时使用它们很重要。

转换器不是 DTO ​

重要的是要理解转换器不是用于请求验证的数据传输对象（DTO）。它们服务于不同的目的：

  • DTO 定义输入契约：它们验证和塑造从请求进入应用的数据
  • 转换器定义输出契约：它们塑造从应用在响应中发出的数据

不要使用转换器来验证或转换请求数据。为此使用 AdonisJS 的验证系统。转换器专门用于将你的后端数据结构序列化为面向客户端的 JSON 响应。

何时使用转换器 ​

在任何后端向客户端返回 JSON 数据的情况下使用转换器：

  • Inertia 应用：前端和后端位于同一代码库的全栈 TypeScript 应用
  • REST API：由独立前端应用（React、Vue、Angular SPA）消费的 API
  • 移动 API：为移动应用提供服务的后端
  • 任何 JSON 响应：你通过 HTTP 发送结构化数据的任何地方

生成的 TypeScript 类型在 Inertia 应用或全栈 TypeScript 单体仓库中最有用，你的前端可以直接从后端导入类型。移动客户端通常不会利用生成的类型，但它们仍然从转换器提供的一致、良好成形的 JSON 响应中受益。
