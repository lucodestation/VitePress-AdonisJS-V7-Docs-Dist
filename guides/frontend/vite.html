Vite ​

本指南涵盖在 AdonisJS 中使用 Vite 进行前端资源打包。你将了解到如何：

  • 安装和配置 Vite 集成
  • 定义入口点并在 Edge 模板中引用资源
  • 在构建中包含图片和字体等静态资源
  • 加载由 Vite 处理的服务端模块
  • 为前端代码配置 TypeScript
  • 配合 React 启用热模块替换
  • 将打包资源部署到 CDN

概述 ​

Vite 是一个现代前端构建工具，提供快速的开发服务器启动和即时热模块替换。AdonisJS 将 Vite 直接嵌入开发服务器，而不是将其作为单独进程运行。这种嵌入式方法意味着你在开发期间只需管理一个服务器，AdonisJS 可以直接访问 Vite 的模块运行器以实现服务器端渲染等功能。

该集成处理了将 Vite 与后端框架连接的复杂性。在开发期间，AdonisJS 通过中间件将资源请求代理到 Vite。在生产环境中，AdonisJS 读取 Vite 生成的 manifest 文件以解析打包资源的正确路径。

官方 @adonisjs/vite 包提供用于生成资源 URL 的 Edge 辅助函数和标签、简化配置的专用 Vite 插件，以及用于加载由 Vite 处理的服务端模块的运行时 API。

另请参阅：Vite 文档

安装 ​

运行以下命令安装和配置该包。这会同时安装 @adonisjs/vite 和 vite，然后创建必要的配置文件。该集成需要 vite@8 或更高版本。

sh
node ace add @adonisjs/vite
查看 configure 命令执行的步骤
  1. 在 adonisrc.ts 文件中注册以下服务提供者。
ts
{
  providers: [
    // ...其他提供者
    () => import('@adonisjs/vite/vite_provider')
  ]
}
  1. 创建 vite.config.ts 和 config/vite.ts 配置文件。
  2. 在 resources/js/app.js 创建前端入口文件。

安装后，将以下内容添加到你的 adonisrc.ts 文件以将 Vite 与构建过程集成。

ts
import { defineConfig } from '@adonisjs/core/build/standalone'

export default defineConfig({
  hooks: {
    buildStarting: [() => import('@adonisjs/vite/build_hook')],
  },
})

hooks 属性注册 Vite 构建钩子，以便在你运行 node ace build 时执行 Vite 构建过程。

另请参阅：Assembler 钩子

配置 ​

设置过程创建两个配置文件。vite.config.ts 文件配置 Vite 打包器本身，而 config/vite.ts 配置 AdonisJS 在后端如何与 Vite 交互。

Vite 配置 ​

vite.config.ts 文件是标准的 Vite 配置文件。你可以根据项目需求在此安装和注册额外的 Vite 插件。

AdonisJS 插件接受以下选项。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      /**
       * 前端代码的入口点文件。每个入口点
       * 产生单独的输出包。你可以为应用的不同部分
       * 定义多个入口点。
       */
      entryPoints: ['resources/js/app.js'],

      /**
       * 更改时触发浏览器重新加载的文件的 glob 模式。
       * 对于 Vite 不跟踪的模板文件很有用。
       */
      reload: ['resources/views/**/*.edge'],
    }),
  ]
})

entryPoints

前端代码的入口点文件。每个入口点产生单独的输出包。你可以为应用的不同部分定义多个入口点，例如一个用于公共网站，另一个用于管理面板。此选项是必需的。

ts
{
  entryPoints: ['resources/js/app.js', 'resources/js/admin.js']
}

buildDirectory

打包资源输出目录的相对路径。该值作为 build.outDir 传递给 Vite，默认为 public/assets。

如果你更改此选项，还必须同时更新 config/vite.ts 文件中的 buildDirectory 值，以保持两个配置同步。

ts
{
  buildDirectory: 'public/dist'
}

reload

更改时触发完整浏览器重新加载的文件的 glob 模式。对于 Vite 不跟踪的文件（如 Edge 模板）使用此选项。默认为 ['./resources/views/**/*.edge']。

ts
{
  reload: ['resources/views/**/*.edge']
}

assetsUrl

生产环境中生成资源链接的 URL 前缀。当将打包资源部署到 CDN 时，将其设置为你的 CDN URL。默认为 /assets。

ts
{
  assetsUrl: 'https://cdn.example.com/'
}

assets

要包含在构建中的额外文件，这些文件不由入口点导入，如仅在 Edge 模板中引用的图片和字体。完整示例请参阅处理静态资源。

ts
{
  assets: ['resources/images/**']
}

serverEntryPoints

与前端代码分开打包的服务端入口点。每个入口在运行时可以使用 vite.loadServerModule 方法加载。完整示例请参阅加载服务端模块。

ts
{
  serverEntryPoints: ['resources/emails/verify_email.tsx']
}

TIP

Vite 8 使用 Rolldown 作为其打包器。如果你从旧项目复制 Vite 配置，请将 build.rollupOptions 属性替换为 build.rolldownOptions。

AdonisJS 配置 ​

config/vite.ts 文件告诉 AdonisJS 在哪里找到 Vite 的构建输出以及如何生成资源 URL。

ts
import { defineConfig } from '@adonisjs/vite'

export default defineConfig({
  /**
   * Vite 构建输出目录的路径。必须与
   * vite.config.ts 中的 buildDirectory 选项匹配。
   */
  buildDirectory: 'public/assets',

  /**
   * 资源链接的 URL 前缀。如果你将资源部署到
   * CDN，在生产环境中设置为你的 CDN URL。
   */
  assetsUrl: '/assets',
})

buildDirectory

Vite 构建输出目录的路径。该值必须与 vite.config.ts 文件中的 buildDirectory 选项匹配。

assetsUrl

生产环境中生成资源链接的 URL 前缀。该值必须与 vite.config.ts 文件中的 assetsUrl 选项匹配。

scriptAttributes

由 @vite 标签生成的每个 script 标签上要添加的键值对属性。

styleAttributes

由 @vite 标签生成的每个 link 标签上要添加的键值对属性。

你可以向生成的 script 和 link 标签添加自定义属性。

ts
import { defineConfig } from '@adonisjs/vite'

export default defineConfig({
  buildDirectory: 'public/assets',
  assetsUrl: '/assets',
  scriptAttributes: {
    defer: true,
  },
})

对于基于正在加载的资源的条件属性，传递函数代替。

ts
import { defineConfig } from '@adonisjs/vite'

export default defineConfig({
  buildDirectory: 'public/assets',
  assetsUrl: '/assets',
  styleAttributes: ({ src, url }) => {
    if (src === 'resources/css/admin.css') {
      return {
        'data-turbo-track': 'reload'
      }
    }
  }
})

目录结构 ​

AdonisJS 不强制要求前端资源的特定目录结构。但是，我们建议将它们存储在 resources 目录中，并为每种资源类型建立子目录。

sh
resources
├── css
│   └── app.css
├── js
│   └── app.js
├── fonts
└── images

Vite 默认将打包文件输出到 public/assets。/assets 子目录将 Vite 输出与 public 文件夹中你可能不希望 Vite 处理的其他静态文件分开。

启动开发服务器 ​

使用 --hmr 标志启动应用以启用热模块替换。AdonisJS 自动将资源请求代理到嵌入的 Vite 服务器。

sh
node ace serve --hmr

热模块替换（HMR） 允许 Vite 在浏览器中更新模块而无需完整页面重载。当你编辑 CSS 文件或 JavaScript 模块时，更改会立即出现，同时保留应用状态。

在模板中包含入口点 ​

使用 @vite Edge 标签为你的入口点渲染 script 和 link 标签。该标签接受入口点路径数组并生成适当的 HTML 标签。

edge
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  @vite(['resources/js/app.js'])
</head>
<body>
  @!section('content')
</body>
</html>

我们建议在 JavaScript 入口点内导入 CSS 文件，而不是将它们注册为单独的入口点。这种方法让 Vite 自动处理 CSS 处理和热替换。

ts
/**
 * 在 JavaScript 入口点中导入 CSS。Vite 处理
 * CSS 并自动处理热替换。
 */
import '../css/app.css'

在模板中引用资源 ​

Vite 构建入口点导入文件的依赖图并更新打包输出中的路径。但是，Vite 无法检测仅在 Edge 模板中引用的资源，因为它不解析模板文件。

使用 asset 辅助函数为 Vite 处理的文件创建 URL。在开发期间，辅助函数返回 AdonisJS 服务器提供的文件路径，该服务器将请求转发到嵌入的 Vite 开发服务器。在生产环境中，它返回带有文件名内容哈希的打包文件路径。

edge
<img src="{{ asset('resources/images/logo.png') }}" alt="Logo">
html
<!-- 开发环境输出 -->
<img src="/resources/images/logo.png" alt="Logo">
html
<!-- 生产环境输出 -->
<img src="/assets/logo-3bc29777.png" alt="Logo">

处理静态资源 ​

Vite 忽略不由前端代码导入的静态资源。仅在 Edge 模板中引用的图片、字体和图标属于此类，会在生产构建中缺失。

使用 AdonisJS 插件的 assets 选项将这些文件包含在构建中。Glob 模式会被展开，每个匹配的文件由 Vite 处理，在文件名中获得内容哈希。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entryPoints: ['resources/js/app.js'],
      assets: ['resources/images/**', 'resources/fonts/**'],
    }),
  ]
})

注册文件后，你可以使用 asset 辅助函数在模板中引用它们。

edge
<img src="{{ asset('resources/images/hero.jpg') }}" alt="Hero image">

不处理直接输出文件 ​

通过 glob 模式注册的文件会经过 Vite 的构建管道，这意味着其他插件可以转换其内容。当文件必须按原样复制到构建输出时，使用 assets 选项的对象形式。

chunks 属性的行为与数组形式完全相同。assets 属性接受精确文件路径（不允许 glob 模式，会抛出错误）并将每个文件作为原始资源输出。两种形式都在 manifest 中以其源路径注册文件，因此 asset 辅助函数以相同方式解析它们。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entryPoints: ['resources/js/app.js'],
      assets: {
        chunks: ['resources/images/**'],
        assets: ['resources/documents/terms.pdf'],
      },
    }),
  ]
})

加载服务端模块 ​

有些 TypeScript 模块必须在你的 Node.js 进程内运行，但仍需要 Vite 的处理才能执行。使用 React Email 编写的邮件模板是一个很好的例子。它们以 .tsx 文件内的 React 组件形式编写，因此 Node.js 无法直接导入它们，但它们在服务器上渲染而不是在浏览器中。

serverEntryPoints 选项和 vite.loadServerModule 方法一起解决了这个问题。你在 Vite 配置中声明模块，AdonisJS 在运行时通过 Vite 加载它们。

在开发期间，模块通过 Vite 的模块运行器求值，具有完整的 TypeScript、JSX 和插件支持。Vite 的 HMR 保持模块新鲜，因此编辑文件会在下次加载时反映，无需重启服务器。当你为生产构建时，每个服务端入口点被打包到构建输出中的 server 目录，loadServerModule 则改为导入预构建文件。

首先在 serverEntryPoints 选项中声明模块。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entryPoints: ['resources/js/app.js'],
      serverEntryPoints: ['resources/emails/verify_email.tsx'],
    }),
  ]
})

接下来，创建邮件模板。组件及其渲染逻辑保持在 .tsx 文件内，因此应用的其余部分只处理纯字符串。

tsx
import { render } from '@react-email/render'
import { Html, Button, Text } from '@react-email/components'

function VerifyEmail(props: { verificationUrl: string }) {
  return (
    <Html lang="en">
      <Text>Click the button below to verify your email address.</Text>
      <Button href={props.verificationUrl}>Verify email</Button>
    </Html>
  )
}

export default function renderVerifyEmail(props: { verificationUrl: string }) {
  return render(<VerifyEmail {...props} />)
}

最后，在需要的地方使用 vite.loadServerModule 方法加载模块。以下示例在发送邮件时将邮件渲染为 HTML 字符串。

ts
import mail from '@adonisjs/mail/services/main'
import vite from '@adonisjs/vite/services/main'

export default class SignupsController {
  async store() {
    const { default: renderVerifyEmail } = await vite.loadServerModule<
      typeof import('../../resources/emails/verify_email.tsx')
    >('resources/emails/verify_email.tsx')

    const html = await renderVerifyEmail({
      verificationUrl: 'https://example.com/verify/token',
    })

    await mail.send((message) => {
      message.to('user@example.com').subject('Verify your email address').html(html)
    })
  }
}

WARNING

传递给 loadServerModule 的入口路径必须在 serverEntryPoints 选项中声明。否则，打包文件在生产环境中不存在，导入将失败。

类型化服务端模块 ​

与其在每次调用时传递模块类型，你可以通过合并到 ServerModuleMap 接口来全局注册条目。合并后，入口路径会自动补全，loadServerModule 的返回值会自动类型化。

ts
declare module '@adonisjs/vite/types' {
  interface ServerModuleMap {
    'resources/emails/verify_email.tsx': typeof import('../resources/emails/verify_email.tsx')
  }
}

重新求值模块 ​

默认情况下，loadServerModule 信任 Vite 的 HMR 在源文件更改时使缓存模块失效。如果模块注册了必须在每次加载时重置的顶层状态，传递 fresh 选项以在导入之前清除模块运行器缓存。该选项仅在开发期间适用。在生产环境中，打包导入始终被缓存。

ts
await vite.loadServerModule('resources/emails/verify_email.tsx', { fresh: true })

TypeScript 配置 ​

如果你为前端代码使用 TypeScript，在 resources 目录内创建一个单独的 tsconfig.json。Vite 和你的代码编辑器将为 resources 目录内的 TypeScript 文件使用此配置。

json
{
  "extends": "../tsconfig.json",
  "compilerOptions": {
    "baseUrl": ".",
    "lib": ["DOM"],
    "paths": {
      "@/*": ["./js/*"]
    }
  }
}

如果你使用 React，添加 jsx 选项。

json
{
  "extends": "../tsconfig.json",
  "compilerOptions": {
    "baseUrl": ".",
    "lib": ["DOM"],
    "jsx": "preserve",
    "paths": {
      "@/*": ["./js/*"]
    }
  }
}

配合热模块替换的 React ​

要在开发期间启用 React Fast Refresh，在布局中的 @vite 标签之前添加 @viteReactRefresh Edge 标签。

edge
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  @viteReactRefresh()
  @vite(['resources/js/app.js'])
</head>
<body>
  <div id="root"></div>
</body>
</html>

然后在你的 Vite 配置中配置 React 插件。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [
    adonisjs({
      entryPoints: ['resources/js/app.js'],
    }),
    react(),
  ],
})

将资源部署到 CDN ​

要在生产环境中从 CDN 提供打包资源，在两个配置文件中配置 assetsUrl 选项。这确保 manifest 文件中的 URL 和懒加载块指向你的 CDN 服务器。

ts
import { defineConfig } from 'vite'
import adonisjs from '@adonisjs/vite/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entryPoints: ['resources/js/app.js'],
      reload: ['resources/views/**/*.edge'],
      assetsUrl: 'https://cdn.example.com/',
    }),
  ]
})
ts
import { defineConfig } from '@adonisjs/vite'

export default defineConfig({
  buildDirectory: 'public/assets',
  assetsUrl: 'https://cdn.example.com/',
})

使用 node ace build 构建应用后，将 public/assets 的内容上传到你的 CDN。

常见问题 ​

生产环境中资源不加载 ​

如果资源在生产环境中加载失败，验证 Vite 是否在 public/assets/.vite/manifest.json 生成了 manifest 文件。manifest 将源文件映射到它们的打包输出路径。

如果 manifest 缺失，确保构建钩子已在 adonisrc.ts 中注册并再次运行 node ace build。

静态图片在构建中缺失 ​

仅在模板中引用的图片和其他静态资源不会自动包含在构建中。Vite 只处理由你的 JavaScript 代码导入的文件。

使用 AdonisJS 插件的 assets 选项注册这些文件，如处理静态资源部分所述。

ts
adonisjs({
  entryPoints: ['resources/js/app.js'],
  assets: ['resources/images/**', 'resources/fonts/**'],
})

如果你的图片在升级到 Vite 8 后消失了，检查你的入口点中的 import.meta.glob 调用。Vite 8 不再通过 glob 导入输出非 JavaScript 文件，因此这些模式必须移到 assets 选项。

HMR 不工作 ​

热模块替换在启动开发服务器时需要 --hmr 标志。

sh
node ace serve --hmr

如果 HMR 仍不工作，检查浏览器控制台的 WebSocket 连接错误。防火墙或代理配置可能阻止 HMR WebSocket 连接。

中间件模式 ​

从 3.x 版本开始，Vite 以中间件模式运行。AdonisJS 不是将 Vite 作为具有自己服务器的单独进程启动，而是嵌入 Vite 并通过中间件代理匹配的请求。

中间件模式的优点包括直接访问 Vite 的模块运行器以加载服务端模块，以及只需管理一个开发服务器。所有资源都通过 AdonisJS 提供，而不是单独的 Vite 进程。

另请参阅：Vite SSR 文档

Manifest 文件 ​

当你为生产构建时，Vite 在打包资源旁边生成一个 manifest 文件。manifest 是一个 JSON 文件，将源文件路径映射到它们的打包输出路径，包括内容哈希。

AdonisJS 读取此 manifest 以解析资源 URL。当你在生产环境中调用 asset 辅助函数或使用 @vite 标签时，AdonisJS 在 manifest 中查找文件并返回正确的打包路径。

manifest 文件默认位于 public/assets/.vite/manifest.json。

另请参阅：Vite 后端集成
