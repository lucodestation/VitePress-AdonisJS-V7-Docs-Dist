浏览器测试 ​

本指南涵盖超媒体和 Inertia 应用的端到端浏览器测试。你将了解到如何：

  • 在测试套件中配置浏览器测试插件
  • 通过 CLI 选项控制测试执行（浏览器、有头模式、追踪、慢动作）
  • 编写带有断言的基本页面访问测试
  • 在测试之间重置数据库状态
  • 使用 Playwright 选择器填写和提交表单
  • 使用录制模式快速生成测试代码
  • 在访问受保护页面之前认证用户

概述 ​

浏览器测试从外到内验证你的应用，完全像真实用户一样导航它。与检查隔离代码片段的单元测试不同，浏览器测试锻炼整个技术栈：路由、控制器、视图、数据库查询和客户端交互协同工作。

对于超媒体和 Inertia 应用，浏览器测试应构成测试套件的大部分。这些应用本质上是关于用户与渲染页面的交互，浏览器测试直接捕获这一现实。当浏览器测试通过时，你对功能确实对用户有效有很高信心。当它失败时，你捕获了用户会遇到的一个 bug。

如果你习惯于单元测试占主导的"测试金字塔"，这种方法可能感觉不同。对于服务端渲染应用，反转这个金字塔是有意义的：浏览器测试每个测试提供更多价值，因为它们验证完整的用户流程而不是实现细节。

设置 ​

浏览器测试需要在 tests/bootstrap.ts 文件中配置三个插件。官方超媒体和 Inertia 启动套件已安装并配置了这些。

ts
import { assert } from '@japa/assert'
import app from '@adonisjs/core/services/app'
import type { Config } from '@japa/runner/types'
import { pluginAdonisJS } from '@japa/plugin-adonisjs'
import testUtils from '@adonisjs/core/services/test_utils'
import { browserClient } from '@japa/browser-client'
import { authBrowserClient } from '@adonisjs/auth/plugins/browser_client'
import { sessionBrowserClient } from '@adonisjs/session/plugins/browser_client'

export const plugins: Config['plugins'] = [
  assert(),
  pluginAdonisJS(app),

  /**
   * 配置 Playwright 并在每个测试之前
   * 创建一个新的浏览器上下文。
   */
  browserClient({ runInSuites: ['browser'] }),

  /**
   * 允许通过浏览器上下文
   * 读写会话数据。
   */
  sessionBrowserClient(app),

  /**
   * 启用 loginAs 方法以在测试期间
   * 认证用户。
   */
  authBrowserClient(app),
]

export const runnerHooks: Required<Pick<Config, 'setup' | 'teardown'>> = {
  setup: [],
  teardown: [],
}

export const configureSuite: Config['configureSuite'] = (suite) => {
  if (['browser', 'functional', 'e2e'].includes(suite.name)) {
    return suite.setup(() => testUtils.httpServer().start())
  }
}

CLI 选项 ​

Playwright 行为在运行测试时通过命令行标志控制。以下选项有助于调试和跨浏览器验证。

--browser

在特定浏览器中运行测试。支持的值有 chromium、firefox 和 webkit。

bash
node ace test --browser=firefox

--headed

在测试执行期间显示浏览器窗口。默认情况下，测试在无头模式下运行。

bash
node ace test --headed

--devtools

浏览器启动时自动打开浏览器开发者工具。

bash
node ace test --devtools

--slow

按指定毫秒数减慢测试操作。对于视觉上跟随测试正在做什么很有用。

bash
node ace test --slow=500

--trace

记录追踪以进行调试。使用 onError 仅在测试失败时记录，或使用 onTest 记录每个测试。

bash
node ace test --trace=onError

录制追踪 ​

追踪捕获测试执行的完整时间线，包括截图、网络请求和 DOM 快照。仅在测试失败时或为每个测试生成追踪。

bash
# 仅在测试失败时记录追踪
node ace test --trace=onError

# 为每个测试记录追踪
node ace test --trace=onTest

追踪存储在 browsers 目录中。使用 Playwright 的追踪查看器重放它们。

bash
npx playwright show-trace browsers/path-to-trace.zip

运行特定测试 ​

运行所有浏览器测试或针对特定文件和文件夹。

bash
# 运行所有浏览器测试
node ace test browser

# 运行特定文件夹中的测试
node ace test --files="posts/*"

基本页面访问 ​

浏览器测试访问一个页面并对其内容做出断言。visit 辅助函数打开一个 URL，返回的页面对象提供断言方法。

ts
import { test } from '@japa/runner'

test.group('Posts index', () => {
  test('display list of posts', async ({ visit, route }) => {
    /**
     * 使用命名路由访问帖子索引页面。
     * visit 辅助函数返回一个 Playwright 页面实例，
     * 扩展了断言方法。
     */
    const page = await visit(route('posts.index'))

    /**
     * 断言 body 包含特定文本。
     * 这将最多等待 5 秒以让文本出现。
     */
    await page.assertTextContains('body', 'My first post')
  })
})

此测试失败，因为数据库中没有帖子存在。失败消息指示断言在等待预期内容时超时。

sh
ℹ AssertionError: expected 'body' inner text to include 'My first post', timed out after 5000ms

 ⁃ (AssertionError [ERR_ASSERTION]: expected 'body' inner text to include 'My first post':undefined:undefined)

数据库状态 ​

测试应从已知的数据库状态开始。使用 testUtils.db().truncate() 钩子在每个测试后清空表，然后创建你的测试需要的特定记录。

另请参阅：数据库测试工具了解迁移和填充文件等其他方法。

ts
import Post from '#models/post'
import User from '#models/user'
import testUtils from '@adonisjs/core/services/test_utils'
import { test } from '@japa/runner'

test.group('Posts index', (group) => {
  /**
   * 在每个测试后清空数据库表。
   * 这确保测试不会相互影响。
   */
  group.each.setup(() => testUtils.db().truncate())

  test('display list of posts', async ({ visit, route }) => {
    /**
     * 创建此测试依赖的数据。
     * 每个测试显式设置自己的状态。
     */
    const user = await User.create({
      email: 'john@example.com',
      password: 'secret',
    })
    await Post.create({
      title: 'My first post',
      content: 'This is my first post',
      userId: user.id,
    })

    const page = await visit(route('posts.index'))
    await page.assertTextContains('body', 'My first post')
  })
})

表单交互 ​

表单使用 Playwright 的定位器方法填写。通过标签文本选择输入，使用 fill 输入值，然后 click 提交。

ts
import testUtils from '@adonisjs/core/services/test_utils'
import { test } from '@japa/runner'

test.group('Session create', (group) => {
  group.each.setup(() => testUtils.db().truncate())

  test('display error when invalid credentials are used', async ({ visit, route }) => {
    const page = await visit(route('session.create'))

    /**
     * 通过关联的标签文本定位输入。
     * 这反映了用户识别表单字段的方式。
     */
    await page.getByLabel('Email').fill('john@example.com')
    await page.getByLabel('Password').fill('secret')

    /**
     * 点击提交按钮。getByRole 通过元素的
     * ARIA 角色查找元素，使测试对标记更改具有弹性。
     */
    await page.getByRole('button').click()
  })
})

录制模式 ​

手动编写定位器需要在浏览器和测试文件之间反复切换。录制模式启动一个浏览器，你的交互会自动转换为测试代码。

创建一个新的测试文件并调用 record 方法而不是 visit。当你运行测试时，会打开一个浏览器，你可以在其中与应用交互。完成后关闭浏览器，将生成的代码复制到你的测试文件中。

ts
import { test } from '@japa/runner'

test.group('Posts create', () => {
  test('create a new post', async ({ record, route }) => {
    /**
     * 在录制模式下打开浏览器。
     * 录制时测试超时被禁用。
     * 与页面交互，然后关闭浏览器
     * 以查看生成的测试代码。
     */
    await record(route('posts.create'))
  })
})

录制后，将 record 调用替换为 visit 并粘贴生成的定位器和操作。

认证用户 ​

受保护的页面需要已认证用户。browserContext.loginAs 方法为该测试中所有后续页面访问认证用户。

WARNING

为了使身份认证在测试期间工作，在你的 .env.test 文件中设置 SESSION_DRIVER=memory。内存驱动允许测试进程管理会话而没有文件或数据库开销。

ts
import User from '#models/user'
import { test } from '@japa/runner'
import testUtils from '@adonisjs/core/services/test_utils'

test.group('Posts create', (group) => {
  group.each.setup(() => testUtils.db().truncate())

  test('display error when missing post title or content', async ({
    visit,
    browserContext,
    route,
  }) => {
    const user = await User.create({
      email: 'john@example.com',
      password: 'secret',
    })

    /**
     * 为此浏览器上下文认证用户。
     * 所有后续页面访问都将已认证。
     */
    await browserContext.loginAs(user)

    const page = await visit(route('posts.create'))
    await page.assertPath('/posts/create')
  })
})

Cookie 和会话 ​

浏览器上下文提供在测试期间读写 cookie、会话和闪存消息的方法。当你的应用行为依赖存储状态时，这些很有用。

设置 Cookie ​

根据 cookie 应如何存储，有三种方法可用。

ts
import { test } from '@japa/runner'

test.group('User preferences', () => {
  test('apply dark mode from cookie', async ({ visit, browserContext, route }) => {
    /**
     * 设置加密 cookie（AdonisJS 中的默认 cookie 行为）。
     */
    await browserContext.setCookie('theme', 'dark')

    /**
     * 设置无加密的普通 cookie。
     * 对于客户端 JavaScript 需要读取的 cookie 很有用。
     */
    await browserContext.setPlainCookie('locale', 'en-us')

    /**
     * 显式设置加密 cookie。
     * 等同于 setCookie。
     */
    await browserContext.setEncryptedCookie('preferences', { sidebar: 'collapsed' })

    const page = await visit(route('dashboard'))
    await page.assertVisible('.dark-mode')
  })
})

读取 Cookie ​

在页面交互后检索 cookie 值以验证你的应用正确设置了它们。

ts
import { test } from '@japa/runner'

test.group('User preferences', () => {
  test('save theme preference to cookie', async ({ visit, browserContext, route }) => {
    const page = await visit(route('settings'))
    await page.getByLabel('Theme').selectOption('dark')
    await page.getByRole('button', { name: 'Save' }).click()

    /**
     * 页面交互后读取 cookie。
     */
    const theme = await browserContext.getCookie('theme')
    const locale = await browserContext.getPlainCookie('locale')
    const prefs = await browserContext.getEncryptedCookie('preferences')
  })
})

设置会话数据 ​

在访问页面之前预填充会话数据。当测试依赖会话状态的功能而不通过 UI 建立该状态时，这很有用。

ts
import { test } from '@japa/runner'

test.group('Onboarding', () => {
  test('resume onboarding from step 3', async ({ visit, browserContext, route }) => {
    /**
     * 在访问页面之前设置会话数据。
     * 页面将读取此状态并相应地恢复。
     */
    await browserContext.setSession({
      onboarding: { currentStep: 3, completedSteps: [1, 2] }
    })

    const page = await visit(route('onboarding'))
    await page.assertTextContains('h1', 'Step 3')
  })
})

设置闪存消息 ​

闪存消息是仅持续到下一个请求的会话数据。设置它们以测试你的 UI 如何显示通知或验证错误。

ts
import { test } from '@japa/runner'

test.group('Notifications', () => {
  test('display success notification', async ({ visit, browserContext, route }) => {
    await browserContext.setFlashMessages({
      success: 'Your changes have been saved'
    })

    const page = await visit(route('dashboard'))
    await page.assertTextContains('.notification', 'Your changes have been saved')
  })
})

读取会话和闪存消息 ​

验证你的应用将预期数据写入会话。

ts
import { test } from '@japa/runner'

test.group('Shopping cart', () => {
  test('add item to cart stored in session', async ({ visit, browserContext, route }) => {
    const page = await visit(route('products.show', { id: 1 }))
    await page.getByRole('button', { name: 'Add to cart' }).click()

    const session = await browserContext.getSession()
    const flashMessages = await browserContext.getFlashMessages()
  })
})
