API 测试 ​

本指南涵盖 AdonisJS 应用中 JSON API 端点的测试。你将了解到如何：

  • 配置 API 客户端和相关插件
  • 使用路由名称为 API 端点编写测试
  • 使用请求发送 JSON 和表单数据
  • 在测试期间处理 cookie 和会话
  • 使用会话或访问令牌认证用户
  • 断言 Inertia 页面组件、props 和部分重载
  • 调试请求和响应
  • 断言响应状态、响应体、头等

概述 ​

AdonisJS 中的 API 测试使用 Japa 的 API 客户端对你的应用发起真实 HTTP 请求。与模拟或仿真请求不同，API 客户端启动你的 AdonisJS 服务器并从外部发送实际网络请求。这种方法完全按照生产环境中的行为测试你的整个 HTTP 层——路由、中间件、控制器和响应。

API 客户端通过专用插件与 AdonisJS 功能（如会话和身份认证）集成，使得测试受保护端点和有状态交互变得简单直接。

配置 ​

api 启动套件在 tests/bootstrap.ts 文件中预配置了三个插件。

ts
import { apiClient } from '@japa/api-client'
import { authApiClient } from '@adonisjs/auth/plugins/api_client'
import { sessionApiClient } from '@adonisjs/session/plugins/api_client'
import type { Registry } from '../.adonisjs/client/registry/schema.d.ts'

declare module '@japa/api-client/types' {
  interface RoutesRegistry extends Registry {}
}

export const plugins: Config['plugins'] = [
  assert(),
  pluginAdonisJS(app),
  /**
   * 配置 Japa 的 API 客户端以发起 HTTP 请求
   */
  apiClient(),
  /**
   * 添加对请求期间读写会话数据的支持
   */
  sessionApiClient(app),
  /**
   * 添加对请求期间认证用户的支持
   */
  authApiClient(app),
]

在测试期间使用会话时，会话驱动必须在 .env.test 文件中设置为 memory。启动套件默认已配置此项。

dotenv
SESSION_DRIVER=memory

配置 Inertia 断言 ​

将 inertiaApiClient 插件与标准 API 客户端一起添加，以使用 Inertia 请求辅助函数和响应断言。保留启动套件已配置的任何会话、身份认证、Shield 和数据库插件。

ts
import { assert } from '@japa/assert'
import { apiClient } from '@japa/api-client'
import app from '@adonisjs/core/services/app'
import type { Config } from '@japa/runner/types'
import { pluginAdonisJS } from '@japa/plugin-adonisjs'
import { inertiaApiClient } from '@adonisjs/inertia/plugins/api_client'

export const plugins: Config['plugins'] = [
  assert(),
  pluginAdonisJS(app),
  apiClient(),
  inertiaApiClient(app),
]

编写你的第一个测试 ​

让我们测试一个验证输入并创建新用户的账户创建端点。我们将编写两个测试：一个用于验证错误，一个用于成功创建。

路由定义在 start/routes.ts 中。

ts
router.post('signup', [controllers.NewAccount, 'store'])

第一个测试验证当必需字段缺失时返回验证错误。client.visit() 方法接受路由名称，并自动从你的路由定义中确定 HTTP 方法和 URL 模式。

ts
import { test } from '@japa/runner'

test.group('Auth signup', () => {
  test('return error when required fields are not provided', async ({ client }) => {
    /**
     * 向 signup 路由发起 POST 请求。
     * 由于未发送数据，验证应失败。
     */
    const response = await client.visit('new_account.store')

    response.assertStatus(422)
    response.assertBodyContains({
      errors: [
        {
          field: 'fullName',
          message: 'The fullName field must be defined',
          rule: 'required',
        },
        {
          field: 'email',
          message: 'The email field must be defined',
          rule: 'required',
        },
        {
          field: 'password',
          message: 'The password field must be defined',
          rule: 'required',
        },
        {
          field: 'passwordConfirmation',
          message: 'The passwordConfirmation field must be defined',
          rule: 'required',
        },
      ],
    })
  })
})

第二个测试发送有效数据并验证用户已创建。你可以在测试中直接查询数据库以验证副作用。

ts
import { test } from '@japa/runner'
import User from '#models/user'

test.group('Auth signup', () => {
  test('create user account', async ({ client, assert }) => {
    /**
     * 使用流畅的 .json() 方法发送 JSON 数据
     */
    const response = await client.visit('new_account.store').json({
      fullName: 'John doe',
      email: 'john@example.com',
      password: 'secret@123A',
      passwordConfirmation: 'secret@123A',
    })

    response.assertStatus(200)
    response.assertBodyContains({
      data: {
        fullName: 'John doe',
        email: 'john@example.com',
      },
    })

    /**
     * 验证用户已持久化到数据库
     */
    const user = await User.findOrFail(response.body().data.id)
    assert.equal(user.email, 'john@example.com')
  })
})

清理数据库状态 ​

创建数据库记录的测试需要在运行之间进行清理以确保隔离。testUtils.db().truncate() 钩子会迁移数据库并在每个测试后清空所有表。

另请参阅：数据库测试工具了解迁移和填充文件等其他方法。

ts
import { test } from '@japa/runner'
import testUtils from '@adonisjs/core/services/test_utils'

test.group('Auth signup', (group) => {
  /**
   * 在每个测试后清空表以确保
   * 下一个测试具有干净的状态
   */
  group.each.setup(() => {
    return testUtils.db().truncate()
  })

  test('create user account', async ({ client, assert }) => {
    // ...
  })
})

发起请求 ​

API 客户端提供两种发起 HTTP 请求的方法：使用路由名称或显式 HTTP 方法。

使用路由名称 ​

client.visit() 方法接受路由名称，并从你的路由器查找 HTTP 方法和 URL 模式。这使你的测试与路由更改保持同步，并在测试中提供类型安全。

ts
const response = await client.visit('posts.store')

使用 HTTP 方法 ​

当你需要直接访问特定 URL 时，使用显式的 HTTP 方法函数。

ts
const response = await client.get('/api/posts')
const response = await client.post('/api/posts')
const response = await client.put('/api/posts/1')
const response = await client.patch('/api/posts/1')
const response = await client.delete('/api/posts/1')

发送请求数据 ​

JSON 数据 ​

使用 json() 方法发送 JSON 负载。Content-Type 头会自动设置。

ts
const response = await client.visit('posts.store').json({
  title: 'Hello World',
  content: 'This is my first post',
})

表单数据 ​

使用 form() 方法发送 URL 编码的表单数据。

ts
const response = await client.visit('posts.store').form({
  title: 'Hello World',
  content: 'This is my first post',
})

Multipart 数据 ​

使用 field() 方法发送 multipart 表单字段。

ts
const response = await client
  .visit('posts.store')
  .field('title', 'Hello World')
  .field('content', 'This is my first post')

测试 Inertia 响应 ​

链式调用 withInertia() 请求 Inertia 响应，然后断言渲染的页面组件及其 props。当完整的 props 对象必须完全匹配时使用 assertInertiaProps，当测试只关心页面 props 的子集时使用 assertInertiaPropsContains。

ts
import { test } from '@japa/runner'

test.group('Posts index', () => {
  test('renders the posts page', async ({ client }) => {
    const response = await client.get('/posts').withInertia()

    response.assertStatus(200)
    response.assertInertiaComponent('posts/index')
    response.assertInertiaPropsContains({
      filters: { status: 'published' },
    })
  })
})

测试部分重载 ​

使用 withInertiaPartialReload 从页面请求特定 props。两个参数都经过类型检查，因此拼错页面或 prop 会导致类型检查失败。

ts
import { test } from '@japa/runner'

test.group('Posts index', () => {
  test('reloads the posts prop', async ({ client }) => {
    const response = await client
      .get('/posts')
      .withInertiaPartialReload('posts/index', ['posts'])

    response.assertStatus(200)
    response.assertInertiaComponent('posts/index')
    response.assertInertiaPropsContains({
      posts: [],
    })
  })
})

Cookie ​

你可以使用 withCookie() 方法及其变体在传出请求上设置 cookie。

ts
/**
 * 设置常规 cookie
 */
const response = await client
  .visit('checkout.store')
  .withCookie('affiliateId', '1')

/**
 * 设置加密 cookie（使用 AdonisJS 加密）
 */
const response = await client
  .visit('checkout.store')
  .withEncryptedCookie('affiliateId', '1')

/**
 * 设置普通 cookie（无签名或加密）
 */
const response = await client
  .visit('checkout.store')
  .withPlainCookie('affiliateId', '1')

会话 ​

withSession() 方法在发起请求之前填充会话存储。这对于测试依赖现有会话状态的流程很有用。

ts
const response = await client
  .visit('checkout.store')
  .withSession({ cartId: 1 })

身份认证 ​

会话身份认证 ​

loginAs() 方法使用你的默认 auth 守卫为请求认证用户。你必须在发起已认证请求之前创建用户。

ts
test('create a post', async ({ client }) => {
  const user = await User.create({
    fullName: 'John',
    email: 'john@example.com',
    password: 'secret',
  })

  const response = await client.visit('posts.store').loginAs(user)
  response.assertStatus(200)
})

令牌身份认证 ​

使用访问令牌或不同的 auth 守卫时，在 loginAs() 之前链式调用 withGuard() 方法以指定使用哪个守卫。

ts
test('create a post via API', async ({ client }) => {
  const user = await User.create({
    fullName: 'John',
    email: 'john@example.com',
    password: 'secret',
  })

  /**
   * 使用 'api' 守卫进行基于令牌的身份认证
   */
  const response = await client
    .visit('posts.store')
    .withGuard('api')
    .loginAs(user)

  response.assertStatus(200)
})

确保你的路由中间件允许使用指定的守卫进行身份认证。

ts
router
  .group(() => {
    router.post('posts', [controllers.Posts, 'store'])
  })
  .use(middleware.auth({ guards: ['web', 'api'] }))

调试 ​

转储请求 ​

构建请求时链式调用 dump() 方法以在发送之前记录请求详情。

ts
const response = await client
  .visit('posts.store')
  .dump()
  .json({ title: 'Hello World' })

转储响应 ​

响应对象提供方法来检查返回的内容。

ts
const response = await client.visit('posts.index')

/**
 * 转储整个响应（状态、头、响应体）
 */
response.dump()

/**
 * 仅转储响应体
 */
response.dumpBody()

/**
 * 仅转储响应头
 */
response.dumpHeaders()

检查服务器错误 ​

使用 hasFatalError() 检查服务器是否返回了 500 级错误。

ts
const response = await client.visit('posts.store').json(data)

if (response.hasFatalError()) {
  response.dump()
}

断言参考 ​

响应对象提供用于验证状态码、响应体内容、头、cookie 和会话数据的断言方法。

状态和响应体断言 ​

方法描述
assertStatus(status)断言响应状态匹配预期值
assertBody(body)断言响应体完全匹配预期值
assertBodyContains(subset)断言响应体包含预期子集
assertBodyNotContains(subset)断言响应体不包含子集
assertTextIncludes(text)断言响应文本包含子字符串

头断言 ​

方法描述
assertHeader(name, value?)断言头存在，可选地检查其值
assertHeaderMissing(name)断言头不存在

Cookie 断言 ​

方法描述
assertCookie(name, value?)断言 cookie 存在，可选地检查其值
assertCookieMissing(name)断言 cookie 不存在

重定向断言 ​

方法描述
assertRedirectsTo(pathname)断言响应重定向到给定路径

会话断言 ​

方法描述
assertSession(key, value?)断言会话键存在，可选地检查其值
assertSessionMissing(key)断言会话存储中缺少某个键
assertFlashMessage(key, value?)断言闪存消息存在，可选地检查其值
assertFlashMissing(key)断言闪存消息中缺少某个键

验证错误断言 ​

方法描述
assertHasValidationError(field)断言闪存消息包含该字段的验证错误
assertDoesNotHaveValidationError(field)断言闪存消息不包含该字段的验证错误
assertValidationError(field, message)断言字段的特定错误消息
assertValidationErrors(field, messages)断言字段的所有错误消息

OpenAPI 断言 ​

方法描述
assertAgainstApiSpec()断言响应体根据你的 OpenAPI 规范有效

另请参阅：Japa API 客户端文档
