测试简介 ​

本指南涵盖 AdonisJS 应用中的测试设置。你将了解到：

  • 关于 Japa，AdonisJS 使用的测试框架
  • 测试如何通过套件和插件进行配置
  • 如何创建和运行你的第一个测试
  • 如何按文件、名称、标签或套件筛选测试
  • 如何使用监视模式进行快速开发
  • 如何为测试覆盖环境变量

概述 ​

AdonisJS 内置支持测试，所有启动套件都已预配置完整的测试设置。你可以立即开始编写测试，无需任何额外配置。

测试层由 Japa 提供支持，这是我们构建并维护了七年多的测试框架。与 Jest 或 Vitest 等通用测试运行器不同，Japa 专为后端应用而构建。它在 Node.js 中原生运行，无需转译器，并包含专门为后端测试设计的插件，例如用于测试 JSON 端点的 API 客户端和用于在测试期间管理临时文件的文件系统插件。

我们选择构建和维护自己的测试框架，以避免 JavaScript 生态系统中常见的频繁变动。目睹社区从 Mocha 转向 Jest 再到 Vitest，我们很高兴投资于我们掌控并可以与 AdonisJS 一起演进的工具。

Japa 与 AdonisJS 的集成 ​

Japa 通过 @japa/plugin-adonisjs 包与 AdonisJS 深度集成。该插件使用 AdonisJS 特定的工具扩展 Japa，让你的测试可以访问应用实例、用于计算 URL 的路由辅助函数，以及在 HTTP 和浏览器测试期间读写 cookie 的方法。

这种集成意味着你编写的测试感觉像是 AdonisJS 原生的，而不是硬接上一个不理解你应用结构的通用测试运行器。

项目结构 ​

AdonisJS 将测试组织成套件（suite），每个套件代表一类测试并拥有自己的配置。典型的项目结构如下所示。

sh
tests/
├── bootstrap.ts
├── unit/
│   └── posts_service.spec.ts
└── browser/
    └── posts.spec.ts

tests/bootstrap.ts 文件配置 Japa 插件和生命周期钩子。单个测试文件位于套件目录中，每个套件可以有不同的超时时间、插件和适合该类型测试的设置逻辑。

理解套件 ​

测试套件将具有共同特征的测试分组在一起。例如，单元测试运行速度快，不需要 HTTP 服务器，而浏览器测试需要运行中的服务器，并且有更长的超时时间来应对浏览器自动化。

超媒体和 Inertia 启动套件预配置了两个套件：

  • unit 测试隔离的代码片段，如服务、工具和模型
  • browser 使用 Playwright 进行端到端测试，模拟真实用户交互

套件在你的 adonisrc.ts 文件中定义。

ts
{
  tests: {
    suites: [
      {
        files: ['tests/unit/**/*.spec.ts'],
        name: 'unit',
        timeout: 2000,
      },
      {
        files: ['tests/browser/**/*.spec.ts'],
        name: 'browser',
        timeout: 300000,
      },
    ],
    forceExit: false,
  }
}

每个套件指定用于定位测试文件的 glob 模式、用于筛选的名称以及以毫秒为单位的超时时间。浏览器测试有更长的超时时间（5 分钟），因为浏览器自动化本质上比进程内的单元测试慢。

配置插件和钩子 ​

tests/bootstrap.ts 文件是你配置 Japa 插件并定义在测试套件前后运行的生命周期钩子的地方。

ts
import { assert } from '@japa/assert'
import app from '@adonisjs/core/services/app'
import type { Config } from '@japa/runner/types'
import { pluginAdonisJS } from '@japa/plugin-adonisjs'
import testUtils from '@adonisjs/core/services/test_utils'
import { browserClient } from '@japa/browser-client'
import { authBrowserClient } from '@adonisjs/auth/plugins/browser_client'
import { sessionBrowserClient } from '@adonisjs/session/plugins/browser_client'

/**
 * 在 plugins 数组中配置 Japa 插件。
 * 了解更多 - https://japa.dev/docs/runner-config#plugins-optional
 */
export const plugins: Config['plugins'] = [
  assert(),
  pluginAdonisJS(app),
  browserClient({ runInSuites: ['browser'] }),
  sessionBrowserClient(app),
  authBrowserClient(app),
]

/**
 * 配置在所有测试前后运行的生命周期函数。
 */
export const runnerHooks: Required<Pick<Config, 'setup' | 'teardown'>> = {
  setup: [],
  teardown: [],
}

/**
 * 通过接入测试套件实例来配置套件。
 * 了解更多 - https://japa.dev/docs/test-suites#lifecycle-hooks
 */
export const configureSuite: Config['configureSuite'] = (suite) => {
  if (['browser', 'functional', 'e2e'].includes(suite.name)) {
    return suite.setup(() => testUtils.httpServer().start())
  }
}

configureSuite 函数允许你添加特定于某些套件的设置逻辑。在此示例中，browser、functional 和 e2e 套件在测试运行之前自动启动 HTTP 服务器。

创建你的第一个测试 ​

使用 make:test 命令生成新的测试文件。

sh
node ace make:test posts/index --suite=browser

这会在 tests/browser/posts/index.spec.ts 创建一个具有以下结构的测试文件。

ts
import { test } from '@japa/runner'

test.group('Posts index', () => {
  test('display a list of all posts', async ({ assert }) => {})
})

测试使用 test.group() 组织成组，这有助于组织相关测试并允许你应用共享的设置和清理逻辑。单个测试使用 test() 定义，并接收一个包含 assert 等用于断言的工具的上下文对象。

运行测试 ​

使用以下命令运行你的整个测试套件。

sh
node ace test

要运行特定套件，将套件名称作为参数传递。

sh
node ace test unit
node ace test browser

筛选测试 ​

Japa 提供多个标志来运行测试的子集。

--tests

按确切的测试标题筛选。

sh
# 运行标题完全匹配的测试
node ace test --tests="can list all posts"

--files

按测试文件名筛选（匹配文件名末尾，不含 .spec.ts）。--files 标志支持通配符以运行目录中的所有测试。

sh
# 运行特定测试文件
node ace test --files="posts/index"

# 运行 posts 目录中的所有测试
node ace test --files="posts/*"

--groups

按确切的组名称筛选。

sh
# 运行特定组中的所有测试
node ace test --groups="Posts index"

--tags

按标签筛选（前缀 ~ 表示排除）。

--matchAll

要求所有指定标签都匹配，而不是任意匹配。

监视模式 ​

在开发期间，使用监视模式在文件更改时自动重新运行测试。

sh
node ace test --watch

当测试文件更改时，只重新运行该文件的测试。当源文件更改时，所有测试都会执行。

TIP

如果你正在迭代单个测试，请将监视模式与 --files 筛选器结合使用。这确保任何文件更改只运行你关注的测试，提供更快的反馈。

其他标志 ​

两个标志在开发期间特别有用。

sh
# 首次失败时停止
node ace test --bail

# 仅重新运行上次运行中失败的测试
node ace test --failed

--bail 标志通过阻止后续测试运行来帮助调试失败的测试。--failed 标志用于快速验证你的修复是否解决了所有失败，而无需运行整个套件。

环境变量 ​

AdonisJS 在运行测试时自动加载 .env.test 文件，将其值与标准 .env 文件合并。在 .env.test 中定义的任何变量都会覆盖 .env 中的相应值。

在项目根目录创建 .env.test 文件以配置测试特定的设置。

dotenv
SESSION_DRIVER=memory

内存会话驱动常用于测试，因为它不会在请求之间持久化会话，确保测试隔离。你可能覆盖的其他变量包括数据库连接设置、邮件驱动或任何在测试期间应表现不同的服务配置。
