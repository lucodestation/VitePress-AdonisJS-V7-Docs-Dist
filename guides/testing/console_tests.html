控制台测试 ​

本指南涵盖 AdonisJS 应用中 Ace 命令的测试。你将了解到如何：

  • 为自定义 Ace 命令编写测试
  • 使用 raw 模式捕获和断言日志记录器输出
  • 测试命令输出中的表格渲染
  • 以编程方式捕获和响应 CLI 提示
  • 在测试中验证提示输入
  • 使用内置断言方法验证命令结果

概述 ​

控制台测试允许你验证自定义 Ace 命令的行为是否正确，而无需手动交互。由于命令通常会生成终端输出并提示用户输入，测试它们需要特殊技术来捕获输出和模拟用户响应。

AdonisJS 通过 ace 服务提供专用的测试 API，让你创建命令实例、在隔离环境中执行它们，并对其行为做出断言。该 API 包括用于捕获日志输出、拦截提示和验证退出代码的工具。

当你的命令执行关键操作（如数据库迁移、文件生成或部署任务）时，测试命令特别有价值。生产环境中的命令失败可能带来严重后果，因此自动化测试有助于在问题到达用户之前捕获它们。

基本示例 ​

让我们从头到尾走一遍测试一个简单命令的过程。首先，使用 make:command 生成器创建一个新命令。

sh
node ace make:command greet

# DONE:    create app/commands/greet.ts

生成的命令包含一个 run 方法，你在其中定义命令的行为。更新它以问候用户。

ts
import { BaseCommand } from '@adonisjs/core/ace'
import { CommandOptions } from '@adonisjs/core/types/ace'

export default class Greet extends BaseCommand {
  static commandName = 'greet'
  static description = 'Greet a user by name'

  static options: CommandOptions = {}

  async run() {
    this.logger.info('Hello world from "Greet"')
  }
}

接下来，为命令创建一个测试文件。如果你还没有定义单元测试套件，请参阅测试简介了解设置说明。

sh
node ace make:test commands/greet --suite=unit

# DONE:    create tests/unit/commands/greet.spec.ts

测试使用 ace 服务创建命令实例、执行它并验证它成功完成。ace.create 方法接受命令类和参数数组（在这种情况下为空，因为命令不接受参数）。

ts
import { test } from '@japa/runner'
import Greet from '#commands/greet'
import ace from '@adonisjs/core/services/ace'

test.group('Commands greet', () => {
  test('should greet and exit with code 0', async () => {
    /**
     * 创建命令实例。第二个参数是
     * 传递给命令的 CLI 参数数组。
     */
    const command = await ace.create(Greet, [])

    /**
     * 执行命令。这会运行 `run` 方法。
     */
    await command.exec()

    /**
     * 断言命令成功退出（退出代码 0）。
     */
    command.assertSucceeded()
  })
})

使用以下命令运行测试。

sh
node ace test --files=commands/greet

测试日志记录器输出 ​

Greet 命令使用 this.logger.info() 向终端写入日志消息。默认情况下，此输出直接发送到 stdout，这使得在测试中难以捕获和断言。

为了解决这个问题，你可以将 ace UI 库切换到 raw 模式。在 raw 模式下，ace 将所有输出存储在内存中而不是写入终端。这允许你检查和断言你的命令产生的确切消息。

TIP

Raw 模式捕获来自 this.logger、this.ui.table() 和其他 UI 方法的所有输出。测试后始终切换回正常模式，以避免影响其他测试。

使用 Japa 的 group.each.setup 钩子在每个测试前后自动切换模式。

ts
import { test } from '@japa/runner'
import Greet from '#commands/greet'
import ace from '@adonisjs/core/services/ace'

test.group('Commands greet', (group) => {
  /**
   * 在每个测试之前切换到 raw 模式。返回的函数
   * 在每个测试后运行以恢复正常模式。
   */
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should log greeting message', async () => {
    const command = await ace.create(Greet, [])
    await command.exec()

    command.assertSucceeded()

    /**
     * 断言确切的日志消息。在 raw 模式下，颜色
     * 表示为函数名，如 `blue()`。
     */
    command.assertLog('[ blue(info) ] Hello world from "Greet"')
  })
})

WARNING

Raw 模式下的日志断言包含颜色函数名。消息 this.logger.info('Hello') 在 raw 模式下变为 [ blue(info) ] Hello。如果你的断言失败，请检查你是否在预期字符串中包含了颜色格式化。

测试表格输出 ​

命令经常使用 this.ui.table() 显示表格数据。你可以通过先切换到 raw 模式，像测试日志输出一样测试表格输出。

考虑一个显示团队成员表格的命令。

ts
import { BaseCommand } from '@adonisjs/core/ace'

export default class ListTeam extends BaseCommand {
  static commandName = 'list:team'
  static description = 'List all team members'

  async run() {
    const table = this.ui.table()
    table.head(['Name', 'Email'])

    table.row(['Harminder Virk', 'virk@adonisjs.com'])
    table.row(['Romain Lanz', 'romain@adonisjs.com'])
    table.row(['Julien-R44', 'julien@adonisjs.com'])

    table.render()
  }
}

使用 assertTableRows 验证表格内容。传递一个二维数组，其中每个内部数组代表一行的单元格。

ts
import { test } from '@japa/runner'
import ListTeam from '#commands/list_team'
import ace from '@adonisjs/core/services/ace'

test.group('Commands list:team', (group) => {
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should display team members table', async () => {
    const command = await ace.create(ListTeam, [])
    await command.exec()

    /**
     * 断言表格行匹配预期数据。每个内部数组
     * 代表一行的列值。
     */
    command.assertTableRows([
      ['Harminder Virk', 'virk@adonisjs.com'],
      ['Romain Lanz', 'romain@adonisjs.com'],
      ['Julien-R44', 'julien@adonisjs.com'],
    ])
  })
})

捕获提示 ​

提示会暂停命令执行并等待用户输入，这会阻塞自动化测试。为了处理这个问题，你必须在执行命令之前捕获提示。捕获会拦截特定提示并提供编程式响应。

捕获使用 command.prompt.trap() 创建，它接受提示标题作为参数。标题必须完全匹配，包括大小写。

WARNING

提示标题区分大小写。如果你的提示询问 "What is your name?" 但你捕获的是 "what is your name?"，捕获将不会匹配，你的测试将挂起等待输入。始终从你的命令中复制确切的提示标题。

回复文本提示 ​

使用 replyWith 为使用 this.prompt.ask() 创建的提示提供文本响应。

ts
import { test } from '@japa/runner'
import Greet from '#commands/greet'
import ace from '@adonisjs/core/services/ace'

test.group('Commands greet', (group) => {
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should greet user by name', async () => {
    const command = await ace.create(Greet, [])

    /**
     * 捕获提示并提供响应。这必须在
     * 调用 exec() 之前设置。
     */
    command.prompt.trap('What is your name?').replyWith('Virk')

    await command.exec()
    command.assertSucceeded()
  })
})

TIP

捕获在触发时被消耗并自动移除。如果测试完成时未触发已捕获的提示，Japa 会抛出错误提醒你预期的提示从未出现。

从选择提示中选择选项 ​

对于使用 this.prompt.choice() 或 this.prompt.multiple() 创建的提示，使用 chooseOption 或 chooseOptions 并提供从零开始的索引。

ts
import { test } from '@japa/runner'
import Setup from '#commands/setup'
import ace from '@adonisjs/core/services/ace'

test.group('Commands setup', (group) => {
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should configure with npm', async () => {
    const command = await ace.create(Setup, [])

    /**
     * 从选择提示中选择第一个选项（索引 0）。
     */
    command.prompt.trap('Select package manager').chooseOption(0)

    await command.exec()
    command.assertSucceeded()
  })

  test('should select multiple databases', async () => {
    const command = await ace.create(Setup, [])

    /**
     * 通过传递索引数组选择多个选项。
     */
    command.prompt.trap('Select databases to configure').chooseOptions([0, 2])

    await command.exec()
    command.assertSucceeded()
  })
})

接受或拒绝确认提示 ​

对于使用 this.prompt.confirm() 或 this.prompt.toggle() 创建的布尔提示，使用 accept 或 reject。

ts
import { test } from '@japa/runner'
import Cleanup from '#commands/cleanup'
import ace from '@adonisjs/core/services/ace'

test.group('Commands cleanup', (group) => {
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should delete files when confirmed', async () => {
    const command = await ace.create(Cleanup, [])

    command.prompt.trap('Want to delete all temporary files?').accept()

    await command.exec()
    command.assertSucceeded()
  })

  test('should abort when rejected', async () => {
    const command = await ace.create(Cleanup, [])

    command.prompt.trap('Want to delete all temporary files?').reject()

    await command.exec()
    command.assertLog('[ blue(info) ] Cleanup cancelled')
  })
})

中级：测试提示验证 ​

提示可以包含验证规则以拒绝无效输入。你可以使用 assertPasses 和 assertFails 直接测试这些验证器，而无需完全执行命令。

assertFails 方法接受输入值和预期错误消息。assertPasses 方法接受应通过验证的值。

ts
import { test } from '@japa/runner'
import CreateUser from '#commands/create_user'
import ace from '@adonisjs/core/services/ace'

test.group('Commands create:user', (group) => {
  group.each.setup(() => {
    ace.ui.switchMode('raw')
    return () => ace.ui.switchMode('normal')
  })

  test('should validate email format', async () => {
    const command = await ace.create(CreateUser, [])

    /**
     * 测试验证而不执行完整命令。
     * 链式调用多个断言以测试各种输入。
     */
    command.prompt
      .trap('Enter your email')
      .assertFails('', 'Email is required')
      .assertFails('invalid', 'Please enter a valid email')
      .assertPasses('user@example.com')
      .replyWith('admin@adonisjs.com')

    await command.exec()
    command.assertSucceeded()
  })
})

你可以将验证断言与 replyWith 链式调用，以同时测试验证器并提供最终响应。

可用的断言 ​

命令实例提供多个断言方法来验证命令行为。

assertSucceeded

断言命令以 exitCode=0 退出，表示成功。

ts
await command.exec()
command.assertSucceeded()

assertFailed

断言命令以非零 exitCode 退出，表示失败。

ts
await command.exec()
command.assertFailed()

assertExitCode

断言命令以特定退出代码退出。当你的命令使用不同的退出代码来表示不同的错误条件时很有用。

ts
await command.exec()
command.assertExitCode(2)

assertNotExitCode

断言命令未以特定代码退出。

ts
await command.exec()
command.assertNotExitCode(1)

assertLog

断言命令写入了特定日志消息。可选地指定输出流为 stdout 或 stderr。需要 raw 模式。

ts
await command.exec()

command.assertLog('[ blue(info) ] Task completed')
command.assertLog('[ red(error) ] Something went wrong', 'stderr')

assertLogMatches

断言命令写入了匹配正则表达式的日志消息。当确切消息变化但遵循某种模式时很有用。需要 raw 模式。

ts
await command.exec()

command.assertLogMatches(/Task completed in \d+ms/)

assertTableRows

断言命令打印了具有特定行的表格。传递一个二维数组，其中每个内部数组代表一行的列值。需要 raw 模式。

ts
await command.exec()

command.assertTableRows([
  ['1', 'Alice', 'alice@example.com'],
  ['2', 'Bob', 'bob@example.com'],
])
