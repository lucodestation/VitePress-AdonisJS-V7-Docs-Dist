加密 ​

本指南涵盖 AdonisJS 应用中的加密和解密。你将了解到如何：

  • 加密和解密敏感数据
  • 选择和配置加密算法
  • 使用用途绑定加密以增强安全性
  • 为加密值设置过期时间
  • 使用消息验证器对数据签名而不加密
  • 实现密钥轮换以无缝更新密钥

概述 ​

加密将可读数据转换为只能使用正确密钥解密的密文。与哈希不同，加密是可逆过程。你加密数据以在存储或传输期间保护它，然后在需要读取原始值时解密它。

AdonisJS 提供加密服务，内置支持三种行业标准算法：ChaCha20-Poly1305、AES-256-GCM 和 AES-256-CBC。这三种都是认证加密算法，意味着它们不仅保护机密性，还能检测篡改。如果有人修改了加密数据，解密将失败而不是返回损坏的数据。

加密服务生成结构化格式的输出，包括驱动标识符、密文、初始化向量和认证标签。这种自描述格式允许你切换算法或轮换密钥，同时保持解密旧值的能力。

基本用法 ​

加密服务提供两个主要方法：encryption.encrypt 用于加密值，encryption.decrypt 用于检索原始数据。

加密值 ​

encryption.encrypt 方法接受任何可序列化的值并返回加密字符串。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class ApiTokenService {
  createToken(userId: number, permissions: string[]) {
    /**
     * 加密令牌负载。服务处理序列化，
     * 因此你可以直接传递对象。
     */
    const token = encryption.encrypt({
      userId,
      permissions,
      createdAt: new Date(),
    })

    // token 看起来像：
    // cbc.base64Ciphertext.base64IV.base64Tag

    return token
  }
}

加密服务支持加密字符串、数字、布尔值、数组、对象和日期。复杂的嵌套结构在加密前自动序列化。

解密值 ​

encryption.decrypt 方法接受加密字符串并返回原始值，如果解密失败则返回 null。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class ApiTokenService {
  verifyToken(token: string) {
    /**
     * 尝试解密令牌。如果令牌无效、被篡改
     * 或使用不同密钥加密，则返回 null。
     */
    const payload = encryption.decrypt(token)

    if (!payload) {
      return null
    }

    return payload as { userId: number; permissions: string[] }
  }
}

解密方法在解密失败时返回 null 而不是抛出异常。这种设计防止时序攻击并简化错误处理。在使用解密值之前，你应该始终检查 null。

用途绑定加密 ​

用途绑定加密确保加密值只有在提供相同用途时才能被解密。这防止令牌在应用的不同上下文中被重用。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class TokenService {
  createPasswordResetToken(userId: number) {
    /**
     * purpose 选项指定加密用途。
     * 此令牌只能使用相同的用途解密。
     */
    return encryption.encrypt(
      { userId },
      { purpose: 'password-reset' } 
    )
  }

  createEmailVerificationToken(userId: number) {
    return encryption.encrypt(
      { userId },
      { purpose: 'email-verification' } 
    )
  }

  verifyPasswordResetToken(token: string) {
    /**
     * 必须提供相同的用途才能解密。
     * 为电子邮件验证创建的令牌在这里无法使用。
     */
    return encryption.decrypt(token, 'password-reset')
  }
}

没有用途绑定时，获得密码重置令牌的攻击者可能将其重用为电子邮件验证令牌（如果两者包含相同的数据结构）。用途绑定加密通过将用途加密绑定到加密值来防止这种攻击。

ts
const token = encryption.encrypt(
  { userId: 1 },
  { purpose: 'password-reset' }
)

encryption.decrypt(token, 'password-reset')     // => { userId: 1 }

/**
 * 尝试使用错误的用途解密会返回 null。
 */
encryption.decrypt(token, 'email-verification') // => null
encryption.decrypt(token)                       // => null

加密值过期 ​

你可以为加密值设置生存时间。在指定持续时间后，即使加密数据有效，解密方法也会返回 null。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class InvitationService {
  createInvitationLink(email: string, teamId: number) {
    const token = encryption.encrypt({ email, teamId }, {
      expiresIn: '24h'
    })
    return `https://app.example.com/invitations/${token}`
  }

  acceptInvitation(token: string) {
    /**
     * 如果令牌已过期，则返回 null，
     * 即使加密数据仍然有效。
     */
    const payload = encryption.decrypt(token)
    if (!payload) {
      return { error: 'Invalid or expired invitation' }
    }

    return payload as { email: string; teamId: number }
  }
}

支持的持续时间格式包括：

格式示例描述
分钟'30m'30 分钟后过期
小时'1h'1 小时后过期
天'7d'7 天后过期

你可以结合用途绑定和过期时间以获得最大安全性。

ts
/**
 * 创建 1 小时后过期且只能用于
 * 密码重置操作的密码重置令牌。
 */
const token = encryption.encrypt(
  { userId: 1 },
  { expiresIn: '1h', purpose: 'password-reset' }
)

/**
 * 必须提供正确的用途才能解密。
 * 如果过期或用途不匹配则返回 null。
 */
const payload = encryption.decrypt(token, 'password-reset')

加密数据库列 ​

在将敏感数据存储到数据库之前加密它。

ts
import { UserSchema } from '#database/schema'
import { beforeSave } from '@adonisjs/lucid/orm'
import encryption from '@adonisjs/core/services/encryption'

export default class User extends UserSchema {
  @beforeSave()
  static encryptSensitiveData(user: User) {
    if (user.$dirty.ssn && user.ssn) {
      user.ssn = encryption.encrypt(user.ssn)
    }
  }

  decryptSsn(): string | null {
    if (!this.ssn) {
      return null
    }
    return encryption.decrypt(this.ssn)
  }
}

选择算法 ​

每种加密算法在安全性、性能和兼容性之间提供不同的权衡。正确的选择取决于你的应用需求。

何时选择 ChaCha20-Poly1305 ​

ChaCha20-Poly1305 是新应用的推荐选择。它在所有平台上提供一致的高性能，包括没有硬件 AES 加速的平台。它广泛部署在现代协议中，包括 TLS 1.3 和 WireGuard。

何时选择 AES-256-GCM ​

当你需要与特别要求 AES 的系统兼容，或在具有 AES-NI 加速的硬件上运行时，AES-256-GCM 是一个极好的选择。它是许多生态系统中的默认密码，即使没有明确的 AES 要求，也能简化互操作性。

何时选择 AES-256-CBC ​

AES-256-CBC 主要用于旧版兼容性，主要是为了解密来自旧系统的现有数据。与 AEAD 密码不同，CBC 需要使用 Encrypt-then-MAC 模式进行单独的 HMAC 认证。对于新的加密需求，优先使用 ChaCha20-Poly1305 或 AES-256-GCM。

WARNING

CBC 模式有实现陷阱的历史，包括填充 oracle 攻击。AdonisJS 内部处理这些问题，但如果你在其他地方实现 CBC，请确保使用 Encrypt-then-MAC 和认证标签的恒定时间比较。

何时选择 Legacy ​

legacy 驱动专为从 AdonisJS v6 迁移到 v7 而设计。它只能解密使用 v6 加密服务加密的数据。当你数据库中有来自需要迁移的 v6 应用的现有加密数据时，使用此驱动。

推荐的迁移策略是：

  1. 将 legacy 驱动与现代驱动一起配置
  2. 使用 legacy 驱动读取加密数据
  3. 使用现代驱动（ChaCha20-Poly1305 或 AES-256-GCM）重新加密数据
  4. 所有数据迁移完成后，移除 legacy 驱动
ts
import encryption from '@adonisjs/core/services/encryption'

export default class MigrationService {
  async migrateEncryptedField(encryptedValue: string) {
    /**
     * 使用 legacy 驱动（v6 格式）解密
     */
    const decrypted = encryption.use('legacy').decrypt(encryptedValue)

    if (!decrypted) {
      return null
    }

    /**
     * 使用现代驱动重新加密
     */
    return encryption.encrypt(decrypted)
  }
}

配置 ​

加密配置位于 config/encryption.ts。你在 list 对象中定义可用的驱动，并指定默认使用哪一个。

ts
import env from '#start/env'
import { defineConfig, drivers } from '@adonisjs/core/encryption'

export default defineConfig({
  /**
   * encryption.encrypt() 和 encryption.decrypt() 在
   * 未显式指定驱动时使用的默认驱动。
   */
  default: 'chacha',

  list: {
    chacha: drivers.chacha20({
      id: 'chacha',
      keys: [env.get('APP_KEY')],
    }),

    /**
     * AES-256-GCM：行业标准认证加密。
     */
    // gcm: drivers.aes256gcm({
    //   id: 'gcm',
    //   keys: [env.get('APP_KEY')],
    // }),

    /**
     * AES-256-CBC：带 HMAC 认证的旧版支持。
     */
    // cbc: drivers.aes256cbc({
    //   id: 'cbc',
    //   keys: [env.get('APP_KEY')],
    // }),

    /**
     * Legacy：解密使用 AdonisJS v6 加密的数据。
     * 使用此驱动将加密数据从 v6 迁移到 v7。
     */
    // legacy: drivers.legacy({
    //   keys: [env.get('APP_KEY')],
    // }),
  },
})

驱动配置选项 ​

所有驱动接受相同的配置选项。

id

类型：string

此驱动配置的唯一标识符。此 ID 嵌入在加密输出中，允许解密过程识别使用了哪个驱动。

keys

类型：string[]

密钥数组。第一个密钥用于加密，而解密时会尝试所有密钥。这实现了无缝密钥轮换。

密钥轮换 ​

加密服务支持多个密钥以实现无缝密钥轮换。数组中的第一个密钥用于加密新值，而解密时会尝试所有密钥。这允许你在不使现有加密数据失效的情况下轮换密钥。

ts
import env from '#start/env'
import { defineConfig, drivers } from '@adonisjs/core/encryption'

export default defineConfig({
  default: 'chacha',

  list: {
    chacha: drivers.chacha20({
      id: 'chacha',
      keys: [
        env.get('APP_KEY'),     // 新密钥：用于加密
        env.get('OLD_APP_KEY'), // 旧密钥：仅用于解密
      ],
    }),
  },
})

轮换密钥时，遵循以下流程：

  1. 生成新的密钥
  2. 将新密钥添加为 keys 数组的第一个元素
  3. 将旧密钥移到第二位
  4. 部署你的应用
  5. 足够时间后（当所有旧的加密值已重新加密或过期时），移除旧密钥
ts
import encryption from '@adonisjs/core/services/encryption'

/**
 * 新的加密自动使用第一个密钥。
 */
const newToken = encryption.encrypt({ userId: 1 })

/**
 * 解密会尝试所有密钥，因此旧令牌仍然有效。
 */
const oldPayload = encryption.decrypt(tokenEncryptedWithOldKey) // 有效
const newPayload = encryption.decrypt(newToken)                 // 有效

WARNING

在你确定使用旧密钥加密的所有数据已使用新密钥重新加密或不再需要之前，绝不要移除旧密钥。移除密钥会使使用它加密的所有数据永久无法读取。

消息验证器 ​

当你需要确保数据完整性而不隐藏内容时，使用消息验证器。与加密不同，消息验证器不加密数据。它对负载进行 base64 编码并使用 HMAC 签名，允许任何人读取数据，同时确保它未被篡改。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class StateService {
  createOAuthState(returnUrl: string, provider: string) {
    /**
     * 对状态签名而不加密它。
     * 数据可读但防篡改。
     */
    return encryption.verifier.sign({ returnUrl, provider })
  }

  verifyOAuthState(state: string) {
    /**
     * 验证签名并返回负载。
     * 如果签名无效则返回 null。
     */
    return encryption.verifier.unsign(state)
  }
}

消息验证器对于你想检测篡改但不需要隐藏数据的场景很有用，如 OAuth 状态参数、CSRF 令牌或 webhook 签名。

带用途和过期时间的验证器 ​

消息验证器支持与加密相同的用途绑定和过期功能。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class CsrfService {
  createToken(sessionId: string) {
    /**
     * 创建 1 小时后过期且绑定到
     * 'csrf' 用途的 CSRF 令牌。
     */
    return encryption.verifier.sign({ sessionId }, '1h', 'csrf')
  }

  verifyToken(token: string, expectedSessionId: string) {
    const payload = encryption.verifier.unsign(token, 'csrf')

    if (!payload || payload.sessionId !== expectedSessionId) {
      return false
    }

    return true
  }
}

使用多个驱动 ​

某些应用需要为不同目的使用不同算法加密数据。encryption.use 方法让你显式选择驱动。

ts
import encryption from '@adonisjs/core/services/encryption'

export default class MultiDriverService {
  /**
   * 使用 ChaCha20-Poly1305 进行高性能加密。
   */
  encryptSessionData(data: object) {
    return encryption.use('chacha').encrypt(data)
  }

  /**
   * 使用 AES-256-GCM 以与外部系统兼容。
   */
  encryptForExternalApi(data: object) {
    return encryption.use('gcm').encrypt(data)
  }
}

在 encryption.use() 中指定的每个驱动都必须在你的 config/encryption.ts 文件的 list 对象中配置。

生成 app key ​

加密服务需要在 APP_KEY 环境变量中存储的加密安全密钥。你可以使用 Ace CLI 生成新密钥。

sh
node ace generate:key

此命令生成随机的 32 字符密钥并将其写入 .env 文件。该密钥使用加密安全的随机数生成器，确保它无法被预测或猜测。

APP_KEY 对应用的安全性至关重要。如果此密钥泄露，攻击者可以解密你所有的加密数据并伪造签名 cookie。请安全存储它，绝不要提交到版本控制，并为每个环境使用不同的密钥。

如果你更改或丢失 APP_KEY，所有现有的加密数据将永久无法读取。使用旧密钥签名的 cookie 将被拒绝，加密的数据库值无法恢复。始终安全备份你的生产密钥。
