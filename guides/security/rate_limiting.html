速率限制 ​

本指南涵盖 AdonisJS 应用中的速率限制。你将了解到如何：

  • 使用 Redis、数据库或内存存储安装和配置 limiter 包
  • 为 HTTP 请求创建节流中间件
  • 基于用户身份认证应用动态速率限制
  • 直接使用速率限制进行登录保护和任务队列
  • 使用多重限制器一次执行多个限制
  • 处理速率限制异常并自定义错误消息
  • 创建自定义存储提供者

概述 ​

速率限制控制用户在给定时间段内可以对你的应用发起多少请求。当用户超过其限制时，后续请求将被拒绝，直到时间窗口重置。

你需要速率限制来保护你的应用免受滥用。没有它，单个用户（或机器人）可以用请求压垮你的服务器，消耗本应供合法用户使用的资源。速率限制还有助于防止对登录表单的暴力破解攻击，保护昂贵的 API 端点免于过度使用，并确保对共享资源的公平访问。

@adonisjs/limiter 包构建在 node-rate-limiter-flexible 之上，后者提供最快的速率限制 API 之一，并使用原子递增来避免竞态条件。

安装 ​

使用以下命令安装和配置该包：

sh
node ace add @adonisjs/limiter
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/limiter 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

    ts
    {
  providers: [
    // ...其他提供者
    () => import('@adonisjs/limiter/limiter_provider')
  ]
}

  3. 创建 config/limiter.ts 文件。

  4. 创建 start/limiter.ts 文件用于定义 HTTP 节流中间件。

  5. 在 start/env.ts 文件中定义以下环境变量及其验证。

    ts
    LIMITER_STORE=redis

  6. 如果使用 database 存储，可选地为 rate_limits 表创建数据库迁移。

配置 ​

速率限制器配置存储在 config/limiter.ts 文件中。你定义哪些存储后端可用以及默认使用哪一个。

ts
import env from '#start/env'
import { defineConfig, stores } from '@adonisjs/limiter'

const limiterConfig = defineConfig({
  /**
   * 默认存储通过环境变量选择，
   * 允许在不同环境中使用不同的存储。
   */
  default: env.get('LIMITER_STORE'),

  stores: {
    redis: stores.redis({}),

    database: stores.database({
      tableName: 'rate_limits'
    }),

    memory: stores.memory({}),
  },
})

export default limiterConfig

declare module '@adonisjs/limiter/types' {
  export interface LimitersList extends InferLimiters<typeof limiterConfig> {}
}

default 属性指定用于速率限制的存储。stores 对象定义所有可用的存储后端。我们建议始终配置 memory 存储，以便在测试期间使用它。

另请参阅：速率限制器配置存根

环境变量 ​

默认存储由 LIMITER_STORE 环境变量控制，允许你在环境之间切换存储。例如，你可能在测试期间使用 memory，在生产环境中使用 redis。

环境变量必须在 start/env.ts 中验证，以确保只允许已配置的存储：

ts
{
  LIMITER_STORE: Env.schema.enum(['redis', 'database', 'memory'] as const),
}

共享选项 ​

所有存储后端接受以下选项：

ts
{
  duration: '1 minute',
  requests: 10,

  /**
   * 在 12 次请求后，在内存中阻塞该键
   * 并停止查询数据库。
   */
  inMemoryBlockOnConsumed: 12,
  inMemoryBlockDuration: '1 min'
}

keyPrefix

存储中键的前缀。数据库存储忽略此选项，因为单独的表提供了隔离。

execEvenly

添加人工延迟以在时间窗口内均匀分散请求。详情请参阅平滑流量峰值。

inMemoryBlockOnConsumed

在内存中阻塞该键之前的请求数，减少来自滥用用户的数据库查询。

inMemoryBlockDuration

在内存中阻塞键的时长。通过首先检查内存来减少数据库负载。inMemoryBlockOnConsumed 选项在用户耗尽配额后继续发起请求时很有用。你可以将它们在内存中阻塞，而不是为每个被拒绝的请求查询数据库：

Redis 存储 ​

Redis 存储需要先配置 @adonisjs/redis 包。

ts
{
  redis: stores.redis({
    connectionName: 'main',
    rejectIfRedisNotReady: false,
  }),
}

connectionName

来自 config/redis.ts 的 Redis 连接。我们建议为 limiter 使用单独的数据库。

rejectIfRedisNotReady

当为 true 时，如果 Redis 连接状态不是 ready，则拒绝速率限制请求。

Database 存储 ​

Database 存储需要先配置 @adonisjs/lucid 包。

WARNING

Database 存储仅支持 MySQL、PostgreSQL 和 SQLite。其他数据库如 MongoDB 不兼容，会在运行时抛出错误。

ts
{
  database: stores.database({
    connectionName: 'mysql',
    dbName: 'my_app',
    tableName: 'rate_limits',
    schemaName: 'public',
    clearExpiredByTimeout: false,
  }),
}

connectionName

来自 config/database.ts 的数据库连接。如果未指定则使用默认连接。

dbName

用于 SQL 查询的数据库名称。从连接配置推断，但在使用连接字符串时必需。

tableName

用于存储速率限制数据的表。

schemaName

用于 SQL 查询的模式（仅 PostgreSQL）。

clearExpiredByTimeout

当为 true 时，每 5 分钟清除过期的键。只移除过期超过 1 小时的键。

节流 HTTP 请求 ​

最常见的用例是使用中间件节流 HTTP 请求。limiter.define 方法创建可重用的节流中间件，你可以应用到路由。

打开 start/limiter.ts 文件查看预定义的全局节流中间件。此中间件允许用户根据其 IP 地址每分钟发起 10 次请求：

ts
import limiter from '@adonisjs/limiter/services/main'

export const throttle = limiter.define('global', () => {
  return limiter.allowRequests(10).every('1 minute')
})

将中间件应用到任何路由：

ts
import router from '@adonisjs/core/services/router'
import { throttle } from '#start/limiter'

router
  .get('/', () => {})
  .use(throttle)

当用户在一分钟内超过 10 次请求时，他们将收到 429 Too Many Requests 响应，直到时间窗口重置。

使用自定义键 ​

默认情况下，请求按用户的 IP 地址进行速率限制。你可以使用 usingKey 方法指定不同的键。当你想要按用户 ID、API 密钥或任何其他标识符限制时，这很有用：

ts
export const throttle = limiter.define('global', (ctx) => {
  return limiter
    .allowRequests(10)
    .every('1 minute')
    .usingKey(`user_${ctx.auth.user.id}`)
})

切换后端存储 ​

你可以使用 store 方法为特定中间件覆盖默认存储：

ts
limiter
  .allowRequests(10)
  .every('1 minute')
  .store('redis')

阻塞滥用用户 ​

blockFor 方法在用户耗尽配额后继续发起请求时延长锁定时间。这比简单地重置计数器更有效地阻止滥用：

ts
limiter
  .allowRequests(10)
  .every('1 minute')
  /**
   * 如果用户在一分钟内发送第 11 次请求，
   * 将其阻塞 30 分钟，而不是仅仅等待
   * 1 分钟窗口重置。
   */
  .blockFor('30 mins')

动态速率限制 ​

不同的用户通常需要不同的速率限制。已认证用户可能比访客获得更高的限制，或者高级订阅者可能获得无限访问，而免费用户受到限制。

传递给 limiter.define 的回调接收 HTTP 上下文，允许你根据请求属性应用不同的限制：

ts
export const apiThrottle = limiter.define('api', (ctx) => {
  /**
   * 已认证用户每分钟获得 100 次请求，
   * 按其用户 ID 跟踪。
   */
  if (ctx.auth.user) {
    return limiter
      .allowRequests(100)
      .every('1 minute')
      .usingKey(`user_${ctx.auth.user.id}`)
  }

  /**
   * 访客用户每分钟获得 10 次请求，
   * 按其 IP 地址跟踪。
   */
  return limiter
    .allowRequests(10)
    .every('1 minute')
    .usingKey(`ip_${ctx.request.ip()}`)
})
ts
import { apiThrottle } from '#start/limiter'

router
  .get('/api/repos/:id/stats', [RepoStatusController])
  .use(apiThrottle)

处理 ThrottleException ​

当用户耗尽速率限制时，中间件抛出 E_TOO_MANY_REQUESTS 异常。该异常通过内容协商自动转换为 HTTP 响应：

  • 带有 Accept: application/json 的请求接收 JSON 错误对象。
  • 带有 Accept: application/vnd.api+json 的请求接收 JSON API 格式的错误。
  • 所有其他请求接收纯文本消息。你可以使用状态页面显示自定义错误页面。

另请参阅：E_TOO_MANY_REQUESTS 异常参考

中间件还会添加以下响应头：

  • X-RateLimit-Limit：可发起的请求总数
  • X-RateLimit-Remaining：剩余请求数
  • Retry-After：客户端可以重试的秒数
  • X-RateLimit-Reset：客户端可以重试的时间戳

自定义错误响应 ​

你可以使用 limitExceeded 钩子自定义错误消息，而无需全局处理异常：

ts
export const throttle = limiter.define('global', () => {
  return limiter
    .allowRequests(10)
    .every('1 minute')
    .limitExceeded((error) => {
      error
        .setStatus(400)
        .setMessage('Cannot process request. Try again later')
    })
})

使用翻译 ​

如果你已配置 @adonisjs/i18n 包，使用 errors.E_TOO_MANY_REQUESTS 键定义翻译：

json
{
  "E_TOO_MANY_REQUESTS": "Trop de demandes"
}

你也可以使用带有插值的自定义翻译键：

ts
limitExceeded((error) => {
  error.t('errors.rate_limited', {
    limit: error.response.limit,
    remaining: error.response.remaining,
  })
})

全局处理异常 ​

为了更多控制，在全局异常处理器中处理异常：

ts
import { errors } from '@adonisjs/limiter'
import { HttpContext, ExceptionHandler } from '@adonisjs/core/http'

export default class HttpExceptionHandler extends ExceptionHandler {
  protected debug = !app.inProduction
  protected renderStatusPages = app.inProduction

  async handle(error: unknown, ctx: HttpContext) {
    if (error instanceof errors.E_TOO_MANY_REQUESTS) {
      const message = error.getResponseMessage(ctx)
      const headers = error.getDefaultHeaders()

      Object.keys(headers).forEach((header) => {
        ctx.response.header(header, headers[header])
      })

      return ctx.response.status(error.status).send(message)
    }

    return super.handle(error, ctx)
  }
}

直接使用 ​

除了 HTTP 中间件，你可以在应用的任何部分直接使用 limiter。这对于保护登录表单免受暴力破解攻击、限制后台任务执行或控制对昂贵操作的访问很有用。

创建 limiter 实例 ​

使用 limiter.use 方法创建具有特定设置的 limiter 实例：

ts
import limiter from '@adonisjs/limiter/services/main'

const reportsLimiter = limiter.use('redis', {
  requests: 1,
  duration: '1 hour'
})
选项描述
requests持续时间内允许的请求数。
duration时间窗口，以秒为单位或作为时间表达式字符串。
blockDuration可选。所有请求耗尽后阻塞键的时长。
inMemoryBlockOnConsumed可选。参阅共享选项。
inMemoryBlockDuration可选。参阅共享选项。

要使用默认存储，省略第一个参数：

ts
const reportsLimiter = limiter.use({
  requests: 1,
  duration: '1 hour'
})

限制昂贵操作 ​

attempt 方法仅在未超过速率限制时执行回调。它返回回调的结果，如果达到限制则返回 undefined：

ts
import limiter from '@adonisjs/limiter/services/main'

const reportsLimiter = limiter.use({
  requests: 1,
  duration: '1 hour'
})

export async function generateUserReport(userId: number) {
  const key = `reports_user_${userId}`

  const executed = await reportsLimiter.attempt(key, async () => {
    await generateReport(userId)
    return true
  })

  if (!executed) {
    const availableIn = await reportsLimiter.availableIn(key)
    throw new Error(`Too many requests. Try after ${availableIn} seconds`)
  }

  return 'Report generated'
}

防止暴力破解登录攻击 ​

penalize 方法专为你想仅在操作失败时才消耗请求的场景设计。这对于登录保护非常完美，你希望跟踪失败的尝试而不是成功的尝试。

ts
import User from '#models/user'
import { HttpContext } from '@adonisjs/core/http'
import limiter from '@adonisjs/limiter/services/main'

export default class SessionController {
  async store({ request, response, session }: HttpContext) {
    const { email, password } = request.only(['email', 'password'])

    /**
     * 创建一个每分钟允许 5 次失败尝试，
     * 然后阻塞 20 分钟的 limiter。
     */
    const loginLimiter = limiter.use({
      requests: 5,
      duration: '1 min',
      blockDuration: '20 mins'
    })

    /**
     * 使用 IP + 电子邮件的组合作为键。这确保如果
     * 攻击者尝试多个电子邮件，我们阻塞攻击者的
     * IP 而不影响从不同 IP 使用自己电子邮件
     * 尝试登录的合法用户。
     */
    const key = `login_${request.ip()}_${email}`

    /**
     * penalize 方法仅在回调抛出错误时
     * 消耗一个请求。
     */
    const [error, user] = await loginLimiter.penalize(key, () => {
      return User.verifyCredentials(email, password)
    })

    if (error) {
      session.flashAll()
      session.flashErrors({
        E_TOO_MANY_REQUESTS: `Too many login attempts. Try again after ${error.response.availableIn} seconds`
      })
      return response.redirect().back()
    }

    /**
     * 登录成功 - 继续创建会话
     */
  }
}

使用多重限制器 ​

有时一个限制不够。在登录期间，你想要每个电子邮件地址的严格限制来保护单个账户，以及每个 IP 地址的宽松限制来阻止攻击者从同一台机器循环使用许多电子邮件。

limiter.multi 方法创建一个由多组选项支持的限制器，每组都有自己的键。你在其上调用的每个方法都会应用于所有这些限制器。

ts
import User from '#models/user'
import limiter from '@adonisjs/limiter/services/main'

const loginLimiter = limiter.multi([
  { key: `login_${request.ip()}`, requests: 10, duration: '1 min' },
  {
    key: `login_${request.ip()}_${email}`,
    requests: 5,
    duration: '1 min',
    blockDuration: '20 mins'
  },
])

/**
 * 回调仅在两个限制器都有可用请求时运行，
 * 当凭据无效时，从每个限制器中消耗一个请求。
 */
const [error, user] = await loginLimiter.penalize(() => {
  return User.verifyCredentials(email, password)
})

除了 key 之外，每个对象接受与 limiter.use 相同的选项。传递存储名称作为第一个参数以覆盖默认存储：

ts
const loginLimiter = limiter.multi('redis', [
  { key: `login_${request.ip()}`, requests: 10, duration: '1 min' },
])

consume、increment、decrement、attempt、penalize、get、set 和 delete 方法的行为与它们的单限制器对应方法相同，只是不需要 key 参数，并按你定义限制器的顺序返回响应数组。使用 list 方法单独访问底层限制器。

手动消耗请求 ​

对于细粒度控制，你可以手动检查和消耗请求，而不是使用 attempt 或 penalize。

WARNING

分别调用 remaining 和 increment 会产生竞态条件，多个并发请求可能都在任一递增计数器之前通过检查。改用 consume 方法，它执行原子性的检查并递增操作。

consume 方法递增计数器，如果已达到限制则抛出异常。你可以选择传递数量作为第二个参数以一次消耗多个槽位（对于"加权"速率限制很有用）。

ts
import { errors } from '@adonisjs/limiter'
import limiter from '@adonisjs/limiter/services/main'

const requestsLimiter = limiter.use({
  requests: 10,
  duration: '1 minute'
})

export async function handleApiRequest(userId: number) {
  const key = `api_user_${userId}`

  try {
    /**
     * 为重量级操作一次消耗 5 个槽位
     */
    await requestsLimiter.consume(key, 5)
    return await performAction()
  } catch (error) {
    if (error instanceof errors.E_TOO_MANY_REQUESTS) {
      throw new Error('Rate limit exceeded')
    }
    throw error
  }
}

不抛出的递增 ​

increment 方法的工作方式类似于 consume，但在超过限制时不抛出异常，它也接受可选的数量。它不抛出异常，而是返回 limiter 响应对象，允许你检查剩余请求并决定如何处理：

ts
import limiter from '@adonisjs/limiter/services/main'

const requestsLimiter = limiter.use({
  requests: 10,
  duration: '1 minute'
})

export async function handleApiRequest(userId: number) {
  const key = `api_user_${userId}`
  const response = await requestsLimiter.increment(key, 5)

  if (response.remainingPoints < 0) {
    throw new Error('Rate limit exceeded')
  }

  return await performAction()
}

数量参数的验证

数量参数必须是正整数。为防止逻辑错误或安全绕过，如果你提供小于或等于 0 的值，limiter 将自动回退到 1。

阻塞键 ​

你可以为在耗尽配额后继续发起请求的用户延长锁定时间。这比标准速率限制更具惩罚性，可以阻止滥用。

当你使用 blockDuration 选项创建 limiter 时，会自动发生阻塞：

ts
import limiter from '@adonisjs/limiter/services/main'

const requestsLimiter = limiter.use({
  requests: 10,
  duration: '1 minute',
  blockDuration: '30 mins'
})

/**
 * 用户每分钟可以发起 10 次请求。如果他们发送
 * 第 11 次请求，将被阻塞 30 分钟。
 * consume、attempt 和 penalize 方法都会
 * 自动执行此行为。
 */
await requestsLimiter.consume('a_unique_key')

你也可以手动阻塞键：

ts
await requestsLimiter.block('a_unique_key', '30 mins')

重置尝试 ​

有时你需要将请求归还给用户。例如，如果后台任务完成，你可能想让用户再排队一个。

decrement 方法减少请求计数。默认情况下，它减少 1，但你可以指定自定义数量作为第二个参数。

ts
import limiter from '@adonisjs/limiter/services/main'

const jobsLimiter = limiter.use({
  requests: 10,
  duration: '5 mins',
})

export async function processReportJob(userId: number) {
  const key = `jobs_user_${userId}`

  await jobsLimiter.attempt(key, async () => {
    await processJob()

    /**
     * 任务完成 - 归还槽位，以便
     * 可以排队另一个任务。
     */
    await jobsLimiter.decrement(key, 5)
  })
}

TIP

就像 increment 和 consume 一样，提供 <= 0 的数量会导致方法回退到 1。

TIP

decrement 方法不是原子性的。在高并发下，请求计数可能短暂变为 -1。如果你需要完全重置键，请使用 delete 方法。

delete 方法完全移除键：

ts
await requestsLimiter.delete('unique_key')

测试 ​

在测试期间，你通常希望使用 memory 存储而不是 Redis 或数据库。在 .env.test 文件中设置环境变量：

dotenv
LIMITER_STORE=memory

使用 limiter.clear 方法在测试之间清除速率限制存储：

ts
import limiter from '@adonisjs/limiter/services/main'

test.group('Reports', (group) => {
  group.each.setup(() => {
    return () => limiter.clear(['memory'])
  })
})

你也可以不带参数调用 clear 以清空所有已配置的存储：

ts
return () => limiter.clear()

WARNING

使用 Redis 时，clear 方法会清空整个数据库。为速率限制器使用单独的 Redis 数据库，以避免清除应用数据。在 config/redis.ts 中通过创建专用连接来配置。

创建自定义存储提供者 ​

你可以通过实现 LimiterStoreContract 接口来创建自定义存储提供者。当你需要使用内置存储不支持的数据库时，这很有用。

ts
import string from '@adonisjs/core/helpers/string'
import { LimiterResponse } from '@adonisjs/limiter'
import {
  LimiterStoreContract,
  LimiterConsumptionOptions
} from '@adonisjs/limiter/types'

export type MongoDbLimiterConfig = {
  client: MongoDBConnection
}

export class MongoDbLimiterStore implements LimiterStoreContract {
  readonly name = 'mongodb'
  declare readonly requests: number
  declare readonly duration: number
  declare readonly blockDuration: number

  constructor(config: MongoDbLimiterConfig & LimiterConsumptionOptions) {
    this.requests = config.requests
    this.duration = string.seconds.parse(config.duration)
    this.blockDuration = string.seconds.parse(config.blockDuration)
  }

  /**
   * 为键消耗一个请求。当所有请求都已消耗时
   * 抛出错误。
   */
  async consume(key: string | number, amount?: number): Promise<LimiterResponse> {}

  /**
   * 消耗一个请求而在耗尽时不抛出。
   */
  async increment(key: string | number, amount?: number): Promise<LimiterResponse> {}

  /**
   * 归还一个请求给键。
   */
  async decrement(key: string | number, amount?: number): Promise<LimiterResponse> {}

  /**
   * 将键阻塞指定时长。
   */
  async block(
    key: string | number,
    duration: string | number
  ): Promise<LimiterResponse> {}

  /**
   * 设置键的已消耗请求计数。
   */
  async set(
    key: string | number,
    requests: number,
    duration?: string | number
  ): Promise<LimiterResponse> {}

  /**
   * 从存储中删除键。
   */
  async delete(key: string | number): Promise<boolean> {}

  /**
   * 清空存储中的所有键。
   */
  async clear(): Promise<void> {}

  /**
   * 获取键的 limiter 响应，如果键不存在
   * 则返回 null。
   */
  async get(key: string | number): Promise<LimiterResponse | null> {}
}

创建配置辅助函数 ​

创建一个辅助函数以在配置文件中使用你的存储。该辅助函数应返回 LimiterManagerStoreFactory 函数：

ts
import { LimiterManagerStoreFactory } from '@adonisjs/limiter/types'

export function mongoDbStore(config: MongoDbLimiterConfig) {
  const storeFactory: LimiterManagerStoreFactory = (runtimeOptions) => {
    return new MongoDbLimiterStore({
      ...config,
      ...runtimeOptions
    })
  }

  return storeFactory
}

使用你的自定义存储 ​

ts
import env from '#start/env'
import { mongoDbStore } from '#app/limiter/mongodb_store'
import { defineConfig } from '@adonisjs/limiter'

const limiterConfig = defineConfig({
  default: env.get('LIMITER_STORE'),

  stores: {
    mongodb: mongoDbStore({
      client: mongoDb
    })
  },
})

包装 rate-limiter-flexible 驱动 ​

如果你在包装来自 node-rate-limiter-flexible 的现有驱动，使用 RateLimiterBridge 类可以简化实现：

ts
import { RateLimiterBridge } from '@adonisjs/limiter'
import { RateLimiterMongo } from 'rate-limiter-flexible'

export class MongoDbLimiterStore extends RateLimiterBridge {
  readonly name = 'mongodb'

  constructor(config: MongoDbLimiterConfig & LimiterConsumptionOptions) {
    super(
      new RateLimiterMongo({
        storeClient: config.client,
        points: config.requests,
        duration: string.seconds.parse(config.duration),
        blockDuration: string.seconds.parse(config.blockDuration)
      })
    )
  }

  /**
   * 桥接类处理大多数方法，但你必须
   * 自己实现 clear()。
   */
  async clear() {
    await this.config.client.collection('rate_limits').deleteMany({})
  }
}
