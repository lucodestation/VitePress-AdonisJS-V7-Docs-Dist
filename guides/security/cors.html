CORS ​

本指南涵盖 AdonisJS 应用中的跨源资源共享（CORS）。你将了解到如何：

  • 安装和配置 CORS 中间件
  • 控制允许哪些源、方法和头
  • 处理跨源请求中的凭据
  • 调试常见的 CORS 错误

概述 ​

当浏览器向与当前页面不同域的服务器发起请求时，它会强制执行跨源资源共享（CORS）限制。这种安全机制防止恶意脚本代表用户向你的 API 发起未授权请求。

例如，如果你的前端运行在 app.example.com，API 运行在 api.example.com，浏览器将阻止来自前端的请求，除非你的 API 显式允许该源。本地开发时也是如此，前端运行在 localhost:3000，API 运行在 localhost:3333。

在发起某些跨源请求之前，浏览器会使用 OPTIONS HTTP 方法发送预检请求。此预检询问你的服务器允许哪些源、方法和头。你的服务器必须响应适当的 CORS 头，然后浏览器才会继续实际请求。

AdonisJS 通过 @adonisjs/cors 包处理 CORS，该包提供中间件，自动响应预检请求并为所有响应附加正确的头。

安装 ​

使用以下命令安装和配置该包：

sh
node ace add @adonisjs/cors
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/cors 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

    ts
    {
  providers: [
    // ...其他提供者
    () => import('@adonisjs/cors/cors_provider')
  ]
}

  3. 创建 config/cors.ts 文件。此文件包含 CORS 的配置设置。

  4. 在 start/kernel.ts 文件中注册以下中间件。

    ts
    server.use([
  () => import('@adonisjs/cors/cors_middleware')
])

配置 ​

CORS 配置位于 config/cors.ts。以下是包含所有可用选项的默认配置：

ts
import app from '@adonisjs/core/services/app'
import { defineConfig } from '@adonisjs/cors'

const corsConfig = defineConfig({
  enabled: true,
  origin: app.inDev ? true : [],
  methods: ['GET', 'HEAD', 'POST', 'PUT', 'DELETE'],
  headers: true,
  exposeHeaders: [],
  credentials: true,
  maxAge: 90,
})

export default corsConfig

在开发环境中，origin 设置为 true 以允许所有源，便于本地前后端设置。在生产环境中，它默认为空数组 []，这会阻止所有跨源请求，直到你显式配置允许的源。

启用和禁用 CORS ​

enabled 选项在不从中间件栈中移除中间件的情况下打开或关闭它。当你想在调试期间或特定环境中临时禁用 CORS 时，这很有用。

ts
{
  enabled: process.env.NODE_ENV !== 'test'
}

配置允许的源 ​

origin 选项控制哪些域可以向你的 API 发起跨源请求。这设置 Access-Control-Allow-Origin 响应头。

动态允许所有源（响应头将镜像请求源）：

ts
{
  origin: true
}

禁止所有跨源请求：

ts
{
  origin: false
}

允许特定域，提供源数组：

ts
{
  origin: ['https://app.example.com', 'https://admin.example.com']
}

使用通配符允许任何源：

ts
{
  origin: '*'
}

WARNING

当 credentials 设置为 true 时，通配符 * 不能用作 Access-Control-Allow-Origin 头的值。出于安全原因，浏览器会拒绝这种组合。当同时配置 origin: '*' 和 credentials: true 时，AdonisJS 会自动通过反射请求源而不是发送字面量 * 来处理这一点。

对于动态源验证，提供回调函数。当允许的源存储在数据库中或你需要自定义验证逻辑时，这很有用：

ts
{
  origin: (requestOrigin, ctx) => {
    /**
     * requestOrigin 是 Origin 头的值。
     * 返回 true 允许，返回 false 拒绝。
     */
    const allowedOrigins = ['https://app.example.com']
    return allowedOrigins.includes(requestOrigin)
  }
}

配置允许的方法 ​

methods 选项指定允许哪些 HTTP 方法用于跨源请求。浏览器的预检请求包含 Access-Control-Request-Method 头，服务器将此值与允许的方法进行检查。

ts
{
  methods: ['GET', 'HEAD', 'POST', 'PUT', 'DELETE']
}

配置允许的头 ​

headers 选项控制跨源请求中允许哪些请求头。浏览器的预检请求包含 Access-Control-Request-Headers 头，列出客户端想要发送的头。

允许所有头：

ts
{
  headers: true
}

允许特定头：

ts
{
  headers: ['Content-Type', 'Accept', 'Authorization']
}

对于动态头验证，提供回调：

ts
{
  headers: (requestHeaders, ctx) => {
    return true
  }
}

暴露响应头 ​

默认情况下，浏览器仅向 JavaScript 暴露有限的一组响应头。exposeHeaders 选项让你指定应对客户端可访问的额外头。

ts
{
  exposeHeaders: ['X-Request-Id', 'X-RateLimit-Remaining']
}

允许凭据 ​

credentials 选项控制 cookie、authorization 头和 TLS 客户端证书是否可以包含在跨源请求中。启用时，服务器发送 Access-Control-Allow-Credentials: true 头。

ts
{
  credentials: true
}

TIP

当前端需要向你的 API 发送身份认证 cookie 或 Authorization 头时，启用 credentials。没有它，浏览器会从跨源请求中剥离凭据。

缓存预检响应 ​

maxAge 选项指定浏览器应缓存预检响应的时长（秒）。这减少了重复跨源调用的预检请求数量。

ts
{
  maxAge: 90
}

将 maxAge 设置为 null 会完全省略 Access-Control-Max-Age 头。将其设置为 -1 会发送头但禁用缓存。

常见场景 ​

为单页应用提供服务的 API ​

当你的 API 和前端部署在不同域上时，配置 CORS 以允许前端的源并带凭据：

ts
import { defineConfig } from '@adonisjs/cors'

const corsConfig = defineConfig({
  enabled: true,
  origin: ['https://app.example.com'],
  methods: ['GET', 'HEAD', 'POST', 'PUT', 'DELETE'],
  headers: true,
  credentials: true,
  maxAge: 90,
})

export default corsConfig

使用不同端口的本地开发 ​

在开发期间，你的前端和后端通常运行在不同端口上。配置 CORS 以允许本地前端源：

ts
import { defineConfig } from '@adonisjs/cors'

const corsConfig = defineConfig({
  enabled: true,
  origin: (requestOrigin) => {
    /**
     * 在开发期间允许任意端口上的 localhost。
     */
    return requestOrigin.startsWith('http://localhost')
  },
  methods: ['GET', 'HEAD', 'POST', 'PUT', 'DELETE'],
  headers: true,
  credentials: true,
  maxAge: 90,
})

export default corsConfig

无凭据的公共 API ​

如果你的 API 是公开的且不需要 cookie 或身份认证头，可以使用宽松的配置：

ts
import { defineConfig } from '@adonisjs/cors'

const corsConfig = defineConfig({
  enabled: true,
  origin: '*',
  methods: ['GET', 'HEAD', 'POST'],
  headers: true,
  credentials: false,
  maxAge: 86400,
})

export default corsConfig
