Lucid - SQL ORM ​

本指南涵盖 Lucid ORM，AdonisJS 的官方数据库 ORM。你将了解到如何：

  • 配置数据库连接
  • 使用查询构建器和模型
  • 创建迁移和定义关系
  • 处理事务和钩子
  • 序列化模型和生成测试数据

概述 ​

Lucid ORM 是一个构建在 Knex 之上的 Active Record ORM，深度集成在 AdonisJS 生态系统中。与需要大量配置的独立 ORM 不同，Lucid 与 AdonisJS 的验证器、身份认证层、缓存、速率限制和队列等功能无缝协作，无需任何额外设置。

Lucid 通过使用特定语言的对象和类封装常见操作来简化数据库交互。它构建在 Knex 之上，这意味着你可以在需要时使用 JavaScript API 表达复杂的 SQL 查询。Lucid 支持多种数据库，包括 MySQL、PostgreSQL、Turso、SQLite 和 MSSQL。基于类的模型系统让你的代码直观且类型安全，而内置的关系支持让你可以建模复杂的数据结构。迁移系统为你的数据库模式提供版本控制，填充文件和工厂帮助你用测试数据填充数据库。

本指南提供 Lucid 功能的高层概述，帮助你理解可用内容以及各部分如何协同工作。详细的 API 参考、高级模式和特定功能的完整文档，请参阅官方 Lucid 文档。

配置 ​

Lucid 的配置位于 AdonisJS 项目根目录的 config/database.ts 文件中。此文件定义你的数据库连接、迁移路径和其他 ORM 设置。

typescript
import env from '#start/env'
import { defineConfig } from '@adonisjs/lucid'

const dbConfig = defineConfig({
  connection: env.get('DB_CONNECTION'),
  connections: {
    postgres: {
      client: 'pg',
      connection: {
        host: env.get('DB_HOST'),
        port: env.get('DB_PORT'),
        user: env.get('DB_USER'),
        password: env.get('DB_PASSWORD'),
        database: env.get('DB_DATABASE'),
      },
      migrations: {
        naturalSort: true,
        paths: ['database/migrations'],
      },
    },
  },
})

export default dbConfig

配置指定默认使用哪个数据库连接（通常通过环境变量设置），并定义每个数据库的连接详情。每个连接包括客户端库（如 PostgreSQL 的 pg 或 MySQL 的 mysql2）、连接凭据和迁移文件的路径。

你可以在 Lucid 配置文档中探索所有可用的配置选项、连接池设置以及读写副本等高级功能。

直接使用查询构建器 ​

在深入了解模型之前，你可以直接使用 Lucid 的查询构建器进行数据库操作。查询构建器提供流畅的 JavaScript API 来构造 SQL 查询，这对于复杂查询或不需要完整 Active Record 模式的情况特别有用。

查询构建器通过 db 服务可用，其工作方式与 Knex 完全相同，因为 Lucid 构建在其之上。

typescript
import db from '@adonisjs/lucid/services/db'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ response }: HttpContext) {
    /**
     * 选择所有已发布的帖子，按创建日期排序。
     * 这返回纯对象数组。
     */
    const posts = await db
      .from('posts')
      .select('*')
      .where('status', 'published')
      .orderBy('created_at', 'desc')

    return response.json(posts)
  }

  async store({ request, response }: HttpContext) {
    const { title, content } = request.only(['title', 'content'])

    /**
     * 插入新帖子并返回生成的 ID。
     * 插入查询返回 ID 数组。
     */
    const [id] = await db
      .insertQuery()
      .table('posts')
      .insert({
        title,
        content,
        status: 'draft',
        created_at: new Date(),
        updated_at: new Date(),
      })

    return response.created({ id })
  }
}

查询构建器自动处理参数化查询，防止 SQL 注入。你可以将其用于选择、插入、更新、删除、连接、聚合和任何其他 SQL 操作。当你需要原始 SQL 进行复杂操作时，可以使用 db.rawQuery()。

完整的查询构建器 API（包括连接、子查询、聚合和高级 where 子句），请参阅 Lucid 查询构建器文档。

使用模型 ​

模型提供面向对象的方式与数据库表交互。每个模型类代表一个表，每个模型实例代表一行。Lucid 使用迁移优先的方法，你在迁移中定义模式，Lucid 自动生成 TypeScript 模式类供你的模型继承。

创建你的第一个迁移 ​

迁移是 Lucid 模式管理的基础。它们为数据库模式提供版本控制，允许你随时间逐步演进模式。每个迁移是一个 TypeScript 文件，带有 up 和 down 方法，定义如何推进模式和如何回滚。

为 posts 表创建迁移：

bash
node ace make:migration posts

这会在 database/migrations/ 中生成一个带时间戳的迁移文件。时间戳确保迁移按正确顺序运行。

typescript
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'posts'

  async up() {
    /**
     * up 方法创建表结构。
     * 使用 schema 构建器定义列和约束。
     */
    this.schema.createTable(this.tableName, (table) => {
      table.increments('id')
      table.string('title').notNullable()
      table.text('content').notNullable()
      table.string('status').defaultTo('draft')
      table.timestamp('created_at')
      table.timestamp('updated_at')
    })
  }

  async down() {
    /**
     * down 方法逆转 up 方法的更改。
     * 这使在需要时回滚迁移成为可能。
     */
    this.schema.dropTable(this.tableName)
  }
}

运行迁移以创建表：

bash
node ace migration:run

Lucid 执行迁移，在你的数据库中创建 posts 表，并在 database/schema.ts 自动生成包含类型安全列定义的模式类。

TIP

迁移默认在事务内运行。如果迁移失败，所有更改会自动回滚，保持数据库处于一致状态。

更多迁移操作（如修改表、添加索引和处理外键），请参阅 Lucid 迁移文档。

自动生成的模式类 ​

运行迁移后，Lucid 扫描你的数据库并生成包含所有列定义及正确类型的 TypeScript 模式类。这种迁移优先的方法保持模型整洁，并确保你的 TypeScript 类型始终与实际数据库模式匹配。

生成的模式类位于 database/schema.ts。

typescript
import { DateTime } from 'luxon'
import { BaseModel, column } from '@adonisjs/lucid/orm'

export class PostsSchema extends BaseModel {
  static table = 'posts'

  @column({ isPrimary: true })
  declare id: number

  @column()
  declare title: string

  @column()
  declare content: string

  @column()
  declare status: string

  @column.dateTime({ autoCreate: true })
  declare createdAt: DateTime | null

  @column.dateTime({ autoCreate: true, autoUpdate: true })
  declare updatedAt: DateTime | null
}

Lucid 自动将数据库类型转换为适当的 TypeScript 类型，将 snake_case 列名转换为 camelCase 属性，将时间戳列转换为 Luxon DateTime 对象。autoCreate 选项意味着 Lucid 在创建记录时设置时间戳，autoUpdate 意味着它在每次保存时更新时间戳。

模式生成规则 ​

可以通过配置模式生成规则来控制默认模式生成。确保你的数据库配置启用了生成并指向 database/schema_rules.ts 文件：

typescript
import { type SchemaRules } from '@adonisjs/lucid/types/schema_generator';

export default {
  types: {
    /**
     * 全局自定义所有 JSON 列使用类型安全的 JSON 包装器，
     * 而不是默认的 'any' 类型。
     */
    jsonb: {
      decorator: '@column()',
      tsType: 'JSON<any>',
      imports: [{ source: '#types/db', typeImports: ['JSON'] }],
    },
  },
  tables: {
    /**
     * 自定义 users 表，使 user_role 列
     * 成为严格的联合类型而不是泛型字符串。
     */
    users: {
      columns: {
        user_role: {
          decorators: [{ name: '@column' }],
          tsType: `'admin' | 'editor'`,
        },
      },
    },
  },
} satisfies SchemaRules;

创建模型 ​

现在创建一个继承生成的模式类的模型：

bash
node ace make:model Post
typescript
import { PostsSchema } from '#database/schema'

export default class Post extends PostsSchema {
  // 你的模型已准备好使用，所有列都从模式继承
}

模型从模式类继承所有列定义。你将在这里添加关系、钩子和自定义方法，而模式类处理列定义。

WARNING

绝不要直接修改 database/schema.ts 中生成的模式类。这些文件在每次迁移后重新生成。相反，在你的模型类中覆盖列或添加自定义逻辑，模型类继承模式类并保留你的更改。

如果你需要更改列类型或添加列，请创建新的迁移。运行迁移后模式类会自动更新。

了解更多关于自定义类型映射和模式生成规则的信息，请参阅 Lucid 模式类文档。

基本 CRUD 操作 ​

模型准备好后，你可以使用直观的 API 执行创建、读取、更新和删除操作。

创建记录：

typescript
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async store({ request, response }: HttpContext) {
    /**
     * 使用 create 方法创建新帖子。
     * Lucid 自动设置 created_at 和 updated_at。
     */
    const post = await Post.create({
      title: request.input('title'),
      content: request.input('content'),
      status: 'draft',
    })

    return response.created(post)
  }
}

读取记录：

typescript
export default class PostsController {
  async index({ response }: HttpContext) {
    /**
     * 获取所有帖子，按创建日期排序。
     * 返回 Post 模型实例数组。
     */
    const posts = await Post.query().orderBy('created_at', 'desc')
    return response.json(posts)
  }

  async show({ params, response }: HttpContext) {
    /**
     * 按 ID 查找特定帖子。
     * 如果未找到则抛出 404 异常。
     */
    const post = await Post.findOrFail(params.id)
    return response.json(post)
  }
}

更新记录：

typescript
export default class PostsController {
  async update({ params, request, response }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    /**
     * 合并更新并保存到数据库。
     * updated_at 时间戳自动更新。
     */
    await post.merge({
      title: request.input('title'),
      content: request.input('content'),
    }).save()

    return response.json(post)
  }
}

删除记录：

typescript
export default class PostsController {
  async destroy({ params, response }: HttpContext) {
    const post = await Post.findOrFail(params.id)

    /**
     * 从数据库删除帖子。
     * 这会触发模型上定义的任何删除钩子。
     */
    await post.delete()

    return response.noContent()
  }
}

对于幂等操作（如 firstOrCreate、updateOrCreate）和批量操作（如 createMany），请参阅 Lucid CRUD 操作文档。

从模型访问查询构建器 ​

虽然基本 CRUD 方法处理常见场景，但你经常需要更复杂的查询。每个模型通过 query() 方法提供对查询构建器的访问，让你在仍使用模型实例的同时拥有完整的 SQL 灵活性。

typescript
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async published({ response }: HttpContext) {
    /**
     * 使用查询构建器构建复杂查询。
     * 结果仍然是 Post 模型实例。
     */
    const posts = await Post.query()
      .where('status', 'published')
      .whereNotNull('published_at')
      .where('created_at', '>', new Date('2024-01-01'))
      .orderBy('published_at', 'desc')
      .limit(10)

    return response.json(posts)
  }

  async search({ request, response }: HttpContext) {
    const searchTerm = request.input('q')

    /**
     * 使用带运算符的 where 子句和多个条件。
     * orWhere 方法向查询添加 OR 条件。
     */
    const posts = await Post.query()
      .where('title', 'ilike', `%${searchTerm}%`)
      .orWhere('content', 'ilike', `%${searchTerm}%`)
      .where('status', 'published')

    return response.json(posts)
  }
}

查询构建器方法返回模型实例而不是纯对象，这意味着你可以获得所有模型功能，如关系、序列化和钩子。你可以链接任何 Knex 查询构建器方法，包括连接、子查询、分组和聚合。

完整的查询构建器 API，请参阅 Lucid 查询构建器文档。

在开发期间美化打印查询 ​

理解你的应用生成什么 SQL 查询有助于调试和优化。Lucid 提供内置的查询调试功能，在开发期间将 SQL 语句美化打印到控制台。

美化打印在开发模式下默认启用。你会在终端中看到格式化的 SQL 查询：

sql
select * from "posts" where "status" = 'published' order by "created_at" desc

该功能在你的数据库配置中设置：

typescript
const dbConfig = defineConfig({
  prettyPrintDebugQueries: true,
  connections: {
    postgres: {
      client: 'pg',
      connection: {},
      /**
       * 启用调试模式以记录此连接的所有查询。
       * 在生产环境中设置为 false 以避免性能开销。
       */
      debug: true,
    },
  },
})

你也可以按查询启用调试：

typescript
const posts = await Post
  .query()
  .debug(true)
  .where('status', 'published')

对查询调试和日志记录的更多控制（包括监听查询事件），请参阅 Lucid 调试文档。

分页 ​

分页通过以可管理的块加载记录，防止处理大型数据集时的性能问题。Lucid 提供基于偏移的分页，与查询构建器和模型无缝集成。

typescript
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ request, response }: HttpContext) {
    const page = request.input('page', 1)
    const limit = 20

    /**
     * 分页帖子，每页 20 条记录。
     * 始终使用 orderBy 以确保分页一致。
     */
    const posts = await Post
      .query()
      .where('status', 'published')
      .orderBy('created_at', 'desc')
      .paginate(page, limit)

    /**
     * 设置分页链接的基础 URL。
     * 这使生成正确的页面 URL 成为可能。
     */
    posts.baseUrl('/posts')

    return response.json(posts)
  }
}

分页器提供关于当前页面的元数据：

json
{
  "meta": {
    "total": 245,
    "perPage": 20,
    "currentPage": 1,
    "lastPage": 13,
    "firstPage": 1,
    "firstPageUrl": "/posts?page=1",
    "lastPageUrl": "/posts?page=13",
    "nextPageUrl": "/posts?page=2",
    "previousPageUrl": null
  },
  "data": [
    // Post 对象
  ]
}

你可以使用此元数据在模板中构建分页 UI：

text
@each(anchor in posts.getUrlsForRange(1, posts.lastPage))
  <a href="{{ anchor.url }}" class="{{ anchor.isActive ? 'active' : '' }}">
    {{ anchor.page }}
  </a>
@endeach

TIP

分页时始终包含 orderBy 子句。没有显式排序时，数据库引擎可能以随机顺序返回记录，导致项目出现在多个页面上或在用户导航时被完全跳过。

基于游标的分页和自定义 JSON 响应格式，请参阅 Lucid 分页文档。

事务 ​

数据库事务通过将多个操作分组为原子单元来确保数据完整性。如果任何操作失败，整个事务回滚，防止可能使数据库处于不一致状态的部分更新。

Lucid 提供托管事务，在成功时自动提交，在异常时回滚：

typescript
import db from '@adonisjs/lucid/services/db'
import Post from '#models/post'
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async store({ request, auth, response }: HttpContext) {
    /**
     * 将操作包裹在事务中。
     * 如果任何操作抛出异常，所有更改自动回滚。
     */
    const post = await db.transaction(async (trx) => {
      const user = auth.getUserOrFail()

      /**
       * 使用事务创建帖子。
       * 此回调内的所有模型操作使用同一个事务。
       */
      const post = new Post()
      post.title = request.input('title')
      post.content = request.input('content')
      post.useTransaction(trx)
      await post.save()

      /**
       * 更新用户的帖子计数。
       * 这共享同一个事务，确保两个操作
       * 一起成功或一起失败。
       */
      user.useTransaction(trx)
      user.postCount = user.postCount + 1
      await user.save()

      return post
    })

    return response.created(post)
  }
}

手动事务控制、隔离级别和保存点，请参阅 Lucid 事务文档。

模型钩子 ​

钩子允许你在模型生命周期的特定点执行代码。你可以使用钩子在保存前哈希密码、验证数据、更新相关记录或执行任何应在模型操作期间自动发生的逻辑。

typescript
import { UsersSchema } from '#database/schema'
import { beforeSave } from '@adonisjs/lucid/orm'
import hash from '@adonisjs/core/services/hash'

export default class User extends UsersSchema {
  /**
   * 在保存到数据库之前哈希密码。
   * 该钩子在插入和更新之前运行。
   */
  @beforeSave()
  static async hashPassword(user: User) {
    /**
     * 仅在密码被修改时进行哈希。
     * $dirty 对象跟踪哪些属性已更改。
     */
    if (user.$dirty.password) {
      user.password = await hash.make(user.password)
    }
  }
}

Lucid 为不同的生命周期事件提供钩子。Before 钩子（@beforeSave、@beforeCreate、@beforeUpdate、@beforeDelete）在数据库操作之前运行，可以修改数据或取消操作。After 钩子（@afterSave、@afterCreate、@afterUpdate、@afterDelete）在数据库操作之后运行，对于发送通知等副作用很有用。Query 钩子（@beforeFind、@afterFind、@beforeFetch、@afterFetch）在获取操作期间运行，可以自动过滤结果。

typescript
import { PostsSchema } from '#database/schema'
import { beforeFind, afterCreate } from '@adonisjs/lucid/orm'

export default class Post extends PostsSchema {
  /**
   * 自动从查询中排除软删除的帖子。
   * 此钩子修改每个查找查询以过滤已删除记录。
   */
  @beforeFind()
  static ignoreDeleted(query) {
    query.where('isDeleted', false)
  }

  /**
   * 创建帖子后发送通知。
   * After 钩子接收已保存的模型实例。
   */
  @afterCreate()
  static async notifyFollowers(post: Post) {
    // 向关注者发送通知
  }
}

WARNING

直接查询构建器更新完全绕过钩子。当你使用 await Post.query().where('id', 1).update({ title: 'New' }) 时，不执行任何钩子，时间戳也不会自动更新。

这种行为出于更新多条记录时的性能原因。如果你需要钩子运行，先获取模型实例，修改它，然后调用 save()。

完整的钩子生命周期信息和高级模式，请参阅 Lucid 钩子文档。

模型关系 ​

关系定义你的模型如何相互连接，使处理相关数据变得容易。Lucid 支持一对一、一对多和多对多关系，具有懒加载和预加载。

定义关系 ​

一个用户有多个帖子：

typescript
import { UsersSchema } from '#database/schema'
import { hasMany } from '@adonisjs/lucid/orm'
import Post from '#models/post'
import type { HasMany } from '@adonisjs/lucid/types/relations'

export default class User extends UsersSchema {
  /**
   * 定义一对多关系。
   * 一个用户可以有多个帖子。
   */
  @hasMany(() => Post)
  declare posts: HasMany<typeof Post>
}

一个帖子属于一个用户：

typescript
import { PostsSchema } from '#database/schema'
import { belongsTo } from '@adonisjs/lucid/orm'
import User from '#models/user'
import type { BelongsTo } from '@adonisjs/lucid/types/relations'

export default class Post extends PostsSchema {
  /**
   * 定义反向关系。
   * 每个帖子属于一个用户。
   */
  @belongsTo(() => User)
  declare user: BelongsTo<typeof User>
}

预加载关系 ​

预加载预先获取关系，避免 N+1 查询问题（每条相关记录执行一次查询）：

typescript
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ response }: HttpContext) {
    /**
     * 为所有帖子预加载 user 关系。
     * 这总共执行两个查询：一个用于帖子，一个用于所有用户。
     */
    const posts = await Post.query().preload('user')

    /**
     * 访问相关用户而无需额外查询。
     * 每个帖子现在都有带有已加载数据的 user 属性。
     */
    posts.forEach(post => {
      console.log(post.user.email)
    })

    return response.json(posts)
  }
}

你可以预加载多个关系并嵌套它们：

typescript
/**
 * 加载用户及其个人资料，以及所有评论及其作者。
 * 嵌套预加载适用于任何深度的关系。
 */
const posts = await Post.query()
  .preload('user', (query) => {
    query.preload('profile')
  })
  .preload('comments', (query) => {
    query.preload('author')
  })

多对多关系 ​

对于像用户属于多个团队这样的多对多关系：

typescript
import { UsersSchema } from '#database/schema'
import { manyToMany } from '@adonisjs/lucid/orm'
import Team from '#models/team'
import type { ManyToMany } from '@adonisjs/lucid/types/relations'

export default class User extends UsersSchema {
  /**
   * 通过中间表定义多对多关系。
   * Lucid 期望一个带有 user_id 和 team_id 列的 team_user 表。
   */
  @manyToMany(() => Team, {
    pivotColumns: ['role', 'joined_at'],
  })
  declare teams: ManyToMany<typeof Team>
}

附加和分离相关记录：

typescript
const user = await User.findOrFail(1)

/**
 * 附加团队及额外的中间表数据。
 * 中间表存储关系加上额外列。
 */
await user.related('teams').attach({
  1: { role: 'admin' },
  2: { role: 'member' },
})

/**
 * sync 仅保留指定团队，分离其他团队。
 * 对于“全部保存”风格的操作很有用。
 */
await user.related('teams').sync([1, 2, 3])

Has-one 关系、关系查询和多态关系等高级模式，请参阅 Lucid 关系文档。

序列化模型 ​

从 HTTP 端点返回模型时，你需要将它们转换为纯 JavaScript 对象。Lucid 提供强大的序列化功能，控制输出中出现哪些字段、转换数据并处理关系。

typescript
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class UsersController {
  async show({ params, response }: HttpContext) {
    const user = await User.query()
      .where('id', params.id)
      .preload('posts')
      .firstOrFail()

    /**
     * 将模型序列化为纯对象。
     * 这自动排除敏感字段并格式化日期。
     */
    return response.json(user.serialize({
      fields: {
        omit: ['password', 'rememberMeToken'],
      },
      relations: {
        posts: {
          fields: {
            pick: ['id', 'title', 'createdAt'],
          },
        },
      },
    }))
  }
}

使用列选项在模型级别控制序列化：

typescript
import { UsersSchema } from '#database/schema'
import { column } from '@adonisjs/lucid/orm'

export default class User extends UsersSchema {
  /**
   * 覆盖 password 列以从所有序列化中排除。
   * 将 serializeAs 设置为 null 防止此字段出现在 JSON 中。
   */
  @column({ serializeAs: null })
  declare password: string

  /**
   * 覆盖 firstName 列以在 JSON 输出中重命名。
   * 数据库列是 snake_case，但 JSON 使用 camelCase。
   */
  @column({ serializeAs: 'firstName' })
  declare firstName: string
}

自定义序列化逻辑、计算属性和与转换器一起使用，请参阅 Lucid 序列化文档和 AdonisJS 转换器文档。

模型工厂 ​

工厂为测试和数据库填充生成假数据。与其手动创建测试记录，不如定义一次工厂并按需生成逼真的数据。

为你的模型创建工厂：

bash
node ace make:factory Post
typescript
import Post from '#models/post'
import Factory from '@adonisjs/lucid/factories'

export const PostFactory = Factory.define(Post, ({ faker }) => {
  /**
   * 定义如何为每列生成假数据。
   * Faker 提供生成逼真假数据的方法。
   */
  return {
    title: faker.lorem.sentence(),
    content: faker.lorem.paragraphs(3),
    status: 'draft',
  }
}).build()

在测试或填充文件中使用工厂：

typescript
import { PostFactory } from '#database/factories/post_factory'

/**
 * 创建带有假数据的单个帖子。
 * 工厂为每个字段生成随机值。
 */
const post = await PostFactory.create()

/**
 * 一次创建多个帖子。
 * 这生成 10 个带有唯一假数据的帖子。
 */
const posts = await PostFactory.createMany(10)

/**
 * 覆盖特定属性，同时为其他属性使用假数据。
 * 当你需要特定值进行测试时很有用。
 */
const publishedPost = await PostFactory
  .merge({ status: 'published' })
  .create()

工厂支持常见变体的状态：

typescript
export const PostFactory = Factory.define(Post, ({ faker }) => {
  return {
    title: faker.lorem.sentence(),
    content: faker.lorem.paragraphs(3),
    status: 'draft',
  }
})
  .state('published', (post) => {
    post.status = 'published'
    post.publishedAt = new Date()
  })
  .build()
typescript
/**
 * 使用状态创建已发布的帖子。
 * 状态为你的工厂提供可重用的变体。
 */
const publishedPosts = await PostFactory
  .apply('published')
  .createMany(5)

关系工厂、在测试中打桩数据库调用和高级工厂模式，请参阅 Lucid 工厂文档。
