Redis ​

本指南涵盖 AdonisJS 应用中的 Redis 集成。你将了解到如何：

  • 安装和配置包
  • 执行 Redis 命令
  • 管理多个连接
  • 使用发布/订阅消息
  • 处理连接错误
  • 配置集群和哨兵

概述 ​

@adonisjs/redis 包是 ioredis（一个 Node.js Redis 客户端）之上的薄封装，在发布/订阅和多个 Redis 连接的自动管理方面提供更好的开发者体验。

你可以使用 Redis 进行缓存、会话存储、任务队列、速率限制和实时消息。该包提供干净的 API 来执行 Redis 命令、管理多个命名连接，并订阅发布/订阅频道，而无需手动管理订阅者连接。

安装 ​

使用以下命令安装和配置包：

sh
node ace add @adonisjs/redis
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/redis 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

    ts
    {
  providers: [
    // ...其他提供者
    () => import('@adonisjs/redis/redis_provider')
  ]
}

  3. 创建 config/redis.ts 文件，包含你的 Redis 服务器的连接配置。

  4. 定义以下环境变量及其验证规则。

    dotenv
    REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=

配置 ​

Redis 包的配置存储在 config/redis.ts 文件中。

另请参阅：配置文件存根

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/redis'

const redisConfig = defineConfig({
  connection: 'main',
  connections: {
    main: {
      host: env.get('REDIS_HOST'),
      port: env.get('REDIS_PORT'),
      password: env.get('REDIS_PASSWORD', ''),
      db: 0,
      keyPrefix: '',
    },
  },
})

export default redisConfig

connection

connection 属性定义默认使用哪个连接。当你不选择显式连接运行 Redis 命令时，它们将针对默认连接执行。

connections

connections 属性是多个命名连接的集合。你可以在此对象内定义一个或多个连接，并使用 redis.connection() 方法在它们之间切换。

每个命名连接配置与 ioredis 接受的配置相同。

通过 Unix 套接字连接 ​

你可以配置 Redis 使用 Unix 套接字进行本地连接。使用 path 属性指定套接字文件位置。

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/redis'

const redisConfig = defineConfig({
  connection: 'main',
  connections: {
    main: {
      /**
       * Unix 套接字文件的路径。
       * 使用套接字连接时移除 host 和 port。
       */
      path: env.get('REDIS_SOCKET_PATH'),
      db: 0,
      keyPrefix: '',
    },
  },
})

export default redisConfig

配置集群 ​

当你在连接配置中定义集群节点数组时，@adonisjs/redis 包会创建集群连接。

集群将数据分布在多个 Redis 节点上以实现水平扩展和高可用性。当你需要扩展到超出单个服务器内存容量或希望自动在节点间分片数据时，使用集群。

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/redis'

const redisConfig = defineConfig({
  connection: 'main',
  connections: {
    main: {
      // highlight-start
      clusters: [
        { host: '127.0.0.1', port: 6380 },
        { host: '127.0.0.1', port: 6381 },
      ],
      clusterOptions: {
        scaleReads: 'slave',
        slotsRefreshTimeout: 10 * 1000,
      },
      // highlight-end
    },
  },
})

export default redisConfig

clusters

集群节点地址数组。每个节点应指定 host 和 port。包将在连接到初始节点后自动发现所有集群节点。

clusterOptions

用于控制行为的集群特定选项。

常见选项：

  • scaleReads：如何分配读操作（'master'、'slave' 或 'all'）
  • slotsRefreshTimeout：刷新集群槽信息的频率（毫秒）

完整选项列表请参阅 ioredis 集群文档。

配置哨兵 ​

哨兵通过自动故障转移提供高可用性。哨兵节点监控你的主服务器和副本服务器，并在主服务器失败时自动将副本提升为主服务器。

你可以通过在连接配置中定义哨兵节点数组来配置 Redis 连接使用哨兵。

另请参阅：IORedis 哨兵配置文档

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/redis'

const redisConfig = defineConfig({
  connection: 'main',
  connections: {
    main: {
      // highlight-start
      sentinels: [
        { host: 'localhost', port: 26379 },
        { host: 'localhost', port: 26380 },
      ],
      name: 'mymaster',
      // highlight-end
      password: env.get('REDIS_PASSWORD', ''),
      db: 0,
    },
  },
})

export default redisConfig

sentinels

哨兵节点地址数组。哨兵将自动检测哪个服务器是当前主服务器并相应地重定向连接。

name

在你的哨兵中配置的主组名称。这必须与哨兵配置匹配。

用法 ​

你可以使用包导出的 redis 服务执行 Redis 命令。redis 服务是一个使用 config/redis.ts 文件中设置配置的单例实例。

TIP

命令 API 与 ioredis 完全相同。查阅 ioredis 文档以查看可用方法的完整列表。

ts
import redis from '@adonisjs/redis/services/main'

await redis.set('username', 'virk')
const username = await redis.get('username')

在连接之间切换 ​

使用 redis 服务执行的命令针对配置文件中定义的默认连接调用。你可以先获取特定连接的实例，然后在其上执行命令。

.connection() 方法在进程生命周期内创建并缓存连接实例。后续调用返回相同的缓存实例。

ts
import redis from '@adonisjs/redis/services/main'

/**
 * 获取连接实例
 */
const redisMain = redis.connection('main')

await redisMain.set('username', 'virk')
const username = await redisMain.get('username')

退出连接 ​

连接是长期存在的，每次调用 .connection() 方法都会得到相同的实例。你可以使用 quit 方法优雅地退出连接，或使用 disconnect 方法立即强制关闭它。

ts
import redis from '@adonisjs/redis/services/main'

/**
 * 优雅地退出主连接
 */
await redis.quit('main')

/**
 * 立即强制退出主连接
 */
await redis.disconnect('main')

你也可以直接使用连接实例退出。

ts
import redis from '@adonisjs/redis/services/main'

const redisMain = redis.connection('main')

/**
 * 使用连接实例退出
 */
await redisMain.quit()

/**
 * 使用连接实例强制退出
 */
await redisMain.disconnect()

错误处理 ​

Redis 连接在应用生命周期的任何时候都可能失败。没有适当的错误处理，连接失败会使你的应用因未处理的 promise 拒绝而崩溃。

默认情况下，AdonisJS 使用应用日志记录器记录 Redis 连接错误，并在永久关闭连接之前最多重试 10 次。重试策略使用指数退避，以在从短暂中断恢复和不因长时间失败而浪费资源之间取得平衡。

重试策略为配置中的每个连接定义。

另请参阅：IORedis 自动重连文档

ts
{
  main: {
    host: env.get('REDIS_HOST'),
    port: env.get('REDIS_PORT'),
    password: env.get('REDIS_PASSWORD', ''),
    // highlight-start
    /**
     * 每次连接尝试失败时调用。
     * 返回 null 停止重试。
     * 返回数字（毫秒）在该延迟后重试。
     */
    retryStrategy(times) {
      // 10 次尝试后停止
      if (times > 10) {
        return null
      }

      // 指数退避：50ms、100ms、150ms 等
      return times * 50
    },
    // highlight-end
  },
}

WARNING

没有适当的错误处理，Redis 连接失败会使你的应用崩溃。默认重试策略在放弃之前尝试 10 次重连。对于生产部署，根据你的可用性要求自定义重试策略并监控 Redis 连接健康。

为生产环境自定义：

ts
retryStrategy(times) {
  // 生产环境更多重试
  if (times > 20) {
    return null
  }

  // 指数退避，最大 5 秒
  return Math.min(times * 50, 5000)
}

你可以使用 .doNotLogErrors() 方法禁用默认错误报告器。这会从 Redis 连接中移除 error 事件监听器。

ts
import redis from '@adonisjs/redis/services/main'

/**
 * 禁用默认错误报告器
 */
redis.doNotLogErrors()

redis.on('connection', (connection) => {
  /**
   * 始终定义错误监听器以防止崩溃。
   * 没有它，未处理的错误会使你的应用崩溃。
   */
  connection.on('error', (error) => {
    console.log(error)
  })
})

发布/订阅 ​

发布/订阅（Publish/Subscribe）是一种消息模式，发布者向频道发送消息而不知道谁接收，订阅者监听频道而不知道谁发送。这种解耦使发布/订阅非常适合实时功能，如通知、实时更新和聊天系统。

Redis 需要多个连接用于发布/订阅。订阅者连接不能执行订阅和取消订阅之外的常规 Redis 操作。当你第一次调用 subscribe 方法时，包会自动为你创建订阅者连接。

订阅频道 ​

subscribe 方法同时处理订阅频道和监听消息。这与 ioredis API 不同，在 ioredis 中你需要使用单独的方法。

ts
import redis from '@adonisjs/redis/services/main'

redis.subscribe('user:add', function (message) {
  console.log(message)
})

你可以使用 options 参数处理订阅生命周期事件。

ts
redis.subscribe(
  'user:add',
  (message) => {
    console.log(message)
  },
  {
    /**
     * 订阅失败时调用
     */
    onError(error) {
      console.log(error)
    },

    /**
     * 订阅建立时调用。
     * count 是活动订阅的总数。
     */
    onSubscription(count) {
      console.log(count)
    },
  }
)

与 IORedis 的 API 差异 ​

直接使用 ioredis 时，你需要使用两个不同的 API 来订阅频道和监听消息。AdonisJS 包装器将它们合并为一个便捷方法。

ts
redis.on('message', (channel, message) => {
  console.log(message)
})

redis.subscribe('user:add', (error, count) => {
  if (error) {
    console.log(error)
  }
})
ts
redis.subscribe(
  'user:add',
  (message) => {
    console.log(message)
  },
  {
    onError(error) {
      console.log(error)
    },
    onSubscription(count) {
      console.log(count)
    },
  }
)

发布消息 ​

你可以使用 publish 方法发布消息。该方法接受频道名称作为第一个参数，消息数据作为第二个参数。

ts
redis.publish(
  'user:add',
  JSON.stringify({
    id: 1,
    username: 'virk',
  })
)

TIP

确保在发布消息之前订阅。在订阅建立之前发布的消息将丢失，因为没有订阅者接收它们。

订阅模式 ​

你可以使用 psubscribe 方法通过通配符订阅频道模式。回调同时接收频道名称和消息。

ts
redis.psubscribe('user:*', (channel, message) => {
  console.log(channel)
  console.log(message)
})

redis.publish(
  'user:add',
  JSON.stringify({
    id: 1,
    username: 'virk',
  })
)

取消订阅 ​

你可以使用 unsubscribe 和 punsubscribe 方法取消订阅频道或模式。

ts
await redis.unsubscribe('user:add')
await redis.punsubscribe('user:*add*')

使用 Lua 脚本 ​

Lua 脚本允许你在 Redis 服务器上原子地执行复杂操作。当你需要多个 Redis 命令一起成功或失败而没有竞态条件时，这很有用。

你可以向 Redis 服务注册 Lua 脚本作为命令。这些命令自动应用于所有连接。

另请参阅：IORedis Lua 脚本文档

ts
import redis from '@adonisjs/redis/services/main'

redis.defineCommand('release', {
  numberOfKeys: 2,
  lua: `
    redis.call('zrem', KEYS[2], ARGV[1])
    redis.call('zadd', KEYS[1], ARGV[2], ARGV[1])
    return true
  `,
})

定义命令后，你可以使用 runCommand 方法执行它。先传递键，然后是参数。

ts
redis.runCommand(
  'release',         // 命令名称
  'jobs:completed',  // 键 1
  'jobs:running',    // 键 2
  '11023',           // 参数 1
  100                // 参数 2
)

你可以在特定连接上执行相同的命令。

ts
redis.connection('jobs').runCommand(
  'release',
  'jobs:completed',
  'jobs:running',
  '11023',
  100
)

你也可以使用 connection 事件为特定连接实例定义命令。

ts
redis.on('connection', (connection) => {
  if (connection.connectionName === 'jobs') {
    connection.defineCommand('release', {
      numberOfKeys: 2,
      lua: `
        redis.call('zrem', KEYS[2], ARGV[1])
        redis.call('zadd', KEYS[1], ARGV[2], ARGV[1])
        return true
      `,
    })
  }
})

转换参数和回复 ​

你可以使用 redis.Command 属性自定义参数如何发送到 Redis 以及回复如何解析。当你想使用 JavaScript 对象、Map 或自定义数据类型时，这很有用。

API 与 IORedis 转换器 API 完全相同。

参数转换器 ​

参数转换器在将数据发送到 Redis 之前修改数据。

ts
import redis from '@adonisjs/redis/services/main'

redis.Command.setArgumentTransformer('hmset', (args) => {
  if (args.length === 2) {
    /**
     * 如果第二个参数是 Map，转换为数组
     */
    if (args[1] instanceof Map) {
      return [args[0], ...utils.convertMapToArray(args[1])]
    }

    /**
     * 如果第二个参数是对象，转换为数组
     */
    if (typeof args[1] === 'object' && args[1] !== null) {
      return [args[0], ...utils.convertObjectToArray(args[1])]
    }
  }
  return args
})

回复转换器 ​

回复转换器修改从 Redis 接收的数据。

ts
import redis from '@adonisjs/redis/services/main'

redis.Command.setReplyTransformer('hgetall', (result) => {
  if (Array.isArray(result)) {
    const obj = {}

    /**
     * Redis 返回 [key1, value1, key2, value2]。
     * 转换为对象格式。
     */
    for (let i = 0; i < result.length; i += 2) {
      obj[result[i]] = result[i + 1]
    }

    return obj
  }
  return result
})

测试 ​

测试使用 Redis 的代码时，你可以为测试配置单独的连接，以将测试数据与开发或生产数据隔离。

首先，在你的 Redis 配置中定义测试连接。

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/redis'

const redisConfig = defineConfig({
  connection: env.get('REDIS_CONNECTION', 'main'),
  connections: {
    main: {
      host: env.get('REDIS_HOST'),
      port: env.get('REDIS_PORT'),
      password: env.get('REDIS_PASSWORD', ''),
      db: 0,
    },
    test: {
      host: env.get('REDIS_HOST'),
      port: env.get('REDIS_PORT'),
      password: env.get('REDIS_PASSWORD', ''),
      db: 1, // 为测试使用不同的数据库
    },
  },
})

export default redisConfig

然后，在 .env.test 文件中运行测试时将 REDIS_CONNECTION 环境变量设置为 test

ts
REDIS_CONNECTION=test

在每个测试后清理测试数据以确保测试隔离。

ts
import { test } from '@japa/runner'
import redis from '@adonisjs/redis/services/main'

test.group('Posts', (group) => {
  group.each.teardown(async () => {
    /**
     * 清除测试数据库中的所有键
     */
    await redis.flushdb()
  })

  test('caches post data', async ({ client }) => {
    // 你的测试代码
  })
})

事件 ​

以下事件由 Redis 连接实例发出。你可以使用 redis.on('connection') 方法监听这些事件。

ts
import redis from '@adonisjs/redis/services/main'

redis.on('connection', (connection) => {
  connection.on('connect', () => {
    console.log('Connected')
  })
})

连接生命周期事件 ​

connect / subscriber:connect

连接建立时发出。subscriber:connect 事件在订阅者连接建立时发出。

ts
redis.on('connection', (connection) => {
  connection.on('connect', () => {})
  connection.on('subscriber:connect', () => {})
})

wait

当连接因配置中启用了 lazyConnect 选项而处于等待模式时发出。执行第一个命令后连接退出等待模式。

ts
redis.on('connection', (connection) => {
  connection.on('wait', () => {})
})

ready / subscriber:ready

在 connect 事件之后、Redis 准备好接受命令时发出。如果你在配置中启用 enableReadyCheck 标志，此事件等待 Redis 服务器报告就绪。

ts
redis.on('connection', (connection) => {
  connection.on('ready', () => {})
  connection.on('subscriber:ready', () => {})
})

error / subscriber:error

无法连接到 Redis 服务器或发生连接错误时发出。正确的错误管理请参阅错误处理。

ts
redis.on('connection', (connection) => {
  connection.on('error', () => {})
  connection.on('subscriber:error', () => {})
})

close / subscriber:close

连接关闭时发出。根据重试策略，IORedis 可能在发出 close 事件后重试建立连接。

ts
redis.on('connection', (connection) => {
  connection.on('close', () => {})
  connection.on('subscriber:close', () => {})
})

reconnecting / subscriber:reconnecting

在连接关闭后尝试重连时发出。

ts
redis.on('connection', (connection) => {
  connection.on('reconnecting', ({ waitTime }) => {
    console.log(waitTime)
  })
  connection.on('subscriber:reconnecting', ({ waitTime }) => {
    console.log(waitTime)
  })
})

end / subscriber:end

连接已永久关闭且不再尝试重连时发出。

ts
redis.on('connection', (connection) => {
  connection.on('end', () => {})
  connection.on('subscriber:end', () => {})
})

集群事件 ​

node:added

新节点添加到集群时发出。仅适用于集群连接。

ts
redis.on('connection', (connection) => {
  connection.on('node:added', () => {})
})

node:removed

节点从集群移除时发出。仅适用于集群连接。

ts
redis.on('connection', (connection) => {
  connection.on('node:removed', () => {})
})

node:error

无法连接到集群节点时发出。仅适用于集群连接。

ts
redis.on('connection', (connection) => {
  connection.on('node:error', ({ error, address }) => {
    console.log(error, address)
  })
})

订阅事件 ​

subscription:ready / psubscription:ready

频道或模式上的订阅建立时发出。

ts
redis.on('connection', (connection) => {
  connection.on('subscription:ready', ({ count }) => {
    console.log(count)
