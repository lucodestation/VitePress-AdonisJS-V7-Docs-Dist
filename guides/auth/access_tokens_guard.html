Access tokens 守卫 ​

本指南涵盖 AdonisJS 中基于令牌的身份认证。你将了解到：

  • 访问令牌如何工作以及何时使用它们
  • 如何在 User 模型上配置令牌提供者
  • 如何颁发带有能力和过期时间的令牌
  • 如何使用令牌认证请求
  • 如何管理令牌（列出、删除、撤销）

概述 ​

访问令牌在服务器无法使用 cookie 的场景中认证 HTTP 请求。这包括原生移动应用、桌面应用、第三方 API 集成，以及与 API 托管在不同域上的 Web 应用。

AdonisJS 使用不透明访问令牌而不是 JWT。不透明令牌是一个加密安全的随机字符串，没有嵌入数据。令牌被哈希并存储在数据库中，验证通过将提供的令牌与存储的哈希进行比较来完成。这种方法允许你通过从数据库删除令牌立即撤销它们，这是 JWT 在过期之前无法做到的。

一个令牌由三部分组成：可配置的前缀（默认为 oat_）、随机令牌值和 CRC32 校验和。前缀和校验和帮助密钥扫描工具识别代码库中泄露的令牌。

配置 User 模型 ​

在使用 access tokens 守卫之前，在你的 User 模型上配置令牌提供者。提供者处理令牌的创建、存储和验证。

ts
import { DateTime } from 'luxon'
import { BaseModel, column } from '@adonisjs/lucid/orm'
import { DbAccessTokensProvider } from '@adonisjs/auth/access_tokens'

export default class User extends BaseModel {
  @column({ isPrimary: true })
  declare id: number

  @column()
  declare fullName: string | null

  @column()
  declare email: string

  @column()
  declare password: string

  @column.dateTime({ autoCreate: true })
  declare createdAt: DateTime

  @column.dateTime({ autoCreate: true, autoUpdate: true })
  declare updatedAt: DateTime

  static accessTokens = DbAccessTokensProvider.forModel(User)
}

DbAccessTokensProvider.forModel 方法接受 User 模型作为第一个参数，以及一个可选配置对象作为第二个参数：

ts
static accessTokens = DbAccessTokensProvider.forModel(User, {
  expiresIn: '30 days',
  prefix: 'oat_',
  table: 'auth_access_tokens',
  type: 'auth_token',
  tokenSecretLength: 40,
})
选项描述
expiresIn默认令牌生命周期。接受数字形式的秒数或像 '30 days' 这样的时间表达式。令牌默认不过期。创建单个令牌时可以覆盖。
prefix公共令牌值的前缀。帮助密钥扫描器识别你的令牌。默认为 oat_。更改此项会使现有令牌失效。
table存储令牌的数据库表。默认为 auth_access_tokens。
type此令牌类型的标识符。当你的应用颁发多种类型的令牌时很有用。默认为 auth_token。
tokenSecretLength随机令牌值的字符长度。默认为 40。

创建令牌表 ​

当你选择 access tokens 守卫时，add 命令会为令牌表创建迁移。运行迁移以创建表：

sh
node ace migration:run

如果你手动配置访问令牌，请自行创建迁移：

sh
node ace make:migration auth_access_tokens
ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'auth_access_tokens'

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments('id')
      table

        .notNullable()
        .unsigned()

        .inTable('users')
        .onDelete('CASCADE')

      table.string('type').notNullable()
      table.string('name').nullable()
      table.string('hash').notNullable()
      table.text('abilities').notNullable()
      table.timestamp('created_at')
      table.timestamp('updated_at')
      table.timestamp('last_used_at').nullable()
      table.timestamp('expires_at').nullable()
    })
  }

  async down() {
    this.schema.dropTable(this.tableName)
  }
}

颁发令牌 ​

使用 User 模型上的令牌提供者创建令牌。create 方法接受用户实例并返回 AccessToken 对象：

ts
import User from '#models/user'
import router from '@adonisjs/core/services/router'

router.post('/users/:id/tokens', async ({ params }) => {
  const user = await User.findOrFail(params.id)
  const token = await User.accessTokens.create(user)

  return {
    type: 'bearer',
    value: token.value!.release(),
  }
})

token.value 属性包含包装在 Secret 对象中的实际令牌字符串。调用 .release() 获取纯字符串值。此值仅在创建时可用。一旦响应发送，纯令牌就无法再次检索，因为只存储了它的哈希。

你也可以直接返回令牌对象，它会自动序列化为 JSON：

ts
router.post('/users/:id/tokens', async ({ params }) => {
  const user = await User.findOrFail(params.id)
  const token = await User.accessTokens.create(user)

  return token
})

/**
 * 响应：
 * {
 *   "type": "bearer",
 *   "value": "oat_MTA.aWFQUmo2WkQzd3M5cW0zeG5JeHdiaV9rOFQzUWM1aTZSR2xJaDZXYzM5MDE4MzA3NTU",
 *   "expiresAt": null
 * }
 */

令牌能力 ​

能力让你限制令牌可以做什么。例如，你可能颁发一个可以读取项目但不能创建或删除项目的令牌。

ts
const token = await User.accessTokens.create(user, ['projects:read', 'projects:list'])

能力存储为字符串数组。定义对你的应用有意义的任何能力。常见模式包括基于资源的能力（projects:read、users:delete）和基于角色的能力（admin、editor）。

要允许所有能力，使用通配符：

ts
const token = await User.accessTokens.create(user, ['*'])

在处理请求时检查能力：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .delete('/projects/:id', async ({ auth, response }) => {
    if (!auth.user!.currentAccessToken.allows('projects:delete')) {
      return response.forbidden('Token lacks projects:delete ability')
    }

    // 删除项目...
  })
  .use(middleware.auth({ guards: ['api'] }))

AccessToken 类提供以下方法用于检查能力：

方法描述
allows(ability)如果令牌具有指定能力或通配符（*）则返回 true。
denies(ability)如果令牌不具有指定能力则返回 true。

令牌过期 ​

在创建令牌时设置过期时间：

ts
const token = await User.accessTokens.create(user, ['*'], {
  expiresIn: '7 days',
})

你也可以在提供者配置中设置默认过期时间，除非被覆盖，否则适用于所有令牌。

令牌名称 ​

为令牌分配名称，以便用户可以在管理界面中识别它们：

ts
const token = await User.accessTokens.create(user, ['*'], {
  name: 'CLI Tool Token',
})

配置守卫 ​

设置令牌提供者后，在 config/auth.ts 中配置身份认证守卫：

ts
import { defineConfig } from '@adonisjs/auth'
import { tokensGuard, tokensUserProvider } from '@adonisjs/auth/access_tokens'

const authConfig = defineConfig({
  default: 'api',
  guards: {
    api: tokensGuard({
      provider: tokensUserProvider({
        tokens: 'accessTokens',
        model: () => import('#models/user'),
      }),
    }),
  },
})

export default authConfig

tokensGuard 方法创建 AccessTokensGuard 的实例。

tokensUserProvider 方法接受两个选项：

选项描述
model导入你的 User 模型的函数。
tokens模型上引用令牌提供者的静态属性名称（通常为 accessTokens）。

认证请求 ​

客户端在 Authorization 头中将令牌作为 bearer 令牌包含：

Authorization: Bearer oat_MTA.aWFQUmo2WkQzd3M5cW0zeG5JeHdiaV9rOFQzUWM1aTZSR2xJaDZXYzM5MDE4MzA3NTU

使用 auth 中间件 ​

将 auth 中间件应用到需要身份认证的路由：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .post('/projects', async ({ auth }) => {
    console.log(auth.user)                    // User 实例
    console.log(auth.authenticatedViaGuard)   // 'api'
    console.log(auth.user!.currentAccessToken) // AccessToken 实例
  })
  .use(middleware.auth({ guards: ['api'] }))

如果令牌缺失、无效或已过期，中间件抛出 E_UNAUTHORIZED_ACCESS。

手动认证 ​

不使用中间件进行认证，调用 auth.authenticate() 或 auth.authenticateUsing()：

ts
router.post('/projects', async ({ auth }) => {
  /**
   * 使用默认守卫认证
   */
  const user = await auth.authenticate()

  /**
   * 使用特定守卫认证
   */
  const user = await auth.authenticateUsing(['api'])
})

检查认证状态 ​

使用 auth.isAuthenticated 检查请求是否已认证：

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class ProjectsController {
  async store({ auth }: HttpContext) {
    if (auth.isAuthenticated) {
      await auth.user!.related('projects').create(projectData)
    }
  }
}

避免非空断言 ​

使用 auth.getUserOrFail() 代替 auth.user! 以避免非空断言运算符：

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class ProjectsController {
  async store({ auth }: HttpContext) {
    const user = auth.getUserOrFail()
    await user.related('projects').create(projectData)
  }
}

当前访问令牌 ​

成功认证后，守卫将令牌附加到 user.currentAccessToken。使用它检查能力、过期时间或其他令牌属性：

ts
router
  .get('/projects', async ({ auth }) => {
    const token = auth.user!.currentAccessToken

    console.log(token.identifier)   // 来自数据库的令牌 ID
    console.log(token.abilities)    // 能力数组
    console.log(token.isExpired())  // 布尔值
    console.log(token.lastUsedAt)   // DateTime 或 null
  })
  .use(middleware.auth({ guards: ['api'] }))

每次使用令牌进行认证时，守卫都会更新 last_used_at 列。

如果你在代码库的其他地方（例如 Bouncer 能力中）使用 currentAccessToken 引用 User 模型，请在模型上声明该属性以避免类型错误：

ts
import { AccessToken } from '@adonisjs/auth/access_tokens'

export default class User extends BaseModel {
  // ...其他属性

  currentAccessToken?: AccessToken
}

列出令牌 ​

使用 all 方法检索用户的所有令牌：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('/tokens', async ({ auth }) => {
    return User.accessTokens.all(auth.user!)
  })
  .use(middleware.auth({ guards: ['api'] }))

all 方法返回有效和已过期的令牌。在你的 UI 中过滤或标记已过期的令牌：

text
@each(token in tokens)
  <div>
    <h3>{{ token.name ?? 'Unnamed token' }}</h3>
    @if(token.isExpired())
      <span class="badge">Expired</span>
    @end
    <p>Abilities: {{ token.abilities.join(', ') }}</p>
  </div>
@end

删除令牌 ​

通过其标识符删除令牌：

ts
await User.accessTokens.delete(user, tokenId)

通过守卫登录和登出 ​

当使用访问令牌作为主要认证方法时（移动应用常见），守卫提供 createToken 和 invalidateToken 方法，与 session 守卫的 login 和 logout 对应：

ts
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async store({ request, auth }: HttpContext) {
    const { email, password } = request.only(['email', 'password'])
    const user = await User.verifyCredentials(email, password)

    return await auth.use('api').createToken(user)
  }

  async destroy({ auth }: HttpContext) {
    await auth.use('api').invalidateToken()
  }
}
ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

const SessionController = () => import('#controllers/session_controller')

router.post('/session', [SessionController, 'store'])
router
  .delete('/session', [SessionController, 'destroy'])
  .use(middleware.auth({ guards: ['api'] }))

WARNING

当凭据验证失败时，User.verifyCredentials 抛出 E_INVALID_CREDENTIALS。对于 API 客户端，包含 Accept: application/json 头以接收 JSON 错误响应而不是重定向。

TIP

如果你的 API 仅通过访问令牌访问（不从浏览器访问），你可能想为 API 路由禁用 CSRF 保护。详情请参阅 shield 配置参考。
