身份认证 ​

本指南介绍 AdonisJS 身份认证系统。你将了解到：

  • 守卫（Guard）和提供者（Provider）如何协同工作来认证用户
  • 你的应用类型应该选择哪种守卫
  • 如何安装和配置 auth 包
  • Initialize auth 中间件的作用

概述 ​

AdonisJS 提供了一个健壮的身份认证系统，用于在不同类型的应用中登录和认证用户，无论你是构建服务端渲染应用、SPA 的 API，还是移动应用的后端。

身份认证包围绕两个核心概念构建：

  • 守卫（Guard） 是特定认证方法的端到端实现。例如，session 守卫通过 cookie 和会话认证用户，而 access tokens 守卫使用 bearer 令牌认证请求。
  • 提供者（Provider） 处理从数据库中查找用户和验证令牌。你可以使用内置的 Lucid 提供者，或为自定义数据源实现自己的提供者。

AdonisJS 的安全原语旨在防御常见漏洞。密码和令牌被正确哈希，实现防御了时序攻击和会话固定攻击。

auth 包不包含的内容 ​

auth 包专注于认证 HTTP 请求。以下功能不在其范围内：

  • 用户注册（表单、电子邮件验证、账户激活）
  • 账户管理（密码找回、电子邮件更新）
  • 授权和权限（改用 Bouncer）

TIP

想要完整的身份认证系统？AdonisJS Kit 提供全栈组件，带有用户注册、电子邮件验证、密码找回、个人资料管理等现成流程。

选择 auth 守卫 ​

AdonisJS 附带三个内置守卫。使用下表确定哪个守卫适合你的应用。

应用类型推荐守卫原因
服务端渲染 Web 应用SessionCookie 与浏览器请求天然配合
同一域上的 SPASession在 api.example.com 和 example.com 之间共享 cookie
不同域上的 SPAAccess tokens跨源请求无法共享 cookie
移动应用Access tokens原生应用无法使用基于 cookie 的会话
第三方 API 访问Access tokens客户端需要可以存储的长期令牌
快速原型Basic auth设置简单，无需数据库表

Session 守卫 ​

session 守卫使用 @adonisjs/session 包来跟踪已登录用户。成功登录后，用户的标识符存储在会话中，会话 cookie 发送到浏览器。后续请求包含此 cookie，允许服务器恢复用户的已认证状态。

会话和 cookie 几十年来一直是 Web 身份认证的标准。当你的客户端可以接受和发送 cookie 时它们工作良好，这对于服务端渲染应用和与 API 托管在同一顶级域上的 SPA 来说都是如此。

另请参阅：Session 守卫文档

Access tokens 守卫 ​

访问令牌是登录后颁发给用户的加密安全随机字符串。客户端存储令牌并将其包含在后续请求的 Authorization 头中。AdonisJS 使用存储在数据库中作为哈希进行验证的不透明访问令牌（不是 JWT）。

当你的客户端无法使用 cookie 时使用访问令牌：

  • 原生移动应用
  • 桌面应用
  • 与 API 位于不同域的 Web 应用
  • 需要编程式 API 访问的第三方集成

客户端应用负责安全存储令牌。访问令牌代表用户提供对应用的无限制访问，因此泄露它们会带来安全风险。

另请参阅：Access tokens 守卫文档

Basic auth 守卫 ​

basic auth 守卫实现 HTTP 认证框架。客户端在每次请求的 Authorization 头中作为 base64 编码字符串发送凭据。如果凭据无效，浏览器显示原生登录提示。

不建议在生产应用中使用基本认证，因为凭据随每个请求发送，且用户体验仅限于浏览器的内置提示。但是，在早期开发或内部工具中它可能有用。

另请参阅：Basic auth 守卫文档

选择用户提供者 ​

用户提供者在认证期间处理查找用户和验证令牌。每种守卫类型对其提供者有特定要求。

session 守卫提供者通过用户的 ID（存储在会话中）查找用户。access tokens 守卫提供者额外针对数据库中的哈希值验证令牌。AdonisJS 为所有内置守卫附带基于 Lucid 的提供者，它们使用你的 Lucid 模型查询数据库。

安装 ​

auth 包已预配置在 web 和 api 启动套件中。要将其添加到现有应用，根据你偏好的守卫运行以下命令之一：

sh
# Session 守卫（推荐用于 Web 应用）
node ace add @adonisjs/auth --guard=session

# Access tokens 守卫（推荐用于 API）
node ace add @adonisjs/auth --guard=access_tokens

# Basic auth 守卫
node ace add @adonisjs/auth --guard=basic_auth
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/auth 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

ts
    {
      providers: [
        // ...其他提供者
        () => import('@adonisjs/auth/auth_provider')
      ]
    }
  1. 在 start/kernel.ts 文件中创建并注册以下中间件。
ts
    router.use([
      () => import('@adonisjs/auth/initialize_auth_middleware')
    ])
ts
    router.named({
      auth: () => import('#middleware/auth_middleware'),
      // 仅在使用 session 守卫时注册
      guest: () => import('#middleware/guest_middleware')
    })

  1. 在 app/models 中创建 User 模型。

  2. 为 users 表创建数据库迁移。

  3. 根据所选的守卫创建额外的迁移（例如 access tokens 守卫的 auth_access_tokens）。

Initialize auth 中间件 ​

在设置期间，@adonisjs/auth/initialize_auth_middleware 被添加到应用的中间件栈中。此中间件在每个请求上运行并创建 Authenticator 类的实例，将其附加到 ctx.auth。

Initialize auth 中间件不认证请求或保护路由。它唯一的职责是设置 authenticator 实例，使其在整个请求生命周期中可用。要保护路由，请使用 auth 中间件。

如果你的应用使用 Edge 模板，authenticator 也可作为 auth 变量使用：

text
@if(auth.isAuthenticated)
  <p>Hello {{ auth.user.email }}</p>
@end

创建 users 表 ​

add 命令在 database/migrations 中创建 users 表的迁移。你可以在运行迁移之前修改此文件以匹配应用需求。

ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'users'

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments('id').notNullable()
      table.string('full_name').nullable()
      table.string('email', 254).notNullable().unique()
      table.string('password').notNullable()

      table.timestamp('created_at').notNullable()
      table.timestamp('updated_at').nullable()
    })
  }

  async down() {
    this.schema.dropTable(this.tableName)
  }
}

修改迁移后，更新 app/models/user.ts 中的 User 模型以反映你添加、重命名或删除的任何列。

下一步 ​

安装 auth 包后，你准备好在应用中实现身份认证：

  • 验证用户凭据：了解如何在登录期间安全地验证密码
  • Session 守卫：为 Web 应用实现基于 cookie 的身份认证
  • Access tokens 守卫：为 API 和移动应用实现基于令牌的身份认证
  • 社交身份认证：允许用户使用 GitHub、Google 和其他提供者登录
