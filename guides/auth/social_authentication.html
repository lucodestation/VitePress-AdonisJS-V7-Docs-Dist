社交身份认证 ​

本指南涵盖使用 Ally 包在 AdonisJS 中进行社交身份认证。你将了解到：

  • 如何安装和配置 Ally 与 OAuth 提供者
  • 如何将用户重定向到提供者并处理回调
  • 如何访问来自提供者的用户信息
  • 如何创建或查找用户并登录
  • 如何为 SPA 和移动应用使用无状态认证
  • 如何创建自定义社交驱动

概述 ​

社交身份认证允许用户使用来自 GitHub、Google、X（以前的 Twitter）或 Discord 等服务的现有账户登录。用户不必创建新的用户名和密码，而是授权你的应用从提供者访问他们的个人资料信息。

AdonisJS 提供 @adonisjs/ally 包用于社交身份认证。Ally 处理 OAuth 流程（重定向用户、交换代码获取令牌、获取用户数据），并在不同提供者之间提供一致的 API。它支持 OAuth 1.0（Twitter）和 OAuth 2.0（X、GitHub、Google 以及大多数其他提供者）。

Ally 不在你的数据库中存储用户或令牌。它处理 OAuth 流程并返回用户信息，然后你使用这些信息在数据库中创建或查找用户，并使用身份认证守卫登录他们。

安装 ​

使用 add 命令安装和配置该包：

sh
node ace add @adonisjs/ally

# 安装期间指定提供者
node ace add @adonisjs/ally --providers=github --providers=google
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/ally 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

ts
    {
      providers: [
        // ...其他提供者
        () => import('@adonisjs/ally/ally_provider')
      ]
    }

  1. 创建 config/ally.ts，包含所选提供者的配置。

  2. 为每个提供者定义 CLIENT_ID 和 CLIENT_SECRET 环境变量。

配置 ​

在 config/ally.ts 中配置你的 OAuth 提供者。每个提供者需要客户端 ID、客户端密钥和回调 URL：

ts
import env from '#start/env'
import { defineConfig, services } from '@adonisjs/ally'

export default defineConfig({
  github: services.github({
    clientId: env.get('GITHUB_CLIENT_ID'),
    clientSecret: env.get('GITHUB_CLIENT_SECRET'),
    callbackUrl: 'http://localhost:3333/github/callback',
  }),
  google: services.google({
    clientId: env.get('GOOGLE_CLIENT_ID'),
    clientSecret: env.get('GOOGLE_CLIENT_SECRET'),
    callbackUrl: 'http://localhost:3333/google/callback',
  }),
})

向提供者注册回调 URL ​

OAuth 提供者要求你在其开发者控制台中注册回调 URL。例如，要使用 GitHub 身份认证：

  1. 转到 GitHub 开发者设置
  2. 创建新的 OAuth App
  3. 将 Authorization callback URL 设置为与配置中的 callbackUrl 匹配

配置中的回调 URL 必须与你在提供者处注册的完全匹配。

将用户重定向到提供者 ​

创建一个将用户重定向到 OAuth 提供者的路由。使用 ally.use() 获取驱动实例并调用 redirect()。

在重定向之前，将 redirect.previousUrl 存储在会话中，以便错误处理器和 back() 调用将用户重定向到应用中的正确页面，而不是 OAuth 提供者的域。

ts
import router from '@adonisjs/core/services/router'

router.get('/github/redirect', ({ ally, session }) => {
  session.put('redirect.previousUrl', '/login')
  return ally.use('github').redirect()
})

请求作用域 ​

作用域定义你的应用可以访问哪些数据。每个提供者有不同可用的作用域。在 config/ally.ts 中或在重定向期间配置它们：

ts
github: services.github({
  clientId: env.get('GITHUB_CLIENT_ID'),
  clientSecret: env.get('GITHUB_CLIENT_SECRET'),
  callbackUrl: 'http://localhost:3333/github/callback',
  scopes: ['user:email', 'read:user'],
}),
ts
router.get('/github/redirect', ({ ally }) => {
  return ally.use('github').redirect((request) => {
    request.scopes(['user:email', 'read:user'])
  })
})

添加查询参数 ​

某些提供者接受额外参数。例如，Google 的 prompt 参数控制同意屏幕行为：

ts
router.get('/google/redirect', ({ ally }) => {
  return ally.use('google').redirect((request) => {
    request.param('prompt', 'select_account')
    request.param('access_type', 'offline')
  })
})

要移除配置中设置的参数，使用 clearParam：

ts
router.get('/google/redirect', ({ ally }) => {
  return ally.use('google').redirect((request) => {
    request.clearParam('prompt')
  })
})

处理回调 ​

用户授权（或拒绝）访问后，提供者将他们重定向到你的回调 URL。在驱动上调用 user() 以将授权码交换为访问令牌并获取用户个人资料。

ts
import router from '@adonisjs/core/services/router'

router.get('/github/callback', async ({ ally }) => {
  const github = ally.use('github')
  const githubUser = await github.user()

  return githubUser
})

如果回调期间出现问题（用户拒绝访问、状态令牌不匹配或授权码缺失），user() 方法会抛出自我处理的异常。异常会自动内容协商响应：

  • 带会话的 HTML 请求：错误消息被闪现到会话，用户被重定向回来。如果你在 OAuth 重定向之前将 redirect.previousUrl 存储在会话中，用户会返回到该页面。
  • JSON 请求：返回带有适当状态码的 JSON 错误响应。
  • JSONAPI 请求：返回 JSONAPI 格式的错误响应。

如果你需要自己处理特定错误情况，你仍然可以在调用 user() 之前检查它们。

ts
router.get('/github/callback', async ({ ally, response }) => {
  const github = ally.use('github')

  if (github.accessDenied()) {
    return response.redirect().toPath('/login?error=access_denied')
  }

  const githubUser = await github.user()
  return githubUser
})

用户属性 ​

user() 方法返回一个规范化的用户对象，在所有提供者之间具有一致的属性：

属性描述
id来自提供者的唯一标识符
email用户的电子邮件地址（如果未请求或不可用，可能为 null）
emailVerificationStateverified、unverified 或 unsupported 之一
name用户的显示名称
nickName用户名或句柄（如果提供者不支持昵称，则与 name 相同）
avatarUrl用户个人资料图片的 URL
token用于进行 API 调用的访问令牌对象
original来自提供者的原始响应

电子邮件验证状态 ​

提供者处理电子邮件验证的方式不同。在信任电子邮件之前检查 emailVerificationState：

  • verified：提供者已验证此电子邮件地址
  • unverified：电子邮件存在但未验证
  • unsupported：提供者不共享验证状态

访问令牌 ​

token 属性包含用于向提供者进行额外 API 调用的 OAuth 令牌：

属性协议描述
tokenOAuth 1 和 2访问令牌字符串
secret仅 OAuth 1令牌密钥（由 Twitter 使用）
typeOAuth 2令牌类型（通常为 bearer）
refreshTokenOAuth 2用于获取新访问令牌的令牌
expiresAtOAuth 2令牌过期的 DateTime
expiresInOAuth 2到过期的秒数

原始响应 ​

通过 original 属性访问提供者特定的数据：

ts
const githubUser = await github.user()
console.log(githubUser.original)

创建用户和登录 ​

Ally 提供用户信息，但不创建用户或会话。从提供者获取用户数据后，你需要：

  1. 在数据库中查找或创建用户
  2. 使用身份认证守卫登录他们

使用 session 守卫 ​

对于服务端渲染应用，在社交身份认证后创建会话。回调期间的错误（拒绝访问、状态不匹配）是自我处理的，会通过闪存消息将用户重定向回来。

ts
import User from '#models/user'
import router from '@adonisjs/core/services/router'

router.get('/github/callback', async ({ ally, auth, response }) => {
  const githubUser = await ally.use('github').user()

  /**
   * 查找现有用户或创建新用户
   */
  const user = await User.firstOrCreate(
    { email: githubUser.email },
    {
      email: githubUser.email,
      fullName: githubUser.name,
      /**
       * 生成随机密码，因为社交用户
       * 不会使用基于密码的登录
       */
      password: crypto.randomUUID(),
    }
  )

  /**
   * 为用户创建会话
   */
  await auth.use('web').login(user)

  /**
   * 重定向到用户尝试访问的页面，
   * 或如果没有存储预期 URL 则重定向到 /dashboard
   */
  return response.redirect().toIntended('/dashboard')
})

使用 access tokens 守卫 ​

对于 API 和移动应用，在社交身份认证后颁发访问令牌。

ts
import User from '#models/user'
import router from '@adonisjs/core/services/router'

router.get('/github/callback', async ({ ally }) => {
  const github = ally.use('github')

  if (github.accessDenied()) {
    return { error: 'access_denied' }
  }

  if (github.stateMisMatch()) {
    return { error: 'state_mismatch' }
  }

  if (github.hasError()) {
    return { error: github.getError() }
  }

  const githubUser = await github.user()

  const user = await User.firstOrCreate(
    { email: githubUser.email },
    {
      email: githubUser.email,
      fullName: githubUser.name,
      password: crypto.randomUUID(),
    }
  )

  /**
   * 为用户创建访问令牌
   */
  const token = await User.accessTokens.create(user)

  return {
    type: 'bearer',
    value: token.value!.release(),
  }
})

禁止某提供者的注册 ​

当提供者仅用于登录或账户关联而不用于创建新的本地账户时，使用 disallowLocalSignup 选项。当你历史上允许使用某个提供者注册但现在想限制为仅登录时，这很有帮助。

ts
export default defineConfig({
  github: services.github({
    clientId: env.get('GITHUB_CLIENT_ID'),
    clientSecret: env.get('GITHUB_CLIENT_SECRET'),
    callbackUrl: 'http://localhost:3333/github/callback',
    disallowLocalSignup: true,
  }),
})

启用 disallowLocalSignup 后，调用 ally.use(provider, { intent: 'signup' }) 将抛出状态码为 403 的异常。

ts
router.get('/github/signup/redirect', ({ ally }) => {
  return ally.use('github', { intent: 'signup' }).redirect()
})

无状态认证 ​

默认情况下，Ally 使用存储在 cookie 中的 CSRF 令牌来防止跨站请求伪造。如果你的应用无法使用 cookie（例如使用 webview 的移动应用），启用无状态模式：

ts
router.get('/github/redirect', ({ ally }) => {
  return ally.use('github').stateless().redirect()
})

router.get('/github/callback', async ({ ally }) => {
  const github = ally.use('github').stateless()

  // 处理回调...
  const user = await github.user()
})

重定向和回调都必须使用无状态模式。没有 CSRF 检查，请确保你的应用有其他保护措施防止未授权的 OAuth 流程。

从现有令牌获取用户 ​

如果你已经有访问令牌（例如来自移动应用的原生 OAuth 流程），直接获取用户信息：

ts
router.post('/auth/github', async ({ request, ally }) => {
  const { accessToken } = request.only(['accessToken'])

  const user = await ally.use('github').userFromToken(accessToken)

  return user
})

对于 OAuth 1 提供者（Twitter），使用 userFromTokenAndSecret：

ts
const user = await ally.use('twitter').userFromTokenAndSecret(token, secret)

动态提供者选择 ​

使用路由参数通过单个路由处理多个提供者：

ts
router
  .get('/:provider/redirect', ({ ally, params }) => {
    if (!ally.has(params.provider)) {
      return 'Unknown provider'
    }

    return ally.use(params.provider).redirect()
  })
  .where('provider', /github|google|twitter/)

router
  .get('/:provider/callback', async ({ ally, params }) => {
    if (!ally.has(params.provider)) {
      return 'Unknown provider'
    }

    const driver = ally.use(params.provider)
    // 处理回调...
  })
  .where('provider', /github|google|twitter/)

你也可以在运行时检查已配置的提供者：

ts
router.get('/login', ({ ally }) => {
  return {
    providers: ally.configuredProviderNames(),
    signupProviders: ally.signupProviderNames(),
  }
})
