Session 守卫 ​

本指南涵盖 AdonisJS 中基于 session 的身份认证。你将了解到：

  • 如何配置 session 守卫
  • 如何登录和登出用户
  • 如何保护路由免受未认证访问
  • 如何访问已认证用户
  • 如何实现“记住我”功能
  • 如何防止已登录用户访问仅限访客的页面

概述 ​

session 守卫使用 @adonisjs/session 包来跟踪已登录用户。当用户登录时，其标识符存储在 session 中，cookie 发送到浏览器。在后续请求中，session 中间件读取此 cookie 并恢复已认证状态。

session 和 cookie 几十年来一直是 Web 身份认证的标准。在构建服务端渲染应用或与 API 托管在同一顶级域上的 SPA（例如你的应用在 example.com，API 在 api.example.com）时，使用 session 守卫。

配置守卫 ​

身份认证守卫在 config/auth.ts 中定义。以下示例展示 session 守卫配置：

ts
import { defineConfig } from '@adonisjs/auth'
import { sessionGuard, sessionUserProvider } from '@adonisjs/auth/session'

const authConfig = defineConfig({
  default: 'web',
  guards: {
    web: sessionGuard({
      useRememberMeTokens: false,
      provider: sessionUserProvider({
        model: () => import('#models/user'),
      }),
    }),
  },
})

export default authConfig

sessionGuard 方法创建 SessionGuard 类的实例。它接受一个用户提供者和一个用于记住我令牌的可选配置对象。

sessionUserProvider 方法创建 SessionLucidUserProvider 的实例，它使用 Lucid 模型在认证期间查找用户。

登录 ​

使用 auth.use('web').login() 方法为用户创建 session。该方法接受一个 User 模型实例并将其标识符存储在 session 中。

ts
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async store({ request, auth, response }: HttpContext) {
    /**
     * 从请求体获取凭据
     */
    const { email, password } = request.only(['email', 'password'])

    /**
     * 使用 AuthFinder mixin 验证凭据
     */
    const user = await User.verifyCredentials(email, password)

    /**
     * 为用户创建 session
     */
    await auth.use('web').login(user)

    /**
     * 重定向到受保护的页面
     */
    return response.redirect('/dashboard')
  }
}

auth.use('web') 方法返回在 config/auth.ts 文件中以 web 名称配置的守卫实例。

登出 ​

使用 auth.use('web').logout() 方法销毁用户的 session。如果用户有活动的记住我令牌，它也会被删除。

ts
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async destroy({ auth, response }: HttpContext) {
    await auth.use('web').logout()
    return response.redirect('/login')
  }
}

保护路由 ​

使用 auth 中间件保护路由免受未认证用户访问。该中间件在 start/kernel.ts 中的命名中间件集合下注册：

ts
import router from '@adonisjs/core/services/router'

export const middleware = router.named({
  auth: () => import('#middleware/auth_middleware'),
})

将中间件应用到需要身份认证的路由：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('dashboard', ({ auth }) => {
    return `Welcome ${auth.user!.fullName}`
  })
  .use(middleware.auth())

默认情况下，auth 中间件使用配置中的 default 守卫进行认证。要显式指定守卫，将它们作为选项传递：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('dashboard', ({ auth }) => {
    return `Welcome ${auth.user!.fullName}`
  })
  .use(
    middleware.auth({
      guards: ['web', 'api'],
    })
  )

当指定多个守卫时，只要其中任何一个认证请求成功，认证就成功。

处理认证错误 ​

当 auth 中间件无法认证请求时，它会抛出 E_UNAUTHORIZED_ACCESS 异常。该异常通过内容协商转换为 HTTP 响应：

  • 带有 Accept: application/json 的请求接收错误对象数组。
  • 带有 Accept: application/vnd.api+json 的请求接收按 JSON API 规范格式化的错误。
  • 服务端渲染应用重定向到 /login。你可以在 app/middleware/auth_middleware.ts 中自定义此路径。

访问已认证用户 ​

认证后，用户实例通过 auth.user 可用。当使用 auth 中间件、silent_auth 中间件，或手动调用 auth.authenticate() 或 auth.check() 时，此属性会被填充。

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('dashboard', async ({ auth }) => {
    const user = auth.user!
    return await user.getAllMetrics()
  })
  .use(middleware.auth())

避免非空断言 ​

如果你不想使用非空断言运算符（!），改用 auth.getUserOrFail() 方法。它返回用户或抛出 E_UNAUTHORIZED_ACCESS：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('dashboard', async ({ auth }) => {
    const user = auth.getUserOrFail()
    return await user.getAllMetrics()
  })
  .use(middleware.auth())

检查认证状态 ​

使用 auth.isAuthenticated 属性检查当前请求是否已认证：

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('dashboard', async ({ auth }) => {
    if (auth.isAuthenticated) {
      return await auth.user!.getAllMetrics()
    }
  })
  .use(middleware.auth())

静默认证 ​

silent_auth 中间件的工作方式与 auth 中间件类似，但在用户未认证时不会抛出异常。请求正常继续，允许你在认证数据可用时选择性地使用它。

这对于同时适用于访客和已认证用户的页面很有用，例如为已登录用户显示个性化内容的首页。

在你的路由器中间件栈中注册该中间件：

ts
import router from '@adonisjs/core/services/router'

router.use([
  // ...其他中间件
  () => import('#middleware/silent_auth_middleware'),
])

在 Edge 模板中访问用户 ​

initialize auth 中间件与 Edge 模板共享 ctx.auth 对象。通过 auth.user 访问已认证用户：

text
@if(auth.isAuthenticated)
  <p>Hello {{ auth.user.email }}</p>
@end

在不受 auth 中间件保护的公共页面上，在访问 auth.user 之前调用 auth.check() 尝试认证：

text
{{-- 检查用户是否已登录而不要求认证 --}}
@eval(await auth.check())

<header>
  @if(auth.isAuthenticated)
    <p>Hello {{ auth.user.email }}</p>
  @else
    <a href="/login">Sign in</a>
  @end
</header>

记住我 ​

“记住我”功能通过在 cookie 中存储长期令牌，在 session 过期后保持用户登录。当 session 过期时，AdonisJS 使用此令牌自动重新创建 session。

创建令牌表 ​

记住我令牌存储在数据库中。为令牌表创建迁移：

sh
node ace make:migration remember_me_tokens
ts
import { BaseSchema } from '@adonisjs/lucid/schema'

export default class extends BaseSchema {
  protected tableName = 'remember_me_tokens'

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments()
      table
        .integer('tokenable_id')
        .notNullable()
        .unsigned()
        .references('id')
        .inTable('users')
        .onDelete('CASCADE')

      table.string('hash').notNullable().unique()
      table.timestamp('created_at').notNullable()
      table.timestamp('updated_at').notNullable()
      table.timestamp('expires_at').notNullable()
    })
  }

  async down() {
    this.schema.dropTable(this.tableName)
  }
}

配置令牌提供者 ​

将 DbRememberMeTokensProvider 分配到你的 User 模型：

ts
import { BaseModel } from '@adonisjs/lucid/orm'
import { DbRememberMeTokensProvider } from '@adonisjs/auth/session'

export default class User extends BaseModel {
  // ...其他模型属性

  static rememberMeTokens = DbRememberMeTokensProvider.forModel(User)
}

启用记住我令牌 ​

在你的守卫配置中启用该功能：

ts
import { defineConfig } from '@adonisjs/auth'
import { sessionGuard, sessionUserProvider } from '@adonisjs/auth/session'

const authConfig = defineConfig({
  default: 'web',
  guards: {
    web: sessionGuard({
      useRememberMeTokens: true,
      rememberMeTokensAge: '2 years',
      provider: sessionUserProvider({
        model: () => import('#models/user'),
      }),
    }),
  },
})

export default authConfig

在登录期间生成令牌 ​

将布尔值作为第二个参数传递给 login() 以生成记住我令牌：

ts
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async store({ request, auth, response }: HttpContext) {
    const { email, password } = request.only(['email', 'password'])
    const user = await User.verifyCredentials(email, password)

    await auth.use('web').login(
      user,
      !!request.input('remember_me')
    )

    return response.redirect('/dashboard')
  }
}

重定向到预期 URL ​

当未认证用户尝试访问受保护页面时，auth 中间件将他们重定向到登录页面。登录后，你可能想将他们送回最初请求的页面，而不是通用的仪表盘。

强制登录流程 ​

当 auth 中间件拒绝未认证请求时，它会在重定向到登录页面之前自动将当前 URL 存储在 session 中。这发生在匹配路由的 GET、导航（非 AJAX）请求上。无需更改 auth 中间件。

在你的登录控制器中，使用 toIntendedRoute() 在成功认证后重定向。它从 session 读取存储的 URL 并回退到提供的默认值。

ts
import User from '#models/user'
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async store({ request, auth, response }: HttpContext) {
    const { email, password } = request.only(['email', 'password'])
    const user = await User.verifyCredentials(email, password)

    await auth.use('web').login(user)

    /**
     * 重定向到用户尝试访问的页面，
     * 或如果没有存储预期 URL 则重定向到仪表盘
     */
    return response.redirect().toIntendedRoute('dashboard')
  }
}

自愿登录流程 ​

当用户从公共页面自愿点击登录链接时，当前 URL 可以作为查询参数传递。登录页面处理器使用 session.setIntendedUrl() 将其存储在 session 中，该方法验证 URL 以防止开放重定向。

edge
<a href="{{ route('auth.login', {}, { qs: { intended: request.url(true) } }) }}">
  Login
</a>
ts
import type { HttpContext } from '@adonisjs/core/http'

export default class SessionController {
  async show({ request, session, view }: HttpContext) {
    const intended = request.input('intended')
    if (intended) {
      session.setIntendedUrl(intended)
    }

    return view.render('auth/login')
  }
}

登录后，无论预期 URL 如何存储，toIntended() 都以相同方式工作。

访客中间件 ​

访客中间件将已认证用户从 /login 或 /register 等页面重定向离开。这防止用户在单个设备上创建多个 session。

ts
import { middleware } from '#start/kernel'
import router from '@adonisjs/core/services/router'

router
  .get('/login', () => {
    // 显示登录表单
  })
  .use(middleware.guest())

默认情况下，中间件使用 default 守卫检查认证。要显式指定守卫：

ts
router
  .get('/login', () => {
    // 显示登录表单
  })
  .use(
    middleware.guest({
      guards: ['web', 'admin_web'],
    })
  )

在 app/middleware/guest_middleware.ts 中配置已认证用户的重定向路径。
