Transmit ​

本指南涵盖 AdonisJS 中使用 Transmit 进行实时服务器到客户端通信。你将了解到如何：

  • 为服务器发送事件安装和配置 Transmit
  • 注册路由并向已连接客户端广播事件
  • 定义频道并授权访问私有频道
  • 设置客户端库以实时接收事件
  • 使用传输层在多个服务器实例之间同步事件
  • 为私有频道订阅认证客户端
  • 监听生命周期钩子以监控连接
  • 使用 Japa 测试广播和频道授权

概述 ​

Transmit 是 AdonisJS 的原生服务器发送事件（SSE）模块。它提供从服务器到客户端的单向通信通道，允许你推送实时更新而无需 WebSocket 的开销。由于 SSE 使用标准 HTTP，它可以通过可能阻止 WebSocket 连接的防火墙和代理。

Transmit 作为围绕频道构建的发布/订阅系统工作。服务器向命名频道广播消息，客户端订阅它们关心的频道。你可以用授权回调保护频道以控制谁接收更新，使其适用于公共广播和私有的、用户特定的通知。

对于客户端到服务器的通信，你继续使用标准 HTTP 请求。Transmit 仅处理服务器到客户端的推送。

安装 ​

使用以下命令安装和配置服务器端包：

sh
node ace add @adonisjs/transmit
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/transmit 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

    ts
    {
  providers: [
    // ...其他提供者
    () => import('@adonisjs/transmit/transmit_provider')
  ]
}

  3. 创建 config/transmit.ts 文件。

同时在前端应用中安装客户端库：

sh
npm install @adonisjs/transmit-client

配置 ​

配置文件位于 config/transmit.ts。它控制保活行为和多实例同步。

另请参阅：配置存根

ts
import { defineConfig } from '@adonisjs/transmit'

export default defineConfig({
  pingInterval: false,
  transport: null,
})

pingInterval（类型：Duration | false）

控制发送 ping 消息以保持 SSE 连接活跃的频率。接受毫秒数、像 '30s' 或 '1m' 这样的持续时间字符串，或 false 以禁用 ping。

ts
import { defineConfig } from '@adonisjs/transmit'

export default defineConfig({
  pingInterval: '30s',
  transport: null,
})

transport（类型：object | null）

配置用于在多个服务器实例之间同步事件的传输层。对于单实例部署设置为 null。

配置详情请参阅多实例同步。

注册路由 ​

Transmit 需要三个 HTTP 路由来处理客户端连接、订阅和取消订阅。使用 registerRoutes 方法在路由文件中注册它们。

ts
import transmit from '@adonisjs/transmit/services/main'

transmit.registerRoutes()

这会注册以下路由：

路由方法用途
__transmit/eventsGET建立 SSE 连接
__transmit/subscribePOST将客户端订阅到频道
__transmit/unsubscribePOST取消客户端对频道的订阅

为路由应用中间件 ​

registerRoutes 方法接受一个可选回调来修改每个已注册的路由。这对于应用中间件很有用，例如要求 SSE 连接进行身份认证。

ts
import transmit from '@adonisjs/transmit/services/main'
import { middleware } from '#start/kernel'

transmit.registerRoutes((route) => {
  route.middleware(middleware.auth())
})

你可以根据路由模式有条件地应用中间件。

ts
import transmit from '@adonisjs/transmit/services/main'
import { middleware } from '#start/kernel'

transmit.registerRoutes((route) => {
  // 仅对 SSE 连接要求身份认证
  if (route.getPattern() === '__transmit/events') {
    route.middleware(middleware.auth())
  }
})

广播事件 ​

导入 transmit 服务并调用 broadcast 方法向频道的所有订阅者发送数据。

ts
import transmit from '@adonisjs/transmit/services/main'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async store({ request }: HttpContext) {
    const post = await Post.create(request.all())

    // 向所有订阅者广播新帖子
    transmit.broadcast('posts', { id: post.id, title: post.title })

    return post
  }
}

排除特定客户端 ​

使用 broadcastExcept 向除一个或多个特定客户端之外的所有订阅者发送消息。当发送者不应接收自己的消息时，这很有用。

ts
import transmit from '@adonisjs/transmit/services/main'
import type { HttpContext } from '@adonisjs/core/http'

export default class MessagesController {
  async store({ request }: HttpContext) {
    const { uid, content } = request.all()

    // 向聊天中的所有人发送，除了发送者
    transmit.broadcastExcept('chats/1/messages', { content }, uid)
  }
}

第三个参数接受单个 UID 字符串或要排除的 UID 数组。

频道 ​

频道名称是区分大小写的字符串，支持字母数字字符和正斜杠。使用正斜杠创建与你的应用资源匹配的层次结构。

ts
// 用于全局通知的公共频道
transmit.broadcast('notifications', { message: 'System update' })

// 资源特定频道
transmit.broadcast('chats/1/messages', { content: 'Hello!' })

// 用户特定频道
transmit.broadcast('users/42', { type: 'profile_updated' })

授权频道 ​

默认情况下，任何客户端都可以订阅任何频道。使用 authorize 方法限制对敏感频道的访问。创建 start/transmit.ts 预加载文件来定义你的授权规则。

sh
node ace make:preload transmit

授权回调接收当前 HttpContext 和提取的频道参数。返回 true 允许访问或 false 拒绝。

ts
import transmit from '@adonisjs/transmit/services/main'

// 仅允许用户订阅自己的频道
transmit.authorize<{ id: string }>('users/:id', (ctx, { id }) => {
  return ctx.auth.user?.id === +id
})

频道模式使用与 AdonisJS 路由相同的参数语法。参数在订阅时从频道名称提取并传递给授权回调。

ts
import transmit from '@adonisjs/transmit/services/main'
import Chat from '#models/chat'

transmit.authorize<{ chatId: string }>(
  'chats/:chatId/messages',
  async (ctx, { chatId }) => {
    const chat = await Chat.findOrFail(+chatId)
    return ctx.bouncer.allows('accessChat', chat)
  }
)

授权回调支持同步和异步逻辑。如果回调抛出错误，访问被拒绝。

TIP

没有 authorize 回调的频道是公开的。任何客户端都可以订阅它们。仅为需要访问控制的频道注册授权。

认证私有频道 ​

授权回调在订阅请求期间运行，而不是在建立 SSE 连接时。为了让 ctx.auth.user 在你的 authorize 回调中可用，使用你的身份认证中间件保护 __transmit/subscribe 路由。

ts
import transmit from '@adonisjs/transmit/services/main'
import { middleware } from '#start/kernel'

transmit.registerRoutes((route) => {
  if (route.getPattern() === '__transmit/subscribe') {
    route.middleware(middleware.auth())
  }
})

使用基于令牌的身份认证时，使用 beforeSubscribe 钩子在客户端附加令牌。钩子接收传出的 Request 并在每次订阅调用之前运行。

ts
import { Transmit } from '@adonisjs/transmit-client'

const transmit = new Transmit({
  baseUrl: window.location.origin,
  beforeSubscribe: (request) => {
    request.headers.set('Authorization', `Bearer ${getToken()}`)
  },
})

TIP

__transmit/events 上的 SSE 连接由浏览器原生的 EventSource 打开，它无法发送自定义头。对于基于令牌的认证，改为认证 subscribe 路由。频道授权仍然保护私有频道，因为客户端必须在接收事件之前通过 authorize 回调。如果你的应用使用基于 cookie 的会话，认证会自动工作，因为订阅请求包含 cookie（credentials: 'include'）。如果你也保护取消订阅路由，以相同方式使用 beforeUnsubscribe 钩子。

客户端设置 ​

使用你的 AdonisJS 服务器的 URL 创建一个新的 Transmit 实例。客户端在实例化时自动建立 SSE 连接。

ts
import { Transmit } from '@adonisjs/transmit-client'

const transmit = new Transmit({
  baseUrl: window.location.origin,
})

订阅频道 ​

使用 subscription 方法创建订阅，然后调用 create 激活它。使用 onMessage 注册消息处理器。

ts
import { Transmit } from '@adonisjs/transmit-client'

const transmit = new Transmit({
  baseUrl: window.location.origin,
})

const subscription = transmit.subscription('chats/1/messages')
await subscription.create()

subscription.onMessage((data) => {
  console.log('New message:', data)
})

你可以在单个订阅上注册多个消息处理器。每个处理器接收来自服务器的解析后的负载。

ts
// 注册多个处理器
subscription.onMessage((data) => {
  appendMessageToUI(data)
})

subscription.onMessage((data) => {
  playNotificationSound()
})

// 注册只运行一次的处理器
subscription.onMessageOnce((data) => {
  console.log('First message received:', data)
})

移除消息处理器 ​

onMessage 方法返回一个取消订阅函数，以停止特定处理器接收消息。

ts
const unsubscribe = subscription.onMessage((data) => {
  console.log(data)
})

// 稍后，停止此特定处理器
unsubscribe()

删除订阅 ​

调用 delete 完全取消对频道的订阅。

ts
await subscription.delete()

监听连接状态 ​

客户端跟踪其连接状态并暴露你可以监听的事件。

ts
transmit.on('connected', () => {
  console.log('SSE connection established')
})

transmit.on('disconnected', () => {
  console.log('SSE connection lost')
})

transmit.on('reconnecting', () => {
  console.log('Attempting to reconnect...')
})

可用的状态事件有 initializing、connected、disconnected 和 reconnecting。

客户端配置选项 ​

baseUrl（类型：string）

你的 AdonisJS 服务器的 URL，包括协议。这是唯一必需的选项。

ts
const transmit = new Transmit({
  baseUrl: 'https://my-app.com',
})

maxReconnectAttempts（类型：number）

连接断开时的最大重连尝试次数。默认为 5。

ts
const transmit = new Transmit({
  baseUrl: window.location.origin,
  maxReconnectAttempts: 10,
})

uidGenerator（类型：() => string）

生成客户端唯一标识符的自定义函数。默认为 crypto.randomUUID()。

ts
import { nanoid } from 'nanoid'

const transmit = new Transmit({
  baseUrl: window.location.origin,
  uidGenerator: () => nanoid(),
})

beforeSubscribe（类型：(request: Request) => void）

每次订阅请求之前调用的钩子。用于修改请求，例如添加自定义头。

ts
const transmit = new Transmit({
  baseUrl: window.location.origin,
  beforeSubscribe: (request) => {
    request.headers.set('X-Custom-Header', 'value')
  },
})

beforeUnsubscribe（类型：(request: Request) => void）

每次取消订阅请求之前调用的钩子。工作方式与 beforeSubscribe 相同。

onReconnectAttempt（类型：(attempt: number) => void）

每次重连尝试时调用的回调。接收当前尝试次数。

onReconnectFailed（类型：() => void）

达到最大重连尝试次数且客户端停止尝试时调用的回调。

onSubscribeFailed（类型：(response: Response) => void）

订阅请求失败时调用的回调。接收来自失败请求的 Response 对象。

onSubscription（类型：(channel: string) => void）

订阅成功创建时调用的回调。

onUnsubscription（类型：(channel: string) => void）

订阅成功删除时调用的回调。

eventSourceFactory（类型：(url: string | URL, options: { withCredentials: boolean }) => EventSource）

用于创建 EventSource 实例的自定义工厂。对于原生 EventSource 不可用的环境很有用。

eventTargetFactory（类型：() => EventTarget | null）

用于创建用于状态更改事件的 EventTarget 的自定义工厂。返回 null 以禁用状态事件。

httpClientFactory（类型：(baseUrl: string, uid: string) => HttpClient）

用于创建用于订阅和取消订阅请求的 HTTP 客户端的自定义工厂。

生命周期钩子 ​

服务器端 transmit 实例发出你可以监听以进行监控和调试的生命周期事件。

ts
import transmit from '@adonisjs/transmit/services/main'

transmit.on('connect', ({ uid }) => {
  console.log(`Client ${uid} connected`)
})

transmit.on('disconnect', ({ uid }) => {
  console.log(`Client ${uid} disconnected`)
})

transmit.on('broadcast', ({ channel, payload }) => {
  console.log(`Broadcast on ${channel}:`, payload)
})

transmit.on('subscribe', ({ uid, channel }) => {
  console.log(`Client ${uid} subscribed to ${channel}`)
})

transmit.on('unsubscribe', ({ uid, channel }) => {
  console.log(`Client ${uid} unsubscribed from ${channel}`)
})

connect、disconnect、subscribe 和 unsubscribe 事件回调还接收一个包含请求的 HttpContext 的 context 属性。

测试 ​

服务器端 transmit 实例暴露你可以在测试中监听的生命周期钩子。transmit.on 方法返回一个停止监听的函数，这使得收集请求期间发出的广播并对其进行断言变得容易。

以下示例使用 Japa 和 @japa/api-client 插件。

断言广播 ​

在发起请求之前注册监听器，执行触发广播的操作，然后停止监听并断言收集的事件。

ts
import transmit from '@adonisjs/transmit/services/main'
import User from '#models/user'
import { test } from '@japa/runner'

test.group('Posts', () => {
  test('broadcasts the created post', async ({ client, assert }) => {
    const user = await User.create({
      fullName: 'Jane',
      email: 'jane@example.com',
      password: 'secret',
    })

    const broadcasts: { channel: string; payload: unknown }[] = []
    const stopListening = transmit.on('broadcast', (event) => broadcasts.push(event))

    const response = await client.post('/posts').loginAs(user).json({
      title: 'Hello world',
    })

    stopListening()

    response.assertStatus(201)
    assert.lengthOf(broadcasts, 1)
    assert.equal(broadcasts[0].channel, `users/${user.id}`)
  })
})

TIP

在请求之后立即调用 transmit.on 返回的函数，以避免收集同一进程中运行的其他测试的广播。

测试频道授权 ​

你可以通过直接向 __transmit/subscribe 路由发送订阅请求来测试频道授权。路由返回：

  • 客户端未认证时返回 401
  • 已认证且已授权时返回 204
  • 已认证但被 authorize 回调拒绝时返回 400
ts
import User from '#models/user'
import { test } from '@japa/runner'

test.group('Transmit', () => {
  test('rejects unauthenticated subscriptions', async ({ client }) => {
    const response = await client.post('/__transmit/subscribe').json({
      uid: 'test-client-uid',
      channel: 'users/1',
    })

    response.assertStatus(401)
  })

  test('allows owners to subscribe to their channel', async ({ client }) => {
    const user = await User.create({
      fullName: 'Jane',
      email: 'jane@example.com',
      password: 'secret',
    })

    const response = await client
      .post('/__transmit/subscribe')
      .loginAs(user)
      .json({
        uid: 'test-client-uid',
        channel: `users/${user.id}`,
      })

    response.assertStatus(204)
  })

  test('denies access to another user channel', async ({ client }) => {
    const owner = await User.create({
      fullName: 'Jane',
      email: 'jane@example.com',
      password: 'secret',
    })

    const otherUser = await User.create({
      fullName: 'John',
      email: 'john@example.com',
      password: 'secret',
    })

    const response = await client
      .post('/__transmit/subscribe')
      .loginAs(otherUser)
      .json({
        uid: 'test-client-uid',
        channel: `users/${owner.id}`,
      })

    response.assertStatus(400)
  })
})

获取频道订阅者 ​

使用 getSubscribersFor 方法检索当前订阅频道的所有客户端的 UID。

ts
import transmit from '@adonisjs/transmit/services/main'

const subscribers = transmit.getSubscribersFor('chats/1/messages')
console.log(`${subscribers.length} clients connected to this chat`)

多实例同步 ​

在负载均衡器后面运行多个服务器实例时，在一个实例上广播的事件不会到达连接到其他实例的客户端。Transmit 通过使用消息总线在所有实例之间同步事件的传输层来解决这个问题。

Redis 传输 ​

安装 ioredis 包并配置 Redis 传输。

sh
npm install ioredis
ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/transmit'
import { redis } from '@adonisjs/transmit/transports'

export default defineConfig({
  pingInterval: '30s',
  transport: {
    driver: redis({
      host: env.get('REDIS_HOST'),
      port: env.get('REDIS_PORT'),
      password: env.get('REDIS_PASSWORD'),
      keyPrefix: 'transmit',
    }),
  },
})

MQTT 传输 ​

ts
import env from '#start/env'
import { defineConfig } from '@adonisjs/transmit'
import { mqtt } from '@adonisjs/transmit/transports'

export default defineConfig({
  pingInterval: '30s',
  transport: {
    driver: mqtt({
      url: env.get('MQTT_URL'),
    }),
  },
})

传输通过配置的消息总线向所有已连接的实例广播事件。默认广播频道是 'transmit::broadcast'。你可以根据需要自定义它。

ts
export default defineConfig({
  transport: {
    driver: redis({ /* ... */ }),
    channel: 'my-app::transmit',
  },
})

生产环境注意事项 ​

为 SSE 禁用压缩 ​

服务器发送事件要求响应流不被压缩。如果你的反向代理应用 GZip 压缩，你必须排除 text/event-stream 内容类型。压缩的 SSE 流会导致连接不稳定和消息缓冲。

WARNING

你必须在反向代理中为 text/event-stream 内容类型禁用压缩。未能这样做将导致 SSE 连接中断或无限缓冲消息。

对于 Traefik：

yaml
traefik.http.middlewares.gzip.compress.excludedcontenttypes=text/event-stream

对于 Nginx：

nginx
# 不要在 gzip_types 中包含 text/event-stream
gzip_types text/plain application/json application/javascript text/css;
