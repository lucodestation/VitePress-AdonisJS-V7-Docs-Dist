健康检查 ​

本指南涵盖 AdonisJS 应用中的健康检查。你将了解到如何：

  • 理解存活探针和就绪探针的区别
  • 使用内置配置命令配置健康检查
  • 为监控服务和编排器暴露端点
  • 使用磁盘空间、内存、数据库和 Redis 的内置检查
  • 缓存健康检查结果以优化性能
  • 为应用特定需求创建自定义健康检查

概述 ​

健康检查允许你的应用向负载均衡器、容器编排器（Kubernetes、Docker Swarm）和监控服务等外部系统报告其运行状态。这些系统定期探测你的应用以确定它是否应接收流量或被重启。

AdonisJS 提供一个内置于核心框架的健康检查系统，带有多个用于常见基础设施关注点的现成检查。你也可以为应用特定的需求（如验证外部 API 连接或队列连接）创建自定义检查。

存活探针 vs 就绪探针 ​

在实现健康检查之前，理解两种探针类型以及何时使用每种很重要。

存活探针回答这个问题："进程是否存活并能响应？"这是一个简单的检查，验证你的应用能够响应 HTTP 请求。如果存活探针反复失败，编排器将重启容器。存活探针应轻量并避免检查外部依赖，因为数据库中断不应导致你的应用进入重启循环。

就绪探针回答这个问题："应用是否准备好接受流量？"此检查验证你的应用及其依赖（数据库连接、Redis、外部服务）是否正常工作。如果就绪探针失败，编排器将实例从负载均衡器中移除但不重启它。这允许应用有时间恢复，例如当数据库连接暂时不可用时。

探针目的失败时应检查依赖
存活进程是否存活？重启容器否
就绪能否处理请求？从负载均衡器移除是

配置健康检查 ​

运行以下命令在应用中设置健康检查。这会创建配置文件和一个带有存活和就绪端点的控制器。

sh
node ace configure health_checks

该命令创建两个文件。第一个是健康检查配置，你在这里注册要运行哪些检查。

ts
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
])

第二个是暴露两个探针端点的控制器。

ts
import { healthChecks } from '#start/health'
import type { HttpContext } from '@adonisjs/core/http'

export default class HealthChecksController {
  /**
   * 存活探针：如果进程正在运行则返回 200。
   * 不检查依赖。
   */
  async live({ response }: HttpContext) {
    return response.ok()
  }

  /**
   * 就绪探针：运行所有已注册的健康检查
   * 并返回详细报告。
   */
  async ready({ response }: HttpContext) {
    const report = await healthChecks.run()
    if (report.isHealthy) {
      return response.ok(report)
    }

    return response.serviceUnavailable(report)
  }
}

存活方法简单地返回 200 状态码，证明进程存活且能处理 HTTP 请求。就绪方法运行所有已注册的健康检查，健康时返回 200，任何检查失败时返回 503（Service Unavailable）。

暴露端点 ​

在路由文件中注册健康检查路由。为每个探针使用单独的路径允许编排器独立配置它们。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('/health/live', [controllers.HealthChecks, 'live'])
router.get('/health/ready', [controllers.HealthChecks, 'ready'])

有了这些路由，你的监控系统可以探测 /health/live 进行存活检查，探测 /health/ready 进行就绪检查。

理解就绪报告 ​

就绪端点返回包含所有已注册检查结果的详细 JSON 报告。

json
{
  "isHealthy": true,
  "status": "warning",
  "finishedAt": "2024-06-20T07:09:35.275Z",
  "debugInfo": {
    "pid": 16250,
    "ppid": 16051,
    "platform": "darwin",
    "uptime": 16.271809083,
    "version": "v21.7.3"
  },
  "checks": [
    {
      "name": "Disk space check",
      "isCached": false,
      "message": "Disk usage is 76%, which is above the threshold of 75%",
      "status": "warning",
      "finishedAt": "2024-06-20T07:09:35.275Z",
      "meta": {
        "sizeInPercentage": {
          "used": 76,
          "failureThreshold": 80,
          "warningThreshold": 75
        }
      }
    },
    {
      "name": "Memory heap check",
      "isCached": false,
      "message": "Heap usage is under defined thresholds",
      "status": "ok",
      "finishedAt": "2024-06-20T07:09:35.265Z",
      "meta": {
        "memoryInBytes": {
          "used": 41821592,
          "failureThreshold": 314572800,
          "warningThreshold": 262144000
        }
      }
    }
  ]
}

报告包含以下属性：

isHealthy

布尔值，指示所有检查是否通过。如果一个或多个检查失败则设置为 false。

status

总体状态：ok（全部通过）、warning（存在警告）或 error（存在失败）。

finishedAt

检查完成的时间戳。

debugInfo

进程信息，包括 PID、平台、运行时间（秒）和 Node.js 版本。

checks

包含每个已注册检查详细结果的数组。

checks 数组中的每个检查包括其名称、状态、消息、结果是否被缓存以及该检查类型特定的任何元数据。

保护就绪端点 ​

就绪报告包含关于你的基础设施的详细信息，你可能不想公开暴露。你可以使用监控系统随每个请求包含的秘密头来保护端点。

Kubernetes 和大多数监控工具支持探针请求上的自定义 HTTP 头，因此你可以配置它们包含你的秘密。

ts
import router from '@adonisjs/core/services/router'

const HealthChecksController = () => import('#controllers/health_checks_controller')

router.get('/health/live', [HealthChecksController, 'live'])
router
  .get('/health/ready', [HealthChecksController, 'ready'])
  .use(({ request, response }, next) => {
    if (request.header('x-monitoring-secret') === 'some_secret_value') {
      return next()
    }
    return response.unauthorized({ message: 'Unauthorized access' })
  })

在 Kubernetes 中，配置探针包含该头。

yaml
readinessProbe:
  httpGet:
    path: /health/ready
    port: 3333
    httpHeaders:
      - name: x-monitoring-secret
        value: some_secret_value

可用的健康检查 ​

AdonisJS 提供多个内置健康检查，你可以在 start/health.ts 文件中注册它们。

DiskSpaceCheck ​

监控可用磁盘空间，并在使用量超过配置的阈值时报告警告或错误。

ts
import { HealthChecks, DiskSpaceCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck()
])

默认警告阈值为 75%，失败阈值为 80%。你可以自定义这些值。

ts
export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck()
    .warnWhenExceeds(80)
    .failWhenExceeds(90),
])

MemoryHeapCheck ​

监控由 process.memoryUsage() 报告的堆大小，并在内存消耗超过阈值时发出警报。

ts
import { HealthChecks, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new MemoryHeapCheck()
])

默认警告阈值为 250MB，失败阈值为 300MB。你可以使用人类可读的字符串自定义这些值。

ts
export const healthChecks = new HealthChecks().register([
  new MemoryHeapCheck()
    .warnWhenExceeds('300 mb')
    .failWhenExceeds('700 mb'),
])

MemoryRSSCheck ​

监控由 process.memoryUsage() 报告的常驻集大小（为进程分配的总内存）。

ts
import { HealthChecks, MemoryRSSCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new MemoryRSSCheck()
])

默认警告阈值为 320MB，失败阈值为 350MB。

ts
export const healthChecks = new HealthChecks().register([
  new MemoryRSSCheck()
    .warnWhenExceeds('600 mb')
    .failWhenExceeds('800 mb'),
])

DbCheck ​

由 @adonisjs/lucid 包提供，此检查验证与你的 SQL 数据库的连接。

ts
import db from '@adonisjs/lucid/services/db'
import { DbCheck } from '@adonisjs/lucid/database'
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new DbCheck(db.connection()),
])

成功的检查返回如下报告。

json
{
  "name": "Database health check (postgres)",
  "isCached": false,
  "message": "Successfully connected to the database server",
  "status": "ok",
  "finishedAt": "2024-06-20T07:18:23.830Z",
  "meta": {
    "connection": {
      "name": "postgres",
      "dialect": "postgres"
    }
  }
}

要监控多个数据库连接，为每个连接注册一次检查。

ts
export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new DbCheck(db.connection()),
  new DbCheck(db.connection('mysql')),
  new DbCheck(db.connection('pg')),
])

DbConnectionCountCheck ​

监控活动数据库连接，并在数量超过阈值时发出警报。此检查仅支持 PostgreSQL 和 MySQL 数据库。

ts
import db from '@adonisjs/lucid/services/db'
import { DbCheck, DbConnectionCountCheck } from '@adonisjs/lucid/database'
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new DbCheck(db.connection()),
  new DbConnectionCountCheck(db.connection()),
])

默认警告阈值为 10 个连接，失败阈值为 15 个连接。

ts
new DbConnectionCountCheck(db.connection())
  .warnWhenExceeds(4)
  .failWhenExceeds(10)

RedisCheck ​

由 @adonisjs/redis 包提供，此检查验证与你的 Redis 服务器的连接，包括集群配置。

ts
import redis from '@adonisjs/redis/services/main'
import { RedisCheck } from '@adonisjs/redis'
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new RedisCheck(redis.connection()),
])

要监控多个 Redis 连接，为每个连接注册一次检查。

ts
export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new RedisCheck(redis.connection()),
  new RedisCheck(redis.connection('cache')),
  new RedisCheck(redis.connection('locks')),
])

RedisMemoryUsageCheck ​

监控 Redis 服务器上的内存消耗，并在使用量超过阈值时发出警报。

ts
import redis from '@adonisjs/redis/services/main'
import { RedisCheck, RedisMemoryUsageCheck } from '@adonisjs/redis'
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck(),
  new MemoryHeapCheck(),
  new RedisCheck(redis.connection()),
  new RedisMemoryUsageCheck(redis.connection()),
])

默认警告阈值为 100MB，失败阈值为 120MB。

ts
new RedisMemoryUsageCheck(redis.connection())
  .warnWhenExceeds('200 mb')
  .failWhenExceeds('240 mb')

缓存结果 ​

每次调用就绪端点时都会运行健康检查。对于不需要在每个请求上运行的检查（如磁盘空间，它变化缓慢），你可以将结果缓存指定时长。

ts
import {
  HealthChecks,
  MemoryRSSCheck,
  DiskSpaceCheck,
  MemoryHeapCheck,
} from '@adonisjs/core/health'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck().cacheFor('1 hour'),
  new MemoryHeapCheck(),
  new MemoryRSSCheck(),
])

在此示例中，磁盘空间检查每小时最多运行一次，后续请求返回缓存结果。内存检查在每个请求上运行，因为内存使用量可能快速变化。

当结果从缓存提供时，检查报告中的 isCached 属性将为 true。

创建自定义健康检查 ​

你可以创建自定义健康检查以验证应用特定的需求，如外部 API 连接、消息队列连接或业务关键服务的可用性。

自定义健康检查是一个继承 BaseCheck 并实现 run 方法的类。你可以将自定义检查放在项目中的任何位置，尽管 app/health_checks/ 是一个合理的位置。

ts
import { Result, BaseCheck } from '@adonisjs/core/health'
import type { HealthCheckResult } from '@adonisjs/core/types/health'

export class PaymentGatewayCheck extends BaseCheck {
  async run(): Promise<HealthCheckResult> {
    /**
     * 尝试访问支付网关的健康端点。
     * 在真实实现中，你会发起 HTTP 请求
     * 以验证服务可达。
     */
    const isReachable = await this.checkGatewayConnectivity()

    if (!isReachable) {
      return Result.failed('Payment gateway is unreachable')
    }

    const latency = await this.measureLatency()

    if (latency > 2000) {
      return Result.warning('Payment gateway latency is high').mergeMetaData({
        latencyMs: latency,
      })
    }

    return Result.ok('Payment gateway is healthy').mergeMetaData({
      latencyMs: latency,
    })
  }

  protected async checkGatewayConnectivity(): Promise<boolean> {
    // 实现
    return true
  }

  protected async measureLatency(): Promise<number> {
    // 实现
    return 150
  }
}

Result 类提供三个用于创建健康检查结果的工厂方法：

方法用途
Result.ok(message)检查成功通过
Result.warning(message)检查通过但存在关注点
Result.failed(message, error?)检查失败，可选地包含错误

使用 mergeMetaData 方法在检查报告中包含额外信息，如延迟测量、连接数或版本号。

注册自定义健康检查 ​

在 start/health.ts 中导入你的自定义检查并与其他检查一起注册。

ts
import { HealthChecks, DiskSpaceCheck, MemoryHeapCheck } from '@adonisjs/core/health'
import { PaymentGatewayCheck } from '#health_checks/payment_gateway_check'

export const healthChecks = new HealthChecks().register([
  new DiskSpaceCheck().cacheFor('1 hour'),
  new MemoryHeapCheck(),
  new PaymentGatewayCheck(),
])

你的自定义检查现在将在每次调用就绪端点时与内置检查一起运行。
