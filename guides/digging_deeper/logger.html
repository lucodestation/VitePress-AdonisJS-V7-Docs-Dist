日志记录器 ​

本指南涵盖 AdonisJS 应用中的日志记录。你将了解到如何：

  • 在 HTTP 请求期间使用请求感知的日志记录器写入日志
  • 为开发环境配置美化打印的日志，为生产环境配置基于文件的日志
  • 为应用的不同部分定义多个日志记录器
  • 使用依赖注入将日志记录器注入到服务中
  • 创建从父日志记录器继承上下文的子日志记录器
  • 保护敏感数据不出现在日志输出中

概述 ​

AdonisJS 包含一个内置的日志记录器，用于将日志写入终端、文件和外部服务。在底层，日志记录器使用 Pino，这是 Node.js 生态系统中速度最快的日志库之一。日志以 NDJSON 格式生成，使其易于使用标准工具解析和处理。

日志记录器与 AdonisJS 深度集成。在 HTTP 请求期间，每个请求自动获得自己的日志记录器实例，该实例在每条日志条目中包含请求 ID，使将日志追溯到特定请求变得简单直接。

TIP

本指南重点关注 HTTP 请求期间的日志记录。对于 CLI 应用，请参阅 Ace ANSI 日志记录器文档，它提供专为命令行工具设计的终端友好的彩色输出。

写入你的第一条日志 ​

导入日志记录器服务并调用任何日志记录方法写入消息。在开发期间，日志以美化格式出现在终端中，包括时间戳、颜色和可读结构。

ts
import router from '@adonisjs/core/services/router'
import logger from '@adonisjs/core/services/logger'

router.get('/', async () => {
  logger.info('Processing home page request')
  return { hello: 'world' }
})

当你访问该路由时，你会在终端中看到如下输出：

[10:24:36.842] INFO: Processing home page request

日志记录器为每个日志级别提供方法，从最详细到最不详细：

ts
import logger from '@adonisjs/core/services/logger'

export default class PostsController {
  async store() {
    logger.trace({ config }, 'Using config')      // 最详细，用于追踪执行
    logger.debug('User details: %o', { id: 1 })   // 调试信息
    logger.info('Creating new post')              // 一般信息
    logger.warn('Rate limit approaching')         // 警告条件
    logger.error({ err }, 'Failed to save post')  // 错误条件
    logger.fatal({ err }, 'Database connection lost') // 关键故障
  }
}

向日志添加上下文 ​

将对象作为第一个参数传递以在日志条目中包含额外数据。对象属性被合并到 JSON 输出中。

ts
const user = { id: 1, email: 'virk@adonisjs.com' }
logger.info({ user }, 'User logged in')

记录错误时，使用 err 键，以便 Pino 的内置序列化器正确格式化错误并包含堆栈跟踪：

ts
try {
  await riskyOperation()
} catch (error) {
  logger.error({ err: error }, 'Operation failed')
}

字符串插值 ​

日志消息支持 printf 风格的插值，用于将值直接嵌入消息字符串中：

ts
logger.info('User %s logged in from %s', username, ipAddress)
logger.debug('Request body: %o', requestBody)  // %o 用于对象
logger.info('Processing %d items', items.length) // %d 用于数字

请求感知的日志记录 ​

在 HTTP 请求期间，使用 ctx.logger 而不是直接导入日志记录器服务。上下文日志记录器自动在每条日志条目中包含请求 ID，使得关联单个请求的所有日志变得容易。

ts
import type { HttpContext } from '@adonisjs/core/http'
import User from '#models/user'

export default class UsersController {
  async show({ logger, params }: HttpContext) {
    logger.info('Fetching user by id %s', params.id)

    const user = await User.find(params.id)
    if (!user) {
      logger.warn('User not found')
      return { error: 'Not found' }
    }

    logger.info('User retrieved successfully')
    return user
  }
}

输出包含请求 ID，允许你过滤特定请求的日志：

[10:24:36.842] INFO (request_id=cjkl3402k0001...): Fetching user by id 42
[10:24:36.901] INFO (request_id=cjkl3402k0001...): User retrieved successfully

配置日志记录器 ​

日志记录器配置位于 config/logger.ts。默认设置在开发环境中使用美化打印输出，在生产环境中使用结构化 JSON。

ts
import env from '#start/env'
import app from '@adonisjs/core/services/app'
import { defineConfig, syncDestination, targets } from '@adonisjs/core/logger'

const loggerConfig = defineConfig({
  default: 'app',

  loggers: {
    app: {
      enabled: true,
      name: env.get('APP_NAME'),
      level: env.get('LOG_LEVEL'),
      destination: !app.inProduction ? await syncDestination() : undefined,
      transport: {
        targets: [targets.file({ destination: 1 })],
      },
    },
  },
})

export default loggerConfig

declare module '@adonisjs/core/types' {
  export interface LoggersList extends InferLoggers<typeof loggerConfig> {}
}

理解配置 ​

syncDestination() 辅助函数为开发环境配置同步、美化打印的输出。默认情况下，Pino 异步写入日志以获得更好的性能，但这会使调试期间将日志与产生它们的代码关联起来变得更加困难。同步目标在你的代码执行时内联写入日志，具有人类可读的格式。

在生产环境中，destination 保持为 undefined，这意味着日志流经配置的传输目标。targets.file({ destination: 1 }) 目标将 JSON 日志写入 stdout（文件描述符 1），这是容器化部署的标准方法，其中日志聚合器收集 stdout。

配置参考 ​

属性描述
default调用 logger.info() 而未指定日志记录器时使用的日志记录器名称
enabled设置为 false 以完全禁用日志记录器
name包含在每条日志条目中的名称，用于识别源应用
level要记录的最低级别。低于此级别的消息被忽略
destination自定义目标流。使用 syncDestination() 实现同步美化输出
transport用于处理和路由日志的 Pino 传输配置

日志级别 ​

日志记录器支持六个级别，从最详细到最不详细排序。当你设置级别时，日志记录器产生该级别及以上的日志。

级别值描述
trace10极其详细的追踪信息
debug20开发期间有用的调试信息
info30一般操作信息
warn40应审查的警告条件
error50需要关注的错误条件
fatal60需要立即行动的关键故障

在你的 .env 文件中设置级别：

dotenv
LOG_LEVEL=debug

将日志写入文件 ​

要将日志写入文件而不是 stdout，使用文件路径配置 targets.file() 辅助函数：

ts
transport: {
  targets: [
    targets.file({ destination: '/var/log/apps/adonisjs.log' })
  ],
}

文件轮转 ​

Pino 不包含内置的文件轮转。使用系统工具如 logrotate 或 pino-roll 包。

sh
npm i pino-roll
ts
transport: {
  targets: [
    {
      target: 'pino-roll',
      level: 'info',
      options: {
        file: '/var/log/apps/adonisjs.log',
        frequency: 'daily',
        mkdir: true,
      },
    },
  ],
}

条件定义目标 ​

使用 targets() 辅助函数通过条件逻辑构建 targets 数组。这比使用三元运算符展开数组更清晰。

ts
import app from '@adonisjs/core/services/app'
import { defineConfig, targets } from '@adonisjs/core/logger'

export default defineConfig({
  default: 'app',

  loggers: {
    app: {
      enabled: true,
      name: env.get('APP_NAME'),
      level: env.get('LOG_LEVEL'),
      transport: {
        targets: targets()
          .pushIf(!app.inProduction, targets.pretty())
          .pushIf(app.inProduction, targets.file({ destination: 1 }))
          .toArray(),
      },
    },
  },
})

pushIf 方法仅在条件为真时添加目标，保持你的配置可读。

使用多个日志记录器 ​

当应用的不同部分需要单独的日志记录行为时，在配置中定义多个日志记录器。例如，你可能希望支付相关的日志写入具有不同保留策略的单独文件。

ts
export default defineConfig({
  default: 'app',

  loggers: {
    app: {
      enabled: true,
      name: env.get('APP_NAME'),
      level: env.get('LOG_LEVEL'),
      destination: !app.inProduction ? await syncDestination() : undefined,
      transport: {
        targets: [targets.file({ destination: 1 })],
      },
    },
    payments: {
      enabled: true,
      name: 'payments',
      level: 'info',
      transport: {
        targets: [
          targets.file({ destination: '/var/log/apps/payments.log' }),
        ],
      },
    },
  },
})

使用 logger.use() 方法访问特定日志记录器：

ts
import logger from '@adonisjs/core/services/logger'

export default class PaymentService {
  async processPayment(amount: number) {
    const paymentLogger = logger.use('payments')

    paymentLogger.info({ amount }, 'Processing payment')
    // ... 支付逻辑
    paymentLogger.info('Payment completed successfully')
  }
}

不带参数调用 logger.use() 返回默认日志记录器。

依赖注入 ​

使用依赖注入时，类型提示 Logger 类，IoC 容器解析默认日志记录器的实例。如果类在 HTTP 请求期间构造，容器自动注入包含请求 ID 的请求感知日志记录器。

ts
import { inject } from '@adonisjs/core'
import { Logger } from '@adonisjs/core/logger'
import User from '#models/user'

@inject()
export default class UserService {
  constructor(protected logger: Logger) {}

  async find(userId: string | number) {
    this.logger.info('Fetching user by id %s', userId)
    return User.find(userId)
  }
}

子日志记录器 ​

子日志记录器从其父级继承配置和绑定，同时允许你添加额外上下文。当你希望特定操作的所有日志都包含共享元数据时，这很有用。

ts
import logger from '@adonisjs/core/services/logger'

const orderLogger = logger.child({ orderId: 'order_123' })

orderLogger.info('Processing order')      // 包含 orderId
orderLogger.info('Validating items')      // 包含 orderId
orderLogger.info('Order complete')        // 包含 orderId

来自 orderLogger 的每条日志条目自动包含 orderId 字段。你也可以为子日志记录器覆盖日志级别：

ts
const verboseLogger = logger.child({}, { level: 'trace' })

条件日志记录 ​

如果为日志消息计算数据很昂贵，在开始工作之前检查级别是否启用：

ts
import logger from '@adonisjs/core/services/logger'

if (logger.isLevelEnabled('debug')) {
  const data = await computeExpensiveDebugData()
  logger.debug(data, 'Debug information')
}

ifLevelEnabled 方法提供基于回调的替代方案：

ts
logger.ifLevelEnabled('debug', async () => {
  const data = await computeExpensiveDebugData()
  logger.debug(data, 'Debug information')
})

隐藏敏感值 ​

日志可能无意中暴露敏感数据。使用 redact 选项自动隐藏特定键的值。在底层，这使用 fast-redact 包。

ts
loggers: {
  app: {
    enabled: true,
    name: env.get('APP_NAME'),
    level: env.get('LOG_LEVEL'),
    redact: {
      paths: ['password', '*.password', 'creditCard'],
    },
  },
}
ts
logger.info({ username: 'virk', password: 'secret123' }, 'User signup')
// 输出：{"username":"virk","password":"[Redacted]","msg":"User signup"}

自定义占位符或完全移除键：

ts
redact: {
  paths: ['password', '*.password'],
  censor: '[PRIVATE]',
}

// 或完全移除属性
redact: {
  paths: ['password'],
  remove: true,
}

使用 Secret 类 ​

脱敏的替代方案是将敏感值包装在 Secret 类中。日志记录器自动脱敏任何 Secret 实例。

另请参阅：Secret 类文档

ts
import { Secret } from '@adonisjs/core/helpers'

const password = new Secret(request.input('password'))

logger.info({ username, password }, 'User signup')
// 输出：{"username":"virk","password":"[redacted]","msg":"User signup"}

Pino 静态成员 ​

@adonisjs/core/logger 模块重新导出 Pino 的静态方法和属性以供高级使用。

有关这些导出的详细信息，请参阅 Pino 文档。

ts
import {
  multistream,
  destination,
  transport,
  stdSerializers,
  stdTimeFunctions,
  symbols,
  pinoVersion,
} from '@adonisjs/core/logger'
