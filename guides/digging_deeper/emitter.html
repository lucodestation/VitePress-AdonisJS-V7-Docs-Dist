事件发射器 ​

本指南涵盖 AdonisJS 应用中的事件发射器。你将了解到如何：

  • 定义和发射类型安全的事件
  • 使用回调或类注册监听器
  • 在测试期间处理错误和伪造事件

概述 ​

事件发射器在 AdonisJS 应用中实现事件驱动架构。当你发射一个事件时，所有已注册的监听器异步执行，不会阻塞触发事件的代码。这种模式对于将副作用与应用主逻辑解耦很有用。

一个常见的例子是用户注册：创建用户账户后，你可能需要发送验证邮件、在支付提供商处配置资源，并为分析记录注册。你可以在控制器中顺序执行所有这些任务，而是发射一个 user:registered 事件，让单独的监听器独立处理每个关注点。

AdonisJS 提供两种定义事件的方法。基于字符串的事件使用 TypeScript 模块扩充实现类型安全，而基于类的事件将事件标识符和数据封装在单个类中。

TIP

如果你在寻找 AdonisJS 及其官方包发射的事件列表，请参阅事件参考指南。

定义事件和事件数据 ​

一个事件由两部分组成：标识符和关联数据。标识符通常是像 user:registered 这样的字符串，数据是你想传递给监听器的任何负载（例如 User 模型的实例）。

基于类的事件将标识符和数据封装在单个类中。类本身作为标识符，类的实例持有事件数据。这种方法无需额外配置即可提供内置的类型安全。

基于字符串的事件 ​

基于字符串的事件使用像 user:registered 或 order:shipped 这样的字符串标识符。为了使这些事件类型安全，你使用 TypeScript 模块扩充定义事件名称及其负载类型。

步骤 1：定义事件类型 ​

创建一个 types/events.ts 文件，并扩充 EventsList 接口以声明你的事件及其负载类型。

ts
import User from '#models/user'

declare module '@adonisjs/core/types' {
  interface EventsList {
    'user:registered': User
  }
}

EventsList 接口将事件名称映射到它们的负载类型。在此示例中，user:registered 事件携带 User 模型实例作为其负载。当你发射事件或注册监听器时，TypeScript 将强制执行此契约。

步骤 2：监听事件 ​

创建一个预加载文件来注册你的事件监听器。运行以下命令生成文件。

sh
node ace make:preload events

这会创建 start/events.ts，它在应用启动时自动加载。使用 emitter.on 方法注册监听器。

ts
import emitter from '@adonisjs/core/services/emitter'

emitter.on('user:registered', function (user) {
  console.log(user.email)
})

监听器回调接收事件负载作为其参数。因为你在 EventsList 中定义了负载类型，TypeScript 知道 user 是 User 模型的实例。

步骤 3：发射事件 ​

使用 emitter.emit 从应用中的任何地方发射事件。第一个参数是事件名称，第二个是负载。

ts
import emitter from '@adonisjs/core/services/emitter'
import User from '#models/user'

export default class UsersController {
  async store({ request }: HttpContext) {
    const data = request.only(['email', 'password'])
    const user = await User.create(data)

    emitter.emit('user:registered', user)
    return user
  }
}

emitter.emit 方法是类型安全的。如果你传递不正确的负载类型或使用未在 EventsList 中定义的事件名称，TypeScript 将报错。

基于类的事件 ​

基于类的事件无需模块扩充即可提供类型安全。事件类同时充当标识符和事件数据的容器。

步骤 1：创建事件类 ​

使用 make:event 命令生成事件类。

sh
node ace make:event UserRegistered

这会创建一个继承 BaseEvent 的事件类。通过构造函数接受事件数据并将其作为实例属性暴露。

ts
import { BaseEvent } from '@adonisjs/core/events'
import User from '#models/user'

export default class UserRegistered extends BaseEvent {
  constructor(public user: User) {
    super()
  }
}

事件类没有行为。它纯粹是一个数据容器，构造函数参数定义事件携带什么数据。

步骤 2：监听事件 ​

从 #generated/events barrel 文件导入事件类，并将其作为 emitter.on 的第一个参数。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'

emitter.on(events.UserRegistered, function (event) {
  console.log(event.user.email)
})

监听器接收事件类的实例。通过你在构造函数中定义的实例属性访问事件数据。

步骤 3：分发事件 ​

基于类的事件使用静态 dispatch 方法而不是 emitter.emit 来分发。

ts
import User from '#models/user'
import { events } from '#generated/events'

export default class UsersController {
  async store({ request }: HttpContext) {
    const data = request.only(['email', 'password'])
    const user = await User.create(data)

    events.UserRegistered.dispatch(user)
    return user
  }
}

dispatch 方法接受与事件类构造函数相同的参数。无需在 EventsList 中定义类型，因为类本身提供完整的类型信息。

监听器 ​

监听器可以定义为内联回调或专用监听器类。内联回调适用于简单逻辑，而监听器类更适合受益于依赖注入和可测试性的复杂操作。

内联回调 ​

将函数直接传递给 emitter.on 以创建简单监听器。

ts
import emitter from '@adonisjs/core/services/emitter'

emitter.on('user:registered', function (user) {
  console.log(`New user: ${user.email}`)
})

同样的方法也适用于基于类的事件。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'

emitter.on(events.UserRegistered, function (event) {
  console.log(`New user: ${event.user.email}`)
})

监听器类 ​

使用 make:listener 命令创建监听器类。

sh
node ace make:listener SendVerificationEmail

这会生成一个带有 handle 方法的类，在事件触发时执行。

ts
export default class SendVerificationEmail {
  async handle() {
    // 发送邮件
  }
}

更新 handle 方法以接受事件负载。对于基于类的事件，将参数类型化为事件类。

ts
import { events } from '#generated/events'

export default class SendVerificationEmail {
  async #sendEmail(to: string) {
  }

  async handle(event: events.UserRegistered) {
    await this.#sendEmail(event.user.email)
  }
}

通过从 #generated/listeners barrel 文件导入来注册监听器。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'
import { listeners } from '#generated/listeners'

emitter.on(events.UserRegistered, [listeners.SendVerificationEmail])

监听器中的依赖注入 ​

监听器类通过 IoC 容器实例化，因此你可以使用 @inject 装饰器通过构造函数注入依赖。

另请参阅依赖注入指南。

ts
import { inject } from '@adonisjs/core'
import { events } from '#generated/events'
import TokensService from '#services/tokens_service'

@inject()
export default class SendVerificationEmail {
  constructor(protected tokensService: TokensService) {}

  async handle(event: events.UserRegistered) {
    const token = this.tokensService.generate(event.user.email)
  }
}

监听方法 ​

发射器提供多种注册监听器的方法，每种适用于不同的用例。

使用 on 的持久监听器 ​

on 方法注册一个监听器，在应用生命周期内每次发射事件时都会触发。

ts
emitter.on('user:registered', function (user) {
  // 每次事件触发时运行
})

使用 once 的一次性监听器 ​

once 方法注册一个只触发一次的监听器，然后自动取消订阅。

ts
emitter.once('user:registered', function (user) {
  // 仅在事件首次触发时运行
})

使用 listen 的多个监听器 ​

listen 方法在一次调用中为单个事件注册多个监听器。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'
import { listeners } from '#generated/listeners'

emitter.listen(events.UserRegistered, [
  listeners.SendVerificationEmail,
  listeners.RegisterWithPaymentProvider,
  listeners.ProvisionAccount,
])

所有监听器在事件触发时并行执行。

使用 onAny 的通配符监听器 ​

onAny 方法注册一个监听器，对应用中发射的每个事件都会触发。

ts
emitter.onAny((name, event) => {
  console.log(`Event fired: ${name}`)
  console.log(event)
})

这对于日志记录、调试或实现对所有事件适用的横切关注点很有用。

取消订阅事件 ​

当不再需要监听器时，你可以移除它们。

使用取消订阅函数 ​

on 和 once 方法返回一个取消订阅函数。调用它以移除监听器。

ts
import emitter from '@adonisjs/core/services/emitter'

const unsubscribe = emitter.on('user:registered', () => {
})

unsubscribe()

使用 off 方法 ​

off 方法移除特定监听器。你需要对已注册的确切函数或类的引用。

ts
import emitter from '@adonisjs/core/services/emitter'

function sendEmail() {
}

emitter.on('user:registered', sendEmail)
emitter.off('user:registered', sendEmail)

这也适用于监听器类。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'
import { listeners } from '#generated/listeners'

emitter.on(events.UserRegistered, listeners.SendVerificationEmail)
emitter.off(events.UserRegistered, listeners.SendVerificationEmail)

清除监听器 ​

使用 clearListeners 移除特定事件的所有监听器。

ts
emitter.clearListeners('user:registered')
emitter.clearListeners(events.UserRegistered)

使用 clearAllListeners 移除所有事件的所有监听器。

ts
emitter.clearAllListeners()

错误处理 ​

当监听器抛出错误时，它不会影响其他监听器，因为它们并行运行。但是，未处理的错误会触发 Node.js unhandledRejection 事件，这可能会使你的应用崩溃或导致意外行为。

定义一个全局错误处理器以捕获和处理来自所有监听器的错误。

ts
import emitter from '@adonisjs/core/services/emitter'

emitter.onError((event, error, eventData) => {
  console.error(`Error in listener for ${event}:`, error)
  // 报告到错误跟踪服务
})

错误处理器接收三个参数：事件名称（或类）、抛出的错误以及传递给监听器的事件数据。

在测试期间伪造事件 ​

测试发射事件的代码时，你通常希望验证事件已发射而不实际运行监听器。例如，测试用户注册时，你可能想确认 user:registered 事件触发而不发送真实邮件。

emitter.fake 方法阻止监听器运行，并返回一个捕获已发射事件以供断言的 EventBuffer。

ts
import emitter from '@adonisjs/core/services/emitter'
import { events } from '#generated/events'

test.group('User signup', () => {
  test('create a user account', async ({ client }) => {
    using fakeEmitter = emitter.fake()

    await client
      .post('signup')
      .form({
        email: 'foo@bar.com',
        password: 'secret',
      })

    fakeEmitter.assertEmitted(events.UserRegistered)
  })
})

using 关键字在变量超出作用域（测试函数结束时）时自动恢复发射器。如果你需要更多控制恢复何时发生，也可以手动调用 emitter.restore()。

伪造特定事件 ​

将事件名称或类传递给 fake 以仅伪造特定事件。其他事件将继续正常触发其监听器。

ts
emitter.fake('user:registered')
emitter.fake([events.UserRegistered, events.OrderUpdated])

断言 ​

fake 返回的 EventBuffer 提供多个断言方法。

ts
const fakeEmitter = emitter.fake()

// 断言事件已发射
fakeEmitter.assertEmitted('user:registered')
fakeEmitter.assertEmitted(events.UserRegistered)

// 断言事件未发射
fakeEmitter.assertNotEmitted(events.OrderUpdated)

// 断言事件发射了特定次数
fakeEmitter.assertEmittedCount(events.OrderUpdated, 1)

// 断言完全没有发射任何事件
fakeEmitter.assertNoneEmitted()

条件断言 ​

将回调传递给 assertEmitted 以断言事件是否带有特定数据发射。

ts
fakeEmitter.assertEmitted(events.OrderUpdated, ({ data }) => {
  /**
   * 仅当 orderId 匹配时才将事件视为已发射
   */
  return data.order.id === orderId
})

回调接收事件数据，如果事件符合你的条件则返回 true。
