OpenTelemetry ​

本指南涵盖 AdonisJS 应用中的 OpenTelemetry 集成。你将了解到如何：

  • 安装和配置 @adonisjs/otel 包
  • 理解追踪（trace）、跨度（span）和属性（attribute）
  • 为 HTTP、数据库和 Redis 使用自动插桩
  • 使用辅助函数和装饰器创建自定义跨度
  • 跨服务传播追踪上下文
  • 使用 Jaeger 在本地测试你的设置

概述 ​

OpenTelemetry 是一个开放标准，用于从你的应用收集遥测数据：追踪、指标和日志。@adonisjs/otel 包提供 AdonisJS 和 OpenTelemetry 之间的无缝集成，以合理的默认值为你提供分布式追踪和自动插桩。

可观测性对于理解应用内部发生的事情至关重要，尤其是在生产环境中。当用户报告"结账页面很慢"时，追踪让你确切看到时间花在哪里。是数据库查询？外部 API 调用？慢服务？没有追踪，你只能猜测。

该包为你处理 OpenTelemetry 设置的复杂性。运行单个命令，你的应用就会自动追踪 HTTP 请求、数据库查询、Redis 操作等。

OpenTelemetry 概念 ​

在深入实现之前，你应该理解几个核心 OpenTelemetry 概念。全面的介绍请参阅官方 OpenTelemetry 文档。

追踪（Trace） 表示请求通过系统的完整旅程。当用户访问你的 API 时，追踪捕获发生的所有事情：HTTP 请求、数据库查询、缓存查找、对外部服务的调用以及响应。

跨度（Span） 是追踪中的单个工作单元。每个数据库查询、HTTP 请求或函数调用都可以是一个跨度。跨度有开始时间、持续时间、名称和属性（键值元数据）。跨度按层次嵌套：HTTP 请求的父跨度包含该请求期间每个数据库查询的子跨度。

属性（Attribute） 是附加到跨度的键值对，提供上下文。例如，HTTP 跨度可能有 http.method: GET、http.route: /users/:id 和 http.status_code: 200 等属性。

安装 ​

使用以下命令安装和配置该包。

sh
node ace add @adonisjs/otel
查看 add 命令执行的步骤

  1. 使用检测到的包管理器安装 @adonisjs/otel 包。

  2. 在 adonisrc.ts 文件中注册以下服务提供者。

    ts
    {
  providers: [
    // ...其他提供者
    () => import('@adonisjs/otel/otel_provider')
  ]
}

  3. 在 start/kernel.ts 文件中注册以下中间件。

    ts
    router.use([
  () => import('@adonisjs/otel/otel_middleware')
])

  4. 创建 config/otel.ts 文件。

  5. 创建带有 OpenTelemetry 初始化的 bin/otel.ts 文件。

  6. 在 bin/server.ts 文件顶部添加导入语句。

  7. 定义以下环境变量及其验证规则。

    dotenv
    OTEL_EXPORTER_OTLP_ENDPOINT=
OTEL_EXPORTER_OTLP_HEADERS=

就这样。你的应用现在具有对 HTTP 请求、数据库查询等的自动追踪。

配置 ​

配置文件位于 config/otel.ts。

ts
import { defineConfig } from '@adonisjs/otel'
import env from '#start/env'

export default defineConfig({
  serviceName: env.get('APP_NAME'),
  serviceVersion: env.get('APP_VERSION'),
  environment: env.get('APP_ENV'),
})

服务标识 ​

该包从多个来源解析服务元数据。

serviceName（类型：string）

你的服务名称。此值从 OTEL_SERVICE_NAME 或 APP_NAME 环境变量解析。

ts
export default defineConfig({
  serviceName: 'my-api'
})

serviceVersion（类型：string）

你的服务版本。此值从 APP_VERSION 环境变量解析，默认为 0.0.0。

ts
export default defineConfig({
  serviceVersion: '1.2.3'
})

environment（类型：string）

你的服务运行的环境。此值从 APP_ENV 环境变量解析，默认为 development。

ts
export default defineConfig({
  environment: 'production'
})

导出器 ​

默认情况下，该包使用 OTLP over gRPC 将追踪导出到 localhost:4317。这是标准的 OpenTelemetry Collector 端点。如果你在本地或基础设施中运行 OpenTelemetry Collector，追踪会自动发送到那里。

你可以使用环境变量配置导出器端点而无需更改任何代码。

dotenv
# title: .env
OTEL_EXPORTER_OTLP_ENDPOINT=https://otel-collector.example.com:4317

对于认证或自定义头：

dotenv
# title: .env
OTEL_EXPORTER_OTLP_HEADERS=x-api-key=your-api-key

所有可用选项请参阅 OpenTelemetry 环境变量规范，更多自定义请查看高级配置。

多个目标（扇出） ​

当你需要同时将遥测数据导出到多个后端时，使用 destinations 选项。

该包通过 destinations.otlp() 提供通用的 OTLP 目标辅助函数。每个目标可以接收所有信号（traces、metrics、logs）或仅接收子集。

ts
import { defineConfig, destinations } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  destinations: {
    grafana: destinations.otlp({
      endpoint: 'https://grafana-otlp.example.com',
      headers: {
        Authorization: `Basic ${process.env.GRAFANA_BASIC_AUTH}`,
      },
      signals: 'all',
    }),

    honeycomb: destinations.otlp({
      endpoint: 'https://api.honeycomb.io',
      headers: {
        'x-honeycomb-team': process.env.HONEYCOMB_API_KEY!,
        'x-honeycomb-dataset': process.env.HONEYCOMB_DATASET!,
      },
      signals: 'all',
    }),
  },
})

当你设置 endpoint 时，该包会自动通过追加以下内容派生每个信号的端点：

  • /v1/traces
  • /v1/metrics
  • /v1/logs

你也可以为每个信号提供显式端点：

ts
import { defineConfig, destinations } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  destinations: {
    custom: destinations.otlp({
      signals: ['traces', 'logs'],
      endpoints: {
        traces: 'https://collector-a.example.com/v1/traces',
        logs: 'https://collector-b.example.com/v1/logs',
      },
    }),
  },
})

TIP

destinations 是可选的。如果你不定义它，该包保持默认的 OpenTelemetry 行为和环境变量配置（OTEL_EXPORTER_OTLP_*、OTEL_TRACES_EXPORTER、OTEL_METRICS_EXPORTER、OTEL_LOGS_EXPORTER）。

调试模式 ​

启用调试模式以在开发期间将跨度打印到控制台。

ts
import { defineConfig } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',
  debug: true,
})

这会添加一个 ConsoleSpanExporter，将跨度输出到你的终端，帮助你在不设置收集器的情况下可视化追踪。

启用和禁用 ​

当 NODE_ENV === 'test' 时，OpenTelemetry 会自动禁用，以避免测试期间的噪音。你可以覆盖此行为。

ts
import { defineConfig } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  /**
   * 在测试中强制启用
   */
  enabled: true,

  /**
   * 或在任何环境中强制禁用
   */
  enabled: false,
})

采样 ​

在高流量的生产环境中，追踪每个请求会产生大量数据。采样控制收集多少百分比的追踪。

ts
import { defineConfig } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  /**
   * 采样 10% 的追踪（推荐用于高流量生产环境）
   */
  samplingRatio: 0.1,

  /**
   * 采样 100% 的追踪（默认，适合开发）
   */
  samplingRatio: 1.0,
})

采样器使用基于父级的采样，意味着子跨度从其父级继承采样决策。这确保你始终获得完整的追踪而不是片段。

另请参阅：OpenTelemetry 采样文档

TIP

如果你提供自定义 sampler 选项，samplingRatio 将被忽略。

自定义插桩 ​

该包无需任何代码更改即可自动插桩常见库。开箱即用，你可以获得 HTTP 请求（传入和传出）、Lucid 数据库查询（通过 Knex）和 Redis 操作的追踪。

为了减少噪音，以下端点默认从追踪中排除。

  • /health、/healthz、/ready、/readiness
  • /metrics、/internal/metrics、/internal/healthz
  • /favicon.ico

你可以配置单个插桩或添加自定义忽略的 URL。

ts
import { defineConfig } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  instrumentations: {
    /**
     * 添加自定义忽略的 URL（与默认值合并）
     */
    '@opentelemetry/instrumentation-http': {
      ignoredUrls: ['/internal/*', '/api/ping'],
      mergeIgnoredUrls: true,
    },

    /**
     * 禁用特定插桩
     */
    '@opentelemetry/instrumentation-pg': { enabled: false },
  },
})

使用 Jaeger 在本地测试 ​

Jaeger 是一个流行的开源分布式追踪平台，实现了 OpenTelemetry 标准。它提供一个用于可视化追踪的 Web UI，非常适合本地开发。

步骤 1：使用 Docker 启动 Jaeger ​

在 Docker 容器中运行 Jaeger。all-in-one 镜像包含收集器、查询服务和 UI。

sh
docker run -d --name jaeger \
  -e COLLECTOR_OTLP_ENABLED=true \
  -p 16686:16686 \
  -p 4317:4317 \
  -p 4318:4318 \
  jaegertracing/all-in-one:latest

此命令暴露：

  • 端口 16686 用于 Jaeger UI
  • 端口 4317 用于 OTLP gRPC（默认端点）
  • 端口 4318 用于 OTLP HTTP

步骤 2：启动你的应用 ​

你的 AdonisJS 应用已默认配置为将追踪发送到 localhost:4317，因此不需要额外配置。

sh
node ace serve --hmr

步骤 3：生成一些追踪 ​

向你的应用发起请求以生成追踪。你可以使用 curl、浏览器或任何 HTTP 客户端。

sh
curl http://localhost:3333/users
curl http://localhost:3333/posts/1

步骤 4：在 Jaeger 中查看追踪 ​

打开 Jaeger UI http://localhost:16686。你应该在下拉列表中看到你的服务。选择你的服务并点击"Find Traces"查看所有捕获的追踪。

点击任何追踪以查看操作的完整时间线：HTTP 请求、数据库查询以及你创建的任何自定义跨度。

TIP

在开发期间保持 Jaeger 运行。它随时间累积追踪，使比较慢速和快速请求或发现应用行为的模式变得容易。

创建自定义跨度 ​

虽然自动插桩涵盖大多数常见操作，但你经常想要追踪自定义业务逻辑。该包为此提供辅助函数和装饰器。

使用 record 辅助函数 ​

record 辅助函数在代码段周围创建一个跨度：

ts
import { record } from '@adonisjs/otel/helpers'

export default class OrderService {
  async processOrder(orderId: string) {
    /**
     * 将同步或异步代码包裹在跨度中
     */
    const result = await record('order.process', async () => {
      const order = await Order.findOrFail(orderId)
      await this.validateInventory(order)
      await this.chargePayment(order)
      return order
    })

    return result
  }

  async validateInventory(order: Order) {
    /**
     * 访问跨度以添加自定义属性
     */
    await record('order.validate_inventory', async (span) => {
      span.setAttributes({
        'order.id': order.id,
        'order.items_count': order.items.length,
      })

      // 验证逻辑...
    })
  }
}

使用装饰器 ​

对于类方法，装饰器提供更简洁的语法。

ts
import { span, spanAll } from '@adonisjs/otel/decorators'

export default class UserService {
  /**
   * 创建名为 "UserService.findById" 的跨度
   */
  @span()
  async findById(id: string) {
    return User.find(id)
  }

  /**
   * 自定义跨度名称和属性
   */
  @span({ name: 'user.create', attributes: { operation: 'create' } })
  async create(data: UserData) {
    return User.create(data)
  }
}

要自动追踪类的所有方法，使用 @spanAll 装饰器。

ts
import { spanAll } from '@adonisjs/otel/decorators'

/**
 * 所有方法都获得跨度。
 */
@spanAll()
export default class PaymentService {
  async charge(amount: number) {
    // ...
  }

  async refund(transactionId: string) {
    // ...
  }
}

/**
 * 自定义前缀："payment.charge"、"payment.refund" 等。
 */
@spanAll({ prefix: 'payment' })
export default class PaymentService {
  // ...
}

在当前跨度上设置属性 ​

使用 setAttributes 向当前活动跨度添加元数据而不创建新跨度。

ts
import { setAttributes } from '@adonisjs/otel/helpers'

export default class OrdersController {
  async store({ request }: HttpContext) {
    const data = request.all()

    /**
     * 向 HTTP 跨度添加业务上下文
     */
    setAttributes({
      'order.type': data.type,
      'order.total': data.total,
      'customer.tier': data.customerTier,
    })

    // 处理订单...
  }
}

记录事件 ​

事件是跨度内带时间戳的注解。使用它们标记重要时刻。

ts
import { recordEvent } from '@adonisjs/otel/helpers'

export default class CheckoutService {
  async process(cart: Cart) {
    recordEvent('checkout.started')

    await this.validateCart(cart)
    recordEvent('checkout.cart_validated')

    const payment = await this.processPayment(cart)
    recordEvent('checkout.payment_processed', {
      'payment.method': payment.method,
      'payment.amount': payment.amount,
    })

    await this.fulfillOrder(cart)
    recordEvent('checkout.completed')
  }
}

上下文传播 ​

当你的应用调用其他服务或处理后台任务时，你需要传播追踪上下文，以便所有操作出现在同一追踪中。

传播到 HTTP 调用 ​

将追踪上下文注入到传出的 HTTP 请求头中。

ts
import { injectTraceContext } from '@adonisjs/otel/helpers'

export default class ExternalApiService {
  async fetchUserData(userId: string) {
    const headers: Record<string, string> = {
      'Content-Type': 'application/json',
    }

    /**
     * 添加 traceparent 和 tracestate 头。
     * 修改原始对象
     */
    injectTraceContext(headers)

    const response = await fetch(`https://api.example.com/users/${userId}`, {
      headers,
    })

    return response.json()
  }
}

传播到队列任务 ​

分发后台任务时，包含追踪上下文。

ts
import { injectTraceContext } from '@adonisjs/otel/helpers'

export default class OrdersController {
  async store({ request }: HttpContext) {
    const order = await Order.create(request.all())

    /**
     * 在任务元数据中包含追踪上下文
     */
    const traceHeaders: Record<string, string> = {}
    injectTraceContext(traceHeaders)

    await queue.dispatch('process-order', {
      orderId: order.id,
      traceContext: traceHeaders,
    })

    return order
  }
}

在你的队列工作进程中，提取上下文并继续追踪。

ts
import { extractTraceContext, record } from '@adonisjs/otel/helpers'
import { context } from '@adonisjs/otel'

export default class ProcessOrderJob {
  async handle(payload: { orderId: string; traceContext: Record<string, string> }) {
    /**
     * 从任务负载中提取追踪上下文
     */
    const extractedContext = extractTraceContext(payload.traceContext)

    /**
     * 在提取的上下文中运行任务
     */
    await context.with(extractedContext, async () => {
      await record('job.process_order', async () => {
        /**
         * 此跨度将是原始 HTTP 请求跨度的子级
         */
        const order = await Order.findOrFail(payload.orderId)
        await this.fulfillOrder(order)
      })
    })
  }
}

用户上下文 ​

当安装了 @adonisjs/auth 时，如果用户已认证，中间件会自动在跨度上设置用户属性。这包括 user.id、user.email（如果可用）和 user.roles（如果可用）。

你可以自定义此行为或添加额外的用户属性。

ts
import { defineConfig } from '@adonisjs/otel'

export default defineConfig({
  serviceName: 'my-app',

  /**
   * 禁用自动用户上下文
   */
  userContext: false,

  /**
   * 或使用解析器自定义
   */
  userContext: {
    resolver: async (ctx) => {
      if (!ctx.auth.user) {
        return null
      }

      return {
        id: ctx.auth.user.id,
        tenantId: ctx.auth.user.tenantId,
        plan: ctx.auth.user.plan,
      }
    },
  },
})

你也可以在代码中的任何地方手动设置用户上下文。

ts
import { setUser } from '@adonisjs/otel/helpers'

export default class AuthMiddleware {
  async handle({ auth }: HttpContext, next: NextFn) {
    await auth.authenticate()

    setUser({
      id: auth.user!.id,
      email: auth.user!.email,
      role: auth.user!.role,
    })

    return next()
  }
}

日志集成 ​

该包自动将追踪上下文注入到 Pino 日志中，向每条日志条目添加 trace_id 和 span_id。这让你在可观测性平台中将日志与追踪关联起来。

在开发中使用 pino-pretty 时，你可以隐藏这些字段以获得更清洁的输出。

ts
import app from '@adonisjs/core/services/app'
import { otelLoggingPreset } from '@adonisjs/otel/helpers'
import { defineConfig, targets } from '@adonisjs/core/logger'

export default defineConfig({
  default: 'app',
  loggers: {
    app: {
      transport: {
        targets: targets()
          .pushIf(!app.inProduction, targets.pretty({ ...otelLoggingPreset() }))
          .toArray(),
      },
    },
  },
})

保持特定字段可见。

ts
otelLoggingPreset({ keep: ['trace_id', 'span_id'] })

高级配置 ​

defineConfig 函数接受 OpenTelemetry Node SDK 的所有选项，为高级用户提供完全控制。

ts
import { defineConfig } from '@adonisjs/otel'
import { BatchSpanProcessor } from '@opentelemetry/sdk-trace-base'
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'

export default defineConfig({
  serviceName: 'my-app',

  /**
   * 使用 HTTP 而不是 gRPC
   */
  traceExporter: new OTLPTraceExporter({
    url: 'https://otel-collector.example.com/v1/traces',
    headers: { 'x-api-key': process.env.OTEL_API_KEY },
  }),

  /**
   * 带批处理配置的自定义跨度处理器
   */
  spanProcessors: [
    new BatchSpanProcessor(new OTLPTraceExporter(), {
      maxQueueSize: 2048,
      scheduledDelayMillis: 5000,
    }),
  ],

  /**
   * 自定义资源属性
   */
  resourceAttributes: {
    'deployment.region': 'eu-west-1',
    'k8s.pod.name': process.env.POD_NAME,
  },
})

所有可用选项请参阅 OpenTelemetry JS 文档。

性能考虑 ​

OpenTelemetry 会给你的应用增加一些开销。SDK 需要创建跨度对象、记录时间信息并将数据导出到你的收集器。在大多数应用中，这种开销可以忽略不计，但你应该注意它。

对于高流量的生产环境，考虑以下建议：

  • 使用采样以减少追踪量。samplingRatio 为 0.1（10%）通常足以识别问题，同时大幅减少开销和存储成本。

  • 使用批处理（默认）而不是立即发送跨度。BatchSpanProcessor 将跨度排队并批量发送，减少网络开销。

  • 对自定义跨度有选择性。自动插桩涵盖大多数需求。仅为你需要额外可见性的业务关键操作添加自定义跨度。不要通过在每一个类上使用 @spanAll 装饰器来过度插桩。

另请参阅：OpenTelemetry 采样文档
