Drive ​

本指南涵盖使用 Drive 在 AdonisJS 中进行文件存储管理。你将了解到如何：

  • 为你的应用安装和配置 Drive
  • 使用 moveToDisk 将文件上传到本地或云存储
  • 使用公共 URL 和签名 URL 显示文件
  • 配置多个存储服务（S3、GCS、R2、DigitalOcean Spaces、Supabase）
  • 实现从浏览器直接上传到云存储
  • 使用 Drive 的 fake API 测试文件上传

概述 ​

AdonisJS Drive 是 FlyDrive（由 AdonisJS 核心团队创建和维护）之上的封装。它提供了统一的 API，用于跨多个存储提供商管理用户上传的文件，包括本地文件系统、Amazon S3、Google Cloud Storage、Cloudflare R2、DigitalOcean Spaces 和 Supabase Storage。

Drive 的关键好处是你可以在存储服务之间切换而无需更改应用代码。在开发期间，你可能为了方便将文件存储在本地文件系统上。在生产环境中，你通过更改环境变量切换到云提供商。你的控制器、服务和模板保持不变。

TIP

Drive 处理读取、写入和删除文件等文件存储操作。它不处理 HTTP multipart 解析。你应该先阅读文件上传指南以了解 AdonisJS 如何处理来自 HTTP 请求的上传文件。

安装 ​

使用以下命令安装和配置 @adonisjs/drive 包：

sh
node ace add @adonisjs/drive

该命令会提示你选择一个或多个存储服务。

add 命令执行的步骤
  1. 安装 @adonisjs/drive 包和你所选服务所需的任何 peer 依赖。
  2. 在 adonisrc.ts 中注册 Drive 服务提供者。
  3. 使用你选择的服务创建 config/drive.ts 配置文件。
  4. 将所选服务的环境变量添加到 .env 和 start/env.ts。

非交互式安装

node ace add 命令需要交互式服务选择。如果你需要非交互式安装 Drive（例如在 CI 脚本中），可以手动执行以下步骤：

  1. 安装包：npm install @adonisjs/drive
  2. 为你的存储服务安装 peer 依赖（例如 S3 需要 npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner）
  3. 在 adonisrc.ts 中注册提供者：将 () => import('@adonisjs/drive/drive_provider') 添加到 providers 数组
  4. 使用你的服务配置创建 config/drive.ts（参阅下方配置部分）
  5. 将所需的环境变量添加到 .env 和 start/env.ts

配置 ​

Drive 的配置存储在 config/drive.ts 中。文件内容取决于你在安装期间选择的服务。

配置文件中的 default 属性决定当你不显式指定服务时使用哪个服务。DRIVE_DISK 环境变量控制此项，允许你在本地使用 fs，在生产环境中切换到 s3。

ts
import env from '#start/env'
import app from '@adonisjs/core/services/app'
import { defineConfig, services } from '@adonisjs/drive'

const driveConfig = defineConfig({
  default: env.get('DRIVE_DISK'),

  services: {
    // 服务配置放在这里
  },
})

export default driveConfig

declare module '@adonisjs/drive/types' {
  export interface DriveDisks extends InferDriveDisks<typeof driveConfig> {}
}

本地文件系统 ​

本地文件系统驱动将文件存储在服务器磁盘上，并可以通过 AdonisJS HTTP 服务器提供它们。

环境变量
dotenv
DRIVE_DISK=fs
配置
ts
{
  services: {
    fs: services.fs({
      /**
       * 文件存储的目录。使用 app.makePath
       * 从应用根目录创建绝对路径。
       */
      location: app.makePath('storage'),

      /**
       * 当为 true 时，Drive 注册一个路由来通过你的
       * AdonisJS 服务器提供本地文件系统中的文件。
       */
      serveFiles: true,

      /**
       * 提供文件的 URL 路径前缀。存储为
       * "avatars/1.jpg" 的文件可通过 "/uploads/avatars/1.jpg" 访问。
       */
      routeBasePath: '/uploads',

      /**
       * 文件的默认可视性。公共文件可
       * 通过 URL 访问。私有文件需要签名 URL。
       */
      visibility: 'public',
    }),
  }
}

TIP

启用 serveFiles 时，你可以通过运行 node ace list:routes 验证路由已注册。你应该会看到一个带有 drive.fs.serve 处理器的 /uploads/* 路由。

基本用法 ​

Drive 扩展了 AdonisJS 的 MultipartFile 类并添加了 moveToDisk 方法。此方法将上传的文件从其临时位置移动到配置的存储服务。

以下示例展示上传和显示用户头像的完整流程。

步骤 1：定义路由 ​

创建用于显示个人资料页面和处理头像上传的路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.get('profile', [controllers.Profile, 'show'])
router.post('profile/avatar', [controllers.Profile, 'updateAvatar'])

步骤 2：创建控制器 ​

控制器使用 moveToDisk 处理文件上传。使用 UUID 生成唯一文件名，以避免多个用户上传同名文件时发生冲突。

ts
import string from '@adonisjs/core/helpers/string'
import type { HttpContext } from '@adonisjs/core/http'
import { updateAvatarValidator } from '#validators/user'

export default class ProfileController {
  async show({ view, auth }: HttpContext) {
    const user = auth.getUserOrFail()
    return view.render('pages/profile/show', { user })
  }

  async updateAvatar({ request, auth, response, session }: HttpContext) {
    const user = auth.getUserOrFail()
    const { avatar } = await request.validateUsing(updateAvatarValidator)

    /**
     * 使用 UUID 生成唯一文件名，以避免多个用户
     * 上传同名文件时发生冲突。
     */
    const key = `${string.uuid()}.${avatar.extname ?? 'txt'}`

    /**
     * 将上传的文件移动到默认磁盘。
     * 文件从其临时位置移动到配置的存储服务。
     */
    await avatar.moveToDisk(key)

    /**
     * 仅将键存储在数据库中，而不是完整 URL。
     * 这允许你切换存储服务而无需更新数据库记录。
     */
    user.avatar = key
    await user.save()

    session.flash('success', 'Avatar updated successfully!')
    return response.redirect().back()
  }
}

步骤 3：创建模板 ​

模板使用 driveUrl 辅助函数显示当前头像，并提供上传新头像的表单。

edge
@layout()
  <div class="form-container">
    <div>
      @if(user.avatar)
        <img
          src="{{ await driveUrl(user.avatar) }}"
          alt="User avatar"
          style="max-width: 200px; border-radius: 8px;"
        />
      @end

      @form({ route: 'profile.update_avatar', method: 'POST', enctype: 'multipart/form-data' })
        <div>
          @field.root({ name: 'avatar' })
            @!input.control({ type: 'file' })
            @!field.error()
          @end
        </div>
        <div>
          @!button({ type: 'submit', text: 'Update avatar' })
        </div>
      @end
    </div>
  </div>
@end

driveUrl Edge 辅助函数生成文件的公共 URL。对于本地文件系统，这返回像 /uploads/abc-123.jpg 这样的路径。对于云提供商，它返回文件的完整 URL。

指定磁盘 ​

默认情况下，moveToDisk 使用 DRIVE_DISK 环境变量中指定的磁盘。你可以显式指定不同的磁盘作为第二个参数：

ts
// 移动到默认磁盘
await avatar.moveToDisk(key)

// 移动到特定磁盘
await avatar.moveToDisk(key, 's3')
await avatar.moveToDisk(key, 'gcs')
await avatar.moveToDisk(key, 'r2')

WARNING

moveToDisk 方法不同于 move 方法。move 方法仅在本地文件系统内移动文件。moveToDisk 方法将文件移动到配置的 Drive 存储服务，该服务可以是本地或基于云的。

使用 Drive 服务 ​

对于文件上传之外的操作，你可以直接使用 Drive 服务。从 @adonisjs/drive/services/main 导入它以读取文件、写入文件、删除文件等。

ts
import drive from '@adonisjs/drive/services/main'

export class FileService {
  /**
   * 获取默认磁盘实例
   */
  async readFile(key: string) {
    const disk = drive.use()
    return disk.get(key)
  }

  /**
   * 获取特定磁盘实例
   */
  async readFromS3(key: string) {
    const disk = drive.use('s3')
    return disk.get(key)
  }

  /**
   * 直接将内容写入存储
   */
  async writeReport(content: string) {
    const disk = drive.use()
    await disk.put('reports/monthly.txt', content)
  }

  /**
   * 删除文件
   */
  async deleteFile(key: string) {
    const disk = drive.use()
    await disk.delete(key)
  }

  /**
   * 检查文件是否存在
   */
  async fileExists(key: string) {
    const disk = drive.use()
    return disk.exists(key)
  }
}

Drive 服务提供更多文件操作方法。完整可用方法列表请参阅 FlyDrive Disk API 文档。

生成 URL ​

Drive 提供两种生成文件 URL 的方法：用于公共文件的 getUrl 和用于私有文件的 getSignedUrl。

公共 URL ​

使用 getUrl 为具有 public 可视性的文件生成 URL。任何拥有 URL 的人都可以访问这些文件。

ts
import drive from '@adonisjs/drive/services/main'

export default class FilesController {
  async show({ params }: HttpContext) {
    const disk = drive.use()
    const url = await disk.getUrl(params.key)

    return { url }
  }
}

在 Edge 模板中，使用 driveUrl 辅助函数：

edge
<img src="{{ await driveUrl(file.key) }}" alt="File" />

{{-- 指定磁盘 --}}
<img src="{{ await driveUrl(file.key, 's3') }}" alt="File" />

签名 URL ​

使用 getSignedUrl 为具有 private 可视性的文件生成临时 URL。这些 URL 在指定持续时间后过期。

当你想要控制对文件的访问时，签名 URL 很有用。例如，你可能将发票存储为私有可视性，并仅在授权用户请求下载时生成签名 URL。

ts
import drive from '@adonisjs/drive/services/main'

export default class InvoicesController {
  async download({ params, auth }: HttpContext) {
    const user = auth.getUserOrFail()
    const invoice = await Invoice.query()
      .where('id', params.id)
      .where('userId', user.id)
      .firstOrFail()

    const disk = drive.use()

    /**
     * 生成 30 分钟后过期的签名 URL。
     * 用户只能在 URL 有效期内下载文件。
     */
    const url = await disk.getSignedUrl(invoice.fileKey, {
      expiresIn: '30 mins',
    })

    return { url }
  }
}

在 Edge 模板中，使用 driveSignedUrl 辅助函数：

edge
<a href="{{ await driveSignedUrl(invoice.fileKey) }}">
  Download Invoice
</a>

{{-- 带过期时间 --}}
<a href="{{ await driveSignedUrl(invoice.fileKey, { expiresIn: '1 hour' }) }}">
  Download Invoice
</a>

{{-- 指定磁盘 --}}
<a href="{{ await driveSignedUrl(invoice.fileKey, 's3', { expiresIn: '1 hour' }) }}">
  Download Invoice
</a>

直传 ​

直传允许浏览器将文件直接上传到你的云存储提供商，绕过你的 AdonisJS 服务器。这对于大文件很有用，因为数据不流经你的服务器，减少了内存使用和带宽成本。

流程如下：

  1. 浏览器从你的服务器请求签名上传 URL。
  2. 你的服务器使用 Drive 生成签名 URL 并返回它。
  3. 浏览器使用签名 URL 将文件直接上传到云提供商。
  4. 浏览器通知你的服务器上传已完成。

步骤 1：定义路由 ​

创建用于生成签名上传 URL 和处理上传完成的路由。

ts
import router from '@adonisjs/core/services/router'
import { controllers } from '#generated/controllers'

router.post('uploads/presign', [controllers.Uploads, 'presign'])
router.post('uploads/complete', [controllers.Uploads, 'complete'])

步骤 2：创建控制器 ​

控制器使用 getSignedUploadUrl 生成签名上传 URL 并处理上传完成通知。

ts
import string from '@adonisjs/core/helpers/string'
import drive from '@adonisjs/drive/services/main'
import type { HttpContext } from '@adonisjs/core/http'

export default class UploadsController {
  /**
   * 为直传生成签名 URL
   */
  async presign({ request, auth }: HttpContext) {
    const user = auth.getUserOrFail()
    const { filename, contentType } = request.only(['filename', 'contentType'])

    /**
     * 为文件生成唯一键
     */
    const key = `uploads/${user.id}/${string.uuid()}-${filename}`

    const disk = drive.use('s3')

    /**
     * 生成允许浏览器直接上传到 S3 的签名 URL
     */
    const signedUrl = await disk.getSignedUploadUrl(key, {
      expiresIn: '15 mins',
      contentType,
    })

    return {
      key,
      url: signedUrl,
    }
  }

  /**
   * 处理上传完成通知
   */
  async complete({ request, auth }: HttpContext) {
    const user = auth.getUserOrFail()
    const { key } = request.only(['key'])

    /**
     * 验证文件存在
     */
    const disk = drive.use('s3')
    const exists = await disk.exists(key)

    if (!exists) {
      return { error: 'File not found' }
    }

    /**
     * 将文件引用保存到数据库
     */
    await user.related('files').create({ key })

    return { success: true }
  }
}

步骤 3：实现客户端上传 ​

在前端，请求签名 URL，然后直接将文件上传到云提供商。

ts
async function uploadFile(file: File) {
  /**
   * 步骤 1：从你的服务器请求签名上传 URL
   */
  const presignResponse = await fetch('/uploads/presign', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      filename: file.name,
      contentType: file.type,
    }),
  })

  const { key, url } = await presignResponse.json()

  /**
   * 步骤 2：使用签名 URL 将文件直接上传到云存储
   */
  const uploadResponse = await fetch(url, {
    method: 'PUT',
    headers: {
      'Content-Type': file.type,
    },
    body: file,
  })

  if (!uploadResponse.ok) {
    throw new Error('Upload failed')
  }

  /**
   * 步骤 3：通知你的服务器上传已完成
   */
  await fetch('/uploads/complete', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ key }),
  })

  return key
}

测试 ​

Drive 提供用于测试文件上传而不与真实存储交互的 fake API。当你 fake 一个磁盘时，所有操作都被重定向到临时本地目录，而不是配置的存储服务。

ts
import { test } from '@japa/runner'
import { fileGenerator } from '@poppinss/file-generator'
import drive from '@adonisjs/drive/services/main'
import { UserFactory } from '#database/factories/user_factory'

test.group('Profile | update avatar', () => {
  test('user can upload an avatar', async ({ client }) => {
    /**
     * Fake 默认磁盘。所有文件操作现在将使用临时本地
     * 目录而不是配置的存储服务。`using` 关键字在
     * 测试结束时自动恢复真实磁盘。
     */
    using fakeDisk = drive.fake()

    const user = await UserFactory.create()

    /**
     * 生成带有有效 PNG 魔数的缓冲区。
     * AdonisJS 使用魔数检测来确定文件类型，
     * 因此普通的 Buffer.from('fake-image') 将被拒绝。
     */
    const pngFile = await fileGenerator.generatePng(1)

    await client
      .post('/profile/avatar')
      .file('avatar', pngFile.contents, {
        filename: pngFile.name,
        contentType: pngFile.mime,
      })
      .loginAs(user)
      .assertStatus(200)

    /**
     * 断言文件已存储
     */
    fakeDisk.assertExists(`${user.id}.png`)
  })

  test('rejects invalid file types', async ({ client }) => {
    using fakeDisk = drive.fake()

    const user = await UserFactory.create()

    const pdfFile = await fileGenerator.generatePdf(1)

    await client
      .post('/profile/avatar')
      .file('avatar', pdfFile.contents, {
        filename: pdfFile.name,
        contentType: pdfFile.mime,
      })
      .loginAs(user)
      .assertStatus(422)

    /**
     * 断言未存储任何文件
     */
    fakeDisk.assertMissing(`${user.id}.pdf`)
  })
})

TIP

AdonisJS 使用魔数检测来确定文件类型，而不是你传递的文件名或内容类型。普通的 Buffer.from('fake-image') 没有有效的魔数，因此 VineJS 文件验证会以 "Invalid file extension undefined" 拒绝它。使用 @poppinss/file-generator 包（包含在 AdonisJS 项目中）为你的测试生成具有正确魔数的缓冲区。

你也可以 fake 特定的磁盘：

ts
// Fake 特定磁盘
using fakeDisk = drive.fake('s3')

// Fake 多个磁盘
using _s3 = drive.fake('s3')
using _gcs = drive.fake('gcs')

如果你需要更多控制真实磁盘何时恢复，也可以手动调用 drive.restore()。

故障排除 ​

上传后文件损坏 ​

一些云存储提供商在流式上传方面存在问题。如果你的文件在上传后损坏，尝试使用 moveAs: 'buffer' 选项在上传前将文件读入内存：

ts
await file.moveToDisk(key, 's3', {
  moveAs: 'buffer',
})

这会在将整个文件发送到存储提供商之前将其读入内存，可以解决某些提供商的兼容性问题。

理解文件可视性 ​

Drive 支持两个可视性级别：

  • public：任何人都可以通过 URL 访问文件。使用 getUrl 生成 URL。
  • private：文件不可公开访问。使用 getSignedUrl 生成带有过期时间的临时 URL。

可视性在你的配置中在磁盘级别设置。上传到该磁盘的所有文件都继承可视性设置，除非被覆盖。

ts
{
  services: {
    // 此磁盘上的所有文件都是公共的
    publicFiles: services.s3({
      // ...凭据
      visibility: 'public',
    }),

    // 此磁盘上的所有文件都是私有的
    privateFiles: services.s3({
      // ...凭据
      visibility: 'private',
    }),
  }
}
